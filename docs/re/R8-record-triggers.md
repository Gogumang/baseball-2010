## 요약
**다 풀었다.** 지급 함수 0xa77f0 을 부르는 곳은 25곳(BL)이고 기록 40종 전부의 번호·조건·시점·대상을 8절 표에 모았다. 0xa77f0 은 "누구의 기록" 이 아니라 **"사람 팀이 공격 중이냐 수비 중이냐"** 로 거른다: 0~15·32~35·37~39 는 사람 공격, 16~31·36 은 사람 수비, 28~31·37~39 는 거르지 않는다(대신 경기 끝 함수가 사람 팀 승리를 본다). 자동진행 뒤·미션·홈런더비에서는 아무 기록도 없다.
웹에 없던 것: **대타 홈런(5)** = 대타를 낸 그 타석의 홈런(ctx+0x160, 교체 0xa5bf0), **백투백(6·7)** = 사람 팀 타석 홈런 카운터 ctx+0x162(홈런 아닌 결과면 0, 3 에서 0), **도루 성공(8)**·**도루 저지(24)** = 주자 플레이(종류 5) 정산에서 잡힌 도루 주자가 있으면 24 한 번, 없으면 옮긴 주자마다 8, **병살·삼중살(26·27)** = 공 하나 플레이의 아웃 2·3 (이벤트 목록이 투구마다 비워지는 것 확인 — E-9 의 "유력" 해소), **3·4연속 파울(32·33)** = ctx+0x15f, 0x51408 판정 v=7 이 파울(L 노트의 "경기/이닝 끝" 정정), **2·3볼넷(34·35)** = 결과 8 개수(사구 제외), 필살송구(36) = R3.
**0xa7998 = 삼진 콤보 18~20 + 한 투수 10/15/20삼진 21~23 판정**(현재 투수의 경기 기록 R[1]·R[0]).
**웹과 가장 큰 차이**: 완투 계열 28~31 을 웹은 조건 없이 주지만 원본 0xa7de8 은 사람 팀 승리 + 모드 ≠ 4(나리 타자편) + 사람이 코스를 확정한 적 있음 + 현재 투수 아웃 == 3×치른 이닝 일 때만 준다 → 모드 4 인 웹에선 원본대로면 한 번도 안 나와야 한다.
남은 것(유력): 대타 플래그의 교체↔타석초기화 순서, 연속 파울 리셋이 0x3dfac 의 모든 갈래를 지나는지, state[0x88]·[0x89] 이름, ctx+0x24 첫 바이트 = 자동진행 표시라는 해석.

## 1. 지급 함수 0xa77f0(ctx, k) — **확정**(게이트 전체), ctx+0x24 의 뜻만 유력

ctx = 경기 장면 `[scene+0x230]` (생성 0xa9024, vtable 0xd8150; 경기 끝 0x4ea0c 가 `[r7+0x230]` 로 0xa7de8 호출). 필드:
- `ctx+8` = 경기 상태 state(전역 0x1552d0c). `state[1]` = 게임 모드, `state[9]` = 공격 팀, `state[0xa]` = 수비 팀, `state[0x31+팀]==0` = 그 팀을 사람이 조작(V5 확정).
- `ctx+0x28` = 저장 관리자 0x1fce1(`[0x1400054]`) 가 돌려준 **기록 누계 바이트 배열**(0x3e9ba~0x3e9bc). 누계는 255 에서 멈춘다.
- `ctx+0x180` = `scene+0x1b64` 를 가리키는 포인터 = **경기 중 G 누계 int** (0x3e9c0~0x3e9ca).
- `ctx+0x24` = `scene+0x1780` 간이 시뮬레이터 객체(0xc0d60 생성, 0x3ea12). 그 첫 바이트는 0xc0dac(시뮬 초기화 — 경기 시작 0x3c158·0x3f584, CPU 경기 0xc2760 등)에서 0, **0xc1b48(자동진행 전환, 호출 0x50794·0x52c50)에서 1**. → 유력: "자동진행(30G 스킵)이 걸린 뒤로는 기록 없음".

```
a77f2: if [[ctx+0x24]] != 0 → return          ; 자동진행 중(유력)
a7802: if ctx+0x28 == 0 → return
a780a: if state[1] ∈ {5,6,7} → return          ; 미션 투수·타자, 홈런더비
a7818: if (k-28) ≤ 11 && (1<<(k-28)) & 0xe0f   ; k ∈ {28,29,30,31, 37,38,39}
          → 무조건 집계 (팀 조건 없음)
a785e: elif state[0x31+state[9]] == 0 (공격 팀이 사람):
          k ≤ 15 or 32 ≤ k ≤ 39, 단 k ≠ 36 → 집계
a78bc: elif state[0x31+state[0xa]] == 0 (수비 팀이 사람):
          16 ≤ k ≤ 31 or k == 36 → 집계
       else return
집계: cnt[k]++ (≤255) ; [ctx+0x180] += u32 0xd8158[k] ;
      0xa91fd(ctx+0x170, &k)   ; 화면 알림 큐에 k 를 넣음(유력: 표시용)
      0x62235([0x1552cfc], k)  ; 누계 해금 (K 3-1)
```
- **대상은 "선수" 가 아니라 "사람 팀"** 이다. 공격 계열(0~15·32~35·37~39)은 사람이 공격할 때, 수비 계열(16~31·36)은 사람이 수비할 때만. 누가 쳤는지(본인·동료)는 여기서 따지지 않는다.
- 28~31(완투 계열)·37~39(점수차 승)는 게이트를 건너뛴다 → 호출하는 쪽(0xa7de8)이 "사람 팀 승리"인지 스스로 가려야 한다(6절).
- 수비 팀도 공격 팀도 사람이 아닌 경기(CPU끼리 0xc2760 등)는 위 무조건 7종만 들어갈 수 있다(그쪽 ctx 는 따로 만든다: 0xc2790 에서 0xa9025).

## 3. 타격 계열 판정 함수

공통: 팀 경기 객체 `T = ctx+0xc+4*팀` 을 `[..]` 로 읽는다. 타자 경기 기록 `B = T+0x34 + 0x18*T[0x32]`(T[0x32] = 현재 타순), `B[0xc]` = 이번 경기 타석 수 n, `0x53101(B,i)` = i번째 타석 결과 코드. 결과 코드: 1~4 = 1루타~홈런(0xa75f4: `code−1 ≤ 3` 이면 안타), 8 = 볼넷.

### 3-1. 0xa7b90 연타석 9·10·11 — **확정**
```
if 공격 팀 사람 && [[ctx+0x24]] == 0 && n > 0:          ; 자동진행 아님을 여기서도 한 번 더 봄
  if n > 4 && 최근 5타석 모두 안타(0xa76f0(B,5)):
       if n > 5 && (n−6)번째 타석도 안타 → 아무것도 안 줌   ; 6연타석 이상은 기록 없음
       else → k 11 (x5)
  elif n > 3 && 최근 4타석 안타 → k 10 (x4)
  elif n > 2 && 최근 3타석 안타 → k 9 (x3)
```
- 0xa76f0(ctx,B,m): 마지막 타석부터 m 개가 모두 결과 1~4 인가. 볼넷(8)·아웃은 끊는다.
- 주의: "4연타석" 인데 앞(5번째 전)이 안타면 첫 가지로 가서 k11 판정을 받는다 → 5연타석이 되는 순간 k11, 4연타석 순간엔 k10. 결국 3·4·5 번째 연속 안타에서 각 한 번씩, 6번째부터는 없음.
- 호출: 0xa876a (0xa8024 안, 5절에서 조건).

### 3-2. 0xa7b00 한 타자 2·3·4홈런 12·13·14 — **확정**
공격 팀 사람일 때 현재 타자의 이번 경기 타석 중 결과 4(홈런) 개수 h: `h==4 → 14, elif h==3 → 13, elif h==2 → 12`. 호출 0xa8750.

### 3-3. 0xa7a7c 한 타자 2·3볼넷 34·35 — **확정**
공격 팀 사람일 때 현재 타자의 결과 8(볼넷) 개수 w: `w==3 → 35, elif w==2 → 34`. 호출 0xa8b40.

### 3-4. 0xa794c 백투백 6 · 백투백투백 7 — **확정**(카운터), 호출 조건은 5절
```
c = ctx+0x162 (s8)
if 공격 팀 사람: c++ ; if c==2 → k 6 ; elif c==3 → k 7, c = 0
else: c = 0
```
- 3연속이면 k6(두 번째 홈런 때) + k7(세 번째 때) 둘 다. k7 뒤 0 으로 돌아가므로 4연속 홈런은 다음 두 개째에서 다시 k6.
- ctx+0x162 가 홈런 아닌 타석에서 0 으로 돌아가는 곳은 5절.

## 4. 투수·볼카운트 계열 (0xa7c4c · 0xa7d0c · 0xa7dbc · 0xa7998) — **확정**(식), 카운터 리셋 지점 일부 유력

ctx 카운터(타석·이닝 단위):
| 칸 | 뜻 | 올림 | 0 으로 |
|---|---|---|---|
| ctx+0x15f (u8) | 이번 타석 **연속 파울** 수 | 0xa7dbc | 0xa5bcc(타석 초기화) · 0xa5fdc(← 0x3dfac 공 도착 판정 끝 0x3e1f4) |

### 4-1. 0xa7c4c 삼진 처리 → 16 삼구삼진 · 17 풀카운트삼진 — **확정**
```
R = 수비팀 현재 투수 기록 ; R[0]++ ; R[1]++
이벤트 목록 ctx+0x30[ctx+0x2c++] = 5 (삼진)
0xa56dc(...) 참이면 state+0x64 −1 ; 0xa57f8(ctx, 0x1a, 1)        ; 투수 아웃 수 +1 (P7 E3)
if ctx+0x161 == 3            → k 16  (이 타석 셋째 공에 삼진 — 파울 포함 공 수)
if state[4]==2 && state[5]==3 → k 17  (2스트 3볼에서 삼진 = 풀카운트)
```
- 호출: 0x3dfac(사람 경기, 공 도착 판정) · 0x51408(판정 v=5) · 0xc15a4 · 0xc1818(간이 경기). 게이트상 **사람이 수비(투수)일 때만** 집계.
- 16·17 은 둘 다 날 수 있다(삼구에 풀카운트는 불가능하므로 실제로는 배타).

### 4-2. 0xa7998 삼진 콤보 18·19·20 · 한 투수 10/15/20삼진 21·22·23 — **확정** (Q0 의 "0x12·0x15" 는 합류 지점의 마지막 값일 뿐, 실제 6종)
```
if 공격 팀이 사람 → return
R = 수비팀 현재 투수 기록
if R[1]==9 → 20 elif R[1]==6 → 19 elif R[1]==3 → 18
if R[0]==20 → 23 elif R[0]==15 → 22 elif R[0]==10 → 21
```
- **대상은 "현재 투수"** 의 기록이다(투수가 바뀌면 새 투수의 R). 호출 0xa8d5a(0xa8024 안 — 5절에서 조건).
- 콤보는 정확히 3·6·9 에서만(12 는 없음). 한 투수 삼진은 정확히 10·15·20.

### 4-3. 0xa7d0c 아웃 처리 → 25 삼구 삼자범퇴 — **확정**
```
이벤트 목록에 0xd(아웃) 추가 ; 0xa57f8(ctx, 0x1a, 1)
if 수비 팀이 사람:
   if ctx+0x16c == 3 && state[6](아웃) == 3 → k 25       ; 반 이닝 공 3개로 3아웃
   if state[6]==3 && ctx+0x184 != 0 → 0xa57f8(ctx, 0x20, 0)  ; (통계 칸 0x20 — 삼자범퇴 계열로 보임, 이 문서 범위 밖)
```
- 삼진 아웃은 0xa7c4c 로 가고 25 를 보지 않는다(공 3개로 3아웃이면 삼진은 있을 수 없으니 상관없음).
- 안타·볼넷이 끼어도 공 3개로 3아웃이면 준다(출루 검사 없음) — 예: 1구 안타, 2구 병살, 3구 아웃. 웹 `threePitchInningRecordIdsOf` 와 같다.

### 4-4. 0xa7dbc 파울 → 32 3연속 파울 · 33 4연속 파울 — **확정**(식) / 리셋 지점 **유력**

### 5-1. 0xa810c — 36 필살송구 아웃 (R3 5절 그대로) — **확정**

### 5-2. 0xa83de — 24 도루 저지 · 0xa83c6 — 8 도루 성공 — **확정**(식) — E-9 의 24 "유력" 을 올린다

### 5-4. 범타·볼넷·사구 갈래와 백투백·삼진 콤보 리셋 — **확정**
- 범타/삼진(타석 결과 5·6 을 B 에 적는 갈래, 0xa8a6a~0xa8aae) 뒤 **ctx+0x162 = 0** (0xa8ab2).

- 사구: `state[0x12]` → B 에 결과 **9** (볼넷 판정 0xa7a7c 는 **부르지 않음** → 사구는 2·3볼넷에 안 들어간다) → 투수 +0x2a ++ → ctx+0x162 = 0 (0xa8bf8).
  → 백투백 카운터는 "사람 팀 타석이 홈런 아닌 결과로 끝나면 0". 그러니 6·7 은 **사람 팀의 연속 타석 홈런**(타순상 이어진 타자). 도루 플레이(종류 5, 타석 완료 아님)는 건드리지 않는다.

### 5-5. 0xa8d5a — 0xa7998 (18~23) 부르는 조건 — **확정**
```

          0xa57f8(ctx, 0x18, 삼진 수 sp+0x20)   ; P1 표의 탈삼진
          if 삼진 수 > 0 → 0xa7998              ; 이번 플레이에 삼진이 있었을 때만
```
- 연속 삼진 R[1] 의 0 리셋 (함수 끝 0xa8fb2~0xa8ff8): 플레이 종류가 4·5 가 아니고 `!(삼진 수 > 0 && state[0x1a] == 0)` 이면 R[1] = 0.
  즉 **삼진 아닌 결과로 끝난 타석마다 콤보가 끊긴다.** "주자 달리는 중 삼진"(state[0x1a]=1) 은 삼진 자체는 R[0]·R[1] 에 들어가지만(0xa7c4c) 정산 끝에서 콤보를 끊는다.

### 5-6. 0xa8e70 — 26 더블플레이 · 0xa8e84 — 27 트리플플레이 — **확정** (E-9 의 "유력" 고리 해결)

## 6. 경기 끝 0xa7de8 — 37~39 점수차 승 · 28~31 완투 계열 — **확정**

## 7. 0xa7998 의 정체 — **확정**
**삼진 콤보(18·19·20) + 한 투수 10/15/20삼진(21·22·23) 판정 함수** (4-2 절). Q0 가 적은 "k=0x12·0x15" 는 `movs r1` 뒤 `b` 로 합류하는 두 BL 자리의 마지막 값이고, 실제로는 0x12/0x13/0x14 와 0x15/0x16/0x17 여섯 값을 준다.
플레이 정산 0xa8024 가 "플레이 종류 4·5 아님 && 이번 플레이 삼진 ≥1" 일 때만 부른다(0xa8d5a). 읽는 값은 **수비 팀 현재 투수의 경기 기록**(0xb8cec: 팀+0x244+4·팀[0]) R[1] 연속 삼진, R[0] 이 투수의 경기 삼진.
웹판은 0xa7c4c·0xa7d0c 를 삼진 계열 판정 자리로 적었으나(gameRecords.ts:159) 16·17 은 0xa7c4c, 18~23 은 0xa7998, 25 는 0xa7d0c 다.

### 7-1. 덤 — 사람 조작 칸 state[0x31+팀] 을 모드별로 세우는 곳 (0x39fdc, 모드 점프표 0xcfef8) — **확정**
모드 0 → 0x39ff6, 1·8·9 → 0x3a076, 2 → 0x3a3c0, **3·4 → 0x3a0e8**, 5·6 → 0x3a588, 7 → 0x3a43e. 모드 3·4 갈래(0x3a20a)는 `0xb6c18(state, 내 팀, 0)`, `(state, 상대, 1)` → **나만의리그 타자편(모드 4)에서도 내 팀 전체가 "사람 팀"** 이다.
따라서 모드 4 에서도 내 팀이 수비할 때 16~27·36 게이트가 열린다(웹이 상대 공격 반 이닝에서 16~23·25 를 세는 것과 맞다). 다만 28~31 은 0xa7de8 이 모드 4 를 따로 막는다(6절).

## 9. 웹 gameRecords.ts 와 다른 점 (번호별, 고치지 않음)

웹 = 원래 저장소 `src/entities/game/model/gameRecords.ts`, 호출 `features/play-game/model/gameFlow.ts:268-277`, `entities/game/model/simulateHalfInning.ts:81-105`, `entities/game/model/batterGameLog.ts:45`. 웹은 나만의리그 타자편(모드 4) 이다.

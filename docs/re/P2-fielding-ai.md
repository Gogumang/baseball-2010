## 요약

**풀린 것(확정)**: 원본 사람 경기 수비는 타구 순간 궤적을 끝까지 미리 계산해 두고, 예측기 **0xb12d0** 이 야수 9명을 복제해 틱마다 "종류별 가장 이른 포구 틱"(낮은 공 ≤1000 / 가슴 1001~1700 / 바운드 전 낮은 공 ≤500·반경 1000 / 점프 1701~4000·±299 / 슬라이딩 501~1500·거리 2000~3000)을 표로 만든다. 포구 반경은 **내야 500 · 외야 300**.
**0xb3b38** 이 우선순위(낮은 공 > 가슴 > 땅볼 > 점프 > 슬라이딩 > 바운드 뒤)로 추적야수와 포구 틱을 고르고, 외야면 가까운 외야수 한 명을 백업(상태 0xc)으로 보낸다. 야수 이동은 목표점으로 **틱당 220 직선(능력치 무관)**, AI 상태 16가지 분기표 0xd8808.
뜬공 아웃 = 타자주자가 있는 플레이에서 공이 처음 쥐어질 때(+0x112=0) — state[0x1f]; 바운드·포구 때 state[0x1e]. state[0x20] = 담장선 넘는 틱, state[0x80] = 폴 맞은 틱(둘 다 타구 시작 0x511ea/0x511f4, 튕김 때 다시), → 그라운드 룰 2루타 확정.
포스/태그업은 주자 +0x88(반드시 밟을 루)로: 바운드면 출발루+1, 뜬공 포구면 출발루. 자동 추가 진루 **0xaf918 = "다음 루에 수비 송구(0xaf284)보다 2틱 넘게 먼저 닿으면 간다"**, 잡힐 뜬공이면 잡힐 때까지 안 뜀 — 단 플레이 **+0x111(끝남)·+0x129** 가 서면 그 모든 검사를 건너뛰고 **주자 전원 무조건 한 루**다 (5a 정정).
송구: 루로 보내기 0xb2c90(직접 뛰는 게 빠르면 직접 밟음), 계획 0xb3444(외야 송구 ≥17000 이면 내야 중계 + 3틱), CPU 협살 0xb3a94(진행률 >35% 주자). CPU 송구는 제어기 0xafa60(홈 송구 20% 특수).
I-controls 정정 2건: 940+8g 는 달리기가 아닌 **송구 속도**(야수 +0x8c=3g 는 읽는 곳 없음), 펌블 굴림은 땅볼 한정이 아니라 **움직이는 공 전부**. sp+0x20 은 "닿는 거리" 가 아니라 h ≤ 500.
**남은 것**: CPU 목표 루 점수식 0xafb24 세부(가중치·난이도), 0xaf284 세부 분기, 0xb030c, 충돌 종류(공 vt 0x6c 호출부), state[0x19] 0.1% 사건의 정체, 페어/파울 0x9d660 문턱, 2아웃 득점 보류(메시지 0x13) 처리, 메시지 0xbc3 처리처, AI 상태 8·9·0xe 세부.

야수 필드 재확인 (0xb0fb4, 0xa0fc4, 0xb0f88, 기반 캐릭터 0xbec7c~0xbf07x):
- 기반 캐릭터(모든 야수·주자·공 공통): **+0x14 현재 위치 (x,y,z)**, **+0x2c 목표점 (x,y,z)**, **+0x3c 달리기 속도**, +0x40 (0 으로 초기화).
  0xbec7c(obj,v,w) = `+0x3c=v, +0x40=w`. **0xbf01c = 도착까지 틱** = `속도==0 ? 1000 : 0x6c5d8(거리(위치,목표), 속도)` (0xbfa2c 거리, 0x6c5d8 나눗셈).
  0xbefec = vt1c(목표점) 로 목표 재설정 후 틱 계산.
- **야수 달리기 속도 +0x3c = cfg+0x18 = 220 — 모든 야수 같은 값** (vt64 = 0xa2164 `ldrsh [cfg,#0x18]`; 0xb0f88 이 9명 모두에 `+0x3c = vt64(), +0x40 = 0, +0xcc = 0`; 0xb1144~0xb115e 도 같다). d_level.dat 파일 0x14 = 0x00dc = 220, 폴백 0xb6f48 `movs #0xdc; strh [+0x18]` 로 이중 확인.
- **940+8g 는 달리기가 아니라 송구 공 속도**다 (I-controls 1a 의 "이동속도" 표기는 틀림, 2b 가 맞음):
  0xa0fc4 → `+0xdc = +0xd4 = 940+8g`, `+0xd8 = ×130/100`. 던지기 0xa1620 이 0xa16da~0xa16ec 에서 `+0xdc = 특수 ? +0xd8 : +0xd4` 로 골라 송구 속도로 쓴다.
- **+0x8c = 3×g (+팀 보너스)** (0xb108c~0xb10fc, g = 등급+1, 선수 없으면 g=2): 쓰는 곳을 `adds #0x80 → [#0xc]`·`movs #0x8c` 두 형태로 0xa0000~0xc0000 전역 검색했으나 **읽는 곳은 0xaf716~0xaf724 (객체 필드를 스택으로 통째 복사) 하나뿐** → 복사본에서 쓰일 수 있음. 이름은 1c 항목에서 다시 본다(현재 **유력: 반응/범위 보정**, E 의 "이동 = 3(g+1)" 표기는 근거 없음).
- 야수 +0x88 = 수비 칸(0~8), +0xe4 = 악송구 보정, +0xec = 선수 레코드, +0xf0 = 팀, +0xa8 = 동작 번호, +0xac = 동작 경과 틱, +0xb4 = 동작 잠금 카운트(0 되면 vt10), +0xb8/+0xc0/+0xc4/+0xe8 = 틱마다 1 씩 줄어드는 카운터 (0xa1284 = 야수 vt0c 틱).

## 1a. 공 쫓는 야수 고르기 — 플레이 vt 0x34 = 0xb3b38 — **확정**(식) / 포구 종류 이름 **유력**

타구 시작(플레이 vt18 = 0xb27ec, 종류 1 → 0xb280a): `vt1c · vt20(1)(=0xb0fb4 능력) · 추적야수(+0x130)=1 · vt24(1)(=0xb12d0 예측표, 2a) · vt34(=0xb3b38 고르기) · vt30(=0xb1c90 송구/커버)`.
(종류 9 도루 = 0xb284a 도 같은 순서, 추적야수 = 1 포수. 분기표 0xd877c.)

야수의 AI 부분 객체 = 야수+0x80: `+0x84 = AI 상태`, `+0x88 = 수비 칸`, `+0x90 = 목표점 (x,y,z)`. 0xb8dbc(ai, s) = 상태 쓰기, 0xb8da8(ai) = 칸 6~8(외야) 인가.

0xb3b38:
```
+0x130 = 0 ; L = 공+0xaa0 (낙구 틱) ; W = 공+0xaa4 (−1 이 아니면 다른 사건 틱 — 담장/바운드로 보임, 유력)
상태가 1 또는 0xc 인 야수는 상태 0 으로 되돌림
표(2a)에서 종류별 최소 틱과 그 야수:  낮은 공 lo(+0x60) · 가슴 mid(+0x84) · 점프 jp(+0x3c) · 땅볼 gd(+0xa8) · 슬라이딩 sl(+0xcc)  (없으면 100000)
Q = 공 예측점(lo 틱) ; near = Q 에 가장 가까운 야수(동작 잠금 +0xb4 ≤ 0, +0xbc == 0 인 야수만)
우선순위 (+0x16c = 포구 종류, +0x170 = 고른 야수):
  1. lo ≤ L                → 종류 0, near                (뜬 채로 낮게 잡힘 → 가장 가까운 야수)
  2. mid ≤ L               → 종류 1, mid 의 야수
  3. gd ≤ L                → 종류 2, gd 의 야수
  4. jp ≤ L (1 이 아니면)   → 종류 3, jp 의 야수   (점프)
  5. sl ≤ L (1 이 아니면)   → 종류 4, sl 의 야수   (슬라이딩)
  6. lo 야수 있고 lo < mid+2 → 종류 0, lo 의 야수        (낙구 뒤 = 바운드 뒤 잡기)
  7. mid 야수 있고 mid+2 < gd+5 → 종류 1, mid 의 야수
  8. gd 야수 있으면          → 종류 2, gd 의 야수 ; 아무도 없으면 종류 0, near
포구 틱 +0x174 / 동작 시작 틱 +0x176 (분기표 0xd87c0):
  종류0: lo / lo · 종류1: mid / mid−2 · 종류2: gd / gd−1 · 종류3: jp / jp−8 · 종류4: sl / sl−6
+0x130(추적야수) = +0x170 ; 추적야수 AI 상태 = 1 (이미 0xb 가 아니면)
m = min(gd, mid, lo) ; W ≠ −1 && W < m 이면 → 추적야수 상태 0xb, 목표 +0x90 = (공점(W−2).x, 0, 공점(W−2).z)   ; 아무도 먼저 못 잡으면 그 지점으로 달려가 줍기
아니고 추적야수가 외야(칸 6~8)면 → 다른 외야수 중 Q 에 가장 가까운 한 명(거리 < 400000) 상태 0xc (백업, 유력)
+0x1f0 ≠ −1 이면 0xb3a94
```
근거: 최소 찾기 0xb3b9c~0xb3be8, 가까운 야수 0xb3c00~0xb3c6c(0xbf9f0), 우선순위 0xb3c6e~0xb3da2, 틱 표 0xb3dc4~0xb3e32, 담장 0xb3e5c~0xb3ebc, 백업 0xb3ebe~0xb3f62.
- 즉 원본 수비는 "가장 가까운 야수"가 아니라 **궤적을 미리 돌려 가장 먼저 잡을 수 있는 야수**를 고르고, 뜬공 직접 포구 > 땅볼 > 필살(점프·슬라이딩) > 바운드 뒤 순으로 우선한다.
- 0xb1900(플레이 vt 0x2c)은 주자 도착 틱과 공 도착을 비교해 3·6·7·8·9·0xc~0x18 같은 코드를 돌려주는 별도 분류기다(타구 종류 연출/해설로 보임 — 이 항목과 무관, 미확인).

## 1b. 낙구 지점 예측 · 목표점 — **확정**(칸 뜻) / 충돌 종류 이름 **유력** (공 물리식 자체는 E-10 에 있음, 다시 풀지 않음)

- 원본은 타구 순간 **공 궤적 전체를 미리 계산해 표로 둔다**: 0xa29bc(공, i) 가 i 번째 점(20바이트: 위치 x,y,z · +0x3c · +0x40 · +0x70 각도 · +0xa9c 바운드 표시)을 공+0x74 부터 적고 `공+0x6c = i+1`(점 개수, 최대 130).
  0xa2b78(out, 공, t) = 점 t (0 ~ 개수−1 로 자름) — 예측기·AI 가 쓰는 "공점(t)" 이다(주소 0xa25b0 은 이것을 부르는 얇은 포장).
- 사건 틱 (모두 −1 로 시작, 0xa2974 초기화):
  - **공+0xaa0 = 낙구 틱** = 처음으로 높이 ≤ 0 이 된 점 번호 (0xa29f4~0xa2a0c `[점+4] ≤ 0 && aa0 == −1 → aa0 = i`)
  - 공+0xaa4 = 충돌 사건(구조체 바이트 +0x3a 또는 +0x39) 첫 틱, 공+0xab0 = 담장 튕김(+0x38) 첫 틱 — 튕기면 각도 += rand(−25,25), 속도 ½ (0xa2c48~0xa2ca8),
    공+0xaa8 = 높이 ≤ 1999 에서 맞은 다른 충돌 첫 틱(각도 교체·속도 ½). 충돌 종류를 가리는 호출부(공 vt 0x6c = 0xa2bf0 를 부르는 곳)는 못 찾았다(유력: 0x3a·0x39 = 담장 위/폴, 0x38 = 담장 면).
  - 공+0xac4 = 낙구점이 홈 (20000,0,29445)(표 0xd7be8)에서 **10274 넘게** 떨어지고 각도가 페어 범위(`각+0x87 ≤ 0x5a`)면 1 — 깊은 타구 표시. 0x528b0(화면)이 낙구 틱에 연출용으로 읽는다.
- **목표점**: 야수 AI 목표는 야수+0x90 (x,y,z). 추적야수는
  - 예측 단계(2a)에서 `플레이+0x127` 이 서 있으면 **낙구 지점 공점(aa0)** 으로 복제 이동,
  - 고르기(1a)에서 아무도 먼저 못 잡으면(aa4 < 최소 포구 틱) **공점(aa4 − 2) 의 (x, 0, z)** 로 달려감(상태 0xb).
  - 보통은 +0x174(포구 틱) 의 공점으로 간다 — 매 틱 이동 쪽(1c)에서 확인.

## 1c. 야수 매 틱 이동 — **확정**(속도·이동식·상태 분기) / 상태 2~5·8·9·0xe 세부 **유력**

- **이동식** (기반 캐릭터 vt 0x24 = 0xbf158): 현재 위치 +0x20(x,y,z) → 목표 +0x2c 로 **직선, 틱마다 속도 +0x3c 만큼**.

## 2b. 포구 순간 · 뜬공 아웃 · 땅볼 포구 — **확정**(흐름·조건) / 메시지 0xbc3 뜻 **유력**

```

f = +0x170 (고른 야수), Q = 공점(+0x174)
f 가 목표에 서 있고(x·z 가 Q 와 같음) 직접 && 종류 0 → f.vt9c (제자리 포구 자세)
현재틱 == +0x176 (동작 시작 틱) → 종류별 동작 (분기표 0xd87f4):
    0 → f.vt94 · 1 → f.vt5c · 2 → f.vt60 · 3 → f.vt90 + 플레이+0x1f7=1 (점프) · 4 → f.vt98 + 플레이+0x1f8=1 (슬라이딩)

    아니면 → 발밑 루 확인(f.vt58, 그 루에 주자 있고 도착 전이면 결과 후보 9) → **0xb2710(플레이, f, 1) = 공 쥐기**
```
**0xb2710 공 쥐기**: `+0x128=1, +0x130=f, +0x12c=1(쥠), +0x12d=1, 야수+0xe0=1, +0x127=0`, 메시지 0x15(포구 연출),
`r = vt90()`(= 0xb36d0 아웃 판정), **`+0x112 = 1`(이번 플레이에서 처음 잡힘), `state[0x1e] = 1`**, `r == 1` 이면 **`state[0x1f] = 1`** + 주자관리 0xa9620·0xa95c0.
- 아웃 판정 0xb36d0 의 결과 1 조건 = `주자+0x98`(이번 타석 타자주자 표시, 0xa93ac 가 세움) && `+0x112 == 0` && 공 쥠 →
  **뜬공 아웃 = "타자주자가 있는 플레이에서, 공이 한 번도 잡히지 않은 채(+0x112=0) 처음으로 쥐어짐"**. +0x112 는 0xb2710 에서만 1 이 된다.

  바운드 뒤에 잡힐 때 타자주자 +0x98 이 어떻게 풀리는지는 주자관리 쪽(0xa9e44 가 +0x98 을 지움)에서 마저 봐야 한다 — **유력**: 바운드 때 주자관리 0xa95e8/0xa9620 호출(0xb4510~0xb453c)이 풀어 준다.
  - 같은 곳: 이번 틱에 잡혔고 `+0x112 == 0` 이면 `state[0x1b] = 1` (노바운드 포구 표시).

- 튕김: 야수 vt 0x70 = 0xb3148 (맞고 튕김: 속도×60% ≥300, 높이속도×30% ≤100, 각 ±20), vt 0x78 = 0xb32e8 (무작위 방향 튕김, 펌블로 보임) —
  둘 다 공을 다시 쏘고 **`state[0x1f] = 0`**, `state[0x20] = 공+0xaa4`, `state[0x80] = 공+0xab0` 를 새 궤적으로 다시 적는다.

## 3. 다이빙·점프 · 에러 — I 결과 확인·보충 — **확정**

- 필살수비 확률(I 2c)은 그대로 맞다. 굴림이 세우는 플레이+0x1f5(점프)·+0x1f6(슬라이딩)은 **예측기(2a)의 포구 창을 넓히는 것뿐**이다:
  점프 = 높이 1701~4000 공을 x·z ±299 안에서, 8틱 이후·낙구 전 ; 슬라이딩 = 높이 501~1500 공을 거리 2000~3000 에서, 낙구 2틱 전 이내, 6틱 이후, 공이 야수보다 홈 쪽.
  고르기(1a)에서 우선순위 4·5 라 **보통 포구(낮은 공·가슴 높이·땅볼)가 낙구 전에 가능하면 필살수비는 쓰이지 않는다.**
  동작은 점프 포구틱−8, 슬라이딩 포구틱−6 에 시작(0xd87c0 분기, 2b), 플레이+0x1f7/+0x1f8 표시.
- 필살수비와 별개로 **비필살 다이빙**이 있다(1c): 추적야수보다 5틱 넘게 먼저 공 길목(거리 1000~2000, 높이 ≤500, 공 시작점이 구역 안)에 닿는 야수가 몸을 날린다(상태 0xd, vt60). 잡는 판정은 없다(연출·길막기로 보임 — 유력).
- **펌블 조건 정정**: I 2a 는 `공.vt18()==0` 을 "땅볼일 때만" 으로 읽었으나, 공 vt18 = 0xa27f0 = **공이 멈췄는가**(현재 점 속도 0, 또는 목표점 도달) 이다.
  → 펌블 굴림(등급별 2.0~0.5%)은 **움직이는 공을 잡을 때마다**(뜬공 직접 포구 포함) 걸리고, 굴러와 멈춘 공을 주울 때만 없다. 송구 받기(공 목록 종류 4)는 이 굴림 전에 빠진다.
  펌블이면 야수+0xb8 = 6(동작 잠금), 메시지 0xbc2 → 화면 0x5187e; 공은 야수 vt78(0xb32e8) 로 무작위 튕김(유력: 0xbc2 처리 쪽에서 부름).
- 악송구(10−등급 + 100)/10000 은 I·E 와 같다.

## 4. CPU 송구 대상 · 중계 · 협살 — **확정**(식) / 일부 칸 이름 **유력**

- **목표 루 고르기**는 I 2b 의 0xb1c90 그대로다: CPU 수비는 플레이+0x160 이 늘 −1 이라 항상 자동 규칙(앞선 주자부터, `주자 도착 틱 ≥ 송구시간` 인 첫 루).
  루마다 받을 야수 = 플레이+0xf0[루] (커버 배정, 0xb1c90 이 채움; −1 이면 없음).
- **루로 보내기 0xb2c90**(플레이 vt 0x58, 인자 루·특수):
  ```
  C = +0xf0[루]; C 없음(−1) → 공 가진 야수 상태 6, 야수.vt48(루) (직접 들고 뛰기), 0
  C 의 목표 루(vt68) ≠ 루 → 0
  t_run   = 공가진야수.vt1c(루 좌표 0xd86b0[루])        ; 직접 뛰어가는 틱
  t_throw = 공가진야수.vtb8(C 의 목표점)                ; 송구 도착 틱
  t_recv  = C.vtc0()                                     ; C 가 루에 닿는 틱
  t_run ≤ max(t_throw, t_recv) → 0xb2a48 로 **직접 밟으러 감**, 1
  거리(공가진야수, C) > 600 이고 C ≠ 자신 → +0x154 = C(받을 야수 지정, 예측기 +0x1e8 과 짝), vt5c(C, 특수)=0xb2e38 송구, 성공하면 던진 야수 상태 0(9 가 아니면)
  거리 ≤ 600 → 아무것도 안 함
  ```
- **송구 계획 0xb3444**(플레이 vt 0x8c, 결과 8바이트 `[0]중계여부 [1]특수 [2]던지는야수 [3]받는야수(중계면 중계맨) [4]최종 받는야수 [5]1구간 틱 [6]전체 틱 [7]목표 루`):
  - **중계 조건**: 던지는 야수가 외야(칸 > 5) && 특수(레이저 +0x1f4 또는 인자) 아님 && 던지는 위치~받는 야수 목표 거리 ≥ **cfg+0x42 = 17000** (d_level 파일 0x3e = 0x4268).
  - **중계맨** = 내야 칸 2~5 중 `송구틱(외야수→i 목표) + 송구틱(i→최종 목표)` 최소(야수 vt 0xbc = 0xa1adc 로 계산). 못 고르면 유격수(5, 상태 0xa 일 때) 아니면 2루수(3).
  - 전체 틱 = 1구간 + 2구간 + **cfg+0x20 = 3틱**(중계 받고 다시 던지는 지연, d_level 파일 0x1c = 3, 폴백 0xb6f78).
  - 직접 송구면 `[5]=[6]=송구틱`, `[1] = 외야수 && 특수 && 송구틱 > 17`.
  - 거리 상한 20400(= 17000×120/100)은 던지기 0xa1620 쪽(I 2b: 넘으면 원바운드)이고, 중계 문턱 17000 과 같은 cfg 칸을 쓴다.
- **협살(런다운) 0xb3a94** — CPU 수비일 때(플레이 틱 0xb4358~0xb4374, `state[0x31+수비측]==1`) 와 고르기 끝(+0x1f0 ≠ −1):
  - 0xb398c: 주자 목록을 뒤에서부터 보며 아웃·정지 아닌 주자 중 **진행률 = 0xbefec×100 / 0xbf01c > 35%** 인 첫 주자.
  - 0xb3a04: 그 주자의 출발 루·도착 루(같으면 +1)와 두 루의 커버 야수(+0xf0[루%4])로 계획 +0x1ec..+0x1f3 을 채움(+0x1f1 = 공 가진 쪽 표시).
  - 두 야수 중 동작 잠금이 아닌 쪽을 상태 **8**(AI 분기 0xb48b6)로 — 주자를 사이에 두고 쫓는 협살 동작.

| 8 | 0xaf918 | **자동 추가 진루** |
| 0xc | 0xafa60 | **CPU 송구 결정** |

보조: 0xaf284(제어기, 루 b) = **수비가 공을 루 b 에 보내는 데 드는 틱 예측**(공 가진 야수가 직접 뛰기 vt1c · 루 담당 야수 표 0xd85a8 [홈→1 포수, 1루→2, 2루→3, 3루→4] 의 도착 vtc0 + 송구 · 중계 17000 규칙 — 틀은 확정, 세부 분기 유력).

**0xaf918 자동 추가 진루** (인자 force) — **정정 2025: 갈래 차례를 다시 떴다. 아래가 디스어셈 그대로다.**
```
af934: for i = 주자수−1 .. 0:                       ; 앞선 주자부터
af946:   주자.vt18() 거짓 && force == 0 → 건너뜀      ; 멈춘 주자는 force 일 때만 본다
af95e:   종류 = 플레이+0x118
af964:   플레이+0x111(끝남) ≠ 0 → 0xafa0e            ; subs r2,#7   = 0x118 − 7
af970:   플레이+0x129       ≠ 0 → 0xafa0e            ; adds r2,#0x18 = 0x111 + 0x18
af97a:   종류 == 7: 주자+0x8c ≥ 주자+0x90+2 면 건너뜀, 아니면 0xafa0e
af98e:   vt94()(= +0x11c ≤ 낙구틱, "뜬공이 잡힐 예정") && 플레이+0x112 == 0 → **함수 끝**
af9ac:   종류 ∈ {2, 3, 8} → **함수 끝**
af9b6:   b = (주자+0x8c + 1) % 4 ; t_run = 주자.vt1c(루 좌표 0xd856c[b]) + 1 ; t_def = 0xaf284(b)
af9fa:   t_def − 1 > t_run (수비보다 2틱 넘게 빠름) && 0xa9924(앞길 비었나) → 0xafa0e

```
→ 평상시 규칙은 그대로 **"다음 루에 수비 송구보다 2틱 이상 먼저 닿으면 한 루 더 간다"** 다. 사람이 주루 키를 한 번 누르면 경기+0x24 = 0 으로 이 자동이 꺼진다(I 3b).

> **정정 (2건).**
> 1. **오프셋**: 두 번째 칸은 `+0x12a` 가 아니라 **`+0x129`** 다 (`af964: subs r2,#7` → 0x111, `af970: adds r2,#0x18` → 0x129). `R3-field-view.md` 도 같은 두 칸을 `+0x111`·`+0x129` 로 적고 있다.
> 2. **뜻이 거꾸로였다**: 예전 본문의 "플레이 +0x111(끝남)·+0x12a 서 있으면 안 봄" 은 **틀렸다**. 두 검사는 `bne 0xafa0e` = **진루 자리로 곧장 뛴다**. 그러니 두 칸 중 하나라도 서 있으면 **틱 비교도, 앞길 검사(0xa9924)도, 종류 2·3·8 거르개도, vt94(잡힐 뜬공)도 안 보고 주자 전원이 무조건 한 루** 간다.
> 또 종류 2·3·8 거르개와 vt94 검사는 **루프 밖이 아니라 루프 안**, 그것도 `+0x111`/`+0x129`/종류 7 갈래 **뒤**에 있다 (`af98e`·`af9ac` 의 `b 0xafa38` = 함수 끝). 앞선 주자가 위 갈래로 이미 진루했으면 그 진루는 남는다.

**0xafa60 CPU 송구 결정** (플레이+0x128 이 서고 공 가진 야수가 준비됨 vtc4, +0xe0, AI 상태 8·9 아님, +0xc8 ≤ 0):
```

```
0xafb24: 루 4칸 × 0x30 바이트 후보표를 만들어(주자별 출발·목표 루, 포스 여부 +0x98/+0x88, 0xaf284 로 수비 틱) 점수를 매긴다.
가중치 상수 100000 · 10000 · 10000000 · 1000000(홈이면 더함) 와 `난이도 + 여유 > 2` 비교(0xb013a) 가 보인다 — 루별 점수식 전체는 **미해결**(시간 관계로 뼈대만).

## 5b. 태그업 · 포스 · 득점 — **확정**(칸 뜻·쓰는 곳) / 2아웃 득점 보류 **유력**

주자 칸(주자 +0x78 부분객체 기준 → 절대 오프셋): `+0x7c 이번 구간 출발 루`, `+0x88 반드시 밟아야 할 루(−1 없음)`, `+0x8c 목표 루`, `+0x90 투구 때 있던 루`, `+0x94 판정끝 표시`, `+0x95 득점`, `+0x96 아웃`, `+0x98 이번 타석 타자주자`.
- **공이 땅에 닿거나 담장선을 넘을 때**(0xb4510~0xb4534, 경기 끝이 아니면) 0xa95e8: 주자 i 마다 `+0x8c ≤ i` 면 `+0x88 = +0x90 + 1`(**다음 루로 밀려 가야 함 = 포스**), 아니면 −1.
  - **`i` 는 배열 번호다** (확정, 2026-09 — I 3b-1). `0xa9564(관리, i)` 로 꺼내는 자리 번호이고,
    목록은 `[타자주자(루 0), …, 앞선 주자]` 로 **빈 루를 건너뛴 오름차순**이다 (채우는 자리 `0xa9a10`·`0xa93ac`).
    2루 주자만 있으면 그 주자의 번호는 2 가 아니라 **1** 이다.
  - ⚠️ **`+0x7c`/`+0x8c` 의 뜻이 이 문서와 어긋난다** (2026-09, 미해결). 직접 뜬 것:
    `vt48`(0xa07b0)은 `+0x80 = 요청 루`, `+0x84 = 옛 +0x7c`, `+0x7c = +0x8c 에서 한 칸(mod 4)` 을 쓰고
    `0xa0a18` 이 **`+0x7c` 의 루 좌표**로 이동 목표를 잡는다. 도착 처리(0xa040c)는 그 뒤에야
    **`+0x8c = +0x7c`** 로 갱신하고, `+0x94` 이고 `+0x8c == +0x88` 이면 요구 루를 푼다.
    곧 **`+0x7c` 가 향하는 루, `+0x8c` 는 마지막으로 닿은 루**로 읽힌다 — 이 절의 "`+0x7c` 이번 구간
    출발 루 / `+0x8c` 목표 루" 와 반대다. (`R3-field-view.md` 101·280 과 `I-controls.md` 3c 는 이미
    **`+0x7c` 를 목표 루**로 적고 있다.) 그렇게 읽으면 `+0x8c ≤ i` 가 곧 "1루부터 내 앞까지 빈 루 없이
    차 있다 = 포스" 가 되어 **사슬 전원이 요구 루를 받는다** — 지금 웹판은 이 칸이 늘 −1 이라
    포스 아웃 가지가 한 번도 안 돈다. 에뮬레이터가 없어 확정 못 했고, 웹판을 바꿔 재 보니
    평범한 단타에서 1루 주자가 2루에서 죽었다(측정표는 웹 `autoAdvance.ts` 주석). **그대로 둔다.**
- **뜬공 아웃**(0xb2774 뒤) 또는 경기 끝이면 0xa9620: 모든 주자 `+0x88 = +0x90`(**원래 루로 돌아가 밟아야 함 = 태그업/리터치**).
- 이어서 0xa95c0: 모든 주자 `+0x94 = 1`. 주자 틱 0xaa0a8 이 `+0x94` 인 주자가 요구 루를 밟으면(출발·목표·요구 루 비교 0xaa0fe~0xaa11e) `+0x94 = 0, +0x88 = −1` 로 풀어 준다.
- 아웃 판정 0xb36d0(I 3c)의 포스(2)·리터치(1)는 이 +0x88/+0x98 을 본다. 태그 거리 ≤ 499 는 I 와 같다.
  리터치 전에 떠난 주자가 먼저 뛰는 것 자체는 막지 않는다(자동 주루는 0xaf918 이 "잡힐 뜬공이면 안 뜀" 으로 막음).
- **득점**(0xaa0a8, 주자 목표 루 4 에 도착 +0x3b):
  - 아웃 ≥ 2 이고 공이 땅에 닿은 플레이(state[0x1e])면, 타자주자가 아직 살아서 1루로 가는 중(목표 > 0, +0x98, 안 죽음)이거나 0xa9ac4 조건이면 **메시지 0x13 으로 보류**(득점 안 셈 — 2아웃 뒤 타자주자 아웃 시 무효 처리로 보임, 유력),
  - 아니면 `주자+0x95 = 1`, **state[0] += 1**(0xaa1ce~0xaa1d4; 이번 플레이 득점 수로 보임 — 정산 0xa8024 의 솔로/2점/3점/만루 구분에 쓰이는 값, 유력), 0xa9520(주자 목록에서 뺌).
  - 타자주자 자신이 홈에 닿았고 `state[0x1d]==0 && state[0xf]==0` 이면 state[0x25] = 1 (장내 홈런 — E-10 1e 와 같음).

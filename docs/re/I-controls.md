# I. 경기 중 사용자 조작 (binary.mod 역분석)

## 요약

**풀린 것(확정)**: 키 → 메시지 전 경로(0절: 주루 0x582/0x584/슬라이딩 0x585, 송구 0x588, 견제 0x10, 구질 7, 타격 0x6a4~0x6a7, 도루 0x583 — 설명서 키와 전부 일치, CLR = −16),
수비 화면 진입(경기 상태 0x17, 플레이 종류 1 타구·2 볼넷·4 견제·5 주자·9 도루), 월드 40000×32500 → 620×500(310 그림 좌우 반전 두 장),
야수 9명 시작 좌표·루 좌표, 야수 능력(속도 940+8g, 사거리 3g), 주자 속도(주루×7/100), **자동 송구 규칙**(앞선 주자부터 송구가 먼저 닿는 루),
송구 속도 계수(내야 70·외야 80), **에러(펌블) 2.0~0.5%**, **악송구 ≈1.1%**, **필살수비(점프/슬라이딩) 1~6% ×2번 굴림, 초감각 +3%p, 나리 타자편 절반**,
**레이저 송구 3~10% → 19틱 반짝임 창 안에 새로 누른 방향키**(CPU 는 자동), 태그 아웃(거리 ≤499)·포스 아웃 조건, 견제 = 수비 시뮬레이션(종류 4),
경기 중 메뉴 항목 표, **자동진행 30G(대전모드 100G, 6회까지)**, '#' 교체 진입 조건, 수비수 동작 번호 → 프레임 식.
**남은 것**: 카메라 추적·경계 식, 슬라이딩 플래그(주자관리+0x31c)의 실제 효과, 자동 주루의 진루 판단, 주자 속도 단위 환산,
동작 번호의 이름, 외야 6·7 의 좌/우 이름, 메뉴 칸 2 가 환경설정인지, 교체 화면 내부, "필살송구 아웃" 기록 증가 지점.
웹판은 이 영역을 전혀 갖고 있지 않다(타격 좌우·스윙·번트·필살타법·도루만, 타구는 `quickAtBat` 결과 코드로 바로 처리).

## 0. 입력 경로 — 키 → 메시지 번호 — **확정**

- 경기 장면(0x104, vtable 0xcfa0c) 슬롯 3 = 0x39f4c: 눌린 키를 `this+0x38` 에, 슬롯 4 = 0x39f68: 뗀 키를 `this+0x3c` 에 둔다.
  `this+0x18` 은 상태 객체(0xbca04 키 처리·반복 계수, 0xbcb48 = 다음 상태 예약): **this+0x1c = 현재 경기 상태**, this+0x40 = 이번 틱 키.
  키 번역 0xbca00 은 항등 — WIPI 원시 코드 그대로다.
- **키 코드**(0x5331c 등에서 확인): 위 −1 · 아래 −2 · 왼 −3 · 오른 −4 · OK −5(또는 '5'=0x35) · **CLR −16** · 숫자 '0'~'9' = 0x30~0x39 · '*' 0x2a · '#' 0x23.
- 조작 객체 두 종류(기반 생성자 0xb8ed9): **사람 = vtable 0xd0a14**(슬롯 3 = 0x536bc), **CPU/자동 = vtable 0xd0a60**(슬롯 3 = 0x53874).
  슬롯 2 = 0x537b0: `[+0x14]=키, [+0x18]=경기 상태`. `[+0xc]` = 0 공격(사람이 타자) / 1 수비(사람이 투수·야수). `[+4]` = 메시지 받는 곳(경기).
  메시지는 `0xbfbac(받는곳, 번호, 인자, 0)` 로 큐에 넣고 경기 장면 vtable 슬롯 12 = **0x509a0** 이 받는다.
- 0x536bc: `[+0x1c]==0` 이면 경기 상태 `[+0x18]` 0xe~0x1a 를 점프표 **0xd0a24** 로 가른다.

| 경기 상태 | 처리 | 키 → 메시지(인자) |
|---|---|---|
| 0xe | 0x532b0 | OK → 1(상태) (확인) |
| 0xf | 0x53580 | 공격: 0x53470 타자 좌우 · 수비: 0x534d8 **구질** + 0x53548 **견제** |
| 0x10 | 0x534b0 | 공격: 타자 좌우 · 수비: 8(키) (코스 고르기) |
| 0x11 | 0x53670 | 수비면 9(키). 공격이면 0x535a4 스윙·번트 + 0x53470 좌우 + 0x53610 도루. `[+0x1c]` 비트9 면 0x5364c('7'~'9' → 0x6a8) |
| **0x17** | **0x53420** | **타구 인플레이**: 공격이면 0x5331c **주루** + OK → 0x585(**슬라이딩**) / 수비면 0x533c8 **송구**. 둘 다 끝에 0x587(0) |
| 0x18 | 0x532f4 | OK → 1(상태) |
| 0x1a | 0x532d8 | (미확인) |

- **주루 0x5331c** (메시지 0x582 = 진루, 0x584 = 귀루, 인자 = 대상 주자 1·2·3 = 1루·2루·3루 주자, −1 = 전원):
  '2'/위 → 0x582(1) · '4'/왼 → 0x582(2) · '8'/아래 → 0x582(3) · '0' → 0x582(−1);
  '3' → 0x584(1) · '1' → 0x584(2) · '7' → 0x584(3) · CLR(−16) → 0x584(−1). 귀루 셋은 `[+0x1c] & 0xf0 == 0` 일 때만.
  → 설명서 StrHOWTO[2] 와 한 글자도 어긋나지 않는다 (귀루 '7' = "홈→3루" 는 3루 주자 되돌리기).
- **송구 0x533c8** (메시지 0x588, 인자 = 목표 루): '8'/아래 → 0(홈) · '6'/오른 → 1(1루) · '2'/위 → 2(2루) · '4'/왼 → 3(3루).
- **견제 0x53548** (메시지 0x10): '3' → 1(1루) · '1' → 2(2루) · '7' → 3(3루).
- **구질 0x534d8** (메시지 7): OK → 0 · '2'/위 → 1 · '4'/왼 → 2 · '6'/오른 → 3 · '8'/아래 → 4 · '0' → 5(마구).
- **타격** 0x535a4: OK → 0x6a5(스윙) · '0' → 0x6a6(필살타법) · '7'/'8'/'9' → 0x6a7(2/1/3) 번트. 0x53470: '4'/왼 → 0x6a4(−3) · '6'/오른 → 0x6a4(+3) (타자 좌우 3칸).
- **도루** 0x53610 (메시지 0x583): '3' → 1 · '2' → 2 · '1' → 3.
- CPU 조작 0x53874 (`[+0x14]` = 이벤트 0xf/0x10/0x11): 0x53850 수비면 0x644, 0x53824 수비·상태>5 면 0x645, 0x537dc 공격이면 상태 0xb → 0x6a9, 0xa → 0x583(−1).
- 웹판: 타격 좌우·스윙·번트·필살타법·도루만 있다(`_INVENTORY` 1장). 주루·송구·견제·구질 키는 없다.

## 4c. 경기 중 메뉴 (*) — **확정**(흐름) / 항목 이름 일부 **유력**

- 공용 키 처리 0x498d4 (경기 장면): 키 −6(소프트키1)은 '*' 로 바꿔 읽는다 (`498e8: adds r3,#6; bne; movs r3,#0x2a`).
- **'*'**: 경기 상태 0xd~0x15 일 때만 → 일시정지 팝업 0x741a0(콜백 0x3cdd0 / 0x3c158) + 0x3c02c 가 메뉴를 연다.
  0x3c02c: 메뉴 객체 this+0xf30 에 `0x6bfe1(1, 칸수)` — **모드 1 이면 4칸, 그 밖 5칸**.
  (vtable 슬롯 6 = 0x463ac 도 같은 팝업을 띄운다 — 폰 인터럽트(전화 등)로 멈출 때.)
- 메뉴 키 0x3c158 하위 0 (0x3c17e): OK(−5) → 선택, CLR(−16)·'*' → 닫기(계속).
  동작 = 표 **0xcfcfc**[행×5 + 칸], 행 = 모드 3·4 → 2, 모드 5~7 → 1, 그 밖 → 0:
  | 행 | 칸 0 | 1 | 2 | 3 | 4 |
  |---|---|---|---|---|---|
  | 0 (일반·시즌·대전 0,1,2,8,9) | 계속 | **자동진행** | 조작방법 | 설정(유력) | 나가기 |
  | 1 (미션·홈런더비 5~7) | 계속 | **다시하기** (StrGAME[7]) | 조작방법 | 설정(유력) | 나가기 |
  | 2 (나만의리그 3·4) | 계속 | 조작방법 | 설정(유력) | 나가기 | (없음) |
  동작 번호 → 점프표 0xcff84: 0 0x3c1fe 계속 · 1 0x3c212 **조작방법**(0x63688 = StrHOWTO 적재 객체, 하위 4) ·
  2 0x3c326 (StrMAINMENU·ui/slt_frame 적재, 하위 5 → 0x5550c; 환경설정으로 보임 — 유력) ·
  3 0x3c504 **나가기**(StrGAME[0]/[1] 확인 → 하위 3 0x3c98e 장면 전환) · 4 0x3c60c **자동진행** · 5 0x3c706 **다시하기**(StrGAME[7]).
  나가기 확인 문구: 모드 1~4·8·9 는 StrGAME[0](이닝 기록·G 사라짐), 그 밖은 StrGAME[1].

## 4d. 자동진행 G 소모 — **확정**

- 질문 0x3c60c: 전역 모드 0x1552d10 이 **8·9(대전모드)** 이면 `경기+0x6b`(이닝) > 5 → StrGAME[2]("6회까지만") 알림,
  아니면 `sprintf(StrGAME[3], 100)`. 그 밖 모드는 `sprintf(StrGAME[4], 30)`:
  ```
  3c67e: movs r2,#0x64 ; StrGAME[3] 의 %d = 100
  3c694: movs r2,#0x1e ; StrGAME[4] 의 %d = 30
  3c69a: ldr r3,=0x1400468 (sprintf)
  ```
- 확정(예) 하위 2 = 0x3c7d8: 비용 = −30 (모드 8·9 면 −100). `저장+0x64`(G포인트) < 비용 이면 StrGAME[5](부족) 알림 후 메뉴 닫기.
  아니면 G = clamp(G − 비용, 0, 99999) (`0x1869f`), 모드 2(시즌)는 G 사용 내역 종류 3, 모드 8·9 는 종류 4 로 적는다(0x22c29).
  그다음 간이 시뮬레이터 객체 this+0x1780 으로 넘긴다(0x3c8da~). 경기 장면 슬롯 2(0x52c50)가 `저장+0x248` 이 0x1b/0x1e 일 때 자동진행을 끝낸다(0xc1b49 / 0xc0ea9) — 7회 직접 플레이 전환 지점으로 보임(유력).
- 웹판: 자동진행 자체가 없다.

## 4b. 교체 (#) — **확정**(진입 조건) / 교체 화면 내부 **미해결**

- 0x498d4 의 '#' 가지 (0x4994a): 0x38984(교체 가능 검사) 참이고 경기 상태가 **0xe 또는 0xf**(투구 전·구질 고르기) 일 때만.
  - 모드 3(나만의리그 투수편): StrGAME[104]("그만 던지시겠습니까") 질문(0xbbef9)만 띄운다.
  - 그 밖: 사람 팀(`경기[9]`/`경기[10]` 로 공격·수비 팀을 가려 `this+0x228+4×팀`)의 벤치 수(`팀+0x33` 투수 / `팀+0x28c` 타자) > 0 이면
    0x49598(this, 0) 교체 화면을 열고 경기 상태를 **0xb** 로 예약한다(0xbcb48).
- 0x38984: 모드 4(나리 타자편)·7(홈런더비)는 막는다(`cmp #4 / #7`) 등 — 내부 전부는 안 읽음.
- 투수 교체 실행은 E 노트 3c 의 0xaf09c (호출지 0x495e0 = 사람 경기 화면)로 이어진다. 대타 기록("대타 홈런" StrGAME[13])은 미확인.

## 2a. 타구 처리 에러(펌블) 확률 — **확정**(식) / 결과 연출 뜻 **유력**

- 수비 플레이 객체 = 경기 장면 +0x200, `new(0x1fc)` + 생성자 0xb0b68, **vtable 0xd8618** (클래스 0xb0b68~0xb4d00).
  필드: +0x18 야수 배열(9, 0xb0c7c = i번 야수), +0x20 주자 관리(0xa9xxx), +0x24 공, +0x28 경기 상태, +0x2c 팀 배열, +0x30 메시지 받는 곳,
  +0x118 플레이 종류(0xb0cb8 이 씀; 견제 = 4), +0x130 공 가진 야수, **+0x160 사람이 고른 송구 목표**(vtable 0x60 = 0xb3118 이 씀, 초기 −1).
- 공을 잡는 순간 처리(vtable 0x48 = 0xb401c 안, 0xb41d0~0xb428c):
  ```
  b41e4: ldr r3,[야수+0xec]        ; 선수 레코드 (없으면 확률 0)
  b41fa: movs r1,#2 ; [sp]=90 ; [sp4]=1 ; bl 0xb570c   ; 경기용 수비 능력치
  b4204: bl 0xbbe98                 ; 등급 0~7
  b420e: 표 0xd87d4 = [200,180,160,140,120,100,80,50]  ; 등급별 /10000
  b4226: rand(0,10000) ; cmp 확률,r0 ; 확률 > 난수 → r4=1
  b426c: r4≠0 이고 공.vt18()==0 → 야수+0xb8 = 6, 메시지 0xbc2(야수)   ; 에러(유력)
  ```
  아니고 `공.vt5c.vt24(4)`(sp+0xc) 이면 메시지 0xbc3(야수) = 포구.
- **등급 0xbbe98** (능력치 → 0~7): ≤125 → 0 · ≤250 → 1 · ≤375 → 2 · ≤525 → 3 · ≤675 → 4 · ≤825 → 5 · ≤925 → 6 · 그 위 7.
  → 에러 확률 = 수비 ≤125 2.0% · ≤250 1.8% · ≤375 1.6% · ≤525 1.4% · ≤675 1.2% · ≤825 1.0% · ≤925 0.8% · 그 위 0.5%.
- 조건: 공.vt18() 이 0 일 때만(땅볼/굴러온 공으로 보임 — 유력). 뜬공 직접 포구에는 이 굴림이 없다.
- 웹판: 에러가 아예 없다(타구는 `quickAtBat` 결과 코드로 바로 안타/아웃).

## 1a. 수비 좌표계와 야수 배치 — **확정**(좌표·식) / 외야 셋의 이름 **유력**

- 월드 좌표는 (x, 높이, z) 정수. 표 **0xd7bdc**(0xa2a88 이 씀) = 루 좌표:
  홈 (20000, 29445) · **1루 (25946, 24175)** · 2루 (20000, 19170) · 3루 (14055, 24175) (첫 칸 (20000,1000,30000) 은 공 놓는 점으로 보임).
  → x 가 클수록 1루 쪽, z 가 작을수록 외야.
- 야수 시작 위치 표 **0xd86ec** (9 × 12바이트, 0xb0fb4 가 씀. 같은 값이 0xcfa8c·0xd3a70·0xd3cf8 에도 있다 — 경기 장면·구장 그리기용 사본):
  | 칸 | x | z | 자리 |
  |---|---|---|---|
  | 0 | 20000 | 24500 | 투수 |
  | 1 | 20000 | 29705 | 포수 |
  | 2 | 25068 | 23275 | 1루수 |
  | 3 | 22130 | 19610 | 2루수 |
  | 4 | 14664 | 22750 | 3루수 |
  | 5 | 17273 | 19150 | 유격수 |
  | 6 | 30700 | 12300 | 1루 쪽 외야(우익, 유력) |
  | 7 | 9100 | 12300 | 3루 쪽 외야(좌익, 유력) |
  | 8 | 20000 | 8000 | 중견 |
  칸 = (선수 레코드 +0x1c 하위 4비트) − 1 (0xb103e~0xb105e 루프). 외야 6·7 이 좌/우 중 어느 포지션 코드인지는 코드표를 못 봐 유력.
- **야수 능력 세팅 0xb0fb4** (vtable 0x20, 플레이 시작 때 야수마다):
  ```
  g  = 0xbbe98(0xb570c(팀,2=수비,선수,90,1)) + 1     ; 선수 없으면 2
  사거리 야수+0x8c = g × cfg[0x28](=3)               ; +팀 보너스
  이동속도 0xa0fc4(야수, cfg[0x1a](=940) + cfg[0x2a](=8) × g)   ; +팀 보너스
  악송구 보정 야수+0xe4 = cfg[0x2c](=2) − 등급 + 8   (= 10 − 등급, 2b 절)
  위치 0xbef58(야수, 표 0xd86ec[칸])
  ```
  cfg = 전역 0x14000c0 = d_level.dat (폴백 0xb6f28 의 `strh` 로 확인: +0x1a=940, +0x28=3, +0x2a=8, +0x2c=2).
  팀 보너스: 전역 모드 1·2·8·9(일반?·시즌·대전)일 때만 `0xbbe98(팀+8 의 short)` 를 사거리·속도에 더한다(0xb10d0~0xb10f2, 시즌 팀 능력치로 보임 — 유력).
- 웹판: 야수 개념이 없다.

## 3a. 주자 속도 — **확정**(저장 값) / 이동 단위 **유력**

- 주자 관리 = 경기 장면 +0x20c (0xa9xxx), 주자 배열 `[관리+8][0..3]` (0 = 타자주자, 1~3 = 1·2·3루 주자, 0xa9374 가 한 칸씩 민다).
- 타자주자 만들기 0xa93ac(관리, 타자, 팀, 투수) — 상태 0x17 진입 0x46418 이 부른다:
  ```

## 2b. 송구 — 수동/자동 목표, 송구 속도, 악송구 — **확정**(식) / 일부 단위 **유력**

- **수동 송구**: 인플레이(상태 0x17)에서 사람이 수비면 방향키/숫자 → 메시지 0x588 → 0x51890 → 플레이 vt 0x60(0xb3118) → **플레이+0x160 = 목표 루**(0 홈·1 1루·2 2루·3 3루). 초기값 −1(0xb0b3a·0xb0b6e).
- **공 가진 야수의 판단 = 플레이 vt 0x30 = 0xb1c90**.
  - 2루 커버: 공(플레이+0x24).vt60 의 x 성분 +90 > 0 이면(1루 쪽 타구) 커버 = 유격수(칸 5), 아니면 2루수(칸 3). 공 잡은 야수가 그 둘 중 하나면 다른 쪽이 커버(0xb1e24~0xb1e84).
  - **플레이+0x160 == −1 (목표 안 고름 = 자동)** 이면 0xb1f54~0xb2038 루프: 주자를 **앞선 주자부터(인덱스 큰 쪽) 거꾸로** 본다.
    이미 멈춘 주자(`주자+0x96`)·도착한 주자(vt18)는 건너뛴다. 그 주자의 목표 루 = 주자.vt68(), 루 좌표 = 표 **0xd86b0**
    (홈 (20000,29445) · 1루 (25946,24175) · 2루 (20000,19170) · 3루 (14055,24175) · 홈).
    `주자 도착까지 틱 = 0xbefec(주자)`, `송구 시간 = 공가진야수.vtC0() + 커버야수.vtB8(루 좌표)`.
    **주자 틱 ≥ 송구 시간(잡을 수 있음)이면 그 루로 던진다.** 못 잡으면 다음(뒤) 주자. 아무도 못 잡으면 목표 없음.
  - 사람이 고른 목표가 있으면 그 루로 바로 간다(같은 함수 0xb1f06~0xb1f40: 목표 == 이미 가진 루면 무시, 받을 야수 상태 0xd·9 면 무시).
- **송구 속도** (야수 vt 0xbc = 0xa1adc, 실제 던지기 vt 0xac = 0xa1620): 속도 계수 = `cfg[0x1c]`(=70, 칸 ≤5 내야) / `cfg[0x1e]`(=80, 칸 6~8 외야) × `[공+0x44]` ÷ 100.
  탄도는 거리(0xbf9f1)와 속도로 asin/cos 표(0xbfab0·0x6c7f4·0x6c71c)를 써 포물선을 만든다. 거리 상한 = `cfg[+0x42|+0x44 32비트] × 120/100`, 넘으면 원바운드(야수+0xc0 = 4, 각도 ±1 — 0xbfaa0 로 부호).
  특수 송구 인자(0xa1620 의 6번째 인자)가 서 있으면 야수+0xe8 = 4, 달리는 속도 = +0xd8(130%).
- **악송구** (0xa1828~0xa1896):
  ```
  r = rand(0,10000)
  기준 = 야수+0xe4 + 특수×100 + 100          ; 야수+0xe4 = cfg[0x2c](2) − 수비등급 + 8 = 10 − 등급
  r < 기준 → 속도 += rand(−50, 특수?0:51) (하한 100), 방향 += rand(−49, 특수?0:50) (−100~+... 범위로 자름)
  ```
  → 악송구 확률 = (110 − 수비등급)/10000 ≈ **1.03~1.10%**, 특수 송구면 +1%p. (1a 절에서 +0xe4 를 "반응 지연"이라 적은 것은 틀렸다 — 악송구 보정값이다.)
- 웹판: 송구가 없다.

## 2c. 필살수비(슬라이딩·점프 캐치) 발동 확률 — **확정**(식·표) / 둘 중 어느 쪽이 슬라이딩인지 **유력 미정**

- 굴림 시점: 경기 장면 메시지 **0x11**(타구가 떠난 순간, 0x50faa 가지). 조건:
  모드 ≠ 7(홈런더비) · 0x36140(this)==0(타구 각도가 파울/담장 밖 판정이 아님으로 보임) · `경기+0x13`==0 · `this+0xfe8`(이번 타구 필살수비 표시)==0.

- 굴림 A 0x50930 → **0x66b30**, 성공이면 `this+0xfe8=1`, 플레이 vt 0x68(1) → **플레이+0x1f5 = 1**.

  ```
  ab = 경기용 수비(0xb570c(ctx,2,선수,90,1)) 또는 ctx 없으면 0xb6414(선수,2,1)
  g  = 0xbbe98(ab)                         ; 0~7

- 웹판: 없음.

## 2d. 레이저 송구 — "반짝이는 순간" 입력 판정 — **확정**(흐름) / 창 길이 기준점 **유력**

- **발동 확률** 0x66a8c (0x523bc 에서 호출):
  `p = 표 0xd2590[g] = [3,4,5,6,7,8,9,10]` (+3 스킬 21), `rand(0,1000) < p×10` → **3~10%**(수비 등급별). 모드 4 반감은 **없다**.
- 굴림 함수 0x523bc (매 틱, 슬롯 2 → 0x524c0): 한 플레이에 한 번(`this+0x19af`)만.
  조건: `this+0x1094` ≤ 0, 공 가진 야수가 있고 준비됨(야수+0x80+8 칸 조건), `경기+0x19`==0, 창 열림 = 0xb2648(플레이) 참, 주자 수(0xa9598) > 0.
  확률 통과 시: 수비 팀이 **사람**(`경기[0x31 + 수비측]` ≠ 0 쪽이 CPU 로 읽힘 — 유력)이면 `this+0x19ad = 1`(**반짝임 시작**), CPU 면 `this+0x19ae = 1`(곧바로 레이저).

- **입력 판정** 0x4e858 (매 틱): 창이 닫히면 `0x19ad = 0`. `0x19ad` 이고 이번 틱 키(`this+0x40`) ≠ 0 이고 `this+0x6c & 0xf == 0`(키 반복 카운트 0 = **새로 누른 키**, 누르고 있기 불가) → `this+0x19ae = 1`.
  같은 틱에 입력 조작 0x533c8 이 그 키를 송구 목표(0x588)로도 보내므로 **방향키/2·4·6·8 한 번 = 목표 선택 + 레이저 확정**.
- **실행** 0x400bc (0x524c0 에서): `0x19ae` 이고 `+0x160 ≠ −1` 이고 `+0x12c` 이고 야수 준비 → `this+0x1992=0, +0x1991=1`, 플레이 vt 0x64(1) → **플레이+0x1f4 = 1**.
  송구 계획 vt 0x8c(0xb3444) 가 `+0x1f4` 를 보고 계획의 특수 플래그(+0x14d)를 세우고, 0xb2e38 → 야수 vt 0xac(0xa1620, 특수=1) 로 던진다(2b 절: 130% 속도·거리 상한 120%, 악송구 +1%p).
- 연출: `this+0x19ac`(공 잡음, 메시지 0x15)·`0x19ad`(반짝임)·`0x19ae`(레이저) 는 0x43cfc 그리기에서 효과 종류 1/2/3 을 고른다. 이펙트 그림 effect/effect_shinning.pzx (0x47cc8 적재).
- 기록 "필살송구 아웃"(StrGAME[44], 기록 36) 증가 지점은 못 찾았다(미해결).
- 웹판: 없음.
- **A = 점프 캐치, B = 슬라이딩 캐치 (유력)** — 포구 가능 판정 플레이 vt 0x24(0xb12d0) 안 0xb14e2~0xb1584, h = 예측 공 높이(`sp+0x88`):
  보통 포구: h ∈ [1001, 1700] (0xb14e4 `h−1001 ≤ 699`) 또는 h ≤ 1000(낮은 공).
  `+0x1f5` 이고 보통 포구 불가면 h ∈ [1701, 4000] 도 잡는다(0xb1552 `h−1701 ≤ 2299`) → 높은 공 = **점프**.

  (h 가 높이라는 것은 수치 범위로 본 판단 — 한 고리 미확인)

## 3b. 주루 조작 — 진루·귀루·슬라이딩 — **확정**(흐름) / 슬라이딩 효과 **미해결**

- **진루** 메시지 0x582 → 0x5209e: `플레이+0x111`(플레이 끝남)==0 이면 **`경기+0x24 = 0`**(자동 주루 끄기 — 사람이 한 번 손대면 그 플레이는 수동),
  0xa9b04(주자관리, 루, **0**). 성공하면 `플레이+0x128 = 1`.
- **귀루** 메시지 0x584 → 0x5222a (같은 0xa9b04, 방향 **1**).
  *(정정 2026-09: 예전에는 진루 1 · 귀루 0 으로 적었다. 0x520ba 가 `r2 = 0` 인 채로 부르고(0x520c4),
  0x5224e 가 `movs r2,#1` 뒤에 부른다(0x52252) — **거꾸로였다.**)*
- 0xa9b04(관리, 루, 방향): 루 = −1 이면 방향 0(진루)은 **3→2→1루 주자 순(앞선 주자부터)**,
  방향 1(귀루)은 **1→2→3루 주자 순(뒤 주자부터)** 으로 하나씩 부른다 (0xa9b22·0xa9b40).
  한 주자: `0xa97a0(루의 주자)` → `0xa9ad4` 로 배열 번호를 얻어
  - **진루(0)**: `0xa9924`(**앞길** 검사, 번호가 큰 쪽 = 앞선 주자를 본다) 통과 시
    `주자.vt48(0xb6228(주자+0x78))` — `0xb6228` 은 `t = +0x8c ; if t ≤ 3 then t+1` = **다음 루**다.
  - **귀루(1)**: `0xa99a8`(**뒷길** 검사, 번호가 작은 쪽 = 뒤 주자를 본다) 통과 시
    `주자.vt48(주자+0x8c)` — 지금 서 있는(마지막으로 닿은) 루로 되돌린다.
  어느 쪽이든 `경기+0x24 = 1`.
  *(정정: `0xb6228` 은 **다음 루**이고 이전 루는 `0xb6238`(`if t > 1 then t−1`) 이다. 두 검사도
  진루/귀루가 서로 바뀌어 적혀 있었다.)*
  - 보강(직접 뜬 것): `0xa9564(관리, i)` 는 **배열 번호**로 꺼내는 것이고(관리+8 = 주자 배열, 관리+0xc = 주자 수),
    "루 b 의 주자" 는 `0xa97a0(관리, b)` 다 — 주자 전부를 돌며 죽지 않은(`+0x96`==0) 주자 중
    **`+0x8c` == b 인 주자를 하나만** 돌려준다. 곧 **원본의 루 한 칸에는 산 주자가 하나뿐**이다.
    `0xa97fc(관리, i)` 는 배열 번호 i−1, i−2 … 로 내려가며 죽지 않은 첫 주자를,
    `0xa97d4(관리, i)` 는 i+1, i+2 … 로 올라가며 찾는다.

### 3b-1. 주자 배열의 번호가 뜻하는 것 — **확정** (2026-09)

배열을 **채우는 자리**를 떠서 확정했다.

```
a93ac  추가(관리, 타자, 팀, 투수)      ; 맨 앞에 끼워 넣는다
  a93c4:  [관리+0xc] > 3 이면 아무것도 안 한다 (최대 4명)
  a93cc:  0xa9374 — for r4 = 3,2,1: data[r4].vt98(data[r4−1])   ; 한 칸씩 밀고
          그 뒤 data[0].vt9c()                                   ; [0] 을 비운다
  a93f0:  새 주자.vt88(0)          ; = 0xa0820 setBase(0) → 루 0 = 홈
  a9400:  새 주자.vt48(1)          ; 1루로 뛰기 시작
  a940a:  +0x88 = 1 (요구 루) · +0x94 = 1 · +0x98 = 1(타자주자) · +0x90 = 0
  a94f2:  [관리+0xc] += 1

a9a10  루 상황 세우기(관리, …, 루표)   ; 루표[1..3] = 1·2·3루가 찼는가 (바이트 4칸, [0] 미사용)
  a9a20:  0xa9250 — 비우기([관리+0xc] = 0)
  a9a24:  for r7 = 3, 2, 1:                    ; **3루부터**
  a9a28:    if 루표[r7] == 0 → 건너뜀           ; **빈 루는 건너뛴다**
  a9a5a:    0xa93ac(…)                          ; 맨 앞에 끼워 넣고
  a9a64:    data[0].vt88(r7)                    ; 그 루에 세운다
  a9a78:    +0x95 = +0x96 = +0x97 = +0x98 = 0   ; 타자주자 표시를 뗀다
```

- 매번 **앞에** 끼우므로 3 → 2 → 1 순으로 넣으면 결과는 `[1루, 2루, 3루]` **오름차순**이 된다.
- 타자가 치면 `0xa93ac` 이 한 번 더 앞에 끼워 `[타자주자(루 0), …, 앞선 주자]` 가 된다.
- 죽은 주자는 지우지 않고 `0xa9520` 이 `+0x96 = 1` 만 세우므로 **번호는 플레이 내내 안 바뀐다.**

→ **배열 번호 i 는 "투구 때 루" 가 아니라 빈 루를 건너뛴 오름차순 목록의 자리다.**
2루 주자만 있으면 목록은 `[타자주자, 2루 주자]` 두 칸이고 2루 주자의 번호는 **1** 이다.
번호가 클수록 **앞선(루가 높은) 주자**다 — `0xa9924` 가 `0xa97d4`(번호 큰 쪽)를 "앞 주자" 로
쓰는 것과 맞는다.

루 번호는 **0 홈 · 1 · 2 · 3 · 4 홈**이다 — `vt88`(0xa0820)이 읽는 좌표표 `0xd77d8` 이
`[0]=(20000,29445) [1]=(25946,24175) [2]=(20000,19170) [3]=(14055,24175) [4]=[0]` 이다.

### 3b-2. `0xa99a8` 의 뜻 — **확정** (2026-09, 예전 "미해결" 을 닫는다)

```
a99a8  (관리, 번호):
  a99b0:  s = data[번호] + 0x7c
  a99b2:  if s ≤ 1 → 0
  a99b6:  이웃 = 0xa97fc(관리, 번호)        ; 번호가 작은 쪽 = **뒤(트레일링) 주자**
  a99bc:  이웃 없으면 → 1
  a99c6:  return (s − 1) > 이웃+0x8c
```

`+0x7c` 는 **지금 향하고 있는 루**다 (`vt48` = 0xa07b0 이 쓰고, `0xa0a18` 이 그 루의 좌표로
이동 목표를 잡는다). 귀루가 돌려보내는 곳은 `+0x8c`(= 서 있는 루) = `s − 1` 이다.
곧 이 함수는 **"되돌아갈 루가 뒤 주자보다 앞서 있는가 = 뒷길이 비었는가"** 이고,
`s ≤ 1 → 0` 은 **홈(0)이나 1루(1)로 가는 중이면 되돌릴 곳이 없다**는 뜻이다(타자주자는 타석으로 못 돌아간다).
예전에 "루 번호 체계가 안 맞는다" 고 적은 것은 **번호가 큰 쪽을 뒤 주자로 착각**했기 때문이다.
- **슬라이딩** OK → 메시지 0x585 → 0x518da: 플레이 종류 2(볼넷)·3 이면 무시, 0xb68dc(경기 끝남) 이면 무시.
  이미 슬라이딩 중인 주자(`주자+0xba` 이고 `+0xbb`==0)가 있으면 무시. 달리는 주자 수(0xa96ec) > 0 이고 소리 재생 중 아님이면
  **주자관리+0x31c = 1**(한 플레이 한 번), 효과음 10. 0xa9fd0 이 플래그와 주자 +0xb8/+0x98 를 지운다.
  이 플래그를 읽는 곳(슬라이딩이 도착 시간·태그 거리에 주는 이득)을 못 찾았다(미해결 — `movs #0xc7; lsls #2` 로는 쓰기 둘만 잡힌다).
- **자동 주루**: 수비 화면 진입 0x46418 이 `경기+0x24` ← 설정+0xbd(환경설정 "주루 수동/자동"로 보임). CPU 조작 0x537dc 는 상태 0xa 에서 0x583(−1).
  자동 주루의 진루 판단식(몇 루까지 뛸지)은 못 읽었다(미해결 — 후보: 주자 클래스 vtable 0xd7afc 의 갱신 vt 0x10 = 0xa289c).

## 3c. 아웃 판정 — 태그·포스 — **확정**(조건) / 거리 단위 **유력**

- 플레이 vt 0x90 = **0xb36d0**. 플레이 종류가 비트마스크 **0x58d**(종류 0·2·3·7·8·10)면 판정 없이 0. 주자마다(뒤에서 앞으로) 결과 코드 sp+0xc:
  - **3 = 태그 아웃**: 공 가진 야수가 있고 `플레이+0x12c`(공 쥠) 이고 주자 아직 안 죽음 이고 **거리(0xbece8(야수,주자)) ≤ 499** 이고 주자가 루 위가 아님(vt18 거짓).
  - **2 = 포스 아웃**: 공 쥔 야수가 루를 밟고 있고(vt18) 그 루(vt58) == 주자의 목표 루(`주자+0x7c` 계열 mod 4) 이고 주자가 밀려 뛰는 중(`+0x7c`≠0, 관리 vt10(주자) 참) 이고 주자가 아직 도착 전.
  - **1**: `주자+0x98`(뜬공 뒤 귀루 의무) 이고 `플레이+0x112`==0 이고 공 쥠 → 리터치(귀루 전 공) 아웃으로 보임(유력).
  - 경기 상태 `+0xb`==0xb(교체 상태) 일 때 첫 주자는 곧바로 아웃 처리(0xb373a) — 뜻 미확인.
  아웃이면 `경기+6`(아웃 수) +1 (0xb36fc·0xb3756), `주자+0x96 = 1`.
- 웹판: 태그/포스 개념 없이 결과 코드로 주자를 옮긴다(`quickAtBat` 진루타 60% 규칙은 CPU 간이 엔진 쪽).

### 3c-1. 웹판 수비 진행기의 "포스 사슬" — 웹 실수 정정 (2026-09)

- 증상: `runDefensePlay` 에서 **2루타 + 1루 주자**를 돌리면 1루 주자가 어느 루에도 안 놓였다.
  틱 추적 결과 주자가 사라진 것이 아니라 **타자주자와 함께 2루에 서** 있었고, 결과를 `BaseState`
  세 칸으로 납작하게 만드는 `basesOf` 가 그중 하나를 지웠다.
- **원본 버그가 아니라 웹 실수다.** 원본에는 "이 타구는 2루타" 라는 결과 코드가 없다 —
  타자주자가 2루까지 가면 그게 2루타이고, 포스 사슬의 머리는 늘 "타자주자 → 1루" 다.
  게다가 원본은 한 루에 산 주자를 둘 놓지 않는다(위 `0xa97a0` 보강 · 앞길/뒷길 검사).
  웹판만 타석 결과 코드가 타자주자의 루를 먼저 정해 놓고, 그 앞 주자를 함께 밀지 않았다.
- 포스 진루는 **자동 진루 제어기(0xaf918 = vt8, 0xae690 이 주루 수동이면 끄는 그것)와 무관하다.**
  웹판도 원래부터 무관했다 — 수동에서도 1루 주자는 2루까지 밀리고 있었다. 모자란 것은 **한 루**였다.
- 고침: 최소 진루 루 = `min(홈, max(출발 루, 타자주자 최소 루 + 목록 번호))`.
  타자주자 최소 루가 1 인 타구(땅볼·뜬공·직선타·단타)에서는 예전 `forcedFlagsOf` 와 결과가 같다.
  뜬 채로 잡히면(0xa9620 리터치 자리) 사슬을 **원래 루로 되돌린다** — 타자주자가 1루에 안 서므로 포스가 없다.
- 전수 측정(6 타구 × 8 루상황 × 2 모드 × 3 아웃 = 288): 고치기 전 **57행**이 "한 루에 둘" 이거나
  "앞 주자가 타자주자보다 뒤" 였고, 고친 뒤 0 행. 멀쩡했던 231행은 진루·득점·아웃·**난수 굴림 수까지 그대로**다.
  자동 갈래가 바뀐 18행은 전부 그 57행 안에 있었다(이루타+만루, 삼루타+1루/1·2루/1·3루/2·3루/만루).

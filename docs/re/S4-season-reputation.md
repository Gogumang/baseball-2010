# S4 — 시즌모드 평판 평가 16칸 (SR+0x1a0) / UNRESOLVED U-06

## 체크리스트
- [x] 1. 선행 문서 읽기 (P4 4a 평판식, R13 ④, B-10 나리 평판식, P7 나리 평판 7칸)
- [x] 2. 0xa3424(지우는 곳) 디스어셈 — 16칸의 정확한 베이스/크기/포인터 경로 확정
- [x] 2b. **채우는 함수 발견: 0xa3440 (0xa3424 바로 뒤)** + 게이트 0xa755c
- [x] 3. 0xa6f1c(평판 계산) 디스어셈 — 각 칸의 가중치 전수
- [x] 4. SR(시즌 레코드) 베이스 포인터가 어디서 오는지 → 경기 중 접근 경로 찾기
- [x] 5. 채우는 곳 전수 탐색 (증가/대입 코드)
- [x] 6. 각 칸 뜻 표 + 가중치 표 작성
- [x] 7. 나리 평판 7칸과의 구조 비교
- [x] 8. 웹판 현황 비교

## 요약

**U-06 풀림.** 평판 평가 16칸을 **채우는 함수를 찾았다**: 지우는 함수 `0xa3424` **바로 다음에 붙어 있는 `0xa3440(SR, k)`** 이다.
`0xa3440` 은 코드 k(0..14)를 점프표 `0xd7d7c` 로 오프셋으로 바꿔 `SR[0x1a0+off]++` 만 한다. 유일한 호출자는 게이트 `0xa755c(ctx, k)` 로,
**모드 2(시즌모드)에서만**, 그리고 **k ≤ 5 는 공격측이 COM 일 때(=내 팀이 수비·투구), k ≥ 6 은 수비측이 COM 일 때(=내 팀이 공격)** 만 적는다.
P4 가 못 찾은 이유는 (a) 함수가 이름 없이 `memset` 함수 바로 뒤에 붙어 있고 (b) 호출이 전부 함수 포인터(`bl 0xca9f8`)라 BL 역참조로 안 잡히며
(c) 호출지 상당수가 `movs r1,#k` 뒤 공통 꼬리로 `b` 해 들어가서 BL 바로 앞만 봐서는 코드를 못 읽기 때문이다.

**칸 이름 15개 중 14개 확정** — 바로 옆에서 같이 불리는 `0xa77f0`(G포인트 기록번호, K 4-5 표)과 1:1로 맞아 떨어진다:
삼중살·벤치클리어링·피안타·수비실수(유력)·병살·탈삼진·내타자삼진·안타·2루타·3루타·솔로/2점/3점/만루 홈런·사이클.
S[15]는 아무도 쓰지 않고, **S[2](피안타)·S[3](수비 실수)는 적기만 하고 평판식이 읽지 않는다.**
표에 **원본의 이상한 점 하나**: 점프표가 코드 4↔5 만 뒤집어 놓아 **탈삼진은 3개당 +1, 병살은 3개당 −2** 가 된다(4절 참고).

**남은 것**: S[3](칸 오프셋 3)이 정확히 무슨 수비 사건인지 — 야수 `+0xb8 == 6`(P2 확정 "펌블")과 `+0xc0 == 4`(원바운드 송구/궤적 끝) 두 경우에 선수 통산 `+0x2e` 와 함께 오른다는 것까지는 봤으나 통산 `+0x2e` 가 무슨 기록인지 확인 못 했다. 평판식이 읽지 않는 칸이라 이식에는 영향 없다.

## 2. 지우는 곳과 채우는 곳 — **확정**

### 2a. 지우기 0xa3424 (SR)
```
000a3424: push {lr}
000a3426: movs r3,#0xd0 ; lsls r3,r3,#1        ; 0xd0<<1 = 0x1a0
000a342a: adds r0,r0,r3
000a342c: movs r1,#0                           ; 값 0
000a342e: movs r2,#0x10                        ; 16 바이트
000a3430: ldr  r3,[0xa343c] = 0x1400428        ; memset 포인터(.data)
000a3432: bl   0xca9f8                         ; 간접 호출 썽크 (blx r3)
```
→ `memset(SR+0x1a0, 0, 16)`. 부르는 곳은 0x83cc(시즌 상태 0xdd = 경기 직전 화면, R13 ④) 하나뿐 (`re xref 0xa3424` → 0x85c8 리터럴 = 0xa3425, 함수 0x83cc).

### 2b. **채우는 함수 0xa3440(SR, k) — 바로 다음 함수**
```
000a3440: push {lr}
000a3442: cmp  r1,#0xe ; bhi 0xa3492           ; k > 14 면 아무것도 안 함
000a3446: ldr  r2,[0xa3498] = 0xd7d7c          ; 점프표
000a3448: lsls r3,r1,#2 ; ldr r3,[r3,r2] ; mov pc,r3
   ... 각 가지가 r3 = 오프셋 을 만들고
000a3488: lsls r3,r3,#1                        ; (0xd0..0xd7 짝수 가지는 <<1)
000a348a: adds r2,r0,r3
000a348c: ldrb r3,[r2] ; adds r3,#1 ; strb r3,[r2]   ; SR[off]++ (u8, 상한 없음 → 255 에서 랩)
```
점프표 0xd7d7c (u32 ×15, 확정):
`0xa344e,0xa3452,0xa3456,0xa345a,0xa3462,0xa345e,0xa3466,0xa346a,0xa346e,0xa3472,0xa3476,0xa347a,0xa347e,0xa3482,0xa3486`

| k | 가지 | 오프셋 |
|---|---|---|
| 0 | 0xa344e (0xd0<<1) | SR+0x1a0 |
| 1 | 0xa3452 | SR+0x1a1 |
| 2 | 0xa3456 (0xd1<<1) | SR+0x1a2 |
| 3 | 0xa345a | SR+0x1a3 |
| **4** | 0xa3462 | **SR+0x1a5** |
| **5** | 0xa345e (0xd2<<1) | **SR+0x1a4** |
| 6 | 0xa3466 (0xd3<<1) | SR+0x1a6 |
| 7 | 0xa346a | SR+0x1a7 |
| 8 | 0xa346e (0xd4<<1) | SR+0x1a8 |
| 9 | 0xa3472 | SR+0x1a9 |
| 10 | 0xa3476 (0xd5<<1) | SR+0x1aa |
| 11 | 0xa347a | SR+0x1ab |
| 12 | 0xa347e (0xd6<<1) | SR+0x1ac |
| 13 | 0xa3482 | SR+0x1ad |
| 14 | 0xa3486 (0xd7<<1) | SR+0x1ae |

⚠️ **k=4 와 k=5 만 순서가 뒤집혀 있다** (코드 4 → S[5], 코드 5 → S[4]). 점프표 값이 근거.
k=15(S[15], SR+0x1af)는 **아무도 쓰지 않는다** — 지울 때만 16바이트다. 평판식 0xa6f1c 도 S[15]를 안 읽는다.

### 2c. 게이트 0xa755c(ctx, k) — 이것이 유일한 호출자
```
000a755e: r3=[ctx+8](=st 경기 상태) ; r4 = s8 [st+1] (모드)
000a7566: r0=[0x1400054] ; r3=0x1f55d ; bl 0xca9f8   ; SR = 0x1f55c(전역) — 시즌 레코드 얻기
000a7574: cmp r4,#2 ; bne 나감                        ; **모드 2(시즌모드)에서만**
000a7578: cmp r0,#0 ; beq 나감                        ; SR 없으면 나감
000a757c: r0=[ctx+8]
        r2=0 ; if st[0x31 + s8 st[9]] == 0 → r2=1     ; 한쪽이 사람 조작인가
        r2==0 이면 st[0xa] 로 같은 검사, 그래도 0 이면 나감
000a75b0: cmp r6,#5 ; bgt → side = s8 st[0xa]  else side = s8 st[9]
000a75c2: if st[0x31+side] == 0 (사람) → r2=1
000a75d2: cmp r2,#0 ; **bne 나감**                     ; 그 side 가 사람이면 기록하지 않는다
000a75d6: r0 = SR ; r1 = k ; r3 = 0xa3441 ; bl 0xca9f8 ; → 0xa3440(SR, k)
```
- `st+9`·`st+0xa` = 지금 두 칸(공격측·수비측) 팀 번호. `st[0x31+칸] == 0` 이 사람(P4 4a 와 같은 규칙).
- **k ≤ 5 는 st[9] 쪽이 CPU 일 때만, k ≥ 6 은 st[0xa] 쪽이 CPU 일 때만 센다.**
  두 칸은 서로 반대이므로 결국 **k ≤ 5 = 내 팀이 수비·투구 중일 때 나는 사건**, **k ≥ 6 = 내 팀이 공격 중일 때 나는 사건** 으로 갈린다.
  (확인: k=4/k=6 이 같은 삼진 자리에서 "수비가 사람이면 4, 아니면 6" 으로 갈린다 → 4 는 내가 던져 잡은 삼진, 6 은 내 타자가 당한 삼진.)
- 판정: 확정(디스어셈 전문).

## 3. 16칸 각각의 뜻 — **확정 14칸 / 유력 1칸 / 안 쓰는 칸 1칸**

`0xa755c(ctx, k)` 를 부르는 곳을 **전수**로 찾았다(리터럴 `0xa755d` 를 원시 바이트로 전수 검색 → **0x3abe4·0x439f0 두 곳뿐**,
BL 은 0xa8024 안 7곳 — 0xa851a·0xa85ba·0xa86a6·0xa878c·0xa8a48·0xa8d72·0xa8e8c).
(**정정 2026-09-25**: 처음 판은 리터럴 자리에 0xa75f0 을 같이 적었는데, 0xa75f0 이 담은 값은 `0xa3441` 이다 —
게이트 자신이 기록 함수 0xa3440 을 부를 때 쓰는 포인터이지 게이트의 호출지가 아니다.)
직전의 `movs r1,#k` 만 보면 안 되고(공통 꼬리로 `b` 해 오는 가지가 많다) 가지를 다 따라가야 한다 — 그래서 P4 가 못 찾았다.

|---|---|---|---|---|---|---|

| **S[1]** | 1 | 0x3ab92 (벤치클리어링 진입) | 배경음 44 | **벤치 클리어링**(사구 뒤 20% — R10 상태 0x1e) | 내 투수가 맞힘 | **−1** 개당 |

근거 메모
- **G포인트 표(K 4-5)와 1:1로 맞는다** — 0xa77f0(ctx, 기록번호) 가 바로 옆에서 불린다: 0=3루타·1=솔로·2=2점·3=3점·4=만루·15=사이클·26=병살·27=삼중살. 이 대응이 칸 이름을 확정한다.
- 홈런 가지(0xa8622~0xa86a6): `[sp+0x28]`(이 플레이 득점) 을 1/2/3/4 로 나눠 각각 k=0xa/0xb/0xc/0xd 로 `b #0xa86a6` 공통 꼬리에 모은다.
- 삼진(0xa8a24~0xa8a48): `if st[0x31 + st[0xa]] == 0` (수비가 사람) → k=4, 아니면 k=6. 게이트와 합쳐 "내 투수 탈삼진 = S[5]" · "내 타자 삼진 = S[6]" 으로 갈린다.
- 아웃 수(0xa8e48~0xa8e8c): `[sp+0x30]` = 이 플레이의 아웃 수. 2 → 병살(k=5), 3 → 삼중살(k=0).
- 사이클 판정 0xa7610: 현재 타자의 이번 경기 타석 결과에서 1·2·3·4 루타가 모두 나왔는지 본다(0xcaa00 로 i 번째 결과를 읽어 1/2/3/4 를 각각 sp[0..3] 에 표시).
- S[1]: 0x3ab92 가 든 함수는 주자 1·2·3루를 훑고(0xa97a0), COM 수비면 그 투수 투구수 +10(0x3ab86 — E1 표의 "0x3ab86(+10)"), 배경음 44 를 켠다. 리터럴 풀(0xcfaf8 더그아웃 점표·+0x1758 공격 쪽 9명·0xa0e09)이 R10 의 **상태 0x1e 벤치클리어링 진입 0x3a5f0** 과 같다 → 벤치 클리어링 시작 함수. 사구(st[0xb]==4) 뒤 20% 로 들어온다.
- S[3] (**유력, 한 고리 미확인**): 0x43278 안 두 곳. 0x43278 은 상태 0x17(수비 화면) 매 틱 0x46cc2 가 부르는 함수다.
  `r7 = [경기 + 0x111c + 4×idx]` — idx = (플레이 종류 `[[경기+0x200]+0x118]` == 8(홈런더비) ? 0 : 8). 경기+0x111c 는 R10 8절의 **수비 9명 배열**이고
  r7 은 **야수 객체**다(P2 3절: 야수 +0xec = 선수 레코드, +0xb8/+0xc0 = 틱마다 1 씩 줄어드는 카운터).
  - `[r7+0xb8] == 6` — P2 3절 확정 "펌블이면 야수+0xb8 = 6(동작 잠금), 메시지 0xbc2". (I 2절: 도루 송구 때 포수+0xb8 = 6 도 있다.)
  - `[r7+0xc0] == 4` — I 2절 "거리 상한을 넘으면 원바운드(야수+0xc0 = 4)" / P2 "궤적 끝 → 추적야수+0xc0 = 4".
  - 두 가지 모두 `선수 레코드 +0x2e` 를 1 올리고(0..9999 로 자름), 효과음 **29(함성)** 를 예약한 뒤 `0xa755c(기록ctx, 3)` 을 부른다.
  - 선수 레코드 +0x2e 를 **올리는 곳은 이 두 곳뿐**(원시 바이트로 `strh rX,[rY,#0x2e]` 전수 검색 → 0x4383e·0x43852·0x438ea·0x43904 넷 다 이 함수) 이고, 읽는 곳을 못 찾았다.
    → "수비 실수(펌블·원바운드 송구)" 로 읽었으나 **+0x2e 가 통산 무슨 기록인지 확인 못 함**.
  - 걸리는 점: 야수 배열 인덱스 8 은 P2 의 수비 칸 번호로는 외야수다(0xb8da8 이 칸 6~8 을 외야로 본다). 홈런더비만 0(투수)을 쓴다는 점과 함께
    **배열 인덱스와 수비 칸 번호가 같은지**가 미확인이다. 다음 세션에서 +0x111c 배열을 채우는 곳을 보면 끝난다.
  - 평판식 0xa6f1c 는 S[3] 을 읽지 않으므로 이식에는 영향이 없다.

## 4. 평판 계산 0xa6f1c 다시 읽기 — **확정** (P4 4a 식 재확인, r6 = SR+0x1a0)

`SR = [obj+0x1c]`, `st = [obj+8]`, `u = (st[0x32]==0 ? 1 : 0)`(내 칸), `o = 1−u`.
`R(s)` = 0xb69b0(st, s) = `(s8)st[0x7e+s]` 득점.

**⚠️ 정정 2026-09-25 — 승패 보조 함수 셋을 처음 판이 뒤섞어 적었다.** 리터럴 풀 0xa7180 을 다시 읽으면
`0xa7180=0xb69b1(점수) · 0xa7184=0xb6a4d · 0xa7188=0xca739(÷3) · 0xa718c=0xb6a0d · 0xa7190=0xb69c9 · 0xa7194=0xb8ced(현재 투수)` 이고,
셋은 **서로 다른 것**을 돌려준다:

| 함수 | 돌려주는 것 | 동점이면 |
|---|---|---|

완투 보너스의 문은 **0xb69c8**(사람 팀 승리) 이다. 그래서 **동점이면 `u == 0` 쪽은 −2 와 +2 를 둘 다 받아 합이 0 이고,
`u == 1` 쪽은 둘 다 못 받는다**(원본 그대로).

- **S[4](병살)가 감점인 것은 원본 그대로다.** 점프표 0xd7d7c 가 코드 4↔5 만 뒤집어 놓았기 때문에 "탈삼진 +1/3, 병살 −2/3" 이 된다. 표를 뒤집지 않았다면 "탈삼진 −2/3, 병살 +1/3" 이 됐을 것이다 — 둘 중 어느 쪽이 의도였는지는 알 수 없지만, **실행되는 값은 표 그대로**(탈삼진 +, 병살 −)다. 옮길 때 이 이상함을 그대로 두어야 원본과 같아진다.

### 4a. 한 경기 평판 변화의 범위
- 실제로 더해지는 항의 상한: 승리 +2, 퍼펙트 +7, 삼중살 4×n, 홈런·사이클, t 구간 +6 → s 는 쉽게 11 을 넘어 **g = +6 에서 막힌다**.
- 하한: R(o)>4 로 −4, 패배 −2, 벤치클리어링·병살·삼진 감점 → **g = −2 에서 막힌다**.
- 즉 경기당 평판은 **−2 ~ +6**, SR+0x64 에 그대로 남고 0~999 로 잘린다.

## 5. 나리(마이플레이어) 평판 7칸과의 비교 — **구조가 다르다**

| | 시즌모드 (이 문서) | 나리 (B-10 · P7 B1/B2) |
|---|---|---|
| 담는 곳 | **시즌 레코드 SR+0x1a0..0x1af** (u8 ×16) | **경기 기록 객체 G+0xb4..+0x11c** (경기마다 새로 만드는 객체) |
| 적는 함수 | **0xa3440(SR, k)** — k 0..14 → 점프표 0xd7d7c → `SR[off]++` | **0xa57f8(ctx, code, val)** — code 0..0x1c → 점프표 0xd8218 → G 칸 |
| 게이트 | **0xa755c**: 모드 2 이고 SR 있고, k≤5 면 공격측이 COM, k≥6 이면 수비측이 COM | code ≤ 0x13 이면 `0xa56dc(타자)==0`(지금 타자가 **내 선수**) 일 때만 |
| 지우는 때 | **경기 직전** 시즌 상태 0xdd (0xa3424, memset 16) | 경기 객체를 새로 만들 때 |
| 읽는 곳 | 0xa6f1c (팀 평판, 등급 −2..+6 을 SR+0x62 에 더함) | 0xa6218 (나리 평판, r7 가산 + m 감산 + 평판 구간 보정표 T1/T2) |
| 세는 단위 | **팀** (내 팀 타선 전체 · 내 투수 · 내 수비) | **선수 한 명** (나리 본인의 타석·투구) |

- 겹치는 개념(만루홈런·삼진·병살·안타)은 있지만 **칸도 코드도 함수도 다르다.** 재사용하면 안 된다.
- 나리 쪽엔 "끝내기 안타(G+0xc4)·번트안타(G+0xf4)·역전 득점(G+0x114)·동점 득점(G+0x110)" 같은 **상황 칸**이 있는데 시즌 쪽엔 없다.
- 시즌 쪽엔 나리에 없는 **삼중살·벤치클리어링·탈삼진·피안타·수비 실수·홈런 타점별 4단계·사이클** 이 있다.
- 나리 평판식은 평판 값 구간(T1/T2)으로 배율 보정을 하지만, **시즌 평판식은 보정이 없다** — 등급 g 를 그대로 더한다.
- 두 식의 공통 부품: `0xa77f0`(G포인트 기록번호)은 **두 모드에서 같이 불린다** — 그래서 위 표의 칸 이름을 G포인트 표(K 4-5)로 확정할 수 있었다.

## 7. 이식할 때 주의할 잔가지 — 확정

- `0xa3440` 은 **무조건 +1** 이다. 값 인자가 없다. 삼진 자리(0xa8a14)는 이 플레이의 삼진 수 `[sp+0x20]`(>0) 을 나리 쪽 `0xa57f8(ctx, 0xf, 수)` 에는 그 수만큼 넘기지만, 시즌 칸에는 **1 만 더한다**.
- u8 이고 상한 검사가 없다 → 이론상 255 에서 랩. 한 경기 안이라 실제로는 안 닿는다.
- 홈런은 `S[7](안타)` 과 홈런 타점별 칸을 **둘 다** 올린다(안타 가지 안에서 k=7 → 이어서 k=0xa..0xd). 2루타·3루타도 `S[7]` + `S[8]`/`S[9]` 둘 다.
  → t = S[7]+S[8]+S[9] 에서 2루타·3루타는 **두 번** 세어진다. 원본 그대로 옮길 것.
- 사이클(S[14])은 4번째 루타가 나온 그 플레이에서 한 번만 선다(`[sp+0x1c]==0` 이고 0xa7610 이 참일 때).
- 16칸을 지우는 곳은 **시즌 상태 0xdd(경기 직전 확인) 한 곳뿐**(R13 ④). 경기 시작 후에는 지워지지 않으므로, 경기를 안 하고 화면을 나갔다 오면 다시 0 이 된다.
- 평가 자체(0xa6f1c)는 모드 2 경기마다 `[obj+0x1c](=SR) ≠ 0` 이면 돌아간다 — 정규시즌·포스트시즌·국가대항전 구분 없음 (P4 4a).

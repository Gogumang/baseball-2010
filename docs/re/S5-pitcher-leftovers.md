# S5. 투수편 잔여 5건 (UNRESOLVED U-13~U-17)

## 체크리스트
- [x] U-13a 평가 칸 R+0x130 = 출루 허용 (확정)
- [x] U-13b 평가 칸 R+0x138 = 상대 타자 수 (확정)
- [x] U-13c 평가 칸 R+0x148 = 사구 (확정)
- [x] U-13d 평가 칸 R+0x150 = 세이브 상황(리드 중) (확정)
- [x] U-13e 평가 칸 R+0x158 = t=5 투구 수 (확정)
- [x] U-14 `state+0x6a` = 상수 6 (0-기준 7회) — 7회 콜드게임 = 구원 등판 없음 (확정)
- [x] U-15 게이지 결과 — 원본에 글자 없음, slt_pitch 원 프레임 0x3a~0x43 (확정)
- [x] U-16 CPU 경기도 0xb8c80 4인 로테이션 + 타석마다 0xac428 교체 AI (확정, P1 1-4 정정)
- [x] U-17 S+0x68/0x69 초기화 = 0x3f86c (경기 장면 상태 9 "준비 2", 모드 3 한정) (확정)
- [x] 요약·정정 정리

## 요약
U-13~U-17 **다섯 건 모두 확정**으로 닫았다.

- **U-13** 평가 칸 5개: `R+0x130` 출루 허용 · `R+0x138` 상대한 타자 수 · `R+0x148` 사구 · `R+0x150` 세이브 상황(그 시점 수비팀 리드) · `R+0x158` 최고 등급(t=5) 투구 수.
  이 중 **읽는 코드가 있는 것은 0x148(선발형 퍼펙트 판정)·0x150(구원형 인기도) 둘뿐**이고 나머지 셋은 모으기만 한다.
  덤으로 `R+0x154` 의 정확한 뜻(무안타 이닝이 아니라 **삼자범퇴 이닝**)이 나왔다.
  세이브 후보 판정 `state+0x5c/0x60/0x64` ← 0xa60c0 은 **S1 4절이 이미 같은 결론**으로 풀어 두었다(서로 어긋나는 데 없음).
- **U-14** `state+0x6a` = 경기 상태 초기화 0xb6814 가 넣는 **상수 6**(0-기준 7회). 세 판정의 `state[0x6a] == state[0x6b]` 은
  **"7회 콜드게임으로 끝나 구원 투수가 등판조차 못 했다"** 를 뜻한다(USER_EVT[38] "오늘은 등판할 기회가 없었구나").
- **U-15** 게이지 결과 **글자는 원본에 없다**. `ui/slt_pitch.pzx` 프레임 0x3a~0x43 = 가운데로 작아지며 빨강→분홍→노랑으로 밝아지는 원 하나뿐.
  누른 칸 g → 프레임 `min(0x3b+g, 0x43)`, 등급 `t = max(g−4, 1)`. **t=4 와 t=5 는 같은 그림**이다. "PERFECT" 는 설명서(StrHOWTO[3])에만 있는 말이다.
- **U-16** 정규시즌 CPU 끼리 경기도 **경기마다 두 팀 모두 0xb8c80(투수 0~3 한 칸 전진) 4인 로테이션**을 돈다(0xc24fc~0xc254e).
  경기 중에는 간이 엔진 0xc1ba4 가 **타석마다 CPU 교체 AI 0xac428** 을 돌린다. → P1 1-4 정정.
- **U-17** 감독 강판 플래그 `S+0x68`·`S+0x69` 는 **경기 장면 상태 9("준비 2") 의 갱신 0x3f584** 안 0x3f870/0x3f872 에서
  모드 3 일 때 0 이 된다 → **경기마다 초기화되고 경기 사이에 새지 않는다**.

**웹으로 옮길 때 실제로 필요한 것**: R+0x148(사구)·R+0x150(리드 중) 두 칸, `state+0x6a`(= 상수 6) 판정 한 줄,
게이지는 "칸 9개 → t(0~5)" 와 원 그림(글자 아님), CPU 팀 4인 로테이션, 강판 플래그 경기별 초기화.

## 정정 (다른 노트의 서술을 뒤집는 것)
1. **R15 11-1** "`state[0x88]` = 아웃 안 된 주자가 **하나라도** 있으면 1" → **틀렸다**.
   0xa8c6a 의 `movs r5,#0` 가 루프 **안**에 있어 `r5` 는 **주자 목록의 마지막 원소 하나**만 반영한다(0xa8c2e 에서 r5·r4 를 0 으로 두고 진입).
   예: 야수선택으로 타자주자가 살고 1루 주자가 죽으면 `state[0x88]`(출루 허용) 과 `R+0x130` 이 **서지 않는다** → 그 경기는 퍼펙트로 계산될 수 있다(원본 버그).
2. **P1 1-4** "정규 CPU 경기 0xc239c 는 (리그+0x32)%4 를 써 두기만 하고 0↔k 교환이 없다 → 정규시즌 CPU 끼리 경기의 선발 교체는 미확인" → **정정**.
   0↔k **맞바꿈**은 없지만 **0xb8c80 로테이션 전진**이 있다(0xc2516·0xc2540, 날짜 카운터 != 0 일 때). CPU 팀도 4인 로테이션이다.
   후보로 남겨 둔 `0xb8870 → 0x1f84d·0xb53f0` 은 **타순·라인업 쪽**이라 투수와 무관하다.
3. **P1 5-1** "코드 0x14~0x21 은 수비측 현재 투수가 본인일 때만 적는다" → **정정**. 0xa584e 의 가드는 `코드 − 0x14 ≤ 0xb`, 곧
   **코드 0x14~0x1f 까지만**이다. **코드 0x20(R+0x154)·0x21(R+0x158) 은 상대 투수가 던져도 기록된다.**
4. **P1 5-1** "R+0x154 = 무안타 이닝 수(유력)" → **삼자범퇴(완전한) 이닝 수**로 정정. 안타(0xa80b4·0xa80e0)뿐 아니라
   **볼넷(0xa8e12)·사구(0xa8e2e)도 `R+0x184` 를 끈다**.
5. **P1 5-1** "R+0x14c = 연속 탈삼진(유력)" → **확정**으로 올린다. 이 값을 0 으로 지우는 `0xa57f8(R, 0x1e, 0)` 은
   0xa60c0 끝(0xa619e)에 있고, 0xa60c0 은 **투수가 바뀐 직후 한 번만** 돈다(S1 4절과 같은 결론 — 게이트는 `수비팀+0x296`,
   이 칸을 세우는 곳이 투수 교체 적용 0xaebe4 의 0xaee44 다). 곧 **새 투수가 올라올 때 연속 탈삼진을 0 으로 되돌린다**는 뜻이라 앞뒤가 맞는다.
6. **P1 2-1** "S+0x68·S+0x69 를 0 으로 되돌리는 곳은 못 찾음(경기 시작 초기화로 보임, 미확인)" → **0x3f870/0x3f872 로 확정**.
7. **P1 4-1** "결과 그림 … 'PERFECT/GOOD/BAD' 글자는 문자열이 아니라 그림이라 어느 t 가 어느 글자인지 미해결" → **그런 그림 자체가 없다**(U-15).

## U-13. 투수 평가 칸 R+0x130 / 0x138 / 0x148 / 0x150 / 0x158 — **전부 확정**

### 0. 쓰기 경로 재확인 (P1 5-1 표 보강)
기록 함수 `0xa57f8(R, 코드, 값)` 의 점프표 `0xd8218` (u32 34칸, 칸 = 코드). 투수 칸은 전부
`movs rX,#imm ; lsls rX,rX,#1 ; adds r2,r4,rX` 꼴로 **imm×2 = 오프셋**이다.
| 코드 | 핸들러 | 하는 일 |
|---|---|---|
| 0x17 | 0xa591c | `R+0x130 (u8) = (값 != 0)` |
| 0x19 | 0xa5948 | `R+0x138 += 1` |
| 0x1d | 0xa5958 | `R+0x148 += 1` |
| 0x1f | 0xa596a | `R+0x150 (u8) = (값 != 0)` |
| 0x21 | 0xa597e | `R+0x158 += 1` |

**게이트 정정 (P1 5-1 보강, 확정)**: 0xa584e 의 `r3 = 코드 − 0x14 ; cmp r3,#0xb ; bhi ; cmp r7,#0 ; bne ; → return`
→ "수비팀 현재 투수가 본인" 필터(r7)는 **코드 0x14~0x1f 에만** 걸린다.
**코드 0x20(R+0x154)·0x21(R+0x158) 은 필터를 그냥 지나간다** — 상대 투수가 던져도 내 R 에 쌓인다.

### 1. R+0x130 = **출루 허용 표시** (확정)
쓰는 곳 0xa8c86 (정산 0xa8024 안):
```
000a8c2e: r5 = 0 ; r4 = 0
000a8c5c: 루프 i = 0 .. 0xa9598(R+0x14)-1           ; R+0x14 = 주자 목록(0xa9564(list,i) = list[8][i])
000a8c66:   r0 = 주자 + 0x78 ; r3 = [r0+0x1e]        ; 주자+0x96 = 아웃 표시 (P2 표)
000a8c6a:   r5 = 0 ; if r3 == 0 : r5 = 1             ; ★ r5 를 루프 안에서 매번 0 으로 지운다
000a8c80: 0xa57f8(R, 0x17, r5)                       ; R+0x130 = r5
000a8ca6: if r5 && 수비팀이 사람(state[0x31+state[0xa]]==0) : state[0x88] = 1
```
- 뜻: **정산 뒤 루에 살아남은 주자가 있다(= 출루를 허용했다)**. state[0x88] 과 같은 값이고, 차이는
  R+0x130 은 사람/CPU 를 안 가리고 늘 쓴다는 것뿐.
- **원본 버그 (정정 대상, 아래 "정정" 절 참조)**: `movs r5,#0` 가 루프 **안**(0xa8c6a)이라 r5 는
  **주자 목록의 마지막 원소 하나**만 반영한다. R15 11-1 의 "아웃 안 된 주자가 하나라도 있으면 1" 은 틀렸다.

### 2. R+0x138 = **상대한 타자 수(타석 수)** (확정)
쓰는 곳 0xa8db0:
```
000a8d98: r3 = state[0x26]           ; 플레이 종류 (4 견제 · 5 주자만)
000a8da2: if r3 == 4 || r3 == 5 → 건너뜀
000a8daa: 0xa57f8(R, 0x19, 0)        ; R+0x138 += 1
```
- 정산 0xa8024 는 한 플레이(= 한 타석 결과)마다 한 번 돈다(R8 5절). 파울은 0xa8024 를 안 부른다(0x51408 v=7).
  주자 단독 플레이(도루·견제)를 뺀 나머지 = **타석 완료 1회** → R+0x138 = 투수가 상대한 타자 수.

### 3. R+0x148 = **사구(몸에 맞는 공) 허용 수** (확정)
쓰는 곳 0xa8e2a:
```
000a8e1c: r3 = state[0x12]           ; 사구 칸 (P7 A1 "9 = 몸에 맞는 공", R10 6절 "판정 4 = 몸에 맞는 공")
000a8e22: if r3 == 0 → 건너뜀
000a8e28: 0xa57f8(R, 0x1d, 0)        ; R+0x148 += 1
000a8e2e: R+0x184 = 0                ; ★ 사구도 "완전한 이닝" 표시를 끈다
```
- 읽는 곳: **0xa6b0a** (인기도 0xa690c 선발형 퍼펙트 판정 — P1 5-3 의 "볼넷 R+0x144, R+0x148, 피안타, 실점 모두 0").
  퍼펙트게임 조건에 사구가 들어가야 하므로 뜻이 맞아떨어진다.
- 덤(P1 5-1 "R+0x154 무안타 이닝(유력)" 보강): 볼넷(0xa8e0e, 코드 0x1c)·사구(0xa8e2a, 코드 0x1d) **둘 다**
  `R+0x184 = 0` 을 한다. 안타(0xa80b4·0xa80e0)도 끈다. → **R+0x154 는 "무안타 이닝"이 아니라 "삼자범퇴(완전한) 이닝" 수**다.

### 4. R+0x150 = **세이브 상황 표시(그 시점에 수비팀이 리드 중)** (확정)
쓰는 곳 0xa6194, 함수 **0xa60c0(R)** = **세이브 후보 투수 갱신**. 호출: 0x52284(함수 0x51408) · 0xc26a2(간이 타석 루프 0xc262c),
둘 다 게이트가 `수비팀+0x296 != 0` 이다. 그 칸을 세우는 곳은 **투수 교체 적용 0xaebe4 의 0xaee44**(`team+0x294`(교체 예약)를 처리한 뒤 `team+0x296 = 1`) 이고,
0xc26ac 가 부른 뒤 0 으로 지운다. → **투수가 바뀐 바로 그 순간 한 번만** 돈다 (S1 4절과 같은 결론).
```
0xa60c0(R):
  state = R+8
  r7 = (state[0x69] − state[0x6b])·3 − state[6] + 3        ; 남은 아웃 수
        ; state[0x69] = 마지막 이닝 인덱스 · state[0x6b] = 지금 이닝(0-기준) · state[6] = 아웃
  d = 0xb69b0(state, state[0xa])      ; 수비팀 점수   (state[0xa] = 수비측)
  o = 0xb69b0(state, state[9])        ; 공격팀 점수   (state[9]  = 공격측)
  need = 0 ; hit = 0
  if d > o:
      if d − o > 3 :  if r7 > 8 : need = 9 ; hit = 1      ; 4점 이상 앞서도 3이닝(9아웃) 넘게 남으면 세이브 상황
      else          :  if r7 > 2 : need = 3 ; hit = 1      ; 3점 이하 리드 + 1이닝(3아웃) 넘게 남음
      if d <= o + 주자수 + 2 and r7 > 0 : need = 1         ; 동점주자가 대기 타석까지 와 있으면 1
      if need 또는 hit:
          state+0x5c = state[0xa]                          ; 세이브 측
          state+0x60 = 0xae83c(수비팀)[0]                   ; 세이브 후보 투수 번호
          state+0x64 = need                                ; 세이브 요건 (1 / 3 / 9)
  r7' = (d > o)
  0xa57f8(R, 0x1f, r7')      ; R+0x150 = 수비팀이 앞서는가
  0xa57f8(R, 0x1e, 0)        ; R+0x14c = 0
```
- 읽는 곳: **0xa6d16** (인기도 0xa690c 구원형 — P1 5-3 의 "R+0x150 서 있으면 … R+0x124 ∈ {1,3} → +3").
  즉 **"리드를 지키러 나온 상황(세이브 기회)" 표시**로 쓰인다 (교체 순간에만 갱신되므로 "등판 시점" 값이다).
- 덤으로 P1 "남은 것" 의 **세이브 투수 판정 state+0x5c/0x60/0x64 의 출처가 여기**로 밝혀졌다
  (P1 6절이 "0xa7ed0 이 state+0x64 ≤ 0 일 때 세이브" 라고 적은 그 칸).
- 같은 함수가 `R+0x14c`(연속 탈삼진)도 0 으로 지운다 — **새 투수가 올라올 때 연속 기록을 끊는 것**이라 앞뒤가 맞는다(정정 5).
- 따라서 `R+0x150` 은 정확히 **"이 투수가 등판한 순간 팀이 앞서고 있었나"** 다 = 세이브 기회 표시.

### 5. R+0x158 = **최고 등급(t=5) 투구 수** (확정)
쓰는 곳 0xa5e0a. 그 함수 전체가 4줄이다:
```
000a5e00: 0xa5e00(R, t):
000a5e02:   if t != 5 → return
000a5e0a:   0xa57f8(R, 0x21, 0)      ; R+0x158 += 1
```
호출: 0x3e13e · 0x3e168 (둘 다 함수 0x3dfac = 공이 포수까지 간 판정) — 인자 r1 은 둘 다
`[scene + 0xbe<<5] = scene+0x17c0` = **투구 등급 t (P1 4-1)**.
두 자리는 결과 코드 스위치(`scene+0x10ac − 1`, 표 0xcffb4 13칸) 의 두 가지이고, 각각 뒤에서
`scene+0x1104 != 7 이면 state[4]++`(스트라이크) / `state[5]++`(볼) 을 한다 → **스트라이크·볼 판정마다 1번**.
→ R+0x158 = **게이지에서 t=5(최상) 로 던진 공의 수**(마구도 늘 t=5 라 포함된다).

### 6. 읽는 곳 정리 (확정)
`movs #imm ; lsls #1 ; (adds|ldr|ldrb)` 꼴 전수 조사(스크립트 work/S5/scan2.py) + 리터럴 풀 조사(`re xval`) 결과:
| 칸 | 쓰는 곳 | 읽는 곳 |
|---|---|---|
| R+0x130 출루 허용 | 0xa8c86 | **없음** (state[0x88] 이 대신 쓰임) |
| R+0x138 상대 타자 수 | 0xa8db0 | **없음** |
| R+0x148 사구 | 0xa8e2a | 0xa6b0a (선발형 인기도 퍼펙트 판정) |
| R+0x150 리드 중 | 0xa6194 | 0xa6d16 (구원형 인기도) |
| R+0x158 t=5 투구 수 | 0xa5e0a | **없음** |
→ 0x130·0x138·0x158 은 **모으기만 하고 아무 데도 안 쓰는 칸**이다(원본에 표시 화면도 없음).

## U-14. `state+0x6a` — **확정: 늘 6 (= 0-기준 7회). "콜드게임으로 7회에 끝나 등판을 못 했다" 판정**

### 1. 전수 조사 — 읽는 곳 3 · 쓰는 곳 1
`state` = 전역 `[0x1552d0c]` = 경기 장면 this+0x174 (H 4절) = 기록 컨텍스트 `R+8`
(0xa57f8 이 `[R+8]+0xa` 로 수비측을 읽는다).
Thumb 에서 오프셋 0x6a 는 `ldrb/strb` 의 imm5(≤31)를 넘으므로 반드시 `adds rX,#K` 로 주소를 만들어야 한다.
`.text` 전체에서 (가) `adds rX,#0x6a`, (나) `adds rX,#K` 뒤 `ldrb/strb [rX,#0x6a−K]`,
(다) `adds rX,#K1` + `adds/subs rX,#K2` (K1±K2 = 0x6a), (라) `movs rX,#0x6a` + 레지스터 오프셋,
(마) `strh [rX,#0x6a]` · `str [rX,#0x68]` 을 모두 훑었다 (스크립트 `work/S5/scan6a.py`, `work/S5/scanoff.py`).

| 주소 | 대상 | 하는 일 |
|---|---|---|
| **0xb6818** | **state** | **`state+0x69 = 8` 바로 뒤 `state+0x6a = 6`** (아래 2절) |
| 0x12ade | state (`[0x1552d0c]`) | 읽기 — 0x1278c 감독 평가 글 |
| 0xa666e | state (`R+8`) | 읽기 — 0xa6218 평판 |
| 0xa6ec2 | state (`R+8`) | 읽기 — 0xa690c 인기도 |
| 0x351be · 0x467ca · 0x48f46 · 0x48f66 · 0x5171e · 0x76aec | **점수판 객체** `[scene+0xf10]` (R10 5절) | 딴 객체 (같은 자리에서 +0x60/+0x61/+0x64/+0x68=0x10/+0x69/+0x6c 를 같이 쓴다 — 점수판 칸 좌표·폭) |
| 0xfba4 · 0x156e4 · 0x1c05e · 0x9bffe · 0x9c926 · 0x771e8 · 0x1a5be · 0x1a5fa · 0xd7d98 | 무관한 객체 | — |

→ **경기 상태의 +0x6a 에 값을 넣는 곳은 0xb6818 하나뿐이고, 경기 중에는 아무도 고치지 않는다.**

### 2. 값은 6 — 경기 상태 초기화 0xb6814 (확정)
```
000b6814: push {r4, lr}
000b6816: r1 = state
000b6818: r1 += 0x69 ; [r1] = 8          ; state+0x69 = 8   ← 마지막 이닝 인덱스(9회)
000b681e: r1 += 1    ; [r1] = 6          ; state+0x6a = 6   ← ★ 이 칸
000b682a: [state+0x44] = 2 …             ; (이하 H 4절)
```
- 부르는 곳: 경기 장면 진입 `0x31c2`(바로 앞 0x31b6 이 `memset(state, 0, 0xa4)`) · 간이 CPU 경기 `0xc23a8`.
  (S1 2절 표도 "0xb6814 … +0x69 = 8, +0x6a = 6" 을 적어 두었다. 값은 같고, **그 6 이 무슨 뜻인지**가 이 절의 내용이다.)
- `state+0x6b`(현재 이닝, **0-기준**)은 0xb6798 이 0 으로 두고 0xb6b6c(아웃>2 이고 state[9]==1 = 말 끝)가 +1 한다.
- `state+0x69 = 8` 은 0xa60c0(세이브 판정, U-13 4절)의 `(state[0x69] − state[0x6b])·3 − 아웃 + 3 = 남은 아웃 수` 와 들어맞는다.

### 3. 그래서 뜻은 "7회에 끝난 경기" (확정)
세 곳 모두 `(s8)state[0x6a] == (s8)state[0x6b]` 하나뿐이므로, 조건은 **"끝난 이닝 인덱스 == 6", 곧 7회에 경기가 멈췄다** 이다.
경기 끝 판정 `0xb68fc` 를 보면 **콜드게임은 이닝 인덱스 > 5(= 7회부터) 이고 10점 차**일 때다:
```
000b690e: r6 = state+0x6b
000b6948: r3 = (s8)[r6]            ; 현재 이닝
000b694c: if r3 <= 5 → 0 (안 끝남)  ; ★ 7회(인덱스 6)부터만 콜드게임
000b6962~: 점수 차 ≥ 10 이면 끝
```
→ **인덱스 6(7회)에서 끝난 경기 = 가장 이른 콜드게임**이고, 이때 P1 1-3 의 구원 등판(`이닝 인덱스 == 7`, 즉 8회)이 아직 오지 않았다.
`state+0x6a` 는 그 문턱을 담아 둔 **고정 상수 6**이다 (0xb694c 가 5 를 직접 쓰는 것과 값이 하나 차이나는 이유: 그쪽은 `> 5`, 이쪽은 `== 6`).

| 곳 | 조건(7회 콜드게임)이 참일 때 |
|---|---|
| 0xa666e (평판 0xa6218, 구원 가지) | 가점 r = 감점 pen = 0 → **평판 변화 없음** |
| 0xa6ec2 (인기도 0xa690c, 구원형) | 아웃 ≤ 2 이면 p = 0 → **인기도 변화 없음** |
| 0x12ade (감독 글 0x1278c) | 구원 + 결과칸 0 이면 **StrUSER_EVT[38] "오늘은 등판할 기회가 없었구나."** |

### 4. 판정
- **확정**: `state+0x6a` = 0xb6814 가 넣는 상수 **6** (0-기준 7회). 세 판정은 "경기가 7회 콜드게임으로 끝났다" 를 뜻하고,
  구원 투수(8회 등판)가 **등판 자체를 못 한 경기**를 가려낸다. P1 이 "구원 '등판 없음' 판정으로 추정" 이라 적은 것이 맞았다.
- **빈틈(원본대로)**: 8회 인덱스 7 에서 콜드게임이 나면(내 팀이 그 이닝에 수비를 안 했을 때) 등판을 못 했는데도 조건이 안 선다.
  그땐 인기도 구원형의 `승리 +5 / 아님 −2`·`아웃 ≤ 2 → −2`, 평판의 `아웃/3 ≤ 0 → −2` 가 그대로 걸리고 감독 글도 보통 글(2~37)이 나온다.

### 5. 웹판
- 웹에는 투수편 경기 평가도 콜드게임도 없다(`quickAtBat.ts` 에 10점 차 종료 없음). 옮길 때 필요한 것은
  **"끝난 이닝 인덱스 == 6 이면 구원 평가를 통째로 건너뛴다"** 한 줄과 USER_EVT[38] 이다.

## U-16. 정규시즌 CPU 끼리 경기의 선발 교체 — **확정 (P1 1-4 정정)**

### 1. 선발: 두 팀 모두 경기마다 4인 로테이션 한 칸 (확정)
간이 CPU 경기 준비 **0xc239c** 안, 팀 두 개를 만든(0xb891c·0xb8768·0xb8870·0xb88c8) 바로 뒤 **0xc24fc~0xc254e**:
```
mode = [sp+0x1c]                                  ; 이 경기를 부른 모드
if mode == 2 :                                    ; 시즌모드
    g = 0x1f55c(전역)+0xb2 (s8)                    ; 시즌 저장 레코드의 날짜 카운터
    if g != 0 : 0xb8c80(팀A) ; 0xb8c80(팀B)
elif mode == 3 || mode == 4 :                     ; 나만의리그 투수편·타자편
    g = 0x1fa2c(전역)+0xb2 (s8)                    ; 나만의리그 레코드의 날짜 카운터
    if g != 0 : 0xb8c80(팀A) ; 0xb8c80(팀B)
(그 밖의 모드에서는 아무것도 안 한다)
```
`0xb8c80(team)` → `0xb5ca8(roster)` = **로스터 투수 0~3 을 한 칸 당기고 0번을 3번 자리로** (0x30 바이트 memmove, P1 1-1).
경기용 팀 객체는 `0xb891c` 가 `team[i] = i` 로 만들므로 **선발 = 로스터 투수 0번** → 결과적으로
**CPU 팀도 사람 팀 상대와 똑같이 로스터 투수 0~3 의 4인 로테이션을 하루 한 칸씩 돈다**.
- 날짜 카운터가 0 인 날(시즌 첫 경기)만 돌리지 않는다 — 1-1 의 사람 경기 준비 0x1c46c 와 같은 규칙이다.
- 로테이션은 **로스터 레코드를 실제로 섞는다**(영구). CPU 경기와 사람 경기가 같은 로스터를 공유하므로 한 팀은 하루에 한 번만 돈다.

**P1 1-4 정정**: "정규 CPU 경기 0xc239c 는 (리그+0x32)%4 를 써 두기만 하고 0↔k 교환은 없다 → 정규시즌 CPU 끼리 경기의 선발 교체는 미확인" 은 틀렸다.
0↔k **맞바꿈**(0xb8c94)은 과연 없지만, 그 대신 **0xb8c80 로테이션 전진**이 있다. 따라서
- 정규시즌(시즌·나만의리그 양쪽 모두): **0xb8c80 로테이션** (이 노트, 확정)
- 포스트시즌 0xc2c4c: `state+0x2e+side = g%4` 를 0xb6c34 로 읽어 **0xb8c94(team, 0, k) 맞바꿈** (0xc2d28, P1 1-0 그대로)
`0xb6c2c`(state+0x2e+side 쓰기)를 0xc239c 가 하는 것은 **포스트시즌 코드와 공유하는 준비 작업**일 뿐, 정규 경기에서는 읽히지 않는다.
(참고로 같은 자리의 다른 설정자들도 단순 setter 다: `0xb6c18(state, side, v) = state[0x31+side]`(**CPU 조작 표시**),
`0xb6bd4(state, side, v) = state[0x28+side]`, `0xb6c2c = state[0x2e+side]`.)

### 2. 경기 중 투수 교체: 간이 엔진도 CPU 교체 AI 를 돌린다 (확정)
`0xc1ba4`(간이 타석 하나 — 타석마다 0xc262c 가 부른다)의 **앞부분**은 P1 1-3 이 적은 "8회 내 구원 투수 투입"이고,
그 뒤 **0xc1c4a~0xc1cfc** 가 매 타석 CPU 교체를 돌린다:
```
r6 = 0xac228(engine+0x7c, engine+0x74, [engine+0x80], state)      ; 먼저 다른 교체 판정(미확인)
if r6 : 0x668cc(스킨, engine+0x74, 0)
r4 = 0x66864(스킨)                                                ; 모드 2·3·4 에서는 늘 1
if [engine+0x94] > 0 && state[1] == 3 && 0xb6389(수비팀 현재 투수) :
        건너뜀                                                     ; ★ 투수편에서 마운드에 내 선수가 서 있으면 CPU AI 가 손대지 않는다
if r4 == 0 : 건너뜀
r6 |= 0xac428(engine+0x7c, engine+0x78(수비팀), [engine+0x80], state,
              [sp]=engine+0x68, [sp+4]=(state[1]==3), [sp+8]=0, [sp+0xc]=max(r7,0))
if r6 : 0x668cc(스킨, engine+0x78, 1)                              ; 교체 알림
```
- `0xac428` = **CPU 투수 교체 AI**(E-6 에 내용이 있다. 체력%·실점 등을 보고 벤치에서 고른다). 실행은 `0xaf09c`(0xac644).
- `[sp+4] = (모드 == 3)` 이 E-6 의 "마선수 건너뜀" 인자다 → 투수편에서 CPU AI 는 **내 육성 투수를 새 투수로 고르지 않는다**.
- → **CPU 끼리의 정규시즌 경기에서도 선발이 무너지면 그 자리에서 구원으로 바뀐다**(같은 0xac428 규칙).
  간이 경기는 화면이 없을 뿐 교체 판정은 사람 경기와 같은 함수를 쓴다.

### 3. 남은 한 가지 (미해결)
- `0xac228(engine+0x7c, engine+0x74, …)` 가 무엇을 판정하는지는 안 읽었다(교체 연출 쪽 인자 engine+0x74 = 공격팀으로 보여 **대타/대주자** 후보).
  투수 교체 자체는 0xac428 하나로 설명된다.
- `0xb8870(team, rand(0,5))`·`0xb88c8(team, rand(0,5))`(0xc24a4·0xc24b4)는 `0xb8680(team)` → `0x1f84c(저장, i)` → `0xb53f0(…, 1)` 로 가는
  **타순·라인업 쪽**이다(R13 8절의 분류와 같다). 투수 선발과는 무관하다 — P1 1-4 가 후보로 남긴 `0x1f84d·0xb53f0` 은 여기서 털린다.

### 4. 웹판 차이 (파일:줄)
- `src/entities/team/model/teamRoster.ts:45` `startingPitcherOf` 는 늘 투수 0번이고 로테이션이 없다.
  원본은 **CPU 경기에서도** 경기마다 `0xb5ca8`(0↔1↔2↔3 한 칸 전진)을 돌린다 → 웹은 `leagueDay.ts:49-50`·`gameFlow.ts:193,224` 에서
  같은 투수가 계속 선발로 나온다.
- 웹 `quickAtBat.ts` 에는 경기 중 투수 교체가 없다(원본 0xac428 에 해당하는 것이 없음).

## U-17. 감독 강판 플래그 `S+0x68` / `S+0x69` 초기화 위치 — **확정: 0x3f86c (경기 장면 상태 9 "준비 2")**

### 1. 자리
`S = [scene+0xf08]` = 나만의리그 선수 레코드(career). 같은 객체의 `+0x62`(s16) 가 평판, `+0x64` 가 이번 경기 평판 변화다 (P1 2-1·5-2).
플래그를 **세우는** 곳은 P1 이 적은 그대로 감독 강판 판정 0x504cc 안 두 곳뿐이다:
`0x5054c` → `S+0x69 = 1` (체력 0% 판정 1회용), `0x5058a` → `S+0x68 = 1` (체력 ≤20% 판정 1회용).

### 2. 0 으로 되돌리는 곳 — 0x3f85c~0x3f872 (확정)
```
0003f84c: r3 = scene+0x1104 ; r1 = [r3]                  ; 모드
0003f856: 0x39fdc(scene, 모드)                            ; 사람 경기 장면 초기화 (P1 1-0)
0003f85a: r0 = scene+0x1104
0003f85c: if [r0] != 3 → 건너뜀                           ; ★ 나만의리그 투수편에서만
0003f862: r3 = [scene+0xf08]  (= S)
0003f86a: r2 = S+0x68 ; r3 = S+0x69
0003f870: [r2] = 0
0003f872: [r3] = 0
```
- 이 코드가 있는 함수는 **0x3f584** 이고, 0x3f584 는 경기 장면 갱신 표 `0xd0530` 의 **상태 9("준비 2", R10 2절 표)** 항목이다
  (`0x52e3a → 0x3f584`, 표 0xd0530 의 10번째 칸 = 상태 9).
- 상태 흐름(R10 8절): 상태 7(경기 준비) → **9(준비 2)** → 8(자원 적재) → 0xc(인트로) → … 이므로
  **경기 하나가 시작될 때 딱 한 번** 돈다. 경기 중에는 다시 돌지 않는다.
- 전수 조사(`work/S5/scanoff.py` 로 `.text` 의 `adds rX,#0x68/0x69` + strb 를 모두 확인): career 객체의 이 두 칸을 건드리는 곳은
  **0x3f870·0x3f872(0 으로) 와 0x504cc 의 두 곳(1 로)** 뿐이다. 나머지 히트는 전부 점수판 `[scene+0xf10]` 이나 경기 상태 `[0x1552d0c]` 다.

### 3. 결론
- **강판 판정은 경기 사이에 새지 않는다.** 경기마다 상태 9 에서 두 플래그가 0 이 되므로,
  "체력 ≤20% 로 한 번" · "체력 0% 로 한 번" 의 주사위는 **매 경기 새로 한 번씩** 굴린다 (P1 2-1 의 "초기화로 보임, 미확인" 을 확정으로 올린다).
- 다만 **모드 3(나만의리그 투수편)일 때만** 0 으로 만든다. 다른 모드에서는 그대로 남지만,
  강판 판정 0x504cc 자체가 `모드 != 3 → 0` 으로 먼저 빠지므로 실제 영향은 없다.
- 자동진행/강판 뒤 남은 경기를 간이 엔진이 도는 동안에도(P1 2-2) 이 플래그는 건드리지 않는다 — 다음 경기 시작 때 지워진다.

### 4. 웹판
- 웹에는 감독 강판이 없다(I 4a, P1 2-3). 옮길 때 이 두 플래그는 **경기 객체의 필드로 두고 경기 시작 때 false 로** 두면 된다
  (원본처럼 시즌 레코드에 얹을 필요는 없다 — 경기 사이에 남을 일이 없으므로 동작이 같다).

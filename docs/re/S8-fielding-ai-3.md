| `P+0x20` | 주자관리(runner manager) 객체 | 0xb4948 `ldr r0,[r1,#0x20]` → 0xa9564/0xa9598 호출 |

> 상태 8·9 분기가 `j(루프 첨자) == [P+0x130]` 을 비교하는 것도 이것으로만 말이 된다.

## 1. AI 상태 8 = **협살(rundown, 런다운)** — **확정**

분기표 `0xd8808`[8] = `0xb48b6`. 상태 8 은 P2 가 추측했던 "+0x1ec 계열"이 맞고, 그 정체는 **협살**이다.

### 1-1. 협살 기록칸 `P+0x1ec` ~ `P+0x1f3` (8바이트) — 확정

`0xb3a04(out, P)` 가 이 8바이트를 만든다 (`0xb3a0e`~`0xb3a1a`: 먼저 8바이트 전부 −1 로 memset, 헬퍼 `0x1400428`).

| 칸 | 뜻 | 만드는 줄 |
|---|---|---|
| `+0x1ec` (=out[0]) | ~~주자의 **현재 루**를~~ out[2](**달려가는 루**)를 커버하는 야수 번호 | 0xb3a6c~0xb3a6e |
| `+0x1ed` (=out[1]) | ~~주자의 **목표 루**를~~ out[3] 루를 커버하는 야수 번호 | 같은 루프 i=1 |
| `+0x1ee` (=out[2]) | ~~주자의 현재 루~~ **달려가는 루** = `주자+0x7c` | 0xb3a3c/0xb3a40 |
| `+0x1ef` (=out[3]) | ~~주자의 목표 루~~ **마지막으로 닿은 루** = `주자+0x8c`; **+0x7c 와 같으면 +1** | 0xb3a3e~0xb3a4c |
| `+0x1f0` (=out[4]) | **협살 대상 주자 번호** | 0xb3a4e |
| `+0x1f1` (=out[5]) | 0/1 = 두 야수 중 **지금 공을 쥔 쪽**, 없으면 −1 | 0xb3a78~0xb3a7c (`야수번호 == [P+0x130]`) |
| `+0x1f2`,`+0x1f3` | 안 씀(−1 그대로) | |

### 1-2. 협살 대상 주자 고르기 `0xb398c(P)` — **확정** (P2 의 "35%" 수치를 식까지 확인)

```
for i = 주자수(0xa9598(주자관리)) − 1 ... 0:          ; 뒤 주자부터
    R = 0xa9564(주자관리, i)
    if R+0x96(=+0x78+0x1e) != 0: continue             ; 이미 끝난 주자
    if R+0x94(=+0x78+0x1c) != 0: continue
    a = 0xbefec(R)      ; ★ 지금 자리에서 목표 루까지 **남은** 틱 = R.vt0x1c(R+0x2c)
    b = 0xbf01c(R)      ; ★ 출발점(R+0x14)에서 목표 루(R+0x2c)까지 **전체** 틱, 0 이면 건너뜀
    if (100*a)/b > 0x23(=35): return i                 ; ★ 남은 비율 35% 초과
return −1                                              ; 0xb39e4 `movs r0,#1; rsbs r0,r0,#0`
```
→ **"다음 루까지 아직 35% 넘게 남은 주자 중 가장 뒤 주자"**. 35 는 `cmp r0,#0x23` 즉시값(0xb39d8)으로 **박혀 있다**(설정·난이도 아님).

> **정정 3**: P2 "남은 것"·1c 요약의 "**35% 넘게 간** 주자에 협살" 은 방향이 반대다.
> `0xbefec`(0xbefec~0xbf016) 은 `self.vt0x1c(self+0x2c)` 즉 **남은** 틱이고, `0xbf01c` 는 `dist(self+0x14, self+0x2c)/self+0x3c` 즉 **전체** 틱이다.
> 따라서 조건은 `남은/전체 > 35%` — **루에 35% 미만으로 붙은 주자는 협살하지 않는다**. (협살은 "루에서 멀리 떨어진 주자" 에 거는 것이라 의미도 이쪽이 맞다.)

### 1-3. 협살 시작 `0xb3a94(P)` — 확정

1. `0xb3a04` 로 8바이트를 만들어 `P+0x1ec` 에 그대로 복사(0xb3aa8~0xb3ab0).
2. i=0,1 검사: `루 = sb[P+0x1ee+i]` 가 −1 이거나 `[P+0xf0+(루%4)*4]` 가 −1 이면 **중단**(0xb3ab8~0xb3adc).
3. 두 야수에 대해: `야수+0xb4 > 0` 이면 건너뛰고(동작 중), 아니면 `야수.vt0x10()`(0xa124c, 동작 정지) 뒤
   **`0xb8dbc(야수+0x80, 8)` = AI 상태 8 지정**(0xb3b08~0xb3b20).

### 1-4. 언제 시작하나 — 확정

플레이 틱 `0xb401c` 안 0xb433c~0xb4378:
```
if sb[P+0x1f0] == −1:                 ; 협살 진행 중이 아니고
    if !0xb3fa8(P): skip              ; 협살 가능 검사
if state[0x31 + state[0xa]] == 1:     ; ★ 수비 팀이 CPU 일 때만
    0xb3a94(P)                        ; 협살 시작
```
`0xb3fa8(P)` = `0xb398c` 가 −1 이 아니고, `out[5] != −1` 이며 공 쥔 야수가 out[0]/out[1] 중 하나일 것(0xb3fc2~0xb3fe2).
*(정정 2026-10-08, 메인 fbc7b16 — 0xb3a04 · 0xb3fa8 · 0xb48b6 직접 뜸)* 위 표의 칸 이름은 +0x7c/+0x8c 를 거꾸로 부르던 때의 것이다(CORRECTIONS 2b) — [k] = 커버[[2+k] % 4] · [k] == 플레이+0x130 이면 [5] = k. 0xb3fa8 은 거기서 더 본다: **b3ff0 야수 [0](달려가는 루의 커버)가 있고 +0xe0(쥠) == 0 이면 0 · b4004 +0x130(공 가진 야수) > 5(외야)면 0** — 곧 달려가는 루의 커버가 공을 쥐고 공 가진 야수가 내야일 때만 협살이 선다(예전 웹은 '공 가진 야수가 두 커버 중 하나' 만 봐 포수가 쥔 공으로 타자주자 0↔1루 협살이 섰다 — 원본 표 전체 CPU 수비에서 협살 4324 → 67). 협살 AI 0xb48b6 b4976 의 '내가 주자의 [달려가는 루] 커버인가' 도 +0x7c 다.
→ **협살은 사람이 수비할 때는 절대 안 일어난다.** (Q1 의 `state[0x31+팀]==0 = 사람` 규약)

### 1-5. 협살 종료 `0xb26b8(P)` — 확정

`memset(P+0x1ec, 0, 8)`(0xb26c8) → `P+0x1f0 = −1`(0xb26d6) → 야수 9명 중 **상태(+0x84)가 8 인 야수는 전부 상태 0 으로**(0xb26da~0xb26f6, `0xb8dbc(f+0x80, 0)`).
부르는 곳: 아웃 판정 0xb3946, 플레이 틱 0xb4336, 그리고 상태 8 자신(0xb4912).

## 2. AI 상태 9 = **송구 받기(루로 가서 받을 준비) + 송구 실행 게이트** — **확정**

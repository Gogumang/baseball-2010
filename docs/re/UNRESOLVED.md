# ③ "유력"에 머문 것 중 웹에 그대로 옮기면 틀릴 수 있는 것

원 노트가 **확정이 아니라 "유력(한 고리 미확인)"** 으로 적었는데, 그 가정 위에 웹 구현이 올라가면
값이 통째로 달라질 수 있는 것만 모았다. 위 표와 겹친다.

| 항목 | 유력인 이유 | 틀렸을 때 생기는 일 | 어디 |
|---|---|---|---|
| **마구 번호(공 `+0x10`)를 되돌리는 곳이 없다** | 되돌리는 코드를 못 찾았다는 **부재 증명**이라 유력 | 맞으면 "첫 마구 뒤 모든 투구에 마구 보정이 남는다"는 큰 규칙이 생기고, 틀리면 마구는 한 구만 특별하다 — **정반대의 밸런스** | H2 3-4, DECISIONS |
| **투수 평가의 "실점"(`R+0x128`)을 채우는 코드가 없다** | 같은 부재 증명 | 맞으면 완투승이 늘 완봉으로 세어지고 실점 감점이 안 걸린다. 틀리면 투수편 평가가 전부 달라진다 | P1 요약 |
| **일반·대전모드에 보직 불일치 벌점이 없다** | "보직을 읽는 곳 전수" 로 낸 부재 증명 | 설명서에는 −20% 가 있다. 맞으면 일반모드는 벌점 없음, 틀리면 수비가 20% 약해진다 | P7 J1, INVENTORY 2 |
| **`combo.pzx` 를 그리는 코드가 아예 없다** | 같은 부재 증명 | 맞으면 삼진 콤보 표시는 빠진 기능이다 | R2 (4) |
| **구원 투수를 사람에게 넘기는 고리** | 8회 교체까지는 확정, 조작권 이양 한 줄이 유력 | 투수편 구원 등판이 아예 사람 손에 안 올 수 있다 | P1 1절 |
| **마투수 난입 순서 = `XlsACE_PIT_DATA` 행 순서** | "행 순서 = 메모리 순서" 가정 | 난입하는 마투수가 단계마다 다른 사람이 된다 | H 3절 (U-25) |
| **올해의 목표 창이 표 `0xd7f9e` 를 읽는다** | 읽는 줄을 못 봤다 | 목표 수치가 다른 표에서 올 수 있다 | R9 (U-23) |
| **장비 "필요 인기도" 표 `0xd44c4`** | 읽는 곳이 설명 줄 한 곳뿐 | 가격/인기도 조건이 뒤바뀔 수 있다. 구매 처리를 못 찾은 U-04 와 같은 뿌리 | R12 "바로잡은 것" |
| **`skin+0xb0/+0xa4/+0xb4` = team_logo / game_ui / stadium_symbol** | 쓰는 곳을 못 찾아 그림 크기·번호로 맞췄다 | 화면에 엉뚱한 그림이 뜬다(치명적이진 않음) | P6 요약 |
| **투수 쪽 단일 PZX `+0x3c` 의 좌/우 뜻** | 타자 쪽(`0` 우타 / `1` 좌타)만 확정 | 투수 스프라이트가 좌우 반대로 그려진다 | R6 ④ |
| **미션 머리띠 `[this+0x88]==6` → 타자편** | 모드 번호(5 투수 / 6 타자)와 거꾸로 보인다 | 미션 화면의 머리띠가 반대로 나온다 | P6 요약, Q2 |
| **`0x5eae1` 반환 1~4** | R11 은 미해결로 적었으나 **Q2 가 이미 확정**했다 (1 육성투수 · 2 육성타자 · 3 명예투수 · 4 명예타자) | 문서끼리 어긋나 있으니 **Q2 를 따를 것** | R11 vs Q2 |

> 참고: **확정된 원본 버그**(CPU 끼리 경기 승패 뒤집힘, CPU 도루 확률 고정, 국가대항전 결승 50:50,
> 동점 처리, 이벤트 490 질병, GP 아이템 알림 등)는 여기가 아니라 `DECISIONS.md` 에 모여 있다.

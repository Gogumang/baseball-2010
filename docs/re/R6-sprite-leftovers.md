## 요약
다섯 항목 모두 디스어셈으로 풀었다(확정). 단일 PZX 클래스(투수 쪽)의 +0x3c 좌/우 뜻만 유력으로 남았다.
① fence_season 은 묶음 4개 × 5장이다. 바탕 = 관중석 k단×5, 덧그림 = k×5+1+[구장+0x89] 이다(0x77494). +0x89 값은 장면마다 다르다: 시즌 홈 경기 = 만원 판정(+0x65)+1, 대전 = 3, 관리 화면 미리보기 = 0. 덧그림 1~4번은 빈 좌석 → 관중 적음 → 보통 → 만원이다. 이 그림은 시즌 홈 경기와 대전모드에서만 쓰고 나머지는 fence.pzf 를 쓴다.
② 메인 바퀴의 "그림 1~4" 는 이미지 번호가 아니라 경우 번호다. 실제로는 main_ui 이미지 0·1·2 를 쓴다. 칸이 315°→0° 로 돌며 오른쪽 아래 설명 패널(이미지3, (96,289))로 납작해지며 접혀 들어가는 원근 연출이다. 경우 3·4 는 상하 대칭 가지인데 화면 밖에 그려진다.
③ 효과 1·L 은 반투명 겹치기다. 그림 무게는 L/16 이라 L=7 이면 7/16(약 44%)이다. 어둡게 하는 효과가 아니다. 효과 0x10·b 는 |b|≥2 일 때 정수 배 확대, b<0 이면 1/|b| 축소다. 효과 0x11·b 는 뒤집기로, b=0 좌우 · 1 상하 · 2 둘 다다. 0xbb91d 종류는 다음과 같다(a = 크기 ×a/10).
   - 1: 보통
   - 2: a/10 크기
   - 4: 회색
   - 8: 채널마다 +b 밝게
   - 0x10: b/32 섞기
④ 타자 그림 +0x3c 는 손(0 우타/1 좌타)이다. 우타이면 효과 0x11(좌우)로 뒤집는다. 구장(+0x60)도 같은 값으로 우타자 때 통째로 뒤집히고, 판정 사각형은 좌타일 때 480−x−w 로 뒤집힌다. 웹은 좌타 배치만 그린다.
⑤ 관리 화면 초상화 바닥은 mode_ui 프레임10 박스0 (0,65,240,72) 에서 나온 y = 65+72−2 = **135** 다.

## 1. fence_season.pzf 20프레임 ↔ 구장 아이템 — 확정

**그리기 함수 0x77494** (구장 객체, …). `[obj+0x30]` = fence.pzd + (fence_season.pzf | fence.pzf) 분할 리소스(0x76ba4 에서 적재).
```
774b8: ldrsb r2,[obj+0x88] ; cmp r2,#3 ; bgt → 프레임목록[0]           ; 관중석 번호
774ca: r3 = r2*5 ; r0 = 프레임목록[r3]                                 ; 바탕 = 프레임 관중석×5
77562: r2 = ldrsb [obj+0x88] ; ≤3 이면 r3 = r2*5 + ldrsb [obj+0x89]      ; 아니면 r3 = [obj+0x89]
77586: adds r3,#1 ; r0 = 프레임목록[r3]                                 ; 덧그림 = 관중석×5 + [0x89] + 1
775d4: ldrsb r3,[obj+0x8a] ; ≤3 → [obj+0x40](fence_board) 프레임[r3]   ; 전광판 번호 = board 프레임 번호
```
- **바탕 프레임 = 관중석×5** (0·5·10·15 = 1단·2단·3단·4단 관중석), **관중 덧그림 = 관중석×5 + 1 + [obj+0x89]**.
- [obj+0x89] 를 쓰는 곳 (전수, all.dis `adds rX,#0x89` + strb):
  | 호출지 | 값 | 장면 |
  |---|---|---|
  | 0x353ca (경기 준비 0x352e8, 모드 2 시즌 & 우리 팀 홈) | 시즌레코드 **+0x65 + 1** = 만원 판정(0/1/2)+1 → 1·2·3 | 시즌 홈 경기 |
  | 0x3543c · 0x35496 (모드 8·9 대전) | 3 | 대전모드 |
  | 0x629a · 0x7aae · 0x9c2c · 0xe52e (시즌 관리 장면 구장 미리보기) | 0 | 구장관리·관리 화면 |
  - +0x65 (J 4-7): 관중 ≥ 수용×80% → 2, > 35% → 1, 그 밖 0.
- 그림(스크래치패드 snd/fence/fence_season/frames 눈 확인): 묶음 안 1번째 덧그림 = **빈 파란 좌석**, 2번 = 관중 드문드문, 3번 = 반쯤, 4번 = **꽉 참**.
  → 프레임 뜻: `5k` 바탕(관중석 k단) · `5k+1` 빈 좌석(관리 화면 미리보기) · `5k+2` 관중 적음(35% 이하) · `5k+3` 보통(35~80%) · `5k+4` 만원(≥80%, 대전모드 고정).
- 관중석 4~6(트로피컬·콜로세움·스페이스, `[obj+0x88] > 3`)은 0x76ba4 가 `hidden_fence_{n−4}.pzx` 를 적재하고, 여기서는 이미지[0] 한 장 + 덧그림 `[0x89]+1` 번 이미지를 그린다(히든 구장도 관중 단계 그림을 가짐 — 그 PZX 의 이미지 1~4, 유력).
- 전광판: `[obj+0x8a]` ≤ 3 → fence_board 프레임 [0x8a] (소형·중형·대형·초대형), > 3 → hidden_board_{n−4} 이미지[0].
  - **전광판 화면(board_ani 흐르는 글자)** 은 그림과 따로다 (0x77726~0x777d8, 2026-09-25 재확인):
    설정 +0x3a 가 켜져 있고 `[obj+0x8a] ∉ {0, 5}` 이고 `[obj+0x90]`(board_ani) 이 적재됐을 때만 그린다.

## 2. 메인 메뉴 바퀴 칸별 main_ui 그림 분기 — 확정 (정정 포함)

**정정**: F 문서의 "main_ui 이미지 1~4" 는 이미지 번호가 아니라 **경우 번호 [sp+0x18]** 다. 실제로 그리는 이미지는 main_ui **0 · 1 · 2** 셋뿐이고, 경우 3·4 는 경우 2·1 을 **상하로 뒤집은** 것이다.

바퀴 그리기 0x24b1c 의 칸 고리 (a = 칸 각도, x·y = 칸 중심, (x0,y0) = 이미지0 가운데 맞춤 좌상단):
```
24d80: 0xba815(out, main_ui[+0x98], 3, 0)  → 이미지3(설명 패널 149×63) 폭·높이 (sp40..46)
24db0: sp28 = scrW − 패널폭 + 5  (=96)      ; 24dc0: sp24 = 중심y − 패널높이/2 (=320−31=289)
24ef0: (a − 19) > 322 (부호 없음) → 0x24fe6 로 건너뜀   ; a < 19 또는 a > 341 이면 아예 안 그림
24efe: a > 332  → 경우 2: 이미지[2] 를 (sp28, sp24 − 5), 효과 0
24f1c: a > 323  → 경우 1: 이미지[1] 를 (x0 + 10, y0), 효과 0
24f32: a ≤ 27   → 경우 3: 이미지[2] 를 (sp28, sp24 + 패널높이 − 5), 효과 0x11·[sp]=1
24f56: a ≤ 36   → 경우 4: 이미지[1] 를 (x0 + 10, y0), 효과 0x11·[sp]=1
그 밖           → 경우 0: 이미지[0](76×28 칸 버튼) 를 (x0, y0), 효과 0
24f98: 경우 ≠ 0 이면 칸 아이콘(img_text 프레임)을 그리지 않는다

- main_ui 이미지(public/sprites/main_ui): 0 = 76×28 파란 칸 버튼, 1 = 93×23 (더 넓고 납작), 2 = 125×15 (아주 납작), 3 = 149×63 흰 설명 패널.
- 설명 패널(이미지3)은 같은 함수 0x25036~0x25052 에서 (sp28, sp24) = **(96, 289)** 에 그린다 (`0xba759(main_ui, 3, 종류0, x, y, …, y보정 1)`). 상태 4 진입 연출 중([+0xfc] ≠ −1)엔 표 0xce8bc(x)·0xce88c(y) 오프셋을 더해 미끄러져 들어온다. 이어 (x+5, y+5, w−10, h−10) 로 잘라 설명 글을 쓴다.

  315 → 324(경우1: 조금 납작한 이미지1) → 333(경우2: 아주 납작한 이미지2 를 패널 윗변 y=284 에 붙임) → 342·351·0(안 그림). 반대로 돌면 거꾸로 펼쳐져 나온다.

- 웹판: `src/pages/main-menu/ui/MainMenuScreen.tsx:67-71` 는 바퀴 대신 배너+셀렉트(사용자 결정). `DescriptionPanel.tsx:17` 이 main_ui/003 을 쓰나 원본 위치 (96,289)·접힘 연출은 없다.

## 3b. 효과 0x10(확대/축소) · 효과 0x11(뒤집기) — 프레임 단계 확정

프레임 클래스 vtable **0xd57c0** (+0x10 = 그리기 **0x944b5**, +0x18/+0x1c = 박스 계산 0x9483d/0x948cd). 프레임 = 파트 목록([+8], 개수 u8 [+0xc]), 파트 16바이트 = (이미지*, dx s16 +4, dy s16 +6, …).
그리기 0x944b4(frame, X, Y, 효과 e, [sp]=b, [sp+4]=c): 파트마다 파트 이미지의 vtbl+0xc(img, x', y', −1, 0, 0, e, b, c) 를 부른다.
```
944ca: e == 0x10 && (b+1) > 2 (부호 없음, 곧 |b| ≥ 2):
         b > 0: x' = X + dx·b,   y' = Y + dy·b            ; 확대 (정수 배율)
         b < 0: x' = X + dx/(−b), y' = Y + dy/(−b)         ; 축소 (0xca7b5 = 부호 나눗셈)
       e == 0x10 && |b| ≤ 1 → 보통 그리기와 같음
94592: e == 0x11:
         b == 0: x' = X − (dx + 파트폭)      , y' = Y + dy        ; 좌우 뒤집기 (X 기준 거울)
         b == 1: x' = X + dx, y' = Y − (dy + 파트높이)             ; 상하 뒤집기
         b == 2: x' = X − (dx + 폭), y' = Y − (dy + 높이)          ; 180° 돌림
         b 가 그 밖 → 아무것도 안 그림
946ac: 그 밖 e → x' = X + dx, y' = Y + dy (효과는 이미지 단계로 그대로 넘김)
```
- 박스 계산 0x93b78 (프레임 폭·높이 보정): e == 0x10 && |b| ≥ 2 이면 w·h 를 ×b (b>0) 또는 ÷|b| (b<0).
- 확인: 새 램프 연출(0x37828, F 문서)의 "배율 z = 5→1" 은 **정수 배 확대**, (x − (z−1)·w/2, y − (z−1)·h/2) 는 가운데 고정 보정 → F 문서의 "효과 0x10 = 정수 배율 확대(유력)" 를 **확정**으로 올린다. 음수 b = 1/|b| 축소도 있다.
- 효과 0x11 의 b 는 뒤집기 축: 0 = 좌우, 1 = 상하, 2 = 둘 다. 구장(1항)은 b=0, 메인 바퀴 경우 3·4(2항)는 b=1(상하), 초상화 왼쪽 칸(A-8)은 "플래그 0x11" = 좌우.
- 웹판: 램프 확대는 `renderHud` 쪽 대조 필요(여기선 안 봄). 뒤집기는 canvas scale(−1,1) 로 옮기면 되고 기준은 "X 에서 오른쪽으로 폭만큼 거울"(x' = X − dx − w).

## 3a. 효과 1 · 인자 7 — 확정: **반투명 겹치기 (원본 7/16)**

- 그리기 효과는 번호마다 픽셀 함수 포인터로 나뉜다. 등록은 시작 코드 0x3054~0x3120:
  `0x985ed(k, fn)` (16비트 표면 블릿 0x98974 용, 슬롯 전역 0x15606d0−4k 부근, 점프표 0xd5b60),
  `0x9869d(k, fn팔레트, fn팔레트2)` (PZX 팔레트 이미지용), `0x987f9(k, fnA, fnB)`.
  등록된 효과 번호: 0·1·2·4·0xa·0xb·0xc·0xd·0x10·0x11 (0x10 = 확대, 0x11 = 뒤집기 — 3b).
- 효과 1 의 픽셀 함수: 16비트 **0x9a449**, 팔레트 **0x97769 / 0x9786d**. 인자 b = 단계 L (1~15, 0 이나 16 이상이면 아무것도 안 함):
```
9a45e: L−1 → 마스크표 0xd5e58 + 16·(L−1) (u16×8), 시프트표 0xd5de0 + 8·(L−1) (s8×8)
9a486: s = 원본 픽셀; s == 투명색([sp+0x34]) 이면 건너뜀
9a48c: d = 화면 픽셀
       out = Σ_{i=0..3} (d & M[i]) >> S[i]  +  Σ_{i=4..7} (s & M[i]) >> S[i]   → strh [화면]
```
  M 은 RGB565 채널별 아래 비트를 지우는 마스크(0xf7de·0xe79c·0xc718·0x8610 = ½·¼·⅛·1/16 용). 팔레트판 표 0xd5a70/0xd59f8 는 같은 바이트(비교 확인).
- 단계별 무게 (표를 풀어 계산): **원본 무게 ≈ L/16, 화면 무게 ≈ (16−L)/16**. L=1 → 1/16, 4 → 4/16, 8 → 8/16(정확히 반반), 15 → 15/16.
  **L = 7 → 화면 9/16(½+1/16) + 그림 7/16(¼+⅛+1/16)** — 곧 약 44% 불투명의 반투명 그리기.
- 따라서 F 문서의 "고르지 않은 건물 = 효과 1·인자 7 (어둡게로 보임)" 은 **어둡게가 아니라 반투명(배경이 56% 비쳐 보임)** 이다. 배경이 어두우면 결과적으로 어둡고 흐릿해 보인다.
- 웹판: `src/pages/outing-map/ui/OutingMapScreen.css.ts:23` 는 고른 칸을 `brightness(1.3)` 로 밝힐 뿐, 안 고른 건물 반투명은 없다. 옮길 때 `globalAlpha = 7/16 (≈0.44)` 로 그리면 원본과 같다.

## 3c. 0xbb91d 픽셀 효과 (종류 비트 · a · b) — 확정

`0xbb91d(이미지, x, y, 종류 m, a=[sp], b=[sp+4])` — PZX 이미지를 임시 16비트 버퍼(w×h)로 풀고(0xbba02~0xbba8a: 0xffff 끝, 0xfffe 줄바꿈, 양수 = 투명 칸 수 → 자홍 RGB(255,0,255), 음수(bit15) = 팔레트 색 칸 수) 화면 버퍼에 픽셀마다 직접 쓴다. y 에는 전역 [..+0x40] 세로 보정을 더한다.
```
bb9a2: m & 2 → 출력 크기 바꿈: a==5 → w/2,h/2 ; a==20 → w·2,h·2 ; a==10 → 그대로 ; 그 밖 → w·a/10, h·a/10
bba9a: 원본 좌표 = 출력 좌표 ×10/a (a==5 → ×2, a==20 → /2, a==10 → 그대로)  ; 최근접 표본 (종류와 무관하게 a 로 표본)
bbb5c: 원본 픽셀 == 자홍(투명) 이면 건너뜀
bbb74: m & 4 → 회색: s = R5 + G(상위5) + B5 + 3 ; g = s/4 + s/16 + s/64 (≈ s/3) ; out = g<<11 | g<<6 | g
bbba6: m & 8 → 밝게: R8 = (p&0xf800)>>8 + b, G8 = (p&0x7e0)>>3 + b, B8 = (p&0x1f)<<3 + b, 각 255 에서 자름 → 0x1400748(r,g,b) 로 565
bbbf6: m & 0x10 → 섞기 0xbb8d4(원본, 화면, b): out = 원본·(32−b)/32 + 화면·b/32 (565 채널 곱셈)
그 밖 (m 에 4·8·0x10 없음) → 원본 픽셀 그대로
```
- 종류 **1**: 비트 0 은 이 함수에서 아무 곳도 보지 않는다 → **보통 복사**(a=10 이면 원래 크기).
- 종류 **2**: 크기 a/10 배 (a=20 → **2배 확대**, 5 → 절반), 픽셀은 그대로.
- 종류 **8**: b 만큼 **각 채널에 더해 밝게** (b=200 → 거의 흰색 번쩍, b=140 → 밝은 반짝임).
- 종류 4(회색) · 0x10(b/32 반투명) 은 함수에 있으나 R2 의 HOMERUN 글자는 쓰지 않는다. 비트는 겹쳐 쓸 수 있지만 4 > 8 > 0x10 순으로 하나만 적용된다(if-else).
- R2 홈런 글자 표 풀이: 칸 5·4·3 = 2배 크기로 날아듦, 칸 2·0 = 원래 크기, 칸 1 = +200 밝게(흰 번쩍), 유지 단계 반짝임 = +140 밝게 (a=10 원래 크기).
- 부르는 곳 10곳(all.dis `= 0xbb91d`). 웹판 홈런 글자 연출과의 대조는 R2 몫.

## 4. 그림 객체 +0x3c = 좌우 반전 (좌타/우타) — 확정

**겹침 타자 클래스** (vtable 0xd3a3c, 적재 +8 = 0x78ab1 이 [sp] 인자 = `u8 0xb63c0(rec)` 를 +0x3c 에 저장, C-5) 의 그리기 **0x78cfc**:
```
78d0c: ldrb r3,[obj+0x3c] ; cmp r3,#0 ; bne → 효과 0
78d16: movs r2,#0x11 ; str r2,[sp+0x24]              ; +0x3c == 0 이면 효과 0x11
78d80: 파트 프레임 vtbl+0x10(frame, x+[obj+4], y+[obj+8], 효과=[sp+0x24], b=0, 0)   ; b=0 → 좌우 뒤집기 (3b)
78d34: (몸통 합성 경로) 0xbe8d5(…, [sp+8]=효과) 도 같은 효과값을 넘김
```
- 0xb63c0 = 손 게터: 0 = 우타, 1 = 좌타 (C-5, 0x7cd70 표). 따라서 **좌타(1) = 그림 그대로, 우타(0) = 좌우 뒤집어 그림**. 원본 타자 그림은 좌타 자세로 그려져 있다.
- **구장도 같은 규칙**: 경기 중 타석이 바뀔 때 0x3adb2 · 0x3b0fe · 0x47da2 가 `구장객체([게임+0xf10])+0x60 = 0xb63c0(현재 타자 0xae89d)` 를 쓴다 (0x3adba `adds r4,#0x60 ; strb r0,[r4]`).
  1항의 구장 그리기 0x77494 는 +0x60 ≠ 0(좌타) → 그대로, = 0(우타) → 효과 0x11(좌우)로 x+490/x+480 에 그림. 곧 **우타자 때 펜스·관중·전광판이 통째로 좌우로 뒤집힌다**.
- 판정 좌표도 뒤집는다: 0x35a6a / 0x347ce 가 좌타(1)이면 사각형 x 를 `480 − x − w` 로 거울 (월드 폭 480 기준).
  (여기서는 좌타일 때 거울 — 좌표 표는 우타 기준, 그림은 좌타 기준으로 서로 반대다.)
- **단일 PZX 클래스** (vtable 0xd3ce0, 투수·시즌 캐릭터; 적재 0x793b0 이 첫 스택 인자를 +0x3c 에) 의 그리기 0x79524 는 반대 극성: `+0x3c ≠ 0 → 효과 0x11`. 또 네 번째 스택 인자 ≠ 0 이면 효과 0x10·b=2(**2배 확대**)로 바꾼다(0x79550~0x7955a). 투수 쪽에 넘기는 값이 좌완(1)인지는 호출지까지 따라가지 않았다 → 이 클래스의 좌/우 뜻은 **유력**(좌완 = 뒤집기).
- 웹판: `RALPH_PROGRESS.md:749` "웹 화면은 side 1 배치라 타자 side 를 1 로 둔다" — 웹은 좌타(뒤집지 않은) 배치만 그린다. `src/widgets/batting-stage` 에 좌우 반전(scale(−1,1)) 코드가 없어서, 우타자일 때의 **타자·펜스·전광판 거울상과 판정 사각형 거울**이 모두 빠져 있다 (`career.battingSide` 는 `playerCareer.ts`·등록 화면에만 쓰임).

## 5. 관리 화면 초상화 바닥 y — 확정: **y = 135** (240×320)

초상화 그리기 앞단 0x7fbc4 의 끝 (0x7fdee~0x7fe4c):
```
7fdee: 상태([this+0x174]) == 0x70 · 0x71 (외출 지도 112 · 장소 113) 또는 인자 ≠ 0
         → y = scrH − 0x44                                  (= 252, A-8 과 같음)
7fe1a: 그 밖 → r1 = [this+0x138] 의 프레임목록[10]  (ldr [r3+0x28] = 10번째)
7fe38:        0x94a65(out, 프레임10, 0, 박스0)             ; 모드 0 = 박스 원값 (x,y,w,h)
7fe3e:        y = out.y + out.h − 2
7fe4c: bl 0x7f998(this, y)                                  ; 클립 (0,0,scrW,y+1) 뒤 칸마다 0xba169

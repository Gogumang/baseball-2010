## 요약
**풀린 것 (확정)**: 필살타법은 '0' 키로 남은 횟수 ≠ 0 일 때 이번 스윙에 기술 번호(선수+0x18)를 싣고, 실제 스윙 순간 1 줄인다. 효과는 타격 판정 0xab214 에 넘기는 12바이트 보정 0x34d6c 뿐 — 히트·파워 +150~220, 잘 맞을 확률 +15~20%, 홈런 확률 +6~9%. 저장 번호는 1~4 뿐이라 미라지·메테오 스윙은 같은 기술(이름만 타입으로 갈림). 마구는 구질 22 하나이고 종류는 투수+0x18(1~4, 마투수 5~9)로 갈린다. 사람은 구질 '0' 칸, CPU 는 **주자 2명 이상 · 투 스트라이크 · 0-0 · 0-3 이면 반드시**, 그 밖엔 6칸 균등 추첨. 궤적은 pitch.zt1 구질 22 블록(17 레코드)에서 `3(m−1)+폼/2` (1~4) 또는 `m+7` (마투수) 번째 — 마구 4 는 폼에 따라 샤이닝·캐넌·미라지 볼(레코드·이름·표시 구속만 다름). 마구 효과는 보정 구조체(투수 구속·제구 +150~220; B·C % 는 원본 버그로 타자 쪽에 **더해짐**)와 좁은 타이밍 창(±2틱, 0x34be0), 실투 없음·게이지 없이 t=5, 표시 구속 145~170 km/h. 한 경기 횟수: 육성 필살 2·3·4·5 / 마구 4·5·6·7 (기술 번호별), 마선수 Lv1~5 필살 2·2·3·4·5 / 마구 3·4·5·6·7, 스킬 23(무자비 +1 · 혼신 +2). 마선수 고유기 이름은 StrCOMMON 95~99(마투수)·100~104(마타자), 105~114 는 마선수 타입 칸 이름. 마선수 수치 효과는 레벨 표(다섯 명 같음)라 Lv1 = 육성 기술 1, Lv5 = 육성 기술 4 와 같다.
**원본 이상 동작**: 공 객체 +0x10(마구 번호)은 되돌리는 곳이 없어 한 번 마구를 던진 뒤 모든 공에 마구 보정이 남는다(유력, 3-4). 마구 +% 칸이 타자에게 유리한 방향이다(2절).
**남은 것**: 필살 부가 메시지 "종류 4"(2-2)의 뜻, deadly_effect.pzx 와 번호 연결, 공 꼬리 파티클 가지 안의 세부 조건(3-7), 표시 구속 경기+0x19a0 을 읽는 곳, 0x1239 new 의 0 채움 여부.
웹판은 필살·마구가 경기에 전혀 없다(CPU 마구 규칙 코드는 원본과 같지만 `magicCount: 0` 으로 꺼져 있음). 마선수 기술 이름도 일반 기술 이름으로 잘못 붙어 있다(6절).

## 1. 필살타법 발동 — 키 '0' → 메시지 0x6a6 → 0x51dee (확정)

입력: 타격 키 처리 0x535a4 가 '0' 을 메시지 0x6a6 으로 보낸다 (I 노트). 경기 장면 메시지 처리 0x509a0 의 분기 `cmp r2,#0x6a6` (0x50b2a) → **0x51dee**.
일반 스윙(0x6a5 → 0x51db6)과 나란히 놓고 보면 차이는 두 가지뿐이다.

```
51dee: r4 = 경기+0x220 (공격 팀 객체) ; r6 = 0xae89c(팀) = 지금 타자 레코드
51dfc: 경기 상태 [경기+0x1c] == 0x11 (투구 중 스윙 가능 구간) 아니면 무시
51e06: 스윙 객체 S = [경기+0xf9c] ; S+4 (스윙 받을 준비) == 0 이면 무시        ← 일반 스윙도 같음
51e14: 0xaea30(팀) == 0 이면 무시                                         ← 필살만의 조건
51e22: 경기+0xfe0 = 1 (스윙 예약) ; 경기+0xfdc = 0 ; 경기+0xfd8 = 경기+0x1098 (지금 틱)
51e40: S+0x10 = 타자 레코드 +0x18 (필살타법 번호)                           ← 일반 스윙은 S+0x10 = 0
```
- **남은 횟수 읽기 0xaea30(팀)**: `타자+0x18 == 0 이면 0, 아니면 s8 팀[+0x29 + 팀[+0x32]]` — 팀+0x32 = 지금 타순(0~8), 팀+0x29..+0x31 = **타순 칸별 필살 남은 횟수**, 팀+0xe+i = 타순 i 의 선수 번호(0xae89c).
  투수는 0xaea10(팀): `투수(0xae83c)+0x18 == 0 이면 0, 아니면 s8 팀+0x28` (팀당 한 칸). 쓰기 0xae9e8(타자)·0xae9c4(투수).
- 조건은 **"남은 횟수 ≠ 0"** 하나다. 게이지·G포인트·사기 조건은 없다. (−1 은 "아직 안 채움" 표시인데, 0xaebe4 가 타석 전에 채우므로 실제로는 양수/0 만 본다 — 아래 1-2.)
- **소모는 누를 때가 아니라 스윙이 실제로 나갈 때** 경기 틱 0x4e060 에서 한다:
  ```
  4e092: if 경기+0xfe0 (예약) && S+4 != 0 && 경기틱 >= 경기+0xfd8:
  4e0ec:   경기+0xfe5 = 0 ; 경기+0xfe0 = 0 ; 설정+0x13 = 경기+0xfdc
  4e100:   fdc != 0 이면 S->vtbl[0x18](fdc)  아니면 0xa5fac(경기+0x230) 뒤 S->vtbl[0x14]()   (스윙 시작)
  4e136:   if S+0x10 (필살 번호) != 0 && 0xaea30(팀) > 0:  0xae9e8(팀, 남은−1)
  ```
  → 한 번 누르면 한 번 줄어든다. 헛스윙이어도 줄어든다 (결과와 무관).

### 1-2. 한 경기 사용 횟수 — 0xaebe4 (타석 교대·교체 처리) 안 (확정)
- 대타(0xaede0)·투수 교체(0xaec7a)·다른 교체(0xaee8c) 때 그 칸을 **−1** 로 되돌린다 → 새로 들어온 선수는 자기 횟수를 새로 받는다.
- 그다음 (0xaee9a~0xaf00a) 남은 횟수가 음수면 채운다:
  ```
  투수 P = 0xae83c(팀)
  P+0x18 == 0                → 0
  else if 0xaea10(팀) < 0:
      마투수(0xb633d(P)) 이면   n = s8 표 0xd8509[ 레벨 ]   레벨 = s8 전역기록(0x1f1d9)[+0x13a + 순번(0xb63a1(P))]
      아니면                   n = u8 표 0xd84ff[ P+0x18 ]
      스킬 23(0xb62b4(P,0x17), 투수 이름 = 39 혼신) 있으면 n += 2
  타자 B = 0xae89c(팀) 도 같은 틀:
      B+0x18 == 0 → 0
      마타자 → s8 표 0xd84fa[ 전역기록[+0x13f + 순번] ] ,  아니면 u8 표 0xd84f0[ B+0x18 ]
      스킬 23(무자비) 있으면 +1
  ```
- 표 (바이트 확인 `re bytes 0xd84f0 32`):
  | 표 | 색인 | 값 |
  |---|---|---|
  | 0xd84f0 u8 (육성·일반 타자, 필살 번호별) | 0,1,2,3,4,5 | **0, 2, 3, 4, 5, 5** (1 파워 2회 · 2 플레임 3회 · 3 토네이도 4회 · 4 미라지·메테오 5회 — 저장 번호는 1~4, 색인 5 는 안 쓰임) |
  | 0xd84fa s8 (마타자, 레벨별) | Lv0..4 | **2, 2, 3, 4, 5** |
  | 0xd84ff u8 (육성·일반 투수, 마구 번호별) | 0,1,2,3,4..9 | **0, 4, 5, 6, 7, 7…** (1 파이어 4 · 2 웨이브 5 · 3 썬더 6 · 4 샤이닝·캐넌·미라지 7) |
  | 0xd8509 s8 (마투수, 레벨별) | Lv0..4 | **3, 4, 5, 6, 7** |
- 스킬 보정: 타자 스킬 23 무자비 "필살타법 횟수 +1"(StrCOMMON 78) · 투수 스킬 23 → 혼신 "마구 횟수 +2"(StrCOMMON 94, 투수 이름 = 비트+16=39) — 설명 문구와 정확히 맞는다.
- 칸이 타순별이므로 **횟수는 경기 전체에 한 번 주어지고 이닝이 바뀌어도 다시 차지 않는다** (−1 로 되돌리는 곳은 교체뿐).
- 레벨(배운 수 +0x201) 은 여기서 직접 쓰이지 않는다. 쓰이는 것은 **고른 기술 번호 +0x18** 뿐이고, 번호가 클수록 횟수가 많다(배운 수는 고를 수 있는 번호의 상한 — H 노트 6절).

## 2. 필살타법 효과 — 타격 판정에 넣는 12바이트 "보정 구조체" 0x34d6c (확정)

타격 판정 0xab214 를 부르는 곳(0x51306, 경기 장면 0x51108 안)은 바로 앞에서 **0x34d6c(out12, 경기)** 로 12바이트 구조체를 만들어 스택 인자 `[sp+0x14..0x1f]` 로 통째로 넘긴다
(웹 swingResult.ts:15 주석이 "생략"이라 적은 "존 보정 네 쌍 · pctA~D" 가 바로 이것 — **투구 존과 무관하고 필살타법/마구 보정이다**).

```
34da6: S = [경기+0xf9c] ; if S+0x10 (이번 스윙의 필살 번호) != 0:
34db8:   B = 0xae89c(공격팀)
         if 마선수(0xb633d(B), 레코드 +0xa 비트6):  k = 레벨·5 + 순번   (레벨 = 전역기록[+0x13f+순번])
             out+0 = s16 D[0x100 + 2k] ; out+2 = s16 D[0x132 + 2k] ; out+0xa = s8 D[0x1a6 + k] ; out+0xb = s8 D[0x1bf + k]
         elif 0xb6389(B) (레코드 +0xa 비트7 = 육성·명전 선수):  n = 번호−1
             out+0 = s16 D[0x7c + 2n] ; out+2 = s16 D[0x84 + 2n] ; out+0xa = s8 D[0x19e + n] ; out+0xb = s8 D[0x1a2 + n]
         else (일반 CPU 선수) → 모두 0
34ebc: P = [경기+0xf98] ; if P+0x10 (이번 공의 마구 번호) != 0:  투수 = 0xae83c(수비팀)
         마투수: k = 레벨·5+순번 (레벨 = 전역기록[+0x13a+순번])
             out+6 = s16 D[0x9c + 2k] ; out+4 = s16 D[0xce + 2k] ; out+0xa = s8 D[0x16c + k] ; out+0xb = s8 D[0x185 + k]
         elif 비트7: n = 번호−1
             out+6 = s16 D[0x8c + 2n] ; out+4 = s16 D[0x94 + 2n] ; out+0xa = s8 D[0x164 + n] ; out+0xb = s8 D[0x168 + n]
34fcc: out+8 = out+9 = 0
```
D = `[0x14000c0]` = d_level.dat 객체 (**객체 오프셋 = 파일 오프셋 + 4**, balance.json `swing.source` 와 같은 규칙). 파일 바이트로 푼 값:

| 칸 (0xab214 안 쓰임) | 육성 타자 필살 1·2·3·4 | 마타자 Lv0·1·2·3·4 (다섯 명 같음) | 육성 투수 마구 1·2·3·4 | 마투수 Lv0~4 |
|---|---|---|---|---|
| out+0 → **히트 + 값** (0xab4dc: `eff(타자,히트)+out[0]+마선수보너스`) | 150·180·200·220 | 150·150·180·200·220 | — | — |
| out+2 → **파워 + 값** (0xab502) | 150·180·200·220 | 150·150·180·200·220 | — | — |
| out+4 → 투수 **구속 + 값** (0xab550, 히트 쪽에서 빼는 값) | — | — | 150·180·200·220 | 150·150·180·200·220 |
| out+6 → 투수 **제구 + 값** (0xab586, 파워 쪽에서 빼는 값) | — | — | 150·180·200·220 | 150·150·180·200·220 |
| out+0xa → **B(잘 맞음) += B·값/100** (0xabd92) | 15·17·19·20 % | 15·15·17·19·20 % | 10·12·14·15 % | 10·10·12·14·15 % |
| out+0xb → **C(홈런) += C·값/100** (0xabdae) | 6·7·8·9 % | 6·6·7·8·9 % | 7·8·9·10 % | 7·7·8·9·10 % |
| out+8·+9 → B·C 추가 % (0xabdcc·0xabde8) | 늘 0 | | | |

- 0xab214 안 식 (확정): `hitEdge = eff(히트)+out[0]+aB − 배율·(eff(구속)+out[4]+aP)/100`, `powerEdge = eff(파워)+out[2]+aB − 배율·(eff(제구)+out[6]+aP)/100`
  (aB/aP = 웹의 마선수 보너스). 스킬 보정(0x13·0x14·0x15 …) 뒤에 `if out[0xa]: B += B·out[0xa]/100`, `if out[0xb]: C += C·out[0xb]/100`, 그다음 상한 B ≤ 9000 · C ≤ 4500 (0xabeba).
- 즉 **필살타법 = 히트·파워 +150~220 과 잘 맞을 확률 +15~20%·홈런 확률 +6~9%.** 히트존 크기·타구 각도·확정 홈런은 없다 (contact 식 `[sp34]` 에는 구조체가 안 들어간다 — 존 오차 표·타이밍 그대로).
- **레코드 +0x18 에 저장되는 번호는 1~4 뿐이다** (확정: 필살타법 창 확인 0x18150~0x1816c `strb 표0xcc378[칸], [선수+0x18]`, 표 = u32 [1,2,3,4]). "4 + 타입/폼" 은 **이름 고르기에만** 쓴다 (0x180e6~0x1810c: `번호==4 이면 r1 = 4+타입` → StrCOMMON[0x18+r1] / 투수 [0x1e+r1]).
  → **미라지 스윙과 메테오 스윙은 같은 기술 4 다** (효과·횟수·연출 그림 effect_meteor 모두 같고 이름만 타입 0/1 로 다름). 마구 4 = 샤이닝/캐넌/미라지 볼도 이름만 폼으로 갈린다.
  (횟수 표 0xd84f0/0xd84ff 는 색인 5~9 도 채워 두었지만 쓰이는 경로는 못 찾았다.)
- **마구와 필살이 한 타석에서 겹치면** out+0xa/+0xb 는 투수 값이 덮어쓴다 (0x34f66 이 뒤에 쓴다). 그리고 마구의 +0xa/+0xb 는 **타자의 B·C 를 올린다**(부호 양수, 빼는 코드 없음). 마구의 실제 억제력은 out+4/+6(구속·제구 +150~220)뿐이다 — 원본 그대로의 이상한 동작(유력: 의도는 감소였을 것).
- 스킬 23 "무자비 — 필살타법 안타율 +10%", 투수 39 "혼신 — 마구 피장타율 −10%" 의 **확률 보정은 0xab214 에 없다**(스킬 0x17 검사 호출 0건, `grep "movs r1, #0x17"` 결과 판정 함수 밖뿐). 원본에서 적용되는 것은 횟수 +1/+2 뿐이다 (1-2).
- CPU끼리 치는 간이 타석 0xc11f0 은 필살 버튼과 무관하게 **마선수면 늘 레벨 값(out+0/+2 또는 +4/+6)** 을 넣는다 (0xc1224~0xc12c4). % 칸은 넣지 않는다.

### 2-2. 부가 효과 (확정 / 뜻 유력)

## 3. 마구 발동 (확정 / 한 곳 유력)

### 3-1. 구질 칸 6개와 마구 칸 — 0xb6d2c(투수, out[6], 6) (확정)
타석 교대 0x47cc8(0x47fcc)가 경기+0xfac..+0xfc0 (u32 ×6) 를 채운다:
```
b6d44: for i in 0..21:  if 투수+0x1c & 표0xd88c4[i]:  out[ 표0xd8920[i] ] = i      ; 가진 구질을 키 칸에
b6d5e: out[0] == 0 이면 out[0] = 1 (FASTBALL)
b6d6a: 투수+0x18 (마구 번호) != 0 이면 out[5] = 22                                   ; '0' 키 칸 = 마구
```
→ **마구는 구질 22 하나다.** 파이어·웨이브·썬더·샤이닝·캐넌·미라지 볼은 구질 번호가 따로 없고 투수+0x18(1~4) 로만 갈린다 (2절: 효과·횟수·이름).

### 3-2. 사람 투수 — 구질 메시지 7 → 0x50da8 (확정)
키 '0' → 메시지 7(5) (0x534d8, I 노트). 0x50da8:
```
50da8: t = 경기[0xfac + 4·칸] ; t == 0 → 0x9dff9(공, 2) (빈 칸, 무시)
50db8: t == 22 이면 0xaea10(수비팀) > 0 아니면 무시          ; 남은 마구 0 이면 고를 수 없음
50dd2: 경기+0xfc8 (이번 구질) = t
```
- 코스 확정(메시지 9, OK/'5') 0x50e9c: `구질 == 22 && 0xaea10 > 0 이면 0xae9c4(팀, 남은−1)` → 상태 0x11 예약(0xbcb48, 다음 틱에 적용).
- 마구는 투구 게이지를 쓰지 않는다 (P1 노트 0x3f500: 구질 != 22 조건), 스태미나 소모 c = 9(직구와 같음, P1 3-1).

### 3-3. CPU 투수 — 0x344dc (구질 고르기, 0x51214 에서 호출) (확정)
```
344ea: 모드(경기+0x1104) == 7 (홈런더비):  구질 = state+0x38(등장한 마투수 수) > 0 ? 22 : 1   ; 그리고 끝
34506: 구질 = 0
34518: if 투수+0x18 > 0 && 0xaea10(수비팀) > 0:
34536:     if 주자 수 0xa9599(경기+0x20c) >= 2                       → 22
34540:     elif S(state+4) == 2                                      → 22    ; 투 스트라이크
34548:     elif S == 0 && (B(state+5) == 0 || B == 3)                → 22    ; 0-0, 0-3
3455c: 구질 == 0 이면  칸 = rand(0,6) (0xbfa54) ; 구질 = 경기[0xfac+4·칸]
            그 구질이 22 인데 남은 ≤ 0 이면 0 ; 0 이면 1(FASTBALL)
```
- **CPU 마구는 확률이 아니라 상황 규칙**이다: 주자 2명 이상 · 투 스트라이크 · 초구(0-0) · 0-3 이면 남은 횟수가 있는 한 **반드시** 마구. 그 밖에는 6칸 균등 추첨에서 마구 칸(5)이 뽑히면 던진다(1/6, 빈 칸은 직구로).
  (state = [0x1552d0c], +4 스트라이크 · +5 볼 — Q1 노트와 같은 필드.)
- 0x345c0 은 같은 6칸 균등 추첨만 하는 변종인데 호출처를 못 찾았다(쓰이지 않는 듯).
- 소모: 0x345fc(CPU 코스 고르기, 0x5121e)가 상태 0x11 을 예약한 뒤 `구질 == 22 && 공+0x10 != 0 && 0xaea10 > 0 이면 남은−1` (0x34894~0x348d2).

### 3-4. 공 객체에 마구 번호 싣기 — 상태 0x11 진입 0x3de10 (확정)
```
3de18: if 구질 == 22 && 0xaea10(수비팀) > 0:  공(경기+0xf98)+0x10 = 투수+0x18        ; 마구 번호 1~4
3de42: if 구질 == 22 && 투수 순번 0xb63a1 == 2:  0x6dee4([0x1400068])  ; 파티클 관리자 — 3-7 참고
```
- 이 +0x10 이 2절의 `P+0x10 != 0` 이고, 0x34d6c 가 여기서 구속·제구 +150~220 · B/C % 보정을 만든다.
- **순서 문제 (확정)**: 상태 변경 0xbcb48 은 "다음 상태 예약"(+8 에 넣고 +0x18=1)이라 0x3de10 은 **소모 뒤에** 돈다. 그래서 마지막 1회(남은 1→0)는 0x3de10 의 `남은 > 0` 이 거짓 → +0x10 을 새로 쓰지 않는다.
- **공+0x10 은 되돌리는 곳이 없다 (유력)**: 경기+0xf98 참조 26곳(0x33516~0x50de8) 을 모두 보고 공 클래스(vtable 0xd73d0, 메서드 0x9df04~0x9e800) 의 `str …,#0x10]` 을 모두 찾았지만 쓰는 곳은 0x3de10 하나다(0x9e15a·0x9e304 는 다른 클래스 0xd7518 쪽). 반면 스윙 +0x10 은 공마다 0x34444 에서 0 으로 되돌린다.
  → 원본에서는 **한 번 마구를 던진 뒤로는 직구·변화구에도 마구 보정(0x34d6c 투수 쪽)이 계속 붙는다**(투수 교체 뒤에도 값이 남고, 새 투수가 마투수면 그 레벨, 육성이면 +0x10−1 번 칸, 일반 CPU 면 0). 마지막 1회 문제도 이 때문에 실제로는 드러나지 않는다.
  CPU 쪽 소모 조건 `공+0x10 != 0` 도 같은 이유로, 경기 첫 마구가 CPU 것이면 **그 한 번은 소모되지 않는다** (공 객체 new(0x28) 가 0 으로 채워진다고 볼 때 — 0x1239 new 의 0 채움은 미확인).
  이식할 때는 "공마다 +0x10 = (구질==22 ? 번호 : 0)" 으로 정리하는 편이 의도에 맞다(판단은 웹판 쪽에서).

### 3-5. 마구 → pitch.zt1 구질 22 레코드 고르기 — 0x9e944 (확정, 궤적 코드는 안 봄)
타석 교대 0x47cc8 가 `0x9e944(투구데이터, 칸[6], 폼 = 0xb6e24(투수), 마구번호 = 투수+0x18)` 를 부른다 (0x48000~0x4800a).
```

9e9da:   m ≥ 5 (마투수)   :  idx = m + 8
9e9f4:   레코드 = 0x9e88c(블록, idx)                                    ; idx 는 1부터 (0x9e88c 가 idx 개를 세며 앞 레코드를 돌려줌)
```

### 3-6. 마구 효과 정리 — 구질 22 를 보는 곳 전수 (경기+0xfc8 참조 22곳)

## 4. 마선수 고유기 — StrCOMMON 95~114 (확정)

### 4-1. 번호와 이름
마선수 레코드 +0x18 은 모두 **5~9** 다 (XlsACE_BAT_DATA / XlsACE_PIT_DATA 바이트: 마타자 메디카 5 · 어거지죠 6 · 로제 7 · 크라이져 8 · 킹타이거 9, 마투수 싸이커 5 · 레오니 6 · 붕붕머신 7 · 발렌타인 8 · 드래고나 9. 순번 = 번호 − 5 = 0xb63a1).
이름 고르기 (선수 정보 그리기 0x5b8xx~0x5c7xx, 마선수 0xb633d 가지):
- 타자: `StrCOMMON[0x5f + n]` (0x5bd6e) → **100 핑크 봄(메디카) · 101 플레임 스트라이커(어거지죠) · 102 메이든 임팩트(로제) · 103 하트 브레이커(크라이져) · 104 크로스 액스(킹타이거)**
- 투수: `StrCOMMON[0x5a + n]` (0x5c652) → **95 싸이킥 스타(싸이커) · 96 트리플 크로우(레오니) · 97 홀로그램 레이저(붕붕머신) · 98 다크 일루전(발렌타인) · 99 브레스 웨폰(드래고나)**
- 105~114 는 기술이 아니라 **마선수의 타입 칸 이름**: 일반 선수는 타입 문자열표 [0x1400124 + 4·타입] 을 그리는 자리(0x5b98a)에 마선수면 타자 `StrCOMMON[0x69 + 순번]`(0x5b972) = 105 백의천사 · 106 무에타이 · 107 새침부끄 · 108 헤비메탈 · 109 프로레슬링, 투수 `[0x6e + 순번]`(0x5c0d0) = 110 싸이킥커 · 111 사자왕류 · 112 MK-II · 113 뱀파이어 · 114 용인족.
- 비교: 일반 이름은 타자 `StrCOMMON[0x18 + n]` (25~28, 4 + 타입 1 → 29 메테오), 투수 `[0x1e + n]` (31~33, 4 → `[0x22 + 폼>>1]` 34~36).

### 4-2. 발동 조건 — 일반 필살·마구와 같은 길
- 사람: 타자 '0' 키(1절)·투수 구질 '0' 칸(3-2). 조건은 남은 횟수 ≠ 0 뿐 — 마선수 전용 조건 없음.
- CPU 마타자: 휘두를 때마다 남은 횟수가 있으면 **무조건** 필살 (0x34488, Q1 노트 5절). **일반 CPU 타자는 절대 안 씀.**
- CPU 투수: 3-3 상황 규칙 (주자 2+·2스트라이크·0-0·0-3 → 반드시, 그 밖 1/6). 0x344dc 에 마선수 검사는 없지만, 일반 선수 레코드(XlsPITCHER_DATA 120명 · XlsBATTER_DATA 180명)는 +0x18 이 **모두 0** 이라(바이트 확인) 실제로 필살·마구를 쓰는 것은 마선수와 육성·명전 선수(비트7)뿐이다. 0x34d6c 의 "그 밖 → 0" 가지는 사실상 안 쓰인다.
- 홈런더비(모드 7): 마투수가 나온 뒤로 늘 마구 (3-3).

### 4-3. 효과 — 마선수는 레벨 칸, 육성은 기술 번호 칸
0x34d6c: 마선수면 `k = 레벨·5 + 순번` 으로 d_level.dat 표(2절 표의 "마타자/마투수 Lv0~4" 열 — 다섯 명 값이 같다), 비트7(육성·명전)이면 `번호−1`, 그 밖 0.
→ 마선수 고유기는 **이름·궤적 레코드·연출만 고유**하고, 수치 효과는 레벨에만 달렸다 (Lv1 = 육성 1번 기술과 같은 150/15%/6%, Lv5 = 육성 4번과 같은 220/20%/9%).
- 궤적 레코드: 마투수 구질 22 레코드 12~16 (3-5). 마타자는 스윙 궤적 차이 없음(스윙 객체 +0x10 은 0x34d6c·연출에서만 읽음).
- 필살 타구 부가 확률 30% (0x34c74, 2-2), 일반은 15~30%.
- 표시 구속: 마투수 3-6 표 칸 4~8.
- 연출: 마타자 파티클 2-3 표(순번별), 마투수 3-7 (드래고나만 공 꼬리 022.ptc, 붕붕머신은 0x6dee4).

# BALANCE — 숨은 판정값 표 (balance.json) 와 그 효과

> 2026-10-26 · r265 · 웹 커밋 `046df1c7` (브랜치 `round9-r265`)
>
> 사용자 질문: "능력치 밖으로 보이는 능력치들도 json 같은 걸로 따로 뺄 수 있어? 그걸 어떻게 바꾸면 안타나 삼진 같은 확률이 오르는 건가?"

## 한 줄 답

- **뺄 수 있고, 뺐다.** 화면에 보이는 능력치(히트·파워·수비·주루 / 제구·구속·변화·체력) 말고도 안타·삼진·홈런·실책을 정하는
  숨은 값 **65개**를 `src/shared/config/balance/balance.json` 한 파일로 모았다. 게임 코드는 이 파일을 읽는다.
- **기본값은 원본(binary.mod)과 똑같다.** 고치지 않으면 게임은 원본 그대로 돈다(시험 9361개 · soak 전부 그대로 통과, 타율 하네스 결과도 한 자리까지 같음).
- 값을 바꾸면 확률이 바뀐다. **가장 크게 듣는 것은 "내 선수 타자 보너스"(400)와 "맞힐 확률 기본값"(1200)** 이다.
  아래 [효과 측정](#효과-측정)에 바꿔 본 결과가 있다.

## 어떻게 고치나

1. `src/shared/config/balance/balance.json` 을 연다. 항목 하나는 이렇게 생겼다.
   ```json
   {
     "id": "swing.ownBatterBonusBase",
     "category": "swing",
     "name": "내 선수 타자 보너스(1년차)",
     "value": 400,
     "source": "d_level.dat 0x1d4 (cfg+0x1d8) · 0xab3f2",
     "effect": "나만의리그에서 육성 타자의 히트·파워에 더하는 값(연차마다 깎임). 올리면 …",
     "range": { "min": 0, "max": 999 }
   }
   ```
2. `value` 만 고친다. `range` 밖 값은 앱이 켜질 때 오류로 막는다(0 으로 나누기 같은 사고를 막으려고). 표(배열)는 칸 수를 바꿀 수 없다.
3. 저장에는 아무것도 쓰지 않는다. 원래 값으로 되돌리면 원본 그대로다.
4. 시험(`yarn test`)은 JSON 과 상관없이 늘 원본 값으로 돈다(`originalBalanceForTests` — vitest `setupFiles`).
   JSON 을 고쳐도 시험이 깨지지 않는다. 원본 값 자체는 `originalBalance.ts` 에 있고 `balance.test.ts` 가 JSON 기본값과 하나씩 견준다.

## 판정 흐름에서 값이 들어가는 자리 (쉬운 말)

공 하나를 칠 때 원본(0xab214)은 세 가지 확률을 만든다.

| 확률 | 뜻 | 이 확률을 움직이는 숨은 값 |
|---|---|---|
| **A 맞힐 확률** (만분율) | 넘지 못하면 **헛스윙** → 삼진 | 맞힐 확률 기본값 1200 · 능력 계수 500/1000 · 내 선수 보너스 400 · 타이밍(폭 24) · 코스 오차 표 · 제구 등급 배율 |
| **B 잘 맞을 확률** | 넘으면 강한 타구(라이너 15·장타 18·홈런성 24), 못 넘으면 약한 타구(파울 9·땅볼 0·빗맞음 3) | 잘 맞을 기본 280/250 · 히트·파워 계수 · 스윙 세기 500 · 지친 투수 2000 · 타이밍 중심 77 · 스킬 % · 상한 9000 |
| **C 홈런성** | B 안에서 홈런성(24)이 될 확률 | 홈런성 기본 50/70 · 파워 계수 · 상한 4500 |

- "능력 차" = 타자 히트(또는 파워) + 내 선수 보너스 − 투수 구속(또는 제구) × 제구 등급 배율.
  **신인 히트 100 은 이 식에서 보너스 400 이 더 크다** — 그래서 신인 타율은 거의 이 보너스가 정한다.
- 공이 맞으면 결과(안타/아웃/홈런)는 수비 판이 낸다. 펌블·악송구·송구 속도·주자 속도가 여기서 들어간다.
- 화면 능력치도 바로 쓰이는 게 아니다. 경기 전 **사기 · 질병 · 부상 · 장비 · 스킬**로 깎이거나 더해진 "실효 능력치"가 들어간다.

## 효과 측정

r209 · r242 타율 하네스(`batterHitRateHarness`)로 잰다. 신인 타자(나리 1년차, 히트·파워 100, 사기 100)가 경기 300판 동안
**모든 공에 스윙**하고, 스윙 키는 정타 틱(N−2)과 앞뒤 한 틱 중 하나를 고른다("보통 타이밍"). 한 번에 한 값만 바꾼다.

- 헛스윙률 = 헛스윙 ÷ 스윙. 타율 = (안타+홈런) ÷ 타석. 삼진률 · 홈런률 = ÷ 타석. 늘 치므로 볼넷이 없고 타석 = 타수다.
- 파울 뜬공 아웃은 세지 않는 근사다. 판 수가 300 이라 ±1~2%p 는 흔들림이다(예: 맞힐 확률 900 의 타율).
- 다시 재려면: `BALANCE_SWEEP=결과.jsonl yarn vitest run src/features/play-game/model/balanceSweep.test.ts --maxWorkers=1`

능력치가 높아질수록 커진다(감소가 % 라서).

## 항목 표 (65개 — 원본 주소와 웹 위치)

범주별 개수: 타이밍 6 · 스윙 판정 32 · 스킬 2 · 실효 능력치 6 · 투구 12 · 수비 5 · 주루 2.
`d_level.dat` 오프셋은 파일 오프셋이다(적재 객체 cfg+ = 파일 + 4). 리터럴 1200(0xab65a) · 24(0x34c42) · 9000/4500(0xabebc/0xabec4) ·
120(0xabefa) · 2000(0xab840) · 500(0xab812) · 번트 50/75(0xabe0e) 와 표 0xd87d4 · 0xd25b0 · 0xd8890 · 0xcfd60 · 0xd2589 · 0xd257d · 0xd896c 는
r265 에서 `re.py` 로 다시 읽어 값이 같음을 확인했다. 웹 위치는 그 값을 읽는 파일이다.

## 아직 표에 없는 것 (남은 일)

- **화면 글의 숫자**: 관리 화면 상세 창의 "+50 · −100 · 30% · 60%" 글(`abilityDetail.ts` · `seasonPlayerDetail.ts`)과 그 사기 감소 표 사본은
  표를 따르지 않는다(원본 글 그대로). 표 값을 바꾸면 화면 설명과 실제 판정이 달라진다.
- **간이 타석 고유 상수**(`BALANCE.quickAtBat` — 0xc11f0, CPU 끼리 타석): 생성기가 만드는 `original/data/balance.json` 에 남아 있다.
  등급 표(0xd896c)만 `pitching.controlTierRows` 를 같이 읽는다.
- 타구 방향(0x5141c 문턱 −50/50 · 표 [10,80]…) · 필살 타구 2%(0x51502) · CPU 도루 시도 표(0xd047c) · 투구 AI 구질 고르기 ·
  펌블 뒤 튕김 · 레이저 송구 확률 · 지친 투수 표시 문턱 같은 값은 아직 넣지 않았다.
- 스킬 표의 1%·2% 밖 나눗수는 원래 "추정"(위치 분석 3차) 이다.
- `pitchGauge.ts` 의 흩어짐 표 사본(시험만 씀)은 표를 읽지 않는다.

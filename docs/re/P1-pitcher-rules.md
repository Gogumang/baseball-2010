## 요약
**풀린 것**
- 등판(1절, 확정): 경기 전 0x1c46c 가 날짜 카운터 g(리그+0x32 = 시즌+0xb2)로 로스터를 돌린다. 투수편 선발은 0xa4f60 이 k=((g−1)%6)/2+1 로 0↔k 를 맞바꿨다 되돌려 **짝수 g 마다 내 투수가 로스터 0번(선발)** — "2경기마다". 구원은 간이 엔진 0xc1ba4 가 **8회(0-기준 7) 내 팀 수비 첫 타석에 벤치의 내 투수로 교체**하고, 그때부터 0xc1d38 가 사람에게 넘긴다(넘기는 고리는 유력). 사람 경기 상대 팀은 0xb5ca8 로 4인 로테이션이 하루 한 칸 돈다.
- 감독 강판(2절, 확정): 0x504cc — 선발만, 평판/100 칸 표 0xcfa58 4줄(체력 ≤20%·체력 0%·한 이닝 4실점·만루) 확률, 글 USER_EVT 85~96(평판 3구간 말투). 스스로 강판은 팝업 코드 0x1b → 0xc1b48(CPU 교체 AI 로 새 투수, 남은 경기 간이 진행).
- 스태미나(3절, 앞 에이전트, 확정): 구질별 9/11/12/13 소모, 용량 = 체력 실효·사기 보정 + 250(+200 첫 투수), 회복 40/80/20%, 체력%별 능력치 감소, 십전대보탕.
- 투구 게이지(4절, 확정): 게이지 결과는 등급 t(0~5) 하나. 커서가 틱마다 한 칸, 누른 칸 g → t=max(g−4,1), 안 누르면 0. 게이지를 끄면 제구/250 행의 확률표 0xd896c. t 는 능력치 배율 70~110% 와 목표점 흩어짐 표 0xcfd60(배율 [12,20,25,30])에만 쓰인다. 게이지는 스태미나 소모와 무관(설명서와 다름).
- 경기 뒤 평가(5절, 확정): 투수 기록 칸(R+0x124~0x158), 선발형/구원형 인기도 식(선발 p −2~12), 평판 식(+ 공통 꼬리 표 0xd82a0·0xd82c8 — 웹 타자편에도 없음), 사기(선발 p 반감), 감독 글 2~37·38.
- 투수 레코드 칸(6절): +0x20 아웃·+0x22 실점·+0x24 세이브·+0x26 탈삼진·+0x28 투구 수·+0x2e 승·+0x2f 패, 방어율 = 실점×2700/아웃.

**원본 버그 후보**: 평가 객체 "실점"(R+0x128) 을 채우는 코드가 없다(유력) → 완투 승은 늘 완봉으로 세고, 실점 감점이 안 걸린다. 게이지 모드의 체력 0% 감점은 죽은 코드. USER_EVT 97~99(연속 4안타 강판)는 쓰이지 않는다.

**남은 것**: 승리·패전·세이브 투수 판정(state+0x44~0x60 을 쓰는 곳), 투수 레코드 +0x2a, 평가 칸 R+0x130·0x138·0x148·0x150·0x158 의 정확한 뜻, state+0x6a 의 뜻(구원 "등판 없음" 판정), 감독 강판 플래그 S+0x68·0x69 초기화 위치, 정규시즌 CPU 끼리 경기의 선발 교체(1-4), 게이지 결과 글자(PERFECT 등)와 t 의 대응.

  투수 쪽 두 배 소모는 효과 74 = 설명 34 "비겁자"(투수 비트 18, "투구 스태미나 소모량 x2").
  (투수 비트 n ≥ 8 → 이름 n+16 — A 문서 4절.)

## 3. 스태미나(체력) — **확정** (소모·회복·능력치 감소·십전대보탕)

### 3-0. 어디에 있나
- 투수 선수 레코드(0x30 바이트, 팀 투수 배열 +0x14) 의 **+0x2c s16 = 스태미나, 0~10000 (=0.00~100.00%)**. 경기용 객체가 아니라 **시즌 내내 이어지는 레코드 값**이다.
  같은 레코드의 시즌 칸 초기화 0xb6cc4: +0x20·+0x22·+0x24·+0x26·+0x28·+0x2a = 0, **+0x2c = 10000**, +0x2e·+0x2f = 0 (시즌 시작 — 호출 0x1b832·0xc58a·0x20560·0xa4038).
- 경기 중 현재 투수 = `0xae83c(team)` → `0xb89dc(team, team[0])` (team[0] = 등판 슬롯).
- 체력% = `0xaebb0(team)` = trunc(+0x2c / 100). state[1]==7 이면 늘 100.

### 3-1. 투구 한 개의 처리 0xa5e14(game, 구질번호) — 확정
```
P = 수비팀 현재 투수 (0xae83c)
P+0x28 (투구 수) += 1, 0..9999 로 자름           ; a5e30~a5e4c
game+0x16c += 1 ; 수비팀 객체+0x27c += 1 (이번 투수 투구 수, E-6 의 team+0x27c) ; 0xa57f8(game, 0x1b, 0) ...
c = 0x66ef0(구질)                                   ; 기본 소모
if 0xb62b4(현재 타자, 22) || 0xb62b4(P, 18): c *= 2   ; a5f0e~a5f3c  (타자 스킬 22 / 투수 스킬 18 비겁자)
if 0xb62b4(P, 10): c -= 1                           ; a5f52~a5f60  (투수 스킬 10 끈기 "지치지 않는 체력")
0xaeb08(수비팀, c)                                  ; 소모 적용
```
- **순서가 ×2 다음 −1** 이다: 비겁자 + 끈기 → 2c−1.
- 구질번호는 사람 투구에서 고른 구질(0x3dec6: `r1 = [r7]`), 간이 경기(0xc26c8)에서는 **늘 1(FASTBALL)**. 간이 경기는 0xc26be~0xc271c 루프가 한 바퀴 = 한 투구.
- **게이지 결과는 이 함수에 들어오지 않는다** → PERFECT 여부와 스태미나 소모는 무관 (확정: 인자가 game·구질 둘뿐).

기본 소모 0x66ef0: 표 0xd2624 = **[9, 11, 12, 13]**, 점프표 0xd2634(22칸)로 구질 → 칸:
| 구질 번호 | 뜻 (J-6 구질표) | 소모 c |
|---|---|---|
| 1 | FASTBALL | 9 |
| 2~9 | 기본 변화구 8종 | 11 |
| 10~17 | 상위 변화구 8종 | 12 |
| 18~21 | 히든 4종 (P.SINKER·P.SLIDER·KNUCKLE·SPECIAL) | 13 |
| 22 | 마구 | 9 |
| 그 밖 | — | 9 |

### 3-2. 소모 적용 0xaeb08(team, c) — 확정
```
P = 0xae83c(team)
V = 0x1f9a8(전역, 모드=state[1], team+0x25)        ; 모드별 팀 레코드(s16 +2 = 팀 사기). 모드 3 → 0x1f940(전역+0xb8)
starter = (team+0x26 − team+0x33 == 1)            ; 유력: 아직 첫 투수(교체 없음) — +0x33 은 남은 벤치 투수 수(E-6)
X = 0x66e44(V, P, starter)                        ; 용량
s = P+0x2c
if s > 0:  s' = s + trunc((X − c)·10000 / X) − 10000 ; 음수면 0      ; = s − ⌈c·10000/X⌉ 꼴
else:      s' = 100                                  ; ★ 0 이면 다음 투구에 1% 로 되돌아간다 (원본 그대로)
P+0x2c = clamp(s', 0, 10000)
```
용량 0x66e44(V, P, starter):
```
st = 0xb6415(P, 3, 1)          ; 체력 실효 능력치(장비·스킬 보정 포함)
m  = V ? V[+2] : 100           ; 팀 사기
m > 90 : st += trunc(st/20)    (+5%)
71~90  : 그대로
51~70  : st += trunc(st/−10)   (−10%)
31~50  : st += trunc(st/−5)    (−20%)
11~30  : st += trunc(−30·st/100) (−30%)
≤10    : st −= trunc(st/2)     (−50%)
X = st + (starter ? 200 : 0) + 250        ; P==0 이면 0
```
- 즉 **한 투구가 깎는 % ≈ 100·c / X**. 예: 체력 400·사기 80·선발 첫 투수 → X = 850, 직구 9 → 1.06%/구, 변화구 11 → 1.29%/구 → 100% 에서 약 80~95구.
- 구원(교체로 들어온 투수)은 +200 이 없다 → 같은 체력이면 더 빨리 지친다.

### 3-3. 체력%가 능력치에 주는 영향 — 확정 (G 노트 0xb58e6 의 인자 뜻을 확정)
- 0x34968(투구 화면)이 `0xb570c(team, 칸 0~2, P, 1, [sp]=0xaebb0(team), [sp+4]=1)` 을 부른다 → 0xb570c 의 [sp+0x24] = **투수 체력%**.
- 0xb58e6~0xb592a: 체력% > 54 없음 · **35~54 −10% · 20~34 −30% · 1~19 −50% · ≤0 −90%** (각각 trunc).
- 0x3493c: trunc(체력%/25) 를 3 에서 자른 0~3 단계(표시용으로 보임, 유력).
- 그 밖에 체력%를 읽는 곳: CPU 교체 AI 0xac496(E-6), 간이 엔진 0xc1430·0xc147a·0xc183c·0xc1862(구위 등급 — 웹 quickAtBat.pitchGradeOf 가 이미 씀), 0x38f68·0x44ef8·0x4dbd2·0x512a0(미확인).

### 3-4. 회복 — 확정
**경기 사이** — 리그 하루를 마친 뒤 0x4ea0c 가 10팀 모두에 `0xb617c(team)` (모드 3 투수편: 0x4f304 루프, 모드 4 타자편: 0x4f2e8, 모드 2 시즌: 0x4f2bc).
0xb617c = 0xb60b4(타자 쪽 처리) → **0xb60e0(투수 회복)**:
```
for 각 투수 p (team+0x14, 0x30 간격, team+0xc 명):
   if 전역 모드(0x1552d10) == 3:  mine = 0xb6389(p) (+0xa 부호비트 = 내 육성 선수), starterRole = (p+0xb & 3) == 0
   else: mine = 0, starterRole = 0
   p+0x2c = clamp(p+0x2c + 100·R, 0, 10000)
R = 0x66ed0(mine, starterRole):  mine & 선발 → 40 · mine & 구원 → 80 · 그 밖(모든 CPU 투수, 다른 모드) → 20
```
- **내 선발 투수는 경기마다 40% 회복**, 구원은 80%, 다른 투수는 20%.
- 모드 2(시즌)도 같은 함수를 부르므로 시즌 투수도 경기마다 20% 회복.

**십전대보탕 (GP 아이템 9, 500G)** — 나만의리그 투수편
- 구매 가드 0x13a5a (함수 0x13460): `0x1fbd1()`(내 투수)+0x2c == 10000 이면 StrMODE[211] "스태미나가 최대입니다 구매 할 수 없습니다".
- 사용 0xa49ec (0xa4488 안): 내 투수 +0x2c = 10000, StrMODE[125] "스태미나가 100% 회복되었습니다".
- 시즌모드의 같은 아이템(0x7c00): 투수 고르기 StrMODE[177] → 그 투수 +0x2c == 10000 이면 [211], 아니면 10000 으로 채우고 [178] (0x7c5e~0x7d2a).

## 1. 등판 판정 — 선발 **확정**, 구원 8회 **확정**(넘겨받는 고리는 유력)

### 1-0. 앞 에이전트가 찾은 고리 (그대로 둠, 한 줄 정정은 1-4)
- 경기용 팀 객체 init 0xb891c: team[i]=i (i 0..13, 투수 순서 = 로스터 투수 배열 순서), team[0xe+i]=i (타자), **+0x33 = 투수 수−1 (벤치)**, **+0x26 = 투수 수**, +0x24 모드, +0x25 팀번호. → 선발 = 로스터 투수 0번.
- 선발 고르기 = 경기 전에 로스터 투수 0번과 k번을 맞바꾸는 0xb8c94(team, 0, k) → 0xb5e98(roster, 0, k, 1)(투수 배열 0x30 레코드 교환).
- CPU 경기(정규 0xc239c ← 0xc2a48, 포스트시즌 0xc2c4c ← 0xc2dac): **k = (리그+0x32) % 4** 를 state+0x2e+side 에 쓰고(0xb6c2c) 두 팀 모두 0↔k 교환.
  리그+0x32 = 하루마다 +1 하는 날짜 카운터(0xb818c 첫머리). → **CPU 팀은 로스터 투수 0~3 의 4인 로테이션** (확정).
- 0xb818c(하루 끝): 포스트시즌이면 0x1f9a8(…, 10)(내 팀 레코드) 에 0xb6190 = **투수 전원 스태미나 10000** (포스트시즌 경기 전 내 팀 완전 회복, 유력).
- 0x1b684 는 **새 시즌 처리(0x1b768: career+0xb3 연차++ 뒤)** 에서만 불린다: 내 투수가 선발(보직≠2)이면 로스터에서 내 선수(+0xa 부호비트) 위치 k 를 찾아 0↔k 교환 → 시즌 시작 때 내 투수를 로테이션 0번에 둔다 (확정).
- 사람 경기 장면 0x39fdc: 0x3a526~0x3a538 두 팀 모두 0↔2 교환(어떤 모드인지 미확인).

### 1-1. 경기 전 준비 0x1c46c (나리 관리 장면, 모드 3·4 사람 경기) — 확정
`0x1cdec` (함수표 0xcc304) → BL 0x1cf00 → 0x1c46c(scene). scene+0xb0 = 시즌 객체 S (S+0x80 = 리그 일정 객체, 그래서 **S+0xb2 = 리그+0x32 = 날짜 카운터 g**, 0xb818c 가 하루 끝에 +1), S+0x12c = 포스트시즌 플래그, scene+0xcc = 모드.
두 팀 객체를 0xb891c 로 만든 뒤(scene+0xb8+측×4) 0x1c574~0x1c5ea:
```
g = S+0xb2
if g != 0:  0xb8c80(상대 팀)                    ; 상대 팀 로테이션 한 칸 돌림
if 모드 == 3:
    if g == 0: 0x1b684(scene) ; 0x1faa1(전역, 1, 1)   ; 시즌 첫 경기: 내 선발 투수를 로스터 투수 0번에
    k = 0xa4f60(S)
    k == -1 → 0xb8c80(내 팀)                    ; 구원·그 밖: 보통 로테이션
```

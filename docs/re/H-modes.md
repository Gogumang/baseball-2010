##### 장착 칸 = 선수기록 +0x14 — 쓰는 곳 전수 (확정, 2026-10 디스어셈)
**+0x14 는 보유 비트(+0x1b8)의 사본이 아니라 "장착" 비트다.** 경기 중 스킬 효과(0xb62b4 = `([rec+0x14] >> s) & 1`)는 이 칸만 본다.

  스킬 창 확인 키 `0x13140` · 대화 `0x147b0`(3 해제 · 4 장착 · 6 확장)에 모드 검사가 없고, 확장의 `0x22c29` 인자만 모드 4 면 1 아니면 2(`0x148c6~0x148d4`).
  이름만 갈린다 — `0x8457c(s)`: s ≤ 7 → StrCOMMON[0x37+s], 그 밖에 모드 4(`0x7b970` = `[mgr+0x20]==4`)면 [0x37+s], 아니면 [0x47+s] → 투수 비트 8~23 은 표 번호 비트+16.
- **효과 호출지 — 장착(0xa4bf8·0xb62b4)과 보유(0xa3a74)의 갈림 (확정, 메인 897d7b7 · d65557f)**:
  장착 = 스윙 결과 0xab214 · 실효 능력치 0xb6414(5·7·20·22) · 훈련 0x17f5c 의 병아리 0·몹쓸몸 3 · 행운 6(부상 0x1b562 · 질병 0xadbba · 경기 뒤 사기 0xa741c) ·
  스태미나 소모 0xa5e14 의 비겁자 18(0xa5f32)·끈기 10(0xa5f54) · 마구 횟수 0xaebe4 의 혼신 23(0xaef08) · 실투 0x33cbc 의 16·17·22.
  보유 = 유리몸 4(0x1b550·0xadba8) · 훈련 카운터(0x18b90) · 엔딩 전설 7(0xa3ade) · 칭호(0x1a1c0 — 전설 0x1a380 · 닥터K 0x1a768) · 연속 기록 0x8a6fc · 경기 뒤 카운터 0x12bc2 · 도감.
  → 보유했지만 장착 안 된 플러스 스킬은 경기·훈련 효과가 없다. 최면요법(0xa4970)은 0~23 중 장착∧마이너스마다 0xa4430 을 불러 해제 이력(+0x1d0)도 남긴다.
- **미해결**: 목록 객체 `0x85ad0` 의 내용·차례, 그리기 `0x81dc0` 의 좌표·색, 새 선수 `+0x1c6` 초깃값(0 추정 — 쓰는 곳은 확장 0x148f8 하나).
- **슬롯 확장 — 같은 대화 0x147b0 의 번호 6 (0x1484c)**:
  비용 = `표 0xcc4f7[L] × 1000`(L = P+0x1c6 → **5000 / 10000 G**), G 는 `[[저장+0xac]+0x64]`(0x1f1d9).
  모자라면 StrMODE[65] "G포인트가 부족합니다. 구매 페이지로 이동하시겠습니까?" (2,2) → 번호 2 의 예 = 0xbcb49(장면+0x18, 0x8b)(구매 화면으로 보임, 유력).
  넉넉하면 G −= 비용(0~99999 로 자름), 0x22c29(저장, 모드 4 면 1 아니면 2, 비용) = **소모 GP 통계**(P6 2c 탭 4 의 [176]/[177] 타자편·투수편 소모 GP, 확정), **L = min(L+1, 2)** 를 P+0x1c6 에 쓰고 0x1f1b9·0x1fded·0x22755(…,1)·0x1f1e1(저장), 이어서 StrMODE[136] "플러스 스킬 장착 슬롯이 %d개로 확장되었습니다"(%d = 0xcc4f4[새 L]) 알림 (1,1).
  StrMODE[135] "%d G포인트가 소모됩니다 슬롯을 확장하시겠습니까?" 는 이 흐름에서 안 쓴다(위 6절 300행의 "135/136 유력" 중 135 는 여기 아님).
- **웹 차이**: 웹은 경기 중 스킬 효과에 보유 스킬 전부(+0x1b8)를 쓴다. 원본은 장착(+0x14)만 — 플러스 스킬은 6/8/10 개 상한 안에서 얻은 순서대로 자동 장착되고 넘친 것은 효과가 없다. 장착 창·확장도 웹에 없다(코드는 이번에 안 고침).

##### 필살타법(투수는 마구) 선택 — 키 처리 0x17cec (확정)
탭(창 +0x188) 0·1 = 필살타법/마구 목록, 탭 2 = 구질(투수편, J 담당).
칸 i(0~3)에서:
1. 이미 사용 중(0xa43c4: 선수 레코드 +0x18 == 번호)이면 StrMODE[69] "현재 사용 중인 스킬입니다".
   **원본 어긋남 (확정, 메인 05e1690)** — 저장과 비교가 서로 다른 번호를 쓴다:
   ```
   18166  ldr r2,=0xcc378 ; ldr r3,[칸×4 + 표]   ; 표 = [1,2,3,4]
   1816c  strb r3,[선수+0x18]                    ; ★ 저장: 4 + 타입을 안 더한다 → 1~4
   a43c4  n = 칸+1 ; n>3 이면 n += rec[0xb]>>5 ; return rec[0x18] == n   ; ★ 비교: 넷째 칸은 4 + 타입
   ```
   → **장타형(타입 1)이 메테오 스윙을 고르면 저장 4 · 비교 5** 라 "사용 중"([69])이 안 뜨고, 같은 0xa43c4 를 쓰는 주황 아이콘(`0x803d4`)도 안 붙는다.
   원본 버그로 보고 그대로 옮긴다. 경기 쪽은 저장값(4)으로 돌아 미라지와 같은 기술이다(H2 1-2).
2. 배운 수(저장 +0x201) ≤ i 이면 StrMODE[71] "트레이닝 완료 후 사용할 수 있습니다".
3. 아니면 "[이름]을 사용하시겠습니까?"(StrMODE[70]).
- **번호 = 표[i]** (타자 0xcc378·투수 0xcc368 둘 다 [1,2,3,4]), 번호가 4 이면 **4 + 레코드 +0xb 상위 3비트(타입/폼)**.
- 이름: 타자 StrCOMMON[24 + 번호] → 1 파워 스윙 · 2 플레임 스윙 · 3 토네이도스윙 · 4/5 미라지/메테오 스윙(타입 0/1).
  투수 StrCOMMON[30 + 번호] → 1 파이어 볼 · 2 웨이브 볼 · 3 썬더 볼 · 4+폼 → 샤이닝/캐넌/미라지 볼.
  → 한 선수가 가질 수 있는 필살타법은 **4개**, 넷째는 타입이 정한다 (확정). 배우는 순서는 훈련 칸 4(0x17f5c, 필요 횟수 4/5/6/7).
- **경기에서 쓰는 것은 고른 번호 +0x18 뿐 (확정, 메인 05e1690 · 6222c92)**: 성공 확률 `0x34c74` 가 `p = 0xcfdbe[S+0x10 − 1]`(S+0x10 = 타자 +0x18, `0x51e40`)이고,
  '0' 키 `0x51e14` 는 `0xaea30` 이 `+0x18 == 0 → 0` 이라 **번호를 안 골랐으면 키를 무시**한다(마타자는 +0x18 이 5~9 라 통과). 필살 연출 파티클(`0x49aec`)도 같은 번호로 고른다.
  → 넷 다 배우고 파워 스윙(1)을 고르면 15%, 장타형 메테오도 저장이 4 라 25% — 다섯째 30 은 육성 선수에겐 안 쓰인다.
- 트레이닝 칸 4 는 `0x12e02~0x12e2e` 가 레벨 검사 없이 이 창(`mode` 훈련, 상태 0x6c)을 열고, 그 앞 사기 0 가드(`0x12d8a`)만 돈다.
- **미해결**: 새 선수의 +0x18 초깃값(0 추정 — 배우기 0xa3bac 는 이 칸을 안 쓴다).
- 웹판: `src/widgets/special-swing/ui/SpecialSwingWindow.tsx:77` 이름을 `BATTER_BURSTS[cursor]` 로 뽑는다 → 넷째 칸이 늘 "미라지 스윙". 원본은 타입 1 이면 "메테오 스윙".
  같은 파일 :66 은 칸을 "레벨"(`index + 1 === level`)로 표시한다. 원본은 칸마다 다른 기술이고 "사용 중" 표시는 레코드 +0x18(고른 기술 번호)이다.
  확인 키로 기술을 바꾸는 동작(StrMODE[69]~[71])도 웹판에는 없다. 스킬 장착 상한 6/8/10·확장 5000/10000G 는 웹판에서 찾지 못했다(`/usr/bin/grep` 로 검색).

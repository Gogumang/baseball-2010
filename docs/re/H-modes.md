### H-2. 홈런더비 (모드 7) — 규칙 전체 확정 · 웹 `mainMenu.ts:32` `isAvailable: false`
- 진입: 선수 고르기 창 결과 **2 = 육성 타자 · 4 = 명예 타자** (Q2 확정) → 모드 7
- **기회 10구** (+0x33). 던진 공 수 +0x68
- **비거리**: 결과가 홈런일 때만 `d = |착지점 − (20000, 1000, 30000)| / 265`, **한 타구 상한 160**, 누적 += d
- **마투수 등장**: 누적 비거리가 [800, 1200, 1600, 2000] 을 넘을 때마다 단계 +1
  - 단계 0: 일반 투수, **구질 1 고정**, 목표점 = 좌우별 존 중심 고정 (좌 (19415,1202,29705) / 우 (20585,1202,29705))
  - 단계 s ≥ 1: 마투수 표 [1,2,3,4][s−1] 번째 레코드를 상대 투수로 복사, **구질 22(마구)만**. 순서는 레오니 · 붕붕머신 · 발렌타인 · 드래고나 (유력)
- **콤보**: 직전 공과 이번 공이 모두 홈런이면 콤보 +1, 최대 콤보 갱신, **보너스 G += 콤보 × 5**. 아니면 콤보 0
- **이벤트 존**: 공이 날아가는 중 화면 y < 높이/3 이고 필드 플래그 +0x127 이 서면 그 자리에 존, 적중하면 **보너스 G += 200**. 존은 8프레임 주기로 깜빡 (`stadium/event_zone.pzx`)
- **보너스 게임**: 10구가 끝나고 최대 콤보 > 0 이면 **최대 콤보 수만큼** 추가 기회 (한 번만)
- **G** = `(누적 비거리 / 100) × [1,2,3,4,5][단계] + 보너스 G`, 99999 상한
- **최고 기록**: 저장 +0x5c(u16). 넘으면 갱신 + 신기록 효과음 0x1f (아니면 0x20)
- **HUD**(0x45a54): 일반 점수판 대신 공 아이콘 10칸, 공 번호 = (보너스 중 ? 최대콤보 : 10) − 남은 기회 + 1, 최고 기록과 비교해 넘으면 강조. 스프라이트 `ui/combo.pzx`, `ui/result.pzx`
- 끝: 예 → 홈런더비 재시작 / 아니오 → 메인 메뉴. 비거리 랭킹은 통신(없음)
- 웹 `pitchIntelligence.ts:39` "홈런더비(모드 7) 분기는 뺐다" → 구질 1 / 마구 분기 추가

#### 1. 홈런더비 (모드 7)

진입 (확정): 메인 메뉴(장면 0x103) 하위 16(갱신 0x29ac8)이 선택창 0x62568(StrMAINMENU[54] 질문 계열)의 결과 this+0x240→+0x12c 를 본다:
0 → 하위 5(모드 목록)로 되돌아감, **2 또는 4 → this+0x13c = 7, 하위 0x27** → 진입 처리 0x32988 → 0x327b8(this, 7) → 0x213c0(앱, 4, 0) 로 나리 타자편 저장을 올리고 곧바로 경기 장면 0x104.
결과 2/4 가 명예타자/육성타자 중 무엇인지는 유력 수준(0x62568 내부 미해독). 같은 꼴로 하위 13(0x2464c)은 나만의리그 타자(4)/투수(3), 하위 14(0x24698)는 시즌(2), 하위 17(0x29a54)은 모드 6 을 this+0x13c 에 넣고 0x27 로 간다.

경기 상태 구조체 = 경기 장면 this+0x174 = 전역 0x1552d0c (같은 객체). 초기화 0xb6814 (확정):
```
b6846: movs r3,#0xa ; strb r3,[+0x33]      ; 남은 기회 10
b6840: strb #0,[+0x38]                     ; 단계(마투수) 0
b685a: str  #0,[+0x40]                     ; 보너스 G 0
+0x68=0(던진 공 수) +0x39/+0x3a/+0x3b/+0x3d/+0x3e/+0x3f = 0
```

|---|---|---|
| +0x01 (s8) | 모드 사본(7) | 확정 |
| +0x33 | 남은 기회 (10 에서 시작) | 확정 |
| +0x34 (s16) | 누적 비거리 | 확정 |
| +0x36 (s16) | 이번 타구 비거리(표시용) | 확정 |

##### 공 하나의 결과 처리 — 0xae24c(아웃/헛스윙 쪽)·0xae3e8(타구 쪽) (확정)
둘 다 `구조체+1 == 7` 일 때만 이 길로 간다.
1. 콤보: 직전 공과 이번 공이 모두 홈런이면 `콤보++`, `+0x3d = max(+0x3d, 콤보)`, **보너스 G += 콤보×5** (`ldr r1,[+0x40]; r3=콤보*5; add; str`, 0xae45a~0xae46a).
   아니거나 기회가 다했으면 콤보 = 0.  그다음 `+0x3a = +0x3b; +0x3b = 0`.
2. 남은 기회가 1 보다 많으면 `+0x33−−, +0x68++`, 그리고 **누적 비거리 ≥ 단계표[단계] 이면 단계++** (표 0xd84dc = [800, 1200, 1600, 2000, 99999]). 다음 공(상태 0xd, 단계 올라도 0xd / 아니면 0xf).
3. 기회가 다했고 `+0x3d > 0` 이고 아직 보너스 전이면: `+0x3e = 1`, **남은 기회 = +0x3d(최대 콤보)**, 콤보 0 → 보너스 게임 시작(상태 0xd).
4. 그 밖이면 끝(상태 0x1a).
5. 이번 공이 이벤트 존에 들었으면(+0x3f) **보너스 G += 200** (`adds r3,#0xc8`, 0xae548) 후 +0x3f = 0.

##### 점수(G) — 0x3af4c, 정산 0x4f574 (확정)
`G = (누적 비거리 / 100) × 배율[단계] + 보너스G`, 배율 표 0xcfb10 = [1, 2, 3, 4, 5] (s8). 정산에서 소지 G 에 더하고 99999 로 자른다(0x4f6ea).
→ 설명서 "마투수가 등장하면 G포인트를 추가로" = 배율 상승.

##### 상대 투수 (확정/유력)
- 단계 0: 일반 투수, 구질은 **1 고정**(0x344dc: 모드 7 이면 `단계>0 ? 0x16(마구) : 1`), 목표점은 타자 좌우(this+0x17e1)별 고정 표 0xcfbcc = 좌 (19415, 1202, 29705) / 우 (20585, 1202, 29705) (0x345fc, 확정).
- 단계 s>0: 0x48d50 에서 마투수 레코드 표[0xcfce8 = 1,2,3,4][s−1] 번째(앱 데이터 +0xac → +0xc64 + 번호×0x30, 0x1f824)를 상대 투수 레코드로 0x30 바이트 복사하고 **구질 22(마구)만** 던진다 (확정).

##### 장착 칸 = 선수기록 +0x14 — 쓰는 곳 전수 (확정, 2026-10 디스어셈)
**+0x14 는 보유 비트(+0x1b8)의 사본이 아니라 "장착" 비트다.** 경기 중 스킬 효과(0xb62b4 = `([rec+0x14] >> s) & 1`)는 이 칸만 본다.
- `rec` = `0x1fc74(저장, 모드)` — 모드 4 → 0x1fc20, 모드 3 → 0x1fbd0, 그 밖 0. 보통은 `[저장+0x38]`(미션 5~7 특수 갈래만 0x1f640)이고,
  `[저장+0x38]` 은 0x1fb02 에서 **팀 로스터 칸 포인터**(`0xb53d1(팀, i)` = 팀[+0x18] + 0x30·i, `+0xa` 가 음수인 칸)로 잡힌다 → 경기에서 읽는 선수 레코드와 같은 꼴(0x30 바이트)이다.
- **켜기 0xb663c(rec, s)**: 이미 켜져 있으면 0 반환. 아니면 `rec+0x14 |= 1<<s`, 그리고 통계 기록 `[[0x1400054]+0xc8]` 의 +0xf4~0xf7(모드 4)·+0xf8~0xfb(모드 3) u32 에도 같은 비트를 OR(바이트 단위 저장) → 0x1f1e1 저장 → 1 반환. 모드 2 등 그 밖 모드는 통계 칸을 안 건드린다(0xb6666·0xb6688 두 비교뿐).
  **+0xf4/+0xf8 = "한 번이라도 켠 스킬" 비트 — 확정 (2026-10-05)**: 쓰는 곳은 0xb663c 하나, 읽는 곳은 전부 수집 보상 k=5 "스킬 모두 수집" 판정 `0x28f8a`(Q2 5-2: 비트 0~7 은 두 편 중 하나, 8~23 은 편마다 → 40개) 하나뿐이다(`[mgr+0xc8]` 기준 +0xf4/+0xf5/+0xf8/+0xf9 접근 전수 스캔). 기록연감 스킬 탭은 이 비트를 안 본다.
  0xb663c 를 부르는 0xa4b04 는 스킬 창(0x1483c)과 **획득 0xa4bd8**(P+0x1b8 OR 뒤 곧바로 `0xa4b04(P,s,1)`, 호출 0x112d0 · 이벤트 0x8c5a2)이 부른다 → 얻자마자 켜진 스킬도 비트가 선다.
  호출은 **0xa4b04 안 두 곳뿐**(0xa4b86·0xa4b8e, `re xref`).
- **끄기 0xb66dc(rec, s)**: 켜져 있으면 `rec+0x14 &= ~(1<<s)` 하고 1. 호출은 0xa4b04(0xa4b96)·0xa4430(0xa4460) 두 곳.
- **장착 동작 0xa4b04(P, s, on)** (P = 저장 선수 구조체, +0x1b8 을 가진 쪽):

##### 필살타법(투수는 마구) 선택 — 키 처리 0x17cec (확정)
탭(창 +0x188) 0·1 = 필살타법/마구 목록, 탭 2 = 구질(투수편, J 담당).
칸 i(0~3)에서:
1. 이미 사용 중(0xa43c4: 선수 레코드 +0x18 == 번호)이면 StrMODE[69] "현재 사용 중인 스킬입니다".
   **원본 어긋남 (확정, 메인 05e1690)** — 저장과 비교가 서로 다른 번호를 쓴다:
   ```
   18166  ldr r2,=0xcc378 ; ldr r3,[칸×4 + 표]   ; 표 = [1,2,3,4]
   1816c  strb r3,[선수+0x18]                    ; ★ 저장: 4 + 타입을 안 더한다 → 1~4
   a43c4  n = 칸+1 ; n>3 이면 n += rec[0xb]>>5 ; return rec[0x18] == n   ; ★ 비교: 넷째 칸은 4 + 타입
   ```
   → **장타형(타입 1)이 메테오 스윙을 고르면 저장 4 · 비교 5** 라 "사용 중"([69])이 안 뜨고, 같은 0xa43c4 를 쓰는 주황 아이콘(`0x803d4`)도 안 붙는다.
   원본 버그로 보고 그대로 옮긴다. 경기 쪽은 저장값(4)으로 돌아 미라지와 같은 기술이다(H2 1-2).
2. 배운 수(저장 +0x201) ≤ i 이면 StrMODE[71] "트레이닝 완료 후 사용할 수 있습니다".

## 1. 큰 그림 — 시즌 상점은 0x957c/0x7d90, 나리 상점은 0x13460/0x14a74 (확정)

R12 가 푼 `0x13460`(키) · `0x14a74`(팝업 결과)는 **나만의리그 쪽 관리 장면**이고, 그와 짝을 이루는 **시즌 쪽 관리 장면**에 같은 구조가 하나 더 있다:

| | 나리(R12) | **시즌(이 노트)** |
|---|---|---|
| 창 객체 | `[scene+0xe0]` | **`[scene+0xc0]`** |
| 레코드 | `[scene+0xb0]` | **`[scene+0xa0]`** |
| 아이템 창 키 핸들러 | 0x13460 | **0x957c** |
| 팝업 결과 핸들러 | 0x14a74 | **0x7d90** (점프표 `0xcbdf4`, 결과코드 2~20) |
| 창 종류 `[win+0x1a4]` | 1 서브 / 2 GP / 3 장비 / **4 = 손 안 댐** | 1 → 0x97de · 2 → 0x98a8 · 3 → 0x95b2 · **4 → 0x9a84 = 구장 아이템** |

→ **R12 의 "kind 4 는 아무것도 안 한다" 는 0x13460(나리) 에 한해 맞고, 구장 아이템은 시즌 쪽 0x957c 가 처리한다.** U-04 가 안 풀렸던 이유가 이것이다.

`0x957c` 머리(0x9584~0x95ae): `win = [scene+0xc0]`, `kind = [win+0x1a4]`; 2→0x98a8, 1→0x97de, 3→0x95b2, 4→0x9a84, 그 밖 `0x9db4`(기본 처리).

## 2. 시즌 레코드의 구장 칸 (확정)

| 오프셋 | 내용 |
|---|---|
| `rec[0x188 + 7*종류 + 칸]` (u8) | **구장 아이템 보유 플래그** — 3종 × 7칸 = 21바이트 (0x188~0x19c) |
| `rec[0x1b8]` (s8) | 현재 **관중석** 칸 |
| `rec[0x1b9]` (s8) | 현재 **전광판** 칸 |
| `rec[0x1ba]` (s8) | 현재 **잔디** 칸 |
| `rec[2]` (s16) | 소지금 (100만 단위, 0~9999) |

종류 r7: 0 관중석 · 1 전광판 · 2 잔디. 칸 k: 관중석·전광판 0~6, 잔디 0~3.

읽는 곳(전부): 0x5f3c·0x7958·0x957c·0xe4d0·0x352e8(구장 그림 미리보기 `0x76ba5`) · 0x71494(대전 업로드) · 0x7182c · 0x7c450(구장관리 정보 상자) · 0xa34b8(관중 수 계산) · 0x83378(아이템 창 설명).
쓰는 곳(**딱 두 곳**): **0x7998**(교체) · **0x8198**(구매). 그 밖엔 없다.

## 3. 가격 표는 0xcbc64 다 — 0xd44c4 는 필요 인기도 사본 (확정)

`0x957c` 의 구장 아이템 분기(0x9ad0~0x9af6):
```
idx = (종류 << 3) + 칸                       ; 한 줄 8칸
가격      = (s16) 0xcbc64[idx] * 100          ; 0x9ada
인기도     = 0xb6e79(rec)                      ; 0x9ae8
필요인기도 = (s16) 0xcbc34[idx]                ; 0x9af0
소지금     = (s16)[rec+2]                      ; 0x9ad4
```
| 표 | 관중석(0~6) | 전광판(0~6) | 잔디(0~3) |
|---|---|---|---|
| **가격 `0xcbc64`** (s16, ×100 → 100만 단위) | 0, 3, 6, 10, 20, 20, 20 | 0, 2, 4, 7, 15, 15, 15 | 0, 1, 2, 3 |
| **필요 인기도 `0xcbc34`** (s16) | 0, 200, 500, 800, 1000, 1000, 1000 | 0, 100, 400, 700, 900, 900, 900 | 0, 0, 0, 0 |

- 즉 실제 가격은 **3억 / 6억 / 10억 / 20억**(관중석), **2억 / 4억 / 7억 / 15억**(전광판), **1억 / 2억 / 3억**(잔디). (소지금 단위 100만 × 100 = 1억)
  확인 팝업은 `0x55cf5(g, 가격*100)` = 만원 단위로 찍으므로 표값 3 → 30000만원 = 3억. ✓
- **`0xd44c4` 는 `0xcbc34` 와 바이트까지 같은 사본**이고 설명 줄(StrITEM[185] "인기도 %d 이상")에서만 읽힌다 → R12 4-3 의 "유력" 판정을 **확정**으로 올린다. J 4-9 의 "가격 표 0xd44c4" 는 **틀렸다**(그 값은 필요 인기도).
- 0xcbc34 · 0xcbc64 는 각각 한 곳(0x957c)에서만 읽힌다. 0xcbc64 는 0x7d90(구매 확정)에서도 읽는다.

## 4. 구매 가드 순서 (확정) — 0x9a84~0x9bd2

`list1 = [win+0x198]`, `list2 = [win+0x19c]`; 종류 `r7 = [l1+0x10]*[l1+0x14] + [l1+0xc]`, 칸 `k` = list2 에서 같은 식.
앞가드: `[win+0x1a8] != 0`(목록 포커스) **이고** 키 `[scene+0x40]` 가 −5 또는 0x35.

1. **미오픈** (0x9afc): `종류 != 2` 이고 `k > 3` 일 때 `0x9f6c1(0x1f1d9(app), 종류, k−4) == 0`
   → **StrMODE[76]** `아직 구매할 수 없는 아이템입니다…` (팝업 1/1)
   → 잔디에는 히든이 없다(4칸뿐).
2. **이미 보유** (0x9b24): `rec[0x188 + 7*종류 + k] != 0` → 0x96b0 (보유 문구, StrMODE[78] 계열)
3. **인기도** (0x9b3e): `0xb6e79(rec) < 0xcbc34[idx]`
   → **StrMODE[62]** `인기도가 부족합니다. 필요한 인기도 : %d` (%d = 필요 인기도)
4. **소지금** (0x9b72): `(s16)[rec+2] < 0xcbc64[idx]*100` → 0x9850 (StrMODE[77] `소지금이 부족합니다`)
5. 통과 → `0x55cf5(g, 가격*100)` 로 금액 서식 → **StrMODE[79]** `소지금 %s이 소모됩니다 구매하겠습니까?`
   → `0xbbef9(buf, 2, 0xe, 1)` = **예/아니오 팝업, 결과코드 14**

> 장비 상점(R12 1b-가)과 가드 **순서가 다르다**: 장비는 미오픈 → 보유 → 인기도 → 소지금 이지만 구장도 같은 순서다. 다만 구장은 "보유" 를 `0x188 + 7*종류 + 칸` 으로, 장비는 `0x188 + 부위*11 + 칸` 으로 센다 (레코드가 서로 다른 장면의 것이라 충돌하지 않는다 — 시즌 `[scene+0xa0]` vs 나리 `[scene+0xb0]`; **같은 레코드인지는 미확인**).

## 5. 구매 확정 — 0x7d90 의 결과코드 14 분기(0x812c) (확정)

앞가드(0x7d92~0x7dc6, R12 2-1 과 같은 꼴): `[app2+9] != 0`(예) · `(s8)[app2+0x21c] == 0`(→ 처리 후 −1) · `결과코드 = [app2+0x248]` 를 2 빼서 0~0x12 이면 점프표 `0xcbdf4`.

점프표 `0xcbdf4` (결과코드 2~20):
| 코드 | 대상 |
|---|---|
| 2 | 0x8214 (장면 상태 0xfa=250) |
| 3~11 · 16~20 | 0x821e (그냥 return) |
| 12 | 0x7f2a |
| 13 | 0x7ff2 |
| **14** | **0x812c — 구장 아이템 구매 확정** |
| **15** | **0x81d0 — 구매완료 팝업 닫힘 → 컬렉터 해금 검사** |
| 20 | 0x7dd0 |

### 5-1. 0x812c — 구매 처리 (확정)
```
r5 = 종류 (list1), r4 = 칸 (list2)          ; 0x8130~0x8156
rec = [scene+0xa0]
소지금 = (s16)[rec+2]
가격   = (s16) 0xcbc64[(종류<<3) + 칸] * 100 ; 0x8166
v = 소지금 − 가격 ;  if v > 9999: v = 9999 ;  if v < 0: v = 0
[rec+2] = v                                  ; 0x8182  strh
rec[0x188 + 7*종류 + 칸] = 1                 ; 0x8192  strb   (보유 기록)
rec[0x1b8 + 종류]        = 칸                ; 0x819e  strb   (그 자리에서 장착)
0x1fded(app) ; 0x22755(app, 1)               ; 능력치 재계산 + 저장
팝업 StrMODE[184] "!C구장 아이템 구매 완료!!N자동으로 적용되며!N[구단관리]-[구장관리]!N에서 교체할 수 있습니다"
   → 0xbbef9(buf, 1, 0xf, 1)  = 알림 1/1, 결과코드 15
```
- **인기도는 깎지 않는다.** 인기도는 순수한 조건일 뿐이다 (차감 코드 없음).
- 소지금 상한 9999 클램프는 장비(0x14b2c)와 같다.
- 구매하면 **자동으로 적용**된다(0x819e). 그래서 문구가 "자동으로 적용되며 … 에서 교체" 다.

### 5-2. 0x81d0 — 컬렉터 해금 검사 (확정)
```
rec = [scene+0xa0]
if 0xa38c5(rec, 0):  0x62369(g, 13, 0)       ; 관중석 4칸(0~3) 전부 보유 → 해금 id 13
if 0xa38c5(rec, 1):  0x62369(g, 16, 0)       ; 전광판 4칸(0~3) 전부 보유 → 해금 id 16
```
`0xa38c4(rec, 종류)` (확정):
```
cnt = 0
for i in 0..3:  if rec[0x188 + 7*종류 + i] != 0: cnt++
return (cnt == 4)
```
→ **컬렉터 = 기본 4칸(1·2·3·4단 / 소·중·대·초대형)을 모두 사면** 열린다.

## 6. 교체 — 구장관리 화면 키 핸들러 0x7958 (확정)

시즌 [구단관리]-[구장관리]. 창은 같은 `[scene+0xc0]`, 레코드 `[scene+0xa0]`, 구장 객체 `[scene+0x10c]`.

```
종류 = [win+0x198] 목록의 행                  ; 0x798e
sel  = 0x8455d(win)                           ; 0x799c  선택 칸
rec  = [scene+0xa0]
rec[0x1b8 + 종류] = sel                       ; 0x79b0  strb  ← 교체가 쓰는 유일한 곳
이름 = StrITEM[base + sel], base = 126(관중석) / 133(전광판) / 140(잔디)   ; 0x79b2~0x79c6
팝업 StrMODE[185] "[%s] 아이템을 적용합니다"  → 0xbbef9(buf, 1, 1, 1)  알림 1/1
0x1fded(app) ; 0x22755(app, 1)                ; 재계산 + 저장
```
- **가격·인기도·보유 가드가 하나도 없다.** 목록에 보유분만 올린다는 뜻(유력 — 목록을 채우는 코드는 안 읽었다).
- 취소(키 −0x10):
  - 목록 포커스 없음 → `0xbcb49(scene+0x18, 0xce)` = **장면 상태 206** 으로 나간다 (0x7a68)
  - 포커스 있음 → 미리보기를 저장값으로 되돌린다 (0x7a8c~): `0x78741(구장, (s8)rec[0x1b8])`, `[구장+0x8a] = (s8)rec[0x1b9]`, `0x76ba5(구장, 1)`
- 같은 미리보기 되돌리기가 상점 쪽 0x957c(0x9c0a~0x9c86)에도 있다. 거기선 잔디까지 되돌린다:
  `v = (s8)rec[0x1ba]` → `0x786c9(구장, v−1, 1)` (v 0→−1, 1→0, 2→1, 3→2). 즉 **잔디 0(거친인조잔디) = 기본 = −1**.
  그리고 `[구장+0x89] = 0`, `[구장+0x8a] = rec[0x1b9]`, `0x77edd(구장, 1)`.
  → J 1-3 의 "구장 객체 +0x88 관중석 · +0x8a 전광판" 과 맞는다 (+0x88 은 `0x78741` 이 세팅).

## 7. 히든 4~6 해금 조건 (확정: 저장 위치·id 표 / 유력: 5·6번의 계기)

해금 플래그 저장 (확정):
```
0x9f6c0(app, 종류, k) → (u8) app[0xe0 + 종류*4 + k]      ; 읽기
0x9f6cc(app, 종류, k, v) → app[0xe0 + 종류*4 + k] = v     ; 쓰기
```
해금 id ↔ 저장 위치 (`0x620b8` 세터 / `0x61f5c` 게터, 같은 표):
| id | 위치 | 뜻 |
|---|---|---|
| 0~3 | app[0x31+id] | 마선수 |
| 4~7 | app[0x32+id] | 마선수 2 |
| 8~12 | app[0x7a+id−8] | 히든 팀 |
| **13·14·15** | app+0xe0 [0][0·1·2] | **관중석 히든 4·5·6** (트로피컬·콜로세움·스페이스) |
| **16·17·18** | app+0xe0 [1][0·1·2] | **전광판 히든 4·5·6** (내추럴·고대의·싸이키) |
| 19~ | app+0xc0 표 | 장비(R12 2-2) |

id 를 실제로 여는 곳:
- **13 (관중석 히든 4)** — `0x81ea`: 구장 아이템을 사고 나서 `0xa38c5(rec, 0)` = 관중석 0~3번을 다 모았으면. **확정**
- **16 (전광판 히든 4)** — `0x820c`: 같은 자리에서 `0xa38c5(rec, 1)`. **확정**
  → StrITEM[249]·[252] `나는야! 관중석/전광판 컬렉터` 와 맞는다.
- **17 (전광판 히든 5)** — `0x1cb48`: `0x1ca4c`(관리 장면 팝업 결과, 0x1cdec 에서 호출) 의 팝업 결과코드 `0x30` 분기. 같은 흐름이 `0xbdae9(…, 5, …, 1500)` 통신을 태우고 결과 `0x2f→0x30→0x31` 로 이어진다 → **명예의 전당(서버) 흐름**으로 보인다. 근거는 StrITEM[253] `빛나는 명예의 전당 선수`. **유력**
- **14·15·18** — 상수로 여는 곳이 **없다**. 대신 두 곳에서 **서버가 준 64비트 비트마스크**를 id 0~0x32(50) 까지 돌며 켠다:
  - `0x4eecc~0x4eeee` (함수 0x4ea0c), `0x2bd08~0x2bd5e` (함수 0x2bb48): `for id in 0..50: if mask & (1<<id): 0x620b9(g, id)` — 알림 없이 조용히 연다.
  → StrITEM[251]·[254] `이벤트 오픈!! gamevil.com` 과 맞는다. **관중석 히든 5(명예의 전당)·히든 6·전광판 히든 6 은 모두 이 통신 경로로만 열린다**(유력 — 통신 패킷 해석은 안 했다).

해금 알림 문구: `0x62368(g, id, 0)` → id 13~18 이므로 StrCOMMON[139] `히든 아이템 오픈!! [%s]` + StrCOMMON[**141**] `시즌모드에서 사용가능합니다` (R12 2-4 의 구간표와 정확히 맞는다).

## 8. 효과가 실제로 쓰이는 곳 — 관중 수 (확정)

`0xa34b8` (경기 관중 수, 0xa35d6~0xa3630):
```
n  = 0xca7b5(…) * 0x78                       ; 평판 쪽 항 (J 4-7 의 max(p,1)/5 × 120)
n += (s16) 0xd7cc4[7 + rec[0x1b9]] * 1000    ; 전광판  (ldrsh [r3, #0xe] = +7칸)
n += 4000
cap = (s16) 0xd7cc4[rec[0x1b8]] * 1000       ; 관중석 수용 상한
n = min(n, cap) ; n = max(n, 3000)
```
→ **J 4-7 의 식이 그대로 맞다**(표는 0xd7cc4 사본, 값은 0xd44f4 앞 14칸과 같다).
- **잔디(`rec[0x1ba]`)는 어떤 계산에도 안 들어간다.** 읽는 곳이 전부 구장 그림/미리보기(0x7958·0x957c·0x7c450·0x352e8·0x71494 업로드)뿐이다 → **순수 겉모습**인데 1억·2억·3억을 받는다 (확정).
- 관중석은 **상한**만, 전광판은 **가산**만 한다. 히든 3종(4·5·6)은 효과값이 4번과 같다(관중석 40000 · 전광판 +5000) → **히든은 성능이 아니라 겉모습**이다.
- 같은 함수 끝(0xa3690~0xa36ca)이 **만원 판정 `rec[0x65]`** 를 쓴다 — `관중 ≥ 수용×80/100 → 2 · > 수용×35/100 → 1 · 그 밖 0`.
  이 칸을 읽는 곳은 경기 준비 0x353c2(구장 `+0x89` = 값 + 1, 관중 수 그림 단계)와 대전 업로드 0x710e0 둘뿐이다 (J 4-7 참고).
  ⚠️ 0xa34b8 은 **경기가 끝난 뒤** 도는 함수라 타석에 보이는 관중 수는 **직전 경기의 것**이다.

## 10. 이 노트가 바로잡는 것

1. **J 4-9 의 "가격 표 0xd44c4"** → 틀렸다. `0xd44c4` 는 **필요 인기도**(0xcbc34 의 사본)이고, 진짜 가격은 **`0xcbc64`**(관중석 0·3·6·10·20·20·20 / 전광판 0·2·4·7·15·15·15 / 잔디 0·1·2·3, 단위 ×100 = 1억). R12 4-3 의 유력 판정 → 확정.
2. **J 4-9 의 "잔디 — 표 행 0(따로 있는지 미확인)"** → 잔디도 `0xcbc64` 3번째 행에 **가격이 있다**(1·2·3억). 필요 인기도는 0(제한 없음)이고 히든도 없다.
3. **R12 의 "구장 아이템 구매 처리를 못 찾았다"(남은 것)** → `0x957c`(가드) + `0x7d90` 결과코드 14/15(확정·해금)로 **풀렸다**. U-04 종료.
4. **R12 1a 의 "kind 4·0·5 는 손대지 않는다"** → 나리 핸들러 0x13460 에 한해 맞다. 시즌 핸들러 0x957c 에는 kind 4 분기가 있다.
5. **P4 4절/J 의 "시즌 레코드 관중석 +0x1b8"** → 맞다. 여기에 **보유 플래그 `+0x188 + 7*종류 + 칸`(21바이트)** 를 더한다.

## 11. 남은 것 (미해결)

- **시즌 레코드와 나리 레코드가 같은 구조체인지**: 구장 보유는 `+0x188 + 7*종류 + 칸`(21칸), 장비 보유는 `+0x188 + 부위*11 + 칸`(44칸) 으로 **같은 0x188 을 다르게 쓴다**. 시즌 장면은 `[scene+0xa0]`, 나리 장면은 `[scene+0xb0]` 에서 레코드를 꺼내므로 서로 다른 객체일 가능성이 크지만, 두 포인터가 같은 타입인지는 확인하지 못했다.
- **관중석 히든 5(id 14) · 히든 6(id 15) · 전광판 히든 6(id 18)** 을 여는 게임 안의 계기: 상수 호출지가 없고 통신 비트마스크(0x4ea0c·0x2bb48, id 0~50)뿐이다. 패킷 형식은 안 봤다.
- **0x1ca4c 가 정말 "명예의 전당" 흐름인지**: 팝업 결과코드 0x2f→0x30→0x31 사슬과 통신 호출까지는 봤지만 화면 이름을 확정하지 못했다(id 17 을 여는 것은 확정).
- **구장관리/상점의 목록을 채우는 코드**(보유분만 교체 목록에 올리는지, 칸 개수를 어디서 정하는지)는 안 읽었다.
- `0x7d90` 점프표의 결과코드 12(0x7f2a)·13(0x7ff2)·20(0x7dd0) 분기(같은 시즌 상점의 다른 창)는 이 노트 범위 밖이라 안 봤다.

## 요약
**U-04 가 풀렸다.** 막혔던 이유는 R12 가 본 `0x13460`/`0x14a74` 가 **나만의리그** 쪽 관리 장면이고, 구장 아이템은 **시즌 쪽 짝 함수 `0x957c`(키·가드) 와 `0x7d90`(팝업 결과)** 이 처리하기 때문이었다. 구매 가드는 미오픈(StrMODE 76) → 이미 보유 → 인기도 부족(62) → 소지금 부족(77) → 확인(79, 결과코드 14) 순이고, 확정 분기 `0x812c` 가 `[rec+2] -= 가격`(0~9999 클램프) · `rec[0x188+7*종류+칸] = 1` · **`rec[0x1b8+종류] = 칸`(즉시 적용)** 을 하고 `0x1fded`/`0x22755` 로 저장한 뒤 StrMODE[184] 완료 팝업(결과코드 15)을 띄운다. 이어지는 `0x81d0` 이 `0xa38c4`(기본 4칸 전부 보유)로 **컬렉터 해금 id 13(관중석)·16(전광판)** 을 연다. **인기도는 조건일 뿐 차감하지 않는다.** 진짜 **가격 표는 `0xcbc64`**(관중석 3·6·10·20억, 전광판 2·4·7·15억, 잔디 1·2·3억)이고, J 4-9 가 가격이라 적은 `0xd44c4` 는 **필요 인기도**(`0xcbc34` 의 사본, 설명 줄 전용)였다 — R12 의 유력 판정을 확정으로 올린다. 교체는 `0x7958`(구단관리-구장관리)이 `rec[0x1b8+종류] = 선택칸` 한 줄로 하며 **가격·인기도·보유 가드가 전혀 없다**. 히든 칸의 해금 플래그는 `app[0xe0 + 종류*4 + k]`(id 13~15 관중석 · 16~18 전광판)이고, 4번=컬렉터(확정), 5번=명예의 전당(전광판 id 17 은 `0x1ca4c` 에서 확정, 관중석 id 14 는 계기 미확인), 6번=gamevil.com 이벤트로 **서버가 준 비트마스크**(0x4ea0c·0x2bb48)를 통해서만 열린다. 효과는 관중 수 계산(`0xa34b8`)에서 전광판이 `+표×1000`, 관중석이 상한으로만 쓰이고 **잔디는 어떤 계산에도 안 들어가는 순수 겉모습**이다. 웹판은 이 기능 전체가 미구현이고 문자열만 들어 있다.

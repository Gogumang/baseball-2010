## 1a. 0x13460 — 상점 창 키 처리 (확정)

`0x13460(scene)` = 관리 장면(0x105 시즌 / 0x106 나리)의 **아이템 창 키 핸들러**. 크기 0x13460~0x13b36.
- `win = [scene+0xe0]`, `kind = [win+0x1a4]` 으로 갈린다 (0x13468~0x1348a):

| kind | 분기 | 창 |
|---|---|---|
| 1 | 0x1364e | **서브아이템 상점** (가격표 0xcc430, 10칸) |
| 2 | 0x1372e | **GP아이템 상점** (가격표 0xcc41b, 10칸) |
| 3 | 0x1349a | **장비 상점** (가격표 0xcc444, 필요 인기도 0xcc50a) |
| 0·4·5·그 밖 | 0x13b30 | **아무것도 안 함** (그대로 return) |

- 공통 앞가드: `[win+0x1a8] == 0` (목록에 포커스 없음) 이면 구매하지 않고 기본 키 처리로. 키 `[scene+0x40]` 가 **−5 또는 0x35**(확인/선택) 일 때만 구매 흐름을 탄다.
- 기본 키 처리 (0x13b16~0x13b2e): 키 == **−0x10**(취소) 이면 `0xbcb49(scene+0x18, 0x6e)` → **장면 상태 0x6e(110)** 로 돌아간다. 그 밖은 `0x819ad(win, 키)` (창 자체 커서 이동).
- 팝업은 모두 `0xbbef9(buf, 종류, 결과코드, 1)` (0x13b0c / 0x13b10) 로 띄운다. 문구는 `0x702b5(팝업문자열표, i)` = **StrMODE[i]**, 서식은 `0x1400468`(sprintf).
- 부르는 곳: 0x1cdec 안의 0x1d0ee (관리 장면 키 분배). R9 의 "상태 111 키 = 0x13460" 과 같다.
- **P6 3절 정정 후보**: P6 는 `[this+0x1a4]==3` 을 "구장 아이템 창" 이라 적었지만, 여기서 kind 3 은 **장비 상점**(0xcc444·0xcc50a 를 읽는다)이고 kind 4 는 이 핸들러가 손대지 않는다 → J 4-9 의 "`[+0x1a4]==4` = 구장 아이템" 쪽이 맞다 (유력).

## 1b. 가드 순서와 문구 (확정)

### (가) 장비 상점 — kind 3 (0x1349a~0x13630)
`sel` = `0x8455d(win)` (칸 0~10), `row` = `[win+0x198]` 목록의 행(부위), `rec` = `[scene+0xb0]`, `mode` = `[scene+0xcc]`.

1. **해금** — `sel > 6` 일 때만: `0x9f69d(0x1f1d9(app), (mode==4), row, sel−7)` 의 하위 바이트가 0 이면
   → **StrMODE[76]** `아직 구매할 수 없는 아이템입니다. 특별한 조건을 통해 오픈됩니다` (팝업 1/1)
   → 즉 **칸 7·8·9 = 히든 장비 3종**, 컬렉터(기록 누계) 해금과 이어진다 (2절).
2. **이미 보유** — `rec[0x188 + row*11 + sel] != 0` → **StrMODE[78]** `이미 가지고 있는 아이템입니다`
3. **인기도** — `0xcc50a[sel]`(s16, `[0,50,150,300,450,600,800,…]`) > `0xb6e79()`(인기도)
   → **StrMODE[62]** `인기도가 부족합니다. 필요한 인기도 : %d` (%d = 필요 인기도)
4. **소지금** — 가격 `p = 0xcc444[ (row*11+sel) + (mode==3 ? 0 : 44) ]`(s16); `p*10 > [rec+2]`(소지금, 100만 단위)
   → **StrMODE[77]** `소지금이 부족합니다`
5. 모두 통과 → **StrMODE[79]** `소지금 %s이 소모됩니다 구매하겠습니까?` (`%s` = `0x55cf5` 금액 서식, 인자 = `p*1000` 만원) → 팝업 2/2

> 가격표 두 블록: **mode 3(나리 투수)** 은 앞 44칸, 그 밖(나리 타자 4·시즌 2)은 뒤 44칸(+0x58). P4 4절의 "앞 44칸 = 나리 장비표, 뒤 44칸 = 투수 쪽" 서술과 **앞뒤가 반대**다 → 여기 디스어셈(0x13584 `cmp r3,#3`)이 근거.

### (나) 서브아이템 상점 — kind 1 (0x1364e~0x1372c)
`r = 0xca7b5(list,5)` (행) · `c = 0xca911(list,5)` (열), 칸 = `r*5 + c`.
1. **이미 보유** — `rec[0x58 + r*5 + c] != 0` → **StrMODE[78]**
2. **소지금** — `p = 0xcc430[ base + r*5 + c ]`(s16); `p*10 > [rec+2]` → **StrMODE[77]**
3. 통과 → **StrMODE[79]** (`%s` = `p*1000`) → 팝업 2/2
- **인기도·해금 가드가 없다** (장비와 다른 점).

### (다) GP아이템 상점 — kind 2 (0x1372e~0x13b14)
`k` = 칸 0~9, `app = 0x1f1d9([0x1400054])`, **보유 G = [app+0x64]**, `rec = 0x1fc75(app, mode)`.

1. **G 부족** — 가격 `g = 0xcc41b[k + (mode==4 ? 10 : 0)] × 100`; `g > [app+0x64]`
   → **StrMODE[65]** `G포인트가 부족합니다. 구매 페이지로 이동하시겠습니까?` → 팝업 **2/2** (예 → R9 의 결과 139 = 구매 페이지)
   → **가장 먼저** 걸리는 가드다. 아래 2~6 은 그 다음.
2. 능력치 한계 표를 먼저 만든다 (`lim[0..3]`):
   - **타자(mode 4)**: `0xcc502[ ([rec+0xb]>>5)*4 + i ]`(s8) × 10, 능력치 이름 = StrMODE[**35**+i] (히트·파워·수비·주루)
   - **투수**: `0xb6705(rec)` 가 0 이면 `0xcc4fa[i+4]`, 아니면 `0xcc4fa[i]` (s8) × 10, 이름 = StrMODE[**40**+i] (제구·구속·변화·체력)
   - → G-5 의 한계표(타자 `[80,80,80,80|80,85,75,75]`·투수 `[80,80,80,80|85,85,85,60]` ×10)와 같은 표다.
3. **k ≤ 3 (능력치 아이템)** — `0xb6415(rec, k, 0)`(기본 능력치) `>= lim[k]`
   → **StrMODE[192]** `[%s] 능력치가 최대입니다` (%s = 능력치 이름) → 팝업 1/1
4. **k == 4 (엄마의도시락)** — 4개를 모두 돌며 `>= lim[j]` 인 것마다 StrMODE[192] 줄을 `0xcc330` 구분자로 이어 붙이고 개수를 센다.
   - 4개 **모두** 최대 → 그 목록만 팝업 1/1 (구매 불가)
   - 3개 이하 → 그 목록 **뒤에 StrMODE[82]** `%d G포인트가 소모됩니다 구매하시겠습니까?` 를 붙여 팝업 2/3 (**일부 최대여도 살 수 있다**)
5. **k == 6 (영지버섯)** — `0xa3a25(rec) == 100`(사기 100) → **StrMODE[91]** `사기 최고 상태입니다`
6. **k == 7 (종합건강진단)** — `rec[5]`(부상 기간) `== 0` **이고** `(s8)rec[0x1b5]`(질병) `<= 0`
   → **StrMODE[208]** `건강한 상태입니다 구매 할 수 없습니다`
7. **k == 8 (최면요법)** — `0xa4f01(rec) == 0`(마이너스 스킬 없음) → **StrMODE[209]** `마이너스 스킬이 없습니다 구매 할 수 없습니다`
8. **k == 9**
   - 타자(mode 4, 이글아이): `(s8)rec[0x54] > 98` → **StrMODE[210]** `[이글아이] 맥스 상태입니다`
   - 투수(십전대보탕): `(s16)[0x1fbd1(app) + 0x2c] == 10000` → **StrMODE[211]** `스태미나가 최대입니다 구매 할 수 없습니다` (P1 4절과 같음)
9. 통과 → **StrMODE[82]** `%d G포인트가 소모됩니다 구매하시겠습니까?` (%d = `g`) → 팝업 2/3
   - **단 타자 k==9(이글아이)** 면 앞에 **StrMODE[224]** `최대 99회 누적 가능합니다` 를 붙이고 `0xcc330` 구분자 두 번 → 같은 팝업 2/3 (0x13ab4~0x13afc)
   - → 즉 224 는 "가드" 가 아니라 **이글아이 구매 확인창에만 덧붙는 안내줄**이다. 투수 십전대보탕에는 안 붙는다.

### (라) StrCOMMON 141·142 는 이 함수에 없다
`0x13460` 안에 StrCOMMON 참조가 없다 (문자열표는 StrMODE 하나 `0x702b5`). 141 `시즌모드에서 사용가능합니다` · 142 `나만의리그 투수편에서 사용가능합니다` 는 **아이템 사용(장착) 쪽**에서 나온다 → 2절에서 이어서 찾는다.

## 2. 장비 구매 확정 · 장착 가드 · 컬렉터 해금 (확정)

### 2-1. 구매 확정 0x14a74 (팝업 결과 처리)
`0x14a74(scene)` — 팝업 결과 핸들러. 앞가드 (0x14aaa~0x14ad0, 세 분기 공통):
`[app2+9] != 0`(예를 골랐다) · `[app2+0x248] == 2`(구매 확인 팝업) · `(s8)[app2+0x21c] == 0` 일 때만 산다. (`app2 = [0x140005c]`)
분기도 `kind = [win+0x1a4]` (1 서브아이템 / 2 GP / 3 장비).

**kind 3 장비 (0x14aaa~0x14c8a)**
1. 소지금 `[rec+2] = clamp(소지금 − 가격×10, 0, 9999)` (0x14b2c `0x270f` = 9999 상한)
2. 보유 플래그 `rec[0x188 + row*11 + sel] = 1`
3. **바로 장착**: `rec2 = 0x1fc75(app, mode)` 의 `rec2[0x19 + row/2]` 의 니블에 `sel + 1` 을 넣는다
   - row 0 → 0x19 상위 니블 · row 1 → 0x19 하위 · row 2 → 0x1a 상위 · row 3 → 0x1a 하위 (0x14b64~0x14b90; 0 = 없음)
4. `0x1fded(app)` · `0x22755(app, 1)` (능력치 다시 계산·저장으로 보임) → `[app2+0x21c] = −1`
5. **컬렉터 해금** (0x14bac~0x14c8a): 부위 0·1·2·3 마다 `0xa5021(rec, 부위)` 가 참(그 부위 11칸을 다 모음)이면 `0x62369(StrMODE전역, id, 0)` 로 해금

| 부위 | 타자(mode 4) id | 투수 id |
|---|---|---|
| 0 | **36** (0x24) | **20** (0x14) |
| 1 | **40** (0x28) | **24** (0x18) |
| 2 | **44** (0x2c) | **28** (0x1c) |
| 3 | **48** (0x30) | **32** (0x20) |
→ K 3-4 의 "36·40·44·48(컬렉터 0x14a74)" 에 **투수 20·24·28·32 를 더한다**(새로 확인).
→ 이 id 들이 바로 장비 상점 7·8·9번 칸의 히든 해금(1b-가 ①, `0x9f69d`)과 이어진다.

**kind 1 서브아이템 (0x14c8c~)**: 소지금 −가격×10(clamp 0~9999), `rec[0x58 + r*5 + c] = 1`, 컬렉터 해금 없음.

### 2-2. 해금 플래그 저장 위치 — `0x9f69c` (확정)
```
0x9f69c: get(obj, isBatter, row, k) → (u8) obj[0xc0 + ((isBatter*4 + row)*4) + k]
0x9f6ac: set(obj, isBatter, row, k, v)
```
→ 장비 히든 3종의 "열렸나" 는 `app + 0xc0` 의 2(타자·투수) × 4(부위) × 4 바이트 표에 있다.
(`0x9f6c0`/`0x9f6cc` 는 같은 꼴의 `app + 0xe0` 표 = 다른 해금.)

### 2-3. 장착 가드 0x17ad0 (확정) — StrMODE[80]·[81]
장착 탭 키 핸들러. 취소(키 −0x10) → `0xbcb49(scene+0x18, 0x6a)` **상태 0x6a(106)**.
`sel = 0x8455d(win)`, `row = [win+0x198]` 목록 행(부위).
- 현재 장착 = `(rec2[0x19 + row/2] 의 해당 니블) − 1` (2-1 과 같은 자리)
- **현재 장착 == sel → StrMODE[80]** `현재 장착 중인 장비입니다` (팝업 1/1) — **가드는 이것 하나뿐**
- 그 밖 → **StrMODE[81]** `[%s] 아이템을 장착하시겠습니까?` (%s = `0x832e9(win, row, sel)` 장비 이름) → 확인 팝업
- 보유·해금 가드가 없다 → 장착 목록에 보유분만 나온다는 뜻(유력).

### 2-4. StrCOMMON 141·142·143 = 해금 알림의 "어디서 쓰나" 줄 (확정)
`0x62368`(열기+알림) 안 0x623ca~0x62482:
- id ≤ 7 → StrCOMMON[**140**] `마선수 오픈!!` → 뒷줄 없음
- 8 ≤ id ≤ 12 → StrCOMMON[**138**] 히든 팀 → 뒷줄 없음
- id ≥ 13 → StrCOMMON[**139**] `히든 아이템 오픈!! [%s]` + 줄바꿈(`0xd1720` 두 번) + **범위별 뒷줄**:
  | id 범위 | 뒷줄 |
  |---|---|
  | 13 ~ 18 | StrCOMMON[**141**] `시즌모드에서 사용가능합니다` |
  | 19 ~ 34 | StrCOMMON[**142**] `나만의리그 투수편에서 사용가능합니다` |
  | 35 ~ 50 | StrCOMMON[**143**] `나만의리그 타자편에서 사용가능합니다` |
  | 51 이상 | 뒷줄 없음 |
→ 컬렉터 id(투수 20~32 · 타자 36~48)가 정확히 이 구간에 들어맞는다 (교차 검증).

## 3. 기간제 아이템 만료 알림 · StrUSER_EVT 85~113 (확정)

### 3-0. 85~113 의 실제 쓰임새 (Q0 의 "85~113 = 연속 기록·아이템 기간 끝" 은 정정)
| 번호 | 내용 | 쓰는 곳 |
|---|---|---|
| 85~96 | **감독 강판 대사** (체력≤20%·체력0%·한 이닝 4실점·만루 × 평판 3구간) | 0x504cc (**P1 2-1 이 맞다**) |
| 97~99 | 연속 4안타 강판 — **쓰이지 않는다** (P1 확인) | — |
| 100~107 | "경기 연속 2안타 이상" 등 연속 기록 **라벨** | (이 노트 밖, 0x8b924 인자로 올 수 있음) |
| 108~112 | 꾸준함·부진 평가 대사 | 〃 |
| **113** | `[구내매점] 사용 기간이 끝났습니다.` | **0x8b1b8** |
→ **겹치지 않는다.** 0x8b1b8 은 **113 하나만** 쓰고, 0x8b924 는 번호를 인자로 받는 범용 함수라 85~96 과 충돌하지 않는다.

### 3a. 0x8b1b8(obj) — 구내매점 만료 알림 (확정)
```
res = 자원열기("data/StrUSER_EVT.zt1")            ; 0x70265(res, 0xd4db0, 1)
strncpy(obj+0xba, 0x702b5(res, 0x71), 0x702d9(res, 0x71))   ; 0x71 = 113
자원닫기
```
- 인자도 분기도 없다 — **USER_EVT[113] 를 팝업 버퍼 `obj+0xba` 에 그대로 넣는 것이 전부**.

### 3b. 0x8b924(obj, idx) — USER_EVT 범용 글 채우기 (확정)
```
memset(obj+0xba, 0, 0x200)
if [obj+0xa] == 0: return
res = 자원열기("data/StrUSER_EVT.zt1")
if [obj+0xb] != 0:  sprintf(obj+0xba, USER_EVT[idx], [obj+0x2e0], [obj+0x2e4], [obj+0x2e8], [obj+0x2ec], [obj+0x2f0], [obj+0x2f4])   ; 인자 6개
else:               if idx == 76: (아무것도 안 함) else strncpy(obj+0xba, USER_EVT[idx])
자원닫기
```
- `[obj+0xa]` = 글을 띄울까 · `[obj+0xb]` = **서식 인자를 쓸까**. idx 는 이벤트 레코드가 준다 → 번호가 고정이 아니다.

### 3c. 알림을 부르는 곳 — 이벤트 큐 0x8cf64 (확정)
`0x8cf64` 가 이벤트 레코드 `ev` 를 처리한다. `ev` 종류가 2 일 때 하위 종류 `[ev+4]` (0..5) 로 **점프표 `0xd4ee4` = [0x8d288, 0x8d304, 0x8d386, 0x8d3fe, 0x8d416, 0x8d41e]**:

| [ev+4] | 하는 일 |
|---|---|
| 0 | `0x8b924(obj, (u16)[ev+6])` — USER_EVT 임의 번호 |
| 1 | 0x8d304 · 2 | 0x8d386 |
| 3 | `0x8b3bc(obj)` — 타이틀·MVP 알림 (USER_EVT 76~78 기준, 모드/투수에 따라 +3, 표 0xd4e30 = `[76,77,78,0]`) |
| 4 | `0x8b23c(obj)` — USER_EVT[83] + StrCOMMON[220]·[221] |

### 3d. 구내매점 기간 — 45경기, 매 경기 1 감소 (확정)
- **구매**(0xa3322): `rec[0x55] = 45`(0x2d) + 안내 **StrMODE[128]** `1년 간 경기 수입이 +200만 증가합니다`
  (바로 위 0xa3314 는 **협회허가증**: `rec[0x56] = 0` + **StrMODE[127]** `트레이드 커맨드를 한번 더 사용 할 수 있습니다`)
- **감소·만료**(0x8afbc~0x8b010, 경기 뒤 처리):
```
if 0x7b999([obj+0xb4])            ; 시즌모드일 때만
   rec = [obj+0x2f8]

```

## 4. 구장 아이템 설명 줄 0x837ea (확정)

`0x83378` 안, 설명 상자를 채우는 대목. **시즌모드(`0x7b998(this)`) 이고 `[this+0x1a4] == 4`** 일 때만 구장 아이템 문구로 간다 (0x83e00~0x83e1c)
→ **J 4-9 의 `[+0x1a4]==4` 가 맞고, P6 3절의 "==3 = 구장 아이템" 은 틀렸다** (1a 참고).
`r7` = 종류 (0 관중석 · 1 전광판 · 2 잔디), `k = (s8)[item+1]` = 칸.

문자열표: `[this+0x1ac]` = **StrITEM** (245·249 를 읽으므로 231칸짜리 StrMODE 일 수 없다) · `[this+0x164]` = **StrMODE**.

### 4-1. 잠긴 히든 칸이면 해금 힌트 (0x83e22~0x83e66)
```
if r7 != 2 and k > 3:
    if 0x9f6c1(0x1f1d9(app), r7, k−4) == 0:        ; app+0xe0 해금표 (2-2)
        글 = StrITEM[245 + k + (r7==1 ? 3 : 0)]  → 그 줄 하나만 쓰고 끝
```
| | k=4 | k=5 | k=6 |
|---|---|---|---|
| 관중석(r7=0) | 249 `나는야!N관중석 컬렉터` | 250 `나의 명예 선수를!N부탁해` | 251 `이벤트 오픈!!Ngamevil.com` |
| 전광판(r7=1) | 252 `나는야!N전광판 컬렉터` | 253 `빛나는 명예의!N전당 선수` | 254 `이벤트 오픈!!Ngamevil.com` |
→ 구장 히든 3종의 해금 경로가 **컬렉터 / 명예의 전당 / 웹 이벤트** 임이 문구로 확인된다.

### 4-2. 효과 줄 (0x83db0~0x83dc8, 0x83e68~0x83ebc)
`v = 0xd44f4[7*r7 + k]` (s16) — J 4-9 의 효과표와 같다.
- **r7 = 0 관중석**: `sprintf("%d명 수용!N가능", v * 1000)` — 서식 문자열은 .text **0xd4c20** (CP949 `%d명 수용!N가능`), 0x83e88
- **r7 = 1 전광판**: `sprintf("%s +%d", StrMODE[218]("관중"), v * 1000)` — 서식 **0xd4c30** `%s +%d`, 0x83eb4
- **r7 = 2 잔디**: 수치 없이 `StrITEM[144 + k]` (조금은 거친 인조잔디 …) 한 줄만, 뒤 줄 없음

### 4-3. 둘째 줄 = 필요 인기도 (0x83eec~0x83f46) — **J 4-9 의 "가격 표" 정정 후보**
```
p = 0xd44c4[8*r7 + k]        ; 관중석 [0,200,500,800,1000,1000,1000] · 전광판 [0,100,400,700,900,900,900]
if p == 0: 줄 = StrITEM[184] "인기도 제한 없음"
else:      줄 = sprintf(StrITEM[185] "인기도 %d 이상", p)
효과 줄 + 0xd41c4 + 이 줄  로 이어 붙인다
```
- `0xd44c4` 는 **바이너리 전체에서 이 한 곳에서만 읽힌다**(xref 1개) → 소지금을 깎는 데 쓰이지 않는다.
- 따라서 **0xd44c4 는 가격이 아니라 "필요 인기도"** 로 보인다 (유력 → 문구는 확정, 소비처 없음이 근거).
- 잔디(r7=2)와 잠긴 히든 칸은 이 줄을 만들지 않는다.

### 4-4. StrMODE 184·185·216 은 여기가 아니다
- StrMODE[184] `구장 아이템 구매 완료!…[구단관리]-[구장관리]에서 교체` · [185] `[%s] 아이템을 적용합니다` 는 **구매/적용 팝업**(J 4-9)이고, [216] `트레이드를 취소하시겠습니까?` 는 트레이드 쪽이다. 설명 줄(0x837ea~)에서 쓰는 184·185 는 **StrITEM** 쪽이다 — Q0 215행의 "StrMODE 184/185/216/218" 중 **218(관중)만 StrMODE**.

## 요약
**풀린 것(확정)**: ① 나리/시즌 상점 키 핸들러 `0x13460` 의 구조 — 창 종류 `[win+0x1a4]` 로 1 서브아이템 / 2 GP / 3 장비로 갈리고 4(구장)·0·5 는 손대지 않는다. 세 갈래의 가드 순서와 문구를 모두 식·표까지 확인했다(장비 = 미오픈 76 → 보유 78 → 인기도 62 → 소지금 77 → 확인 79; 서브 = 보유 78 → 소지금 77 → 79; GP = G부족 65 → 능력치최대 192 / 사기 91 / 건강 208 / 스킬 209 / 이글아이 210 / 스태미나 211 → 확인 82, 이글아이는 224 를 덧붙임). ② 구매 확정 `0x14a74` 가 소지금을 깎고 보유 플래그를 세우고 **즉시 장착**(니블 표 rec2+0x19)하며, 부위를 다 모으면 컬렉터 해금 id 를 연다(타자 36·40·44·48 / **투수 20·24·28·32** — 투수 쪽은 새로 밝힘). 해금 플래그는 `app+0xc0` 의 2×4×4 바이트 표(`0x9f69c`)이고, 이 표가 장비 상점 7·8·9 칸의 "미오픈" 가드와 직결된다. 장착 가드는 `0x17ad0` 의 "현재 장착 중"(StrMODE 80) 하나뿐이다. StrCOMMON 141·142·143 은 가드가 아니라 **해금 알림의 뒷줄**(id 13~18 시즌 / 19~34 나리 투수 / 35~50 나리 타자)이었다. ③ `0x8b1b8` 은 **StrUSER_EVT[113] 구내매점 만료 전용**이고 `0x8b924` 는 번호를 인자로 받는 범용 글 채우기라, **P1 의 "85~96 = 감독 강판 대사" 와 겹치지 않는다**(Q0 의 "85~113 = 연속기록·만료" 서술을 정정). 구내매점은 `rec[0x55] = 45` 로 시작해 시즌모드 경기마다 1 줄고 0 이 되는 순간 이벤트(종류 2, 하위 5)로 알린다. ④ 구장 아이템 설명 줄은 시즌 + `[win+0x1a4]==4` 에서만 만들어지고, 잠긴 히든 칸은 StrITEM 249~254(컬렉터·명예의 전당·웹 이벤트) 힌트를, 열린 칸은 "%d명 수용!N가능"(0xd4c20, 관중석) / "관중 +%d"(0xd4c30 + StrMODE 218, 전광판) / StrITEM[144+k](잔디)를 쓴다.

**바로잡은 것**: P6 3절의 "`[this+0x1a4]==3` = 구장 아이템 창" 은 틀렸고 **4** 가 맞다(0x83e10 에서 확인). P4 4절의 장비 가격표 앞/뒤 44칸 주인이 뒤바뀌어 있다(모드 3 = 투수가 **앞** 44칸). J 4-9 가 "가격 표" 라 적은 `0xd44c4` 는 **읽는 곳이 설명 줄 한 곳뿐**이고 StrITEM[185] "인기도 %d 이상" 으로 찍히므로 **필요 인기도**로 보인다(유력).

**남은 것**: 구장 아이템의 실제 구매 처리(소지금·인기도를 깎고 rec+0x1b8·0x1b9 를 쓰는 코드)를 못 찾았다 — `0xd44c4` 를 읽는 곳이 없어 가격이 어디서 오는지 미해결. `0x8b924` 를 부르는 이벤트(하위 종류 0)에 USER_EVT 100~112(연속 기록·꾸준함/부진)를 넣는 코드도 못 찾았다(이벤트를 만드는 쪽을 따라가지 못함). 0x13460 kind 0·5 에서 아무 일도 안 하는 이유(다른 핸들러가 받는지)도 미확인.

## 요약

**남은 것**: 0x20 에 들어오는 길(못 찾음), 0x18·0x21·0xc 그림의 img_text 번호(388·389·329, 0xb9, 0xc1·0x86)가 무슨 글자인지(그림 확인 안 함), 0x3b80c 띠 9단계의 칸별 좌표, 0x21 속도 칸·안내 띠의 정확한 좌표, 0x13 의 +0x199a 뜻, 0xae3e8(B) 의 세부 가지(견제 가지는 I-controls 4a-3 에서 풀림), 0x10 메시지 8 두 가지의 뜻. 0x13·0x12 그리기의 공 부분은 궤적이라 읽지 않았다.

## 10. 상태 0xd · 0xe — 두 그림 머묾 · 사람 OK 대기 · 소개 판 0x44944 — **확정** (2026-10-07, 메인 17c59c8 · 4c09530 · bc52323 · 35280b0 · c91a24d · 39fe274 · 8477914 · 527cbbf · b01d1be · 39f4f1d · d112628)

### 10-1. 0xd 는 늘 두 그림 (4c09530 — 0x39e14 · 0x48d50(48f3a~48f78) · 0x785a8(점프표 0xd3830) · 0x41230(4138e) · 0x76ac8 · 0xbc9c8 · 0x52c50 직접 뜸)
- 0xd 갱신 0x39e14: `[[장면+0xf10]+0x6c] ≠ 1 && 틱 > 0` 이면 0xe 예약.
- 점수판 +0x6c 를 쓰는 곳 전수(전체 디스어셈의 `str …, #0x6c]`): 만들기 0x76b16 = 0 · 0xd 진입 0x48f42 = 2(+0x61 == 0 일 때) · 점수판 갱신 0x785a8(0x41230 이 [장면+0xf10] 로 부른다) 1 → 2(0x785c8) · 2·3 → 0(0x78626) · 4·5 → 0(0x78650). **1 을 넣는 곳이 없다** → 기다림은 늘 거짓이고 0xd 는 **틱 0(진입)·틱 1(예약)** 두 그림 뒤 0xe 다.
- 틱: 상태 기계 0xbc9c8 이 상태를 바꾸는 그림에서 +0x14(= 장면+0x2c) = 0, 그대로면 ++ — 0x52c50 이 매 그림 0xbc9c8 → 진입 → 키 0x498d4 → 갱신 → 그리기 차례로 부른다. 그래서 0xe 키 잠금 "틱 ≤ 2 = 세 그림"(0x49a26)의 진입 틱 0 도 확정 → OK 는 0xd 두 그림 뒤 다섯 그림째부터.
- 0xd 의 OK 는 사람 조작 0x536bc 점프표(0xe~0x1a) 밖이라 먹지 않는다(35280b0).

### 10-2. 0xe 는 모든 모드에서 사람 OK 를 기다린다 (17c59c8 — 0x532b0 · 0x536bc(점프표 0xd0a24) · 0x53718/0x53874 · 0x39bd4 · 0x39e14 · 0x498d4(0x49a06~0x49ab4) · 0x50674 직접 뜸)

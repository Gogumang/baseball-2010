## 요약

**풀린 것 (확정)** — 모든 목록 화면이 함께 쓰는 격자 위젯의 안쪽이 열렸다. 만들기 `0x79ed5` 의 인자 11개와 저장 칸, 왼쪽 x = `cx − (Σ칸너비 + (열−1)·가로틈)/2`, 위쪽 y = `cy` 그대로(가로만 가운데). 그리기 `0x7a571` 의 칸 좌표식 `x = 왼쪽 + 열·(칸너비[(i−1) mod 열] + 가로틈)` · `y = 위쪽 + 줄·(줄높이 + 세로틈)`, 열림 애니(위에서 한 줄씩 가속하며 떨어짐, `+0x54`/`+0x60`), 커서 둥근 네모(RGB 48/69/205, 모서리 1, 칸보다 3px 크게), 커서 튕김 표 `0xd4080`(dx) · `0xd4050`(dy) = 방향으로 2px 갔다 돌아옴, 스크롤(`g[0x1f4]`/`g[0x1f8]`), 5열 화면 전용 열별 y 보정 `0xd40b8 = [3,3,3,13,13]`, 종류 0~9 별 칸 그리기 점프표 `0xd40c0`. 마선수 창도 전부 열렸다 — 창 칸(`+0x31c`/`+0x31d`/`+0x31e`), 표 읽기 `0x5fa88`(행 0x4c B), 행 접근자 `0x5f381`, 레벨업 실행 `0x5fb24`(비용 `1000·0xd1724[현재레벨]` = 3000/6000/9000/12000, 레벨 `mgr[0x13a+idx]`, G `mgr[0x64]` 상한 99999), 오픈 구매(가격 = 행 +0x11 의 +0xa u16, 오픈 플래그 `mgr[0x30+idx]`), 하위 단계 1·2·10 의 진짜 뜻. 덤으로 U-60 의 두 식(스페셜 목록 줄 y = `[메뉴+0xdc] + 20i − 100 + 스크롤 − 6`, 엔딩 그림 1px/틱, 아이리스 반지름 `r = D(p/100 − k/100 + 1)`, `k = t?110:90`, `p = min(16t,110)`)과 U-51 의 4축 각도표(225·315·45·135)·U-55 의 "칸 너비 + 3px" 이어 붙이기 규칙도 확정했다.

**남은 것** — 능력치 마름모에서 **능력치 값 → 꼭짓점 길이**로 바꾸는 식(`0x5aefd` 의 네 갈래 안, 애니 객체가 섞임), 나리 판 목록 칸 조각 `0x5650c` 안쪽(어느 칸이 이름·타율·방어율인지), 격자 종류 3·4·6 이 쓰이는 화면, `0xd40a0` = [28,30,29,25,27,26] 의 뜻(그림 프레임으로 보임 — 유력).

**주의** — 원본 그대로 옮겨야 할 특이점 둘: ① 칸 x 가 `colW[col]` 이 아니라 `colW[(i−1) mod 열]` 을 쓴다(열 너비가 다르면 어긋남). ② 레벨업 `0x5fb24` 안에 최고 레벨 상한 검사가 없다(바깥에서만 막는다).

## 3. U-50 (1) — 격자 만들기 `0x79ed4`(진입 0x79ed5) — **확정**

### 3-1. 인자 (확정 — 호출지 `0x2e92c` 스택 대조)

`0x79ed5(obj, kind, cx, cy, colW[], rowH, nCols, nRows, hGap, vGap, flag)`

| 자리 | 레지스터/스택 | 뜻 | 저장 칸 |
|---|---|---|---|
| 1 | r0 | 격자 객체 this | — |
| 2 | r1 | **종류 0~9** | `+0x88` (0x79ef2 `adds r3,#0x88; str r4`) |
| 3 | r2 | cx (가로 **중심**) | 계산에만 |
| 4 | r3 | cy (**첫 줄 위쪽 y**, 중심 아님) | `+0x14` |
| 5 | [sp+0x20] | **칸 너비 배열 int[nCols]** | `+0x1c` 부터 4바이트씩 복사 (0x79efe 루프) |
| 6 | [sp+0x24] | 줄 높이 rowH | `+0x44` |
| 7 | [sp+0x28] | 열 수 nCols | `+0xa`(s8) · `+0x74`(int) |
| 8 | [sp+0x2c] | 줄 수 nRows | `+0xb`(s8) · `+0x78`(int) |
| 9 | [sp+0x30] | 가로 틈 hGap | `+0xc`(s8) |
| 10 | [sp+0x34] | 세로 틈 vGap | `+0xd`(s8) |
| 11 | [sp+0x38] | 플래그(u8) | `+0x64` (아래 3-3 의 시프트량) |

- 앞선 노트가 "표"라고 적은 5번째 인자는 **목록 데이터가 아니라 칸 너비 배열**이다. 호출지 0x2e92c 에서 `add r3, sp, #0x12c` — 스택 지역 배열을 넘긴다.
- 6번째 인자를 P6 이 "칸 40"이라 적은 것은 **줄 높이**다(기록연감 `0x12`=18 은 P6 의 "줄높이 18"과 일치).

### 3-2. 만들 때 계산하는 값 (확정)

```
+0x10 왼쪽 x = cx − ( Σ colW[i] + (nCols−1)·hGap ) / 2      (0x79f14~0x79f36, /2 는 0 쪽 반올림)
+0x14 위쪽 y = cy                                            (가운데 정렬 안 함)
+0x58 = s8(nCols) · s8(nRows)        +0x7c = nCols · nRows   (칸 총수)
+0x5c = (rowH + vGap) · (nRows − 1)                          (열림 애니가 내려가는 총 거리)
전역 g=[0x1552cfc] : g[0x1f4] = 0 (첫 보이는 줄) · g[0x1f8] = nRows (마지막 보이는 줄 +1)
```

### 3-3. 열림 애니 `0x79fa8` — **확정**

```
if (+9) return 1;                       // 이미 끝남
+0x4c <<= (s8)+0x64;                    // 인자 11 = 가속 시프트량
+0x54 += +0x4c;                         // 누적 내려간 거리
+0x60 = (+0x44 + (s8)+0xd) · +0x48;     // = (rowH+vGap)·(드러난 줄 수)
if (+0x54 >= +0x60) → 다음 줄 드러내기 (+0x48++, …)
```
→ 목록이 **위에서 한 줄씩, 가속하며 떨어지는** 연출. P6/U-60 이 "애니가 섞여 값을 못 뽑았다"고 한 것의 정체.
**애니가 끝난 뒤** `+0x54 = (rowH+vGap)·(nRows−1)`, `+0x48 = nRows−1` 이 되어 아래 3-4 의 y 가 `위쪽 y + row·(rowH+vGap)` 로 떨어진다.

## 4. U-50 (2) — 격자 그리기 `0x7a570`(진입 0x7a571) — **확정**

`0x7a571(grid, cursor, a3, a4)` — cursor(2번째 인자)는 `+0xc`=열, `+0x10`=줄, `+0x14`=열수 를 가진 커서 객체.
**고른 칸 번호 sel = cursor[0x14]·cursor[0x10] + cursor[0xc]** (0x7a5c2~0x7a5d0).

### 4-1. 스크롤 (확정)

전역 `g = [0x1552cfc]`, `A = g[0x1f4]`(첫 보이는 줄), `B = g[0x1f8]`(끝 줄+1).
`+0x70` = 커서가 방금 움직인 **방향** (0 왼 · 1 오른 · 2 위 · 3 아래 · −1 없음).

```
방향 2(위): if (0 <= sel < A·nCols)            A--, B--       (0x7a65a~0x7a68a)
방향 3(아래): if (B·nCols <= sel <= +0x7c)     A++, B++       (0x7a6a8~0x7a6d6)
그리는 범위 i = A·nCols … B·nCols − 1                        (0x7a6d8~0x7a6fe)
```

### 4-2. 칸 좌표 — 핵심 식 (확정, 0x7a708~0x7a78e)

칸 좌표는 `+0x5c` 가 가리키는 `int2[칸수]` 버퍼(0x7a628 에서 `+0x58`·8 바이트 alloc)에 매 틱 다시 계산된다.

```
col = (i − A·nCols) mod nCols          ; 0xca911 = __modsi3
row = (i − A·nCols) / nCols            ; 0xca7b5 = __divsi3

x[i] = (col == 0) ? +0x10
                  : +0x10 + col · ( colW[(i−1) mod nCols] + hGap )

y[i] = +0x14                                        // i < +0x50 이면 여기서 끝
     = +0x14 + +0x54 − (nRows − row − 1)·(rowH + vGap)   // i >= +0x50
```

- **원본 그대로의 특이점**: x 의 칸 너비를 `colW[col]` 이 아니라 **`colW[(i−1) mod nCols]`** 로 읽는다(0x7a73e `lsls r0,#2; ldr r3,[r0,#0x1c]`). 모든 열 너비가 같은 화면에서만 맞는 식이다. 열 너비가 다른 격자는 어긋난다 — **원본 버그로 그대로 이식**(메모리 규칙).
- 애니가 끝나면 `+0x54 = (rowH+vGap)(nRows−1)` 이므로 `y[i] = +0x14 + row·(rowH+vGap)`.

### 4-3. 열별 y 보정 표 `0xd40b8` (확정)

```
if (+0x88(종류) ∈ {3,4,6,7,8,9})   y[i] -= u8 0xd40b8[ i mod nCols ]
```
`0xd40b8` = **[3, 3, 3, 13, 13]** (5바이트, 0x7a596 에서 5바이트 memcpy).
→ 5열 격자(마선수 7·8, 에디트 9 등)에서 **4·5번째 열만 10px 더 올라간다**.
바로 앞 `0xd40a0` = u32 [28, 30, 29, 25, 27, 26] (6칸, 0x7a58c 에서 24바이트 복사 — 종류별 그림 프레임 번호로 보임, **유력**).

### 4-4. 커서 네모 + 튕김 연출 (확정)

`+8`(u8) 이 참이면 보이는 칸마다 둥근 네모를 깐다 (0x7a844~0x7a888):

```
색 = [0x1400748](ARM 루틴)(0x30, 0x45, 0xcd)      // R48 G69 B205 남색
0x6b7d5( gfx=[0x1400070], x[i]−3, y[i]−3, colW[i mod nCols]+3, rowH+3, 모서리 1, 색 )
```
`0x6b7d5` 은 모서리 반지름(6번째 인자)을 **7로 상한**하는 둥근 네모 채우기 (0x6b7e4 `cmp r7,#7; ble`).

**튕김**(0x7a7f6~0x7a842, 커서 네모가 없을 땐 0x7a8aa 에서 같은 계산):
```
if (+6 && +0x70 != −1 && i == sel):
    x[sel] += s32 0xd4080[ 2·+0x70 + +0x6c ]
    y[sel] += s32 0xd4050[ 3·+0x70 + +0x6c ]
    +0x6c++ ;  if (+0x6c > 1) +0x70 = −1
```
| 표 | 값 |
|---|---|
| `0xd4080` (dx, 2칸 간격) | 방향0 −2,+2 · 방향1 +2,−2 · 방향2 0,0 · 방향3 0,0 |
| `0xd4050` (dy, **3칸** 간격) | 방향0 0,0,0 · 방향1 0,0,0 · 방향2 −2,+2,0 · 방향3 +2,−2,0 |
→ 커서를 옮기면 고른 칸이 **그 방향으로 2px 갔다가 되돌아온다**(2틱).
**원본 그대로의 특이점**: dx 는 2칸 간격, dy 는 3칸 간격으로 같은 `(방향, 단계)` 를 인덱싱한다(0x7a814 `lsls r0,r6,#1` vs 0x7a820 `adds r0,r0,r6`). 표 값이 그에 맞춰 짜여 있어 결과는 위 표대로 맞는다.

### 4-5. 칸 내용 그리기 — 종류별 점프표 `0xd40c0` (확정)

0x7a8fc: `종류 = +0x88; if (종류 > 9) → 0x7b390(중단); pc = [0xd40c0 + 4·종류]`, `r7 = grid+0x94`(그림 자원).

| 2 | `0x7a9cc` | 기록연감 통계 탭 |
| 3, 6 | `0x7ac2e` | (미확인) |
| 4 | `0x7af1a` | (미확인) |
| 5 | `0x7aa68` | 미션 격자 5×3 (P6 2b) |
| 7, 8 | `0x7b14c` | 마선수 격자 5×2 (P6 2a) |

## 1. U-24 (1) — 마선수 레벨업/오픈 창의 칸과 진입 — **확정**

### 1-1. 표 읽기 `0x5fa88(skin)` — 확정
`0x6f9fd("data/XlsACE_LEVEL_UP.zt1"(0xd2164), &len)` 로 읽어 `[skin+0x320]` 에 넣는다.
**행 크기 0x4c = 76바이트** (아래 1-2 의 `muls r3, r1, #0x4c` 로 확정). K 3-3 이 적은 "행 76바이트" 는 맞고, 그 안의 "문자열 74" 는 76−0x11−0xc = **47바이트**여야 앞뒤가 맞는다 (→ 5절 정정).

### 1-2. 행 접근자 `0x5f380`(진입 0x5f381) — 확정
```
0x5f381(skin, idx) → [skin+0x320] + 0x4c·idx + 0x11
```
K 3-3 이 적은 "u16[5] (+0xa) = G 오픈 가격 / 문자열 (+0xc) = 힌트" 는 **이 +0x11 포인터 기준**이다 (행 처음부터는 +0x1b, +0x1d).

### 1-3. 창 상태 칸 (skin 오프셋) — 확정

### 1-4. 마선수 레벨·오픈 플래그 저장 위치 — **확정**

| 무엇 | 위치 | 근거 |
|---|---|---|
| 오픈 여부 | `mgr[0x30 + idx]` (idx 0~9) = 1 | 0x2a1ec `adds r3,r5,r1; adds r3,#0x30; strb 1` |

## 7. U-60 (1) — 스페셜 세로 목록의 줄 y — **확정**

그리기 `0x2524c` 안 `0x253d4~0x256d0`. P6-screens.md:231 이 "y = 줄 y + 스크롤([0x1552d68]) − 6" 까지만 적고 "줄 y" 를 못 뽑은 부분이다.

### 7-1. 줄 y 식 (확정)

```
i = 1 … 7                                  // 0x25520 [sp+0x68]=1 · 0x256ca `cmp #7; bgt`
i ≤ 3 : off_i = [sp+0x18] = 20i − 100      // 0x25518 `movs r1,#0x50; rsbs` · 0x256c0 `adds r1,#0x14`
i ≥ 5 : off_i = [sp+0x1c] − 0x3c = 20i − 60 // 0x25518 `movs r0,#0x14` · 0x256c2 `adds r2,#0x14` · 0x256b0 `subs r2,#0x3c`
i == 4: 아예 안 그린다                      // 0x2562c `cmp #4 ; ble` → 다음 줄로
y_i   = [메뉴+0xdc] + off_i + [0x1552d68] − 7   // 진짜 글자 0x25628 `subs r2,#7`
        그림자는 한 겹 먼저 (−0x27, −6), 진짜 글자가 (−0x28, −7) → (+1,+1) 어긋남 (0x255de·0x255ec)
```
→ **줄 간격 20px**. 윗줄 셋은 `[메뉴+0xdc] − 87 · −67 · −47`, 아랫줄 셋은 **`[메뉴+0xdc] + 40 · +60 · +80`**.

**정정 (이 문서 앞판 오류)**: 앞판은 `off_i = 20i − 100` 한 가지만 적고 `− 6` 이라 했는데,
0x2562c 의 `i ≥ 5` 가지를 빠뜨린 것이고 −6 은 그림자 쪽 값이다. "커서 줄(0번)을 0x25490~0x25516
에서 따로 그린다" 도 틀렸다 — **i == 4(커서 줄)는 어디서도 안 그리고 설명 판이 대신 보여 준다**.
0x253f8~0x2548e 는 바탕 그라데이션, 0x254ce~0x25516 은 그 띠가 자라는 연출이다.

### 7-1a. 아랫줄 셋이 화면 밖인 것은 해상도와 무관하다 — 확정
`i ≥ 5` 의 y 는 **`[메뉴+0xdc] + 40/60/80`** 이라 **늘 화면 높이보다 크다**. `[메뉴+0xdc]` 는
0x237d6 이 넣는 `높이()` 그대로다(바이너리 전체에서 `adds rX,#0xdc` + `str [rX]` 를 훑어 이 객체에
쓰는 곳은 0x237dc 한 곳뿐임을 확인). 따라서 **실기가 240×320 이든 240×400 이든 아래 세 줄은
바닥 밖**이다 — "실기 해상도가 더 컸다" 가설은 **기각**.
설명 판도 마찬가지로 `y = 높이 − h/2` 라 **어느 해상도에서나 아래 h/2 = 32px 가 밖**이다
(아랫단 0x25714, 윗단 바퀴 0x24dc0 이 각각 같은 식을 쓴다).

뜻: 아랫단은 **(폭/2, 높이) = 화면 아래 한가운데를 축으로 한 릴**이다. 바탕 그라데이션도 같은 축으로
위아래 대칭이다 — `선(x 160→240, y = 높이 − i)` 과 `선(x 160→240, y = 높이 + i)` 를
i = 0 … [메뉴+0xe4] 까지 긋고(0x2543c·0x25472, 그리기 0x6a905, 색 `0x192e74` 에 알파를 위 바이트로
얹되 254 에서 2씩 줄어 4 에서 멈춤), `[메뉴+0xe4]` 는 틱마다 ×4 로 자라 **`높이/2`(=160) 에서
멈춘다**(0x254e4~0x25512). 곧 **오른쪽 80px 띠가 바닥에서 160px 올라오는 연출**이고, 릴 글자
가운데 x = `폭 − 0x28` = 200 이 그 띠 한가운데다. 슬롯 1·2·3 = 보이는 윗줄, 4 = 고른 칸(설명 판),
**5·6·7 = 축 아래로 넘어간 숨은 줄**이다.

**띠를 켜는 곳 — 확정 (새로 확인)**: `[메뉴+0xe4]`·`[메뉴+0xe2]` 를 쓰는 곳은 .text 전체에서 셋뿐이다

`상태기계.설정(값)`(0x23882)으로 하위 상태가 되고 전역은 −1 로 지워진다. 곧 **"메인 메뉴를 게임시작
목록으로 바로 열어라" 로 들어올 때만 띠가 자라고**, 윗단 바퀴에서 OK 로 내려온 경우에는 `[0xe4]` 가
0 이라 축 한 줄(y = 높이, 화면 밖)만 그어져 **띠가 아예 안 보인다**. 한 번 자란 뒤 0 으로 되돌리는
코드는 없으므로 그 장면이 사는 동안 띠는 계속 남는다.

**자라는 동안 줄을 안 그린다 — 확정**: 0x254d4 가 `[메뉴+0xe2]` 를 보고 0 이 아니면 키운 뒤
`b 0x256d0` 으로 **줄 묶음(0x25518~0x256b0)을 통째로 건너뛴다**. 0x256d0 은 설명 판이라
**판은 그대로 그려진다**. 그려지는 값은 `1 → 4 → 16 → 64 → 160` 넉 틱이다(띠를 먼저 긋고 그 다음에
키우기 때문).

**알파는 /255 다**: 그리기 0x6a905 가 색의 위 바이트를 알파로 보고, `0` 이거나 `0xff` 면 섞지 않는다(0x6a918).

### 7-1b. 거르개·잘라내기 (확정)
- `0x2524c` 안의 거르개는 **`슬롯 ≠ 4`(0x2562c) 와 슬롯 표 −1(0x2552c)** 둘뿐이다. y 상한도,
  스크롤 상한도, 보이는 슬롯 목록도 **없다**.
- `0x2524c` 는 잘라내기 `0xbae25` 를 한 번도 부르지 않는다(자리표 전수 확인: 0x24b1c~0x258b0 중
  0x251c4 한 자리뿐이고 그건 윗단 것이다). 윗단 0x24b1c 은 설명 **글 칸**에만 쓴다
  (0x25072 → `(판x+5, 판y+5, w−10, h−10)`).
- 화면 밖은 **그리기 쪽이 버린다**: 16비트 블릿 `0x98974` 가 `[그래픽+0x44]` 의 잘라내기 사각형
  (s16 x·y·w·h)과 대상 폭·높이를 견줘 범위 밖이면 `0x99086` 으로 **그냥 되돌아간다**
  (0x989a6~0x98a2a). `0xbae25` 가 그 사각형을 세우고(0xbaeba~0xbaecc), 높이 인자가 음수면
  `높이() − y` 로 채운다(0xbae9e).

### 7-2. 어느 항목을 그리나 (확정)
`[sp+0x64] = (sp+0xa4) + 9·커서 − 0x2d` — 커서 위치마다 **9바이트짜리 창(window) 표**를 잡고 `ldrsb [표, i]`(0x2552a) 로 항목 번호를 꺼낸다. 값이 **−1 이면 그 줄은 건너뛴다**(0x2552c `adds r5,r4,#1; beq`).
항목 그림은 `[0x1552d28 + 4·번호]`(0x25544), 폭의 절반만큼 왼쪽으로 밀어 가운데 맞춤(0x2560a `ldrh [r2,#0x12]; lsrs #1`).
가로 흔들림 인자 `0x21` 은 `[0x1400748]` ARM 루틴으로 만든 색/값(0x255c8).

## 8. U-60 (2) — 엔딩 그림 이동량·원 반지름 식 (`0x882b4`) — **확정**

P6-screens.md:315~320 이 "유력/미확인" 으로 남긴 두 식이다.

### 8-1. 엔딩 그림 미끄러져 들어오기 — 확정
움직이는 칸은 `this+0x2f0`(0xbc<<2) · `this+0x2f4`(0xbd<<2), 짝은 `this+0x2ec`(0xbb<<2).
```
[this+0x2f4] = min( [this+0x2f4] + 1, 0 )        // 0x88778~0x88784
```
→ **한 틱에 1px**, 음수에서 0 까지 올라오고 0 에서 멈춘다. 가로 자리는 `W/2 − [그림+0x20]`(0x8874a~0x88756)로 가운데 맞춤. `[this+0x2f0] == 0` 인지로 두 그림 중 어느 쪽을 먼저 움직일지 고른다(0x886ec·0x887b0).

### 8-2. 원형 전환(아이리스) 반지름 — 확정 (0x887dc~0x88846)
```
D = (앞 단계 값) − [this+0x2fc]            // 0xbf<<2 = 0x2fc
t = [this+0x308]                           // 0xc2<<2 = 0x308, 전환 틱
k = (t == 0) ? 90 : 110
p = min( 16·t, 110 )
r = ( D − D·k/100 ) + D·p/100
[this+0x2f8] = 화면폭 − r                  // 0xbe<<2 = 0x2f8, 원 그리기에 쓰는 값
```
- t = 0 → r = 0.10·D · t = 1 → 0.06·D · t = 2 → 0.22·D · … · **t ≥ 7 → p 가 110 에 걸려 r = D** (원이 화면을 다 덮음).
- 나눗셈은 모두 `__divsi3`(0xca7b5) 정수 나눗셈이다 (0x88806·0x8881e 의 `movs r1,#0x64`).
- P6 이 "0x6c6a9(110, …)/100 식으로 줄거나 는다" 라고 적은 것의 정확한 형태가 위 식이다.

1. **P6-screens.md:127·131·160·187·209·223 — `0x79ed5` 인자 이름이 바뀐다.**

   - `+0x314` 의 1·2·10 은 전부 **팝업 응답 대기 단계**다: 1 = 마선수 **오픈 구매** 확인, 2 = G 부족 → 구매 페이지 이동 확인, 10 = **대전메뉴 나가기** 확인.

3. **K-bursts-special.md 3-3 — XlsACE_LEVEL_UP 행 구성 수치가 안 맞는다.**

4. **H2-special-skills.md:83 — "레벨 = 전역기록[+0x13f+순번]" 은 마타자에만 맞다.**

5. **R4-lineup-screens.md:97 — 교체 상세 창이 "0x5aefd 계열로 보임(미확인)".**

## 1a. 장면 0x105 상태 기계 — 확정(구조·전이) / 유력(일부 상태 이름)

**구조 (확정)**: 장면 객체 this, 상태 기계는 this+0x18 (`+4`=현재 this+0x1c, `+8`=다음 this+0x20, `+0xc`=이전 this+0x24).
`0xbcb48(sm, s)` = `prev = next; next = s; 플래그=1` (다음 틀에 적용). vtable 0xcbbb0 의 [2] = **갱신 함수 0xe9ac**.
0xe9ac 는 한 틀에 세 단계를 돈다:
1. 상태별 갱신: `상태−0xc8 ≤ 0x32` → 점프표 **0xcbea0** (51칸)
2. 시즌 이벤트 폴링(상태 0xc9·0xd1 일 때, 2b 절) · CPU 트레이드 요청 알림(0xec10~, StrMODE[203])

## 1b. 관리 메뉴 6칸과 2경기 주기 — 확정

**메뉴 6칸** (0x3b14 가 `0x6c219(메뉴, 6, 1, 1)` 로 만든 this+0x70. 키 0x8f30):
- 칸 번호 = `메뉴+0xc + 메뉴+0x10 × 메뉴+0x14` (0..5), 점프표 **0xcbe40** → `0xbcb48(sm, 상태)`:
  | 칸 | StrHOWTO[18] | 상태 |
  |---|---|---|
  | 0 | 시즌정보 | 0xcd |
  | 1 | 구단관리 | 0xce |
  | 2 | 트레이닝 | 0xcf |
  | 3 | 외출 | 0xd1 |
  | 4 | 아이템 | 0xd0 |
  | 5 | 다음경기 | 0xd8 |
- 칸 0~4 는 상태를 바꾼 뒤 `0x7ff54(this+0xc0)` 를 부른다(보조 UI 정리, 유력). `this+0xc0 +0x99 ≠ 0`(팝업 중)이면 키 무시.
- **취소(−16)** → 0x140006c = 5, `0xbc290(앱, 0x103)` = 메인 메뉴 장면으로 나감.
- 구단관리 하위 4칸 (this+0x78, 키 0x4e40, 확정): 0 구장관리 → 0xea · 1 트레이드 → 0xe4 · 2 선수영입 → 0xe2 · 3 코치채용 → this+0x11c=2, 0xd7.

**2경기 주기 (확정 — 0xf1 키 0x49a4, 0xcb 분기 0x4c24)**:
```
경기 뒤 흐름: 경기 장면 끝 → 장면 0x105 → 0xcb(phase 2) → 0xe9 관중·수입 → (0xd3 이벤트) → 0xf1 → 확인:
  포스트시즌(SR+0xb4) → 0xef
  SR+0xb2(이번 시즌 치른 경기 수) 가 짝수 → 0xc9 관리 메뉴
```

- 외출 장소 이벤트: s_event 에 trigger≥2 가 없고, 지도 상태 코드가 209 라 0x8cdc0 장소 배정도 걸리지 않는다(2b). 0xd2(0xbfb4)가 0x8ce58 을 부르는 경로는 있으나 시즌 데이터로는 비어 있음(유력).
- 웹판: 없음. 나리 외출(`outingPlaces.ts`)과 값·가드가 다르므로 재사용하면 안 된다.

## 4a. 경기 뒤 팀 평가 (인기도 · 평판 · 사기) — 확정(식) / 유력(일부 기록 칸 이름)

## 5. 선수영입 · 일반 선수 장비 — 확정(가드·표) / 유력(영입 원본 고르기 세부)

  3. 필요 인기도 s16 **0xcbd58** `[0, 50, 150, 300, 450, 600, 800, 0, 0, 0, 0]`[i] > 인기도 → [62]
  4. 가격 s16 **0xcbca8** `[t·11 + i (+44 if 앱+0x24c)]` × 10 (100만 단위) > 소지금 → [77]
  5. 확인 [79] "소지금 %s이 소모됩니다 구매하겠습니까?" (표시 = 값×1000 만) → 적용: 소지금 −= 값×10, 니블 기록, 명예 선수면 0x2328c 로 명예 기록에도 반영, [142] "해당 장비를 장착 했습니다".
- 가격표 앞 44칸은 나리 장비표 0xcc444 와 **같은 값**: 부위 0 `[4,8,12,18,24,32,40,80,110,150,200]` · 1 `[5,9,14,20,27,35,45,90,120,160,210]` · 2 = 부위 0 · 3 `[3,6,10,15,21,28,36,70,100,140,190]`. 뒤 44칸(앱+0x24c ≠ 0, 투수 쪽으로 보임 — 유력): `[5,9,14,20,27,35,45,90,120,150,200]` · `[5,9,14,20,27,35,45,90,120,160,210]` · `[3,6,10,15,21,28,36,70,100,140,190]` ×2.
  → 시즌에서는 **값×10 = 100만 단위** (예 4 → 4000만, 200 → 20억). 필요 인기도 표는 나리 0xcc50a 와 같은 값.
- 장비 효과(경기 능력치)는 G-1 의 0xb570c 경로(장착 보정)와 같다고 보임 — 시즌 쪽 별도 코드는 확인 못 함(유력).
- 웹판: 없음.

## 6. 시즌 팀 질병 · 사기 변화 — 확정

**기록 위치**: 팀 사기 = 팀레코드(`0x1f570(저장, SR[1])`) **+2 s16 (0..100)** · 팀 질병 종류 = **SR+5** (0 건강, 1~4 감기·몸살·식중독·배탈 = StrMODE[185+종류]) · 입원 실패 여유 = SR+6 · 질병 쿨다운 = **SR+0x7c**.

**질병 걸림 = 이벤트 490 (대상 4, 반복, 1년1경기 ~ 13년45경기, 관리 메뉴에서만)** — 조건 22 (0xadb32) 모드 2 갈래:
```
SR+5 ≠ 0 → 불발
m = 팀 사기 ; p = m>70:0 | m>50:2 | m>30:4 | m>10:7 | 그 밖 14   (%)
rand(0,100) < p → 발동        ; 모드 2 는 유리몸·행운 보정이 없다 (나리 갈래만 0xa3a74/0xa4bf8 검사)
SR+0x7c > 0 이면 490 불발 (0xad036~0xad054)
```
- 보상 11(값 0): G 4-3b 대로 글 만들 때(0x8c14e) 값이 `rand(0,4)+1` 로 바뀌어 기록되므로 **실제로 병에 걸린다**(A 문서의 "v≤0 이면 치료 → 원본 버그" 는 이 재기록을 빠뜨린 해석 — 0x8c718 이 읽는 값은 1~4). 적용 0x8c730: [mgr+0x2f8](=SR)+5 = 종류, +6 = 0xd4d98[종류] = 3, +0x7c = 20. 이어 SYS(0,49).

**질병 효과 (J-4 확인)**: 경기용 능력치 0xb570c 시즌 갈래 — 내 팀 선수 전원 **−30%**. 사기 정액 감소: >50 없음 · 31~50 −50 · 11~30 −100 · ≤10 −200 (0 바닥).

# L. 사운드 · 연출 · 안 쓰는 에셋 (binary.mod 역분석)

## 요약
**풀린 것**
- 사운드 52개는 전부 야마하 SMAF: 000 만 MA-2(+ADPCM), 나머지는 MA-3 무압축 악보 — 커스텀 FM 음색 악보형 26개, 야마하 4비트 ADPCM 11025Hz 음성·효과음 샘플형 24개, 011 은 둘 다. ffmpeg 는 못 읽고,
  **WildMIDI master(0.5.1 개발판, `-DWANT_MAFM=ON`)로 52개 모두 WAV 렌더와 MIDI 변환에 성공**했다(scratchpad/snd/wav, mid). 웹에는 미리 렌더해 ogg 로 넣는 길을 권한다.
- 재생 API(0x6ea6c 즉시 / 0x6e498 예약 / 0x6eaf0 배경음 복귀 / 0x6e4d0 볼륨)와 호출지 약 70곳을 번호별로 정리했다. **예약은 큐가 아니라 한 칸 덮어쓰기이고 울리던 소리를 끊는다 — 1-A2·1-A3 절.** 이벤트 스크립트 명령 6 은 "파일 = id−1" 이고, 명령 5 는 진동·흔들기·페이드다.
  음성 샘플은 whisper 로 받아 적어 스위치 분기와 맞췄다: 018 스트라이크 · 016 볼 · 021 삼진 · 024 볼넷 · 023 사구 · 022 타임 · 000 "GAMEVIL".
  배경음은 1 메인메뉴 · 3 모드준비 · 4 관리화면 · 33 경기 · 40 이벤트 · 46 엔딩이고, 31/32 는 승리/패배 징글이다. 002 는 어디서도 안 쓴다.
- 진동은 0x3a44(ms) 로 한다. 저장 +0x3b 가 켜져 있을 때만 세기 100 으로 울리고, 길이는 100/200/300/500ms 다.
- 환경설정 저장 칸: +0x2e 소리(×25), +0x2f 속도(1000/[4,10,16,22,28] ms), +0x3b 진동, +0x2c 난이도. **난이도는 기본값 2(hard) 뒤로 바꾸는 곳이 없다** → 원본은 늘 pitchpattern_hard 를 쓰는데, 웹은 'normal' 을 쓴다.
- battingPattern.arr 는 CPU 타자의 행동 확률표(치기·번트·지켜보기)이고 웹은 쓰지 않는다. d_level.dat 는 경기 밸런스 표이지 난이도가 아니다.
- 장비 외형: (부위, 등급 n 0~10) → 파일·팔레트 줄 규칙을 모두 확정했다. 타자 밴드(몸)는 그림이 없고, 투수 몸은 7~10 만 있다.
- 필살기 그림 고르기(마선수 순번 / 필살타법·마구 번호 → effect 파일), 경기 연출 에셋의 게임 객체 칸, 파티클 26개(id 0~24 = 001~025, 026 은 못 씀),
  slt_pitch.raw(30×30 원형 알파 마스크), 글꼴 ft2 형식(영문 94자, 한글 조합형 488조각), fence_season.pzf(시즌 구장 4단계 × 관중석 4단)를 밝혔다. touch.pzx/touch_oem.pzx 는 코드에서 아무도 부르지 않는다.
**남은 것**
- 연출 에셋 대부분의 **그리는 좌표·타이밍**(deadly_effect·game_effect·player_effect·combo·event_zone·board_ani 애니)은 칸 연결까지만 확인했다. combo.pzx 의 칸은 확정하지 못했다.
- 효과음 일부(8·10·12·13·14·15·26·27·28·44·53·59·61)의 정확한 장면, 17(세이프?)·25(파울?)의 글자.
- ptc 51바이트 필드 뜻, 한글 벌 고르기 식(0x9bba2~0x9bd94), fence_season 프레임과 구장 아이템의 대응.

## 1. 사운드

### 1-A. 재생 API (확정)
사운드 객체는 전역 포인터 `[0x1400058]`. 파일 경로는 0x6e9d4 가 `sprintf("%s/%03d.mmf", dir, n)` (디렉터리 없으면 `"%03d.mmf"`),
문자열 0xd3294 / 0xd32a0. 디렉터리 이름 "sound"(0xcbab0)는 앱 초기화 0x2ed8 가 넣는다.
| 함수 | 뜻 | 근거 |
|---|---|---|
| 0x6ea6c `play(obj, n, vol=-1, loop:u8)` | 즉시 재생. obj+0x40(볼륨)=0 이면 재생 안 하고 loop 일 때 번호만 +0x28 에 기억. 성공하면 loop 일 때 +0x28=+0x2c=n (현재 배경음) | 6ea76 `ldr r3,[r0,#0x40]; cmp r3,#0` → 6ea86 `str r6,[r0,#0x28]` |
| 0x6e9d4 | 실제 로드·재생. n<0 이면 아무것도 안 함. 이미 재생 중이면 멈춤(0x6e258) | 6e9e2 `cmp r1,#0; blt` |
| 0x6e498 `request(obj, n, loop)` | **큐가 아니라 한 칸**이다. 울리던 소리를 끊고(0x6e4b8) +0x30=n, +0x34=loop 로 덮어쓴다. 같은 번호가 이미 들어 있으면 아무것도 안 한다. 0x6eac8 이 틱마다 클립이 비면 예약분을 0x6ea6c 로 튼다 — 1-A2 절 | 6e4c2 `cmp r3,r5; beq` → 6e4c6 `str r5,[r4,#0x30]; strb r6,[r2,#4]` |
| 0x6eaf0 `resumeBgm(obj)` | +0x28(기억한 배경음)을 loop=1 로 다시 튼다 (팝업·일시정지 뒤 복귀 20여 곳) | 6eaf2 `ldr r1,[r0,#0x28]` → 6eb04 bl 0x6ea6c(r3=1) |
| 0x6e438 `stopBgm` | +0x28==+0x2c 면 멈추고 +0x28=-1 | |
| 0x6e4d0 `setVolume(obj, v)` | 0~100 으로 자름, 플래그 [9] 가 켜져 있으면 1~39 → 40 | 6e4ea `cmp r1,#0x27; bgt` / `movs r1,#0x28` |
| 0x2ddc (앱 재개) | +0x2c 가 1..4 이면 그 번호를 loop=1 로 다시 튼다 → 1~4 는 배경음 | 2e22 `ldr r1,[r0,#0x2c]; subs r3,r1,#1; cmp r3,#3; bhi` |

호출 형태는 모두 `ldr r4,=0x6ea6d; bl 0xca9fc`(r4 트램펄린), 인자 r1=번호, r2=-1, r3=loop.
**웹판**: 소리 코드가 전혀 없다 (`grep -ril sound src` → eventTypes.ts 의 `op:'sound'` 타입뿐, 실행하는 코드 없음).

### 1-A2. 예약 `0x6e498` 의 진짜 동작 — **큐가 아니다** (확정, 2026-09 직접 뜸)

앞 판 표가 "예약" 이라고만 적어 둔 것을 전부 떴다. 결론부터: **칸은 하나이고, 예약은 울리던 소리를 끊는다.**

```
0006e498: b570        push {r4,r5,r6,lr}
0006e49a: 1c04        adds r4,r0      ; r4 = 사운드 객체
0006e49c: 3014        adds r0,#0x14   ; r0 = p = obj+0x14 (미디어 객체)
0006e49e: 7c43        ldrb r3,[r0,#0x11]  ; p[0x11] — bit0 = 지금 소리의 loop, 상위 니블 = 마지막 이벤트
0006e4a0: 0612        lsls r2,r2,#0x18
0006e4a2: 1c0d        adds r5,r1      ; r5 = n
0006e4a4: 0e16        lsrs r6,r2,#0x18 ; r6 = (u8)loop
0006e4a6: 07da        lsls r2,r3,#0x1f
0006e4a8: d406        bmi  0x6e4b8    ; 지금 울리는 것이 배경음(loop)이면 멈추러
0006e4aa: 7963        ldrb r3,[r4,#5] ; 기기 예외 플래그
0006e4b4: 2a00        cmp  r2,#0
0006e4b6: d001        beq  0x6e4bc    ; 0 이면 안 멈추고 예약만
0006e4b8: f7ff fece   bl   0x6e258    ; ← stop(p) : 울리던 소리를 **끊는다**
0006e4bc: 6b23        ldr  r3,[r4,#0x30]  ; 지금 예약돼 있는 번호
0006e4be: 1c22        adds r2,r4
0006e4c0: 3230        adds r2,#0x30
0006e4c2: 42ab        cmp  r3,r5
0006e4c4: d001        beq  0x6e4ca    ; **같은 번호면 아무것도 안 한다** (loop 바이트도 안 고침)
0006e4c6: 6325        str  r5,[r4,#0x30]  ; 번호 덮어쓰기
0006e4c8: 7116        strb r6,[r2,#4]     ; +0x34 = loop
0006e4ca: bc70        pop  {r4,r5,r6} ; pop {r0} ; bx r0
```

**칸 수 = 1.** `+0x30`(번호, 빈 값 −1) · `+0x34`(loop 바이트) 뿐이다. 생성자 0x6e8dc 가 `+0x28=+0x2c=+0x30=−1`,
`+0x34=0` 으로 시작한다(0x6e91c~0x6e92c). 예약이 쌓이는 배열도, 개수 칸도 없다 — **늦게 온 번호가 앞 예약을 버린다.**

**중복.** 같은 번호가 이미 들어 있으면 `beq` 로 건너뛴다. 덮어쓰기 자체가 같은 값이라 결과는 같지만 `loop` 바이트를 안 고치는 차이가 있다.

**끊는 조건 — 실전에서는 늘 참이다.** 두 조건 중 `p[0x11] bit0` 은 "지금 울리는 것이 배경음" 이고,
`obj[5]` 는 기기 표(PHONEMODEL) 플래그다. 그런데 초기화 `0x6e6a4` 는 기기 이름 비교를 다 마친 **맨 끝에서
조건 없이** 이 칸을 1 로 쓴다:
```
0006e70c: cmp r4,#0 ; bne 0x6e712 ; 0006e710: b 0x6e854   ; PHONEMODEL 조회 실패면 통째로 건너뜀
   ... SCH-B590 / KTF-T1000 / SPH-V6900 / PT-S / IM-R / SCH-W5 / CANU701D … 기기별 예외 ([4],[7],[8],[9]) ...
0006e84c: ldr r3,[pc,#0x3c]  ; [0x1400058] = 전역 사운드 객체
0006e84e: ldr r2,[r3]
0006e850: movs r3,#1
0006e852: 7153 strb r3,[r2,#5]   ; ← 기기와 무관하게 obj[5] = 1
0006e854: (에필로그)
```
`MC_knlGetConfig("PHONEMODEL", buf, 0x20)` 이 0(성공)을 주기만 하면 obj[5]=1 이다 — 같은 스텁(0x14005d8, API 0x7e)을
쓰는 다른 11곳도 모두 `cmp r0,#0` 을 성공으로 읽는다. **곧 실기에서 예약은 언제나 현재 소리를 끊는다.**

**"끝났다" 를 무엇으로 아는가 — `obj+0x20`(= p[0xc], 미디어 클립 핸들)이 0 인가.**
```
0006eac8: b500        push {lr}
0006eaca: 6b01        ldr  r1,[r0,#0x30] ; adds r3,r1,#1 ; beq 0x6ead6   ; 예약 없음(−1) → 0 반환
0006ead0: 6a03        ldr  r3,[r0,#0x20] ; cmp r3,#0 ; bne 0x6ead6       ; 클립이 살아 있으면 아직
0006eada: 791b        ldrb r3,[r3,#4]    ; r3 = +0x34 loop , r2 = −1
0006eae4: f7ff ffc2   bl   0x6ea6c        ; play(obj, 예약번호, −1, loop)
```
클립은 `0x6e28c` 가 `MC_mediaCreateClip`(스텁 0x14004b8, API 0x4b0)으로 만들어 `p[0xc]` 에 넣고,
콜백 `0x6e404 → 0x6e3b0(p, ev)` 이 **이벤트 3** 을 받았을 때 `0x6e360` 이 stop·close·destroy 하며 0 으로 지운다.
`0x6e258 stop` 은 `MC_mediaStop`(스텁 0x1400528, API 0x4bd)만 쏘고 `p[0xc]` 는 안 지운다 — 그래서 끊은 뒤에도
플랫폼이 이벤트를 줄 때까지 한두 틱을 기다린다.

**`play` 도 절반은 예약이다.** `0x6ea6c` 는 들어오자마자 `str r1(−1),[r0,#0x30]` 으로 **예약 칸을 지우고**(0x6ea7c),
`0x6e9d4` 가 `ldr r3,[r0,#0x14]`(파일 버퍼가 이미 물려 있음) 이면 그 소리를 멈추고 **false** 를 준다(0x6e9e8~0x6ea02).
그러면 `0x6eaba` 가 스스로 `0x6e498` 을 불러 예약으로 떨어진다.

> **정리 — 두 통로의 차이는 "기다림" 이 아니라 "한 틱" 이다.**
> `play` = 통로가 완전히 비어 있으면 그 틱에, 아니면 끊고 다음 틱에.
> `request` = 무조건 끊고 다음 틱에.
> 한 틱 안에서 몇 번을 부르든 **마지막 번호만 들리고 앞엣것은 잘린다.** 예: 볼넷 v3 은 같은 틱에
> `play(24)` 뒤 `request(29)` 를 부르므로(0x51ad8 → 0x51b02) **원본에서도 24 "Base on balls!" 가 29 함성에 잘린다.**
> 앞 판 웹 메모의 "원본은 24 가 다 울린 뒤 29 를 잇는다" 는 오독이었다.
> → 웹판은 통로가 하나라 뒤 소리가 앞 소리를 끊는데, 그것이 **이미 원본과 같은 결과**다.
> `SoundPort.request` 를 따로 두어도 들리는 것은 변하지 않는다 (2026-09, 넣지 않기로 함).

**덤 — 배경음 자동 복귀는 원본에서 죽어 있다.** 틱 `0x6eb18` 은 "비반복 소리가 끝났으면 `+0x48 = 지금틱 + obj[0x4c]`
를 걸고, 그 시각이 지나면 `+0x28` 배경음을 다시 튼다"(0x6eb30~0x6eba8). 그런데 `obj[0x4c]` 는 생성자 인자이고
앱 초기화 `0x2f1c` 가 **0** 을 넘긴다(`movs r3,#0`) → `0x6eb32 cmp r3,#0; beq` 로 늘 건너뛴다.
곧 원본의 배경음 복귀는 전부 손으로 부르는 `0x6eaf0 resumeBgm`(27곳)뿐이다.
(같은 자리 `0x2f24~0x2f28` 이 `obj[0x47] = 1` = 진동 허용을 쓴다.)

### 1-B. 이벤트 스크립트의 사운드 명령 (확정)
r_event/s_event 스크립트 해석기 0x8cf64 는 명령 종류(레코드 [0])로 점프표 0xd4ec0(9칸)을 탄다. **종류 6 = 사운드**(0x8d470):
`n = 레코드[4] − 1`, `loop = n ∈ {1,3,4,0x28,0x21,0x2e,0x2f,0x34,0x2c}` (= 1,3,4,40,33,46,47,52,44), loop 가 아니면 먼저 stopBgm(0x6e438).
```
8d47a: ldrb r3,[r3,#4] ; subs r4,r3,#1 ; cmp r4,#1 / #3 / #4 / #0x28 / #0x21 / #0x2e / #0x2f / #0x34 / #0x2c → r5=1
8d4a6: (loop 아님) bl 0x6e438 ; 8d4b4: r1=r4, r2=-1, r3=r5 → bl 0x6ea6c
```
→ 이 목록이 원작이 **배경음으로 취급하는 번호 전체**다 (47 은 파일이 없다).
events.json 의 `op:'sound', id` 는 원시 바이트라 **파일 번호 = id − 1**. 쓰이는 id(횟수): 2(2) 6(4) 7(1) 8(7) 11(1) 12(10) 19(1) 28(1) 29(13) 31(1) 33(12)
34(50) 35(108) 36(15) 41(21) 43(10) 45(11) 47(15) 49(1) 51(40) 52(16) 53(5) 61(1) 62(27) 63(8).
종류 5(0x8d456) 는 `op:'effect'` — 레코드[4] 를 this+0x2c4 에 넣고 0x8ceac 호출 (연출 번호, 2장 참고).

### 1-C. 파일 포맷 (확정 — 청크를 직접 파싱)

### 1-D. 웹 재생 변환 경로 (확정 — 실제로 52개 전부 변환 성공)
- **ffmpeg 은 안 된다**: 8.x 의 `mmf` 디먹서는 ATR(ADPCM 전용) 파일만 받고 MTR 이 있으면 "MIDI like format found, unsupported" 로 거부 (52개 모두 거부 확인).
- **WildMIDI master (0.5.1 개발판, 커밋 58b6662, 2026-08-20)** 에 SMAF 지원이 들어 있다: `src/smaf2mid.c`(악보→SMF), `src/f_smaf.c`, `src/mafm.c`(야마하 MA FM 합성 +
  ADPCM, `-DWANT_MAFM=ON`, akustikrausch/yamaha-smaf-player 의 Apache-2.0 FM 코어를 이식). 안정판 0.5.0 에는 없다.
  - 빌드: `cmake .. -DWANT_MAFM=ON -DCMAKE_BUILD_TYPE=Release && make` (scratchpad/snd/wildmidi/build)
  - 렌더: `wildmidi -O -o out.wav NNN.mmf` → **52개 모두 소리 있는 WAV** (scratchpad/snd/wav/, 길이·최대음량 snd/durations.txt).
    Mtsu 에 커스텀 음색이 있으면 FM 합성, 없으면(스트림형) Mtsp 파형을 원래 속도로 튼다. `-O` 는 GM 폴백을 OPL3 로 (cfg 불필요).
  - MIDI: `wildmidi -x out.mid NNN.mmf` → 52개 모두 SMF 생성 (snd/mid/). 다만 **스트림 ADPCM 샘플형은 53바이트짜리 음 하나뿐**이라 MIDI 로는 쓸모없고,
    FM 악보형도 프로그램 번호가 커스텀 음색 번호라 GM 신스로 틀면 다른 악기가 난다. → **MIDI 경로는 권하지 않는다.**
  - 귀로 원작과 대조하지는 못했다 (FM 재현 정확도는 WildMIDI 문서도 "M5 fidelity work remains" 라고 적음) → 음색 충실도는 **유력**.
- **권장 경로**: 빌드 도구로 52개를 WildMIDI(MAFM)로 한 번 렌더 → ogg/mp3 로 줄여 public/ 에 두고 WebAudio 로 튼다. 배경음은 loop, 효과음은 1회.
  (브라우저 안에서 SMAF 를 직접 합성하려면 mafm.c 를 wasm 으로 옮겨야 한다 — 가능하지만 비용 큼.)
  스트림형만이라면 야마하 ADPCM 디코더(70줄, WildMIDI `yamaha_adpcm` 동등)로 직접 풀어도 된다.

### 1-E. 진동 (확정)
- 플랫폼: WIPI 스텁은 .data 에 16바이트씩 `str lr,[sp,-4]! ; bl 디스패처 ; .word 0x1fb ; .word API번호`. 진동 = 스텁 0x1400538 (API 0x4c1),
  사운드 객체 틱 0x6eb18 이 `0x4c1(100, obj+0x38)` 로 쏘고 +0x38 을 0 으로 (6eb66 `movs r0,#0x64 ; ldr r3,=0x1400538`). 즉 세기 100, 길이 = +0x38 ms.

> **정정 (62 / 20 — "특수 모드" 는 오독).** `0x1552d0c` 는 모드 플래그가 아니라 **경기 상태 구조체
> 포인터**이고, 0x51b36 이 보는 두 칸은 **이번 플레이의 아웃 종류**다.
> ```
> 00051b36: ldr r3,[pc,#0x9c] ; [0x51bd4] = 0x1552d0c
> 00051b38: ldr r2,[r3]       ; 경기 상태 구조체
> 00051b3a: ldrb r3,[r2,#0x1f] ; cmp #0 ; bne 0x51b4a → 62
> 00051b42: adds r3,#0x87 ; ldrb r3,[r3] ; cmp #0 ; beq 0x51bd8 → 20
> ```
> - `state[0x1f]` = **바운드 없이 잡은 아웃**. `0xb2774 strb r0,[r3,#0x1f]` 이 바로 앞 호출의
>   반환값이 1 일 때 쓴다(0xb276e `cmp r0,#1`). 0xb67fe 초기화, 0xb323c·0xb33b6 이 튕길 때 0.
> - `state[0x87]` = 아웃 판정 `0xb36d0` 의 결과가 **3**(태그성, `0xb3940 cmp r1,#3` → `0xb394e`)
>   이거나 **2 이면서 야수 `+0x3b`**(루에 닿아 있음, `0xb4302`~`0xb4312`) 일 때 선다.
>
> **보탬 — `state[0x87]` 은 "한 번이라도" 가 아니라 "마지막 판정" 이다 (확정, 직접 뜸).**
> `0xb36d0` 은 머리에서 **부를 때마다 이 칸을 지운다**: `b36d2 ldr r3,[r0,#0x28]` · `b36d8 adds r3,#0x87`
> · `b36dc strb r2(=0),[r3]`. 그리고 그 함수는 `b43cc`(이 플레이의 야수 `0xb0c90` 이 `+0xe0`(공 쥠))
> 조건 아래 **매 틱** 돈다. 그런데도 값이 어긋나지 않는 까닭은 **읽는 때**에 있다 —
> ```
> b4540: ldr r1,[sp,#0x34] ; cmp #0 ; beq …   ; **이번 틱 vt90 결과**가 0 이 아닐 때만
> b4546: state[0x1f] 면 플레이+0x12b = 1
> b4556: movs r4,#0xd ; str r4,[sp,#0x38]     ; 결과 코드 **13**
> b4562: vt44(13) · vt54(13) → 판정 스위치 0x51a94 의 v = 13
> ```
> 곧 결과 코드 13 은 **아웃이 난 바로 그 틱의 끝**에 같은 틱 안에서 화면까지 간다. 그래서
> `0x51b36` 이 보는 `state[0x87]` 은 늘 **그 아웃을 낸 판정의 값**이고, 아웃이 안 난 틱의
> 지우기는 아무도 읽지 않는다. (웹처럼 콜을 플레이 끝에 한 번만 내는 구현은 "마지막 아웃을 낸
> 판정이 태그였나" 로 옮기면 된다.)
>
> 그리고 **v11 은 조건 없이 62** 다(0x51b20 → 0x51b2e `movs r1,#0x3e`). 그 v11 을 내는 자리는
> `0x9d5e2~0x9d600` — **파울 + `(s8)state[4] > 1`(2스트라이크) + `(s8)state[0x13] != 0`(번트 종류)**
> → 판정 11 = 아웃. 즉 **2스트라이크 번트 파울 아웃**이다.
> 정리: **62 = 잡아서·태그해서 낸 아웃 + 번트 파울 아웃**, **20 = 루에서 잡은 포스 아웃**.

> **v9 가 서는 자리 (0xb442a~0xb444a).** 그 루의 야수가 `+0x3b`(루에 닿아 있음)이고 `+0xe0`(공을 쥠)
> 인데 아웃 판정 `0xb36d0` 이 서지 않고 주자가 들어오면 `0xb444a movs r3,#9`.
> 즉 **"아웃 될 뻔했는데 살았다"** 만이고, 외야로 나간 안타는 야수가 루에서 공을 쥔 상태가 아니라
> 이 길이 아니다.

같은 함수 0x51408 의 다른 호출: 0x51604 **9** / 0x51620 **5** / 0x51630 → 0x39304() 참이면 **59** 아니면 **6** (한 꼬리 0x5160a·0x51642),
0x5199c·0x519c4 예약 **10**, 0x51fd2 예약 **30**(옆 0x51fc4 에 60), 0x5231a **15**, 0x52392 **14**, 0x523a6 **26**,
0x522aa/0x522b6/0x522c2 진동 300/200/100 (값 3/2/1). 0x524c0: 예약 **10**(0x5268c), **11**(0x527ce), **25**(0x5284a), **60**(0x52bb2, **인플레이 수비 화면 0x528b0**).

> **정정 (함성 60 — "모드 7 홈런더비" 도, "경기 상태 0x18·0x19·0x1a" 도 아니다).**
> `0x528b0` 은 홈런더비가 아니라 **인플레이 수비 화면(경기 상태 0x17)** 이다 (R10 2-1 표의
> "플레이 끝(0x528b0 쪽 0x52a52)"). 그리고 두 자리가 부르는 `0x357e0` 은 경기 상태가 아니라
> `[경기+0xfd4] − 0x18 ≤ 2`, 즉 **타구 결과 코드가 24~26(홈런성)인가** 다 —
> `+0xfd4` = 결과 코드는 E 2-1a · R15 9-1(0x392c2 에 같은 줄) · R2 3-3 이 확정해 둔 칸이다.
> - `0x51fc4` — 결과 코드가 홈런성이면 **60**, 아니면(그리고 [sp+0xec]==0) **30**.
> - `0x52b62~0x52ba4` — 공 `+0xaa0`(낙구 틱) == `+0x68`(지금 틱) && 공 `+0xac4`(낙구점이 홈에서
>   10274 넘게 떨어진 페어 타구, P2 2절) && 결과 코드가 홈런성이 **아님** && 플레이 `+0x113`
>   (낙구 틱에 아무도 못 잡음, P2 2절 0xb4492) → **60**.
>   즉 **외야 깊숙이 페어로 날아간 타구가 아무도 못 잡고 떨어지는 틱의 함성**이다. 홈런은 60 이 아니라 11.

### 1-F2. 17 · 29 · 30 · 38 · 62 호출지 전수 (직접 뜸 — 2026-09)

**뜨는 방법.** 게임 코드는 `0x6ea6c`/`0x6e498` 을 **직접 `bl` 하지 않는다**(전수 스캔: 0x6ea6c 로 오는 bl 3곳,
0x6e498 로 오는 bl 1곳, 전부 사운드 객체 안쪽이다). 대신 리터럴 풀에 `0x6ea6d`/`0x6e499` 를 담아 두고
`ldr r4/r3, [pc,#…]` 로 읽어 **레지스터 호출 베니어 `0xca9fc`(r4로 호출) · `0xca9f8`(r3으로 호출)** 를 탄다.
그래서 호출지 전수는 **리터럴 풀 전수 → 그 풀을 가리키는 `ldr` 전수** 로 뽑아야 한다. 결과:
`play(0x6ea6c)` **47곳** · `request(0x6e498)` **18곳** · `vibrate(0x3a44)` 9곳 · `resumeBgm` 27곳 · `stop(0x6e418)` 15곳 ·
`stopBgm` 4곳 · `setVolume` 2곳. (같은 방법으로 `0x3a45`·`0x6eaf1` 도 나온다.)

**17 — 자리는 하나뿐이다 (확정).** 위 65곳(play+request) 둘레에서 `movs r1,#0x11` 은 **0x51c3a·0x51c50** 뿐이고
둘 다 판정 v9(0x51c14)의 두 갈래다. 다른 `#0x11` 세 곳(0x515bc·0x38e14·0xa1ebe)은 소리가 아니라
각각 `0xbfbad(...)`·그리기 인자·선수 vtable +0x44 의 인자다. **도루도 같은 길**이다 —
도루 키 0x583 → 플레이 종류 9(0x3e07e) → 상태 0x17 → 플레이 틱 0xb43cc 안 0xb442a 에서 v9 가 선다.

### 2-A. 필살기 그림 고르기 0x47cc8 (확정)
타석이 바뀔 때 슬롯 게임+0x1034/+0x103c 의 이전 그림을 해제(vtbl+4)하고 새로 적재(0xb9719).
- **타자**: r7 = 0xb63a1(타자) = 마선수 순번(0~4, 아니면 −1). 점프표 0xd01a8:
  0 → ace/medica_effect · 1 → effect/effect_frame · 2 → effect_power · 3 → effect_tornado · 4 → effect_meteor
  (타자 마선수 순서는 0x78ab0 의 batter_medica·kao·roze·death·tiger → 메디카만 전용, 나머지 넷은 일반 그림을 나눠 씀 — 유력)
- 일반 타자: 필살타법 바이트 [선수+0x18]: 1 → effect_power(파워 스윙) · 2 → effect_frame(**플레임**, 파일명 오타) · 3 → effect_tornado · 4 → effect_meteor (0x47ec0~0x47f0a). 0 이하면 없음.
- **투수**: 늘 effect/effect_pitcher 를 먼저 올리고, 마선수(0xb633d)면 순번 표 0xd01bc: 0 psyker · 1 leony · 2 bbmachine · 3 (0x480e4, 조건 뒤 ballantine) · 4 dragona.
  일반 투수: 마구 바이트 [선수+0x18]: 1 → effect_fire(파이어 볼) · 4 → 0xb6e25 거짓이면 effect_shinning(샤이닝 볼). 웨이브·썬더·캐넌·미라지는 effect_pitcher 만.
- 웹판: `/usr/bin/grep -rl effect_ src` 결과 없음 → 필살기 연출 그림 미사용.

## 3. 장비 외형 스프라이트 item_bat_* / item_pit_* (확정 — 0x78fd8 / 0x79790 디스어셈)
- 두 함수는 선수 그림 객체 vtable 의 슬롯 5(+0x14): 타자 vtable 0xd3a34 [0x789a1, 0x789b9, 0x78ab1(몸 적재), 0x78cf9, 0x78cfd, **0x78fd9**], 투수 vtable 0xd3cd8 [.., 0x793b1, .., **0x79791**].
  인자 `(obj, 부위, n)`: 부위 0 머리 · 1 손 · 2 몸 · 3 다리, **n = 그 부위 장비의 등급 순번 0~10** (n<0 이면 벗김). obj+0x3e+부위 에 n 을 적어 둔다.
  팔레트 인자(b9719 의 넷째 인자) −1 = 그림 기본색.
- **아이템 번호 → (부위, n)** (StrITEM 순서, 부위마다 11개씩 — 이름 표와 파일 수가 딱 맞는다, 매핑 자체는 유력: 호출지에서 아이템→n 변환 식은 미확인):
  | 편 | 부위 | 아이템 번호 | 예 |
  |---|---|---|---|
  | 타자 | 0 머리 | 0~10 헬멧 | 나이스 헬멧 … 천상의 헬름 |
  | 타자 | 1 손 | 11~21 배트 | … 광휘의 배트 |
  | 타자 | 2 몸 | 22~32 밴드 | **그림 없음** (0x7907c `cmp r6,#2 → 끝`) |
  | 타자 | 3 다리 | 33~43 슈즈 | … 이카로스슈즈 |
  | 투수 | 0 머리 | 44~54 모자 | … 로얄 크라운 |
  | 투수 | 1 손 | 55~65 글러브 | … 황금의글러브 |
  | 투수 | 2 몸 | 66~76 아대·선글라스·스카우터·사신의 눈·오페라마스크 | n ≤ 6 이면 그림 없음, 7~10 만 item_pit_body_7~10 |
  | 투수 | 3 다리 | 77~87 신발 | … 황제의 신발 |
- **파일 규칙** (n = 0~10):
  | 부위 | n ≤ 6 | n ≥ 7 | 칸 |
  |---|---|---|---|
  | 타자 머리 | `item/item_bat_head_{n}.pzx` | 같음 | +0x1c |

  | 타자 다리 | `item_bat_leg_0.pzx` + `item_bat_leg_0.mpl` 줄 n−1 | `item_bat_leg_7.pzx` + `item_bat_leg_7.mpl` 줄 n−8 | +0x28 |

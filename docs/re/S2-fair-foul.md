## 요약

**U-01 · U-02 둘 다 확정으로 닫았다.**

**U-01 페어/파울 문턱**: `0x9d660` 은 12바이트짜리 순수 함수로, **각도 하나만** 본다.
`a > 0 이면 a −= 360` 으로 정규화한 뒤 `(unsigned)(a + 135) <= 90` 이면 페어, 아니면 파울.
곧 **−135 ≤ a ≤ −45(양끝 포함)이 페어**다. 좌표·거리·폴 접촉은 이 함수에 없다 —
폴(`state[0x80]`)과 담장(`0x36140`, −135 < a < −45 로 **양끝 제외**)은 각각 따로 판정한다.
웹 `battedBallOutcome.ts` 의 `FAIR_ANGLE = {45, 135}`(양끝 포함)는 부호만 뒤집힌 **같은 식**이다(웹 주석의 "추정" 을 떼도 된다).
덤으로 바로 앞 함수 `0x9d640`(`−145 ≤ a ≤ −35`, `state[0x7]`)도 같이 풀었고,
`state[0x1c]` → `0xb68dc` → `0x9d5bc` 경로에서 **"2스트라이크 번트 파울 = 아웃(코드 11)"** 규칙을 찾아
E-10 1d 와 L 노트가 "경기/이닝 끝" 으로 적어 둔 `0xb68dc`·결과 7 을 **"파울"** 로 정정했다.

**U-02 2아웃 득점 보류**: **P2 의 서술이 방향이 반대였다.** 메시지 `0x13` 은 보류가 아니라
**"득점 1 올려라"**(화면 `0x51fb8` → `0xa5c34` 가 점수 칸 +1)이고, **보류는 메시지를 안 보내고 `state[0]` 만 올리는 쪽**이다.
보류 조건은 `0xaa0a8` 안 `0xaa164~0xaa1c0`: **아웃 ≥ 2 && 공이 땅에 닿은 플레이(`state[0x1e]`) &&
0번 주자(타자주자 칸)가 "살아서 어느 루로 가는 중" 이 아님**(목표 루 ≤ 0 · `+0x98` 꺼짐 · `+0x96` 아웃 중 하나).
푸는 곳은 같은 함수의 꼬리 `0xaa34c`: 진행 중인 주자가 없거나 타자주자가 무사하면,
**`state[6](아웃) > 2` 가 아닐 때만** 보류분을 메시지 `0x13`(주자번호 `0x64`)로 한 번에 내보내고 `state[0] = 0`.
3아웃이면 영영 안 풀고, 다음 플레이 초기화 `0xb67d0` 이 `state[0] = 0` 으로 지운다 → **득점 무효**.
`state[0]` 이 "이번 플레이 득점 수" 라는 P2 의 추측도 함께 정정된다(= 보류 득점 개수).

**남은 것**: 파울 코드 7 이 스트라이크를 어디서 올리는지(점프표 `0xd0488` 의 7 가지)는 안 봤다.
`0xaa05c` 가 부르는 주자 vt `+0x18`(멈춤 여부로 보임)의 내부도 안 읽었다. 둘 다 이번 주제 밖이다.

**다른 노트에 반영할 정정 3건**: ⓐ P2 7절 "웹 45~135 양끝 포함 ↔ 원본 양끝 제외" → 페어/파울 자체는 **일치**.
ⓑ P2 5b "메시지 0x13 으로 보류" → **0x13 은 득점, 보류는 `state[0]`**. ⓒ E-10 1d·L 183 의 `0xb68dc`/결과 7 → **파울**.

## ① 페어/파울 문턱 — **확정**

### 1-1. `0x9d660` 전문 (12바이트짜리 순수 함수)

```
0009d660: push {lr}
0009d662: cmp   r0, #0
0009d664: ble   0x9d66a
0009d666: ldr   r3, [0x9d67c]   ; = 0xfffffe98 = -360
0009d668: adds  r0, r0, r3      ;   a > 0  ->  a -= 360
0009d66a: adds  r3, r0, #0
0009d66c: adds  r3, #0x87       ;   t = a + 135
0009d66e: movs  r2, #0
0009d670: cmp   r3, #0x5a       ;   t vs 90
0009d672: bls   0x9d676         ;   *** 부호 없는 비교(BLS) ***
0009d674: movs  r2, #1
0009d676: adds  r0, r2, #0
0009d678: pop {r1} ; bx r1
```

즉 **`foul = 0x9d660(a)`** 이고 식은

```
if (a > 0) a -= 360;              // 각을 (-360, 0] 으로 정규화
return  (unsigned)(a + 135) <= 90  ?  0 /*페어*/  :  1 /*파울*/;
```

부호 없는 비교라 `a + 135 < 0`(= `a < -135`) 은 큰 수로 감싸여 자동으로 파울이 된다. 따라서

> **페어 ⇔ −135 ≤ a ≤ −45 (양끝 포함)**, 그 밖은 파울. 가운데(중견 방향) = −90, 좌선 = −135, 우선 = −45.
> 정규화 때문에 `a = 225 / 270 / 315` 도 각각 −135 / −90 / −45 와 같다.

**문턱은 오직 각 하나다.** 좌표(거리)·폴 접촉·담장은 이 함수에 전혀 들어오지 않는다 — 좌표와 폴은 별도의 두 판정(아래 1-3)이다.

### 1-2. 호출부 3곳 (`re xref 0x9d660` → 리터럴 `0x9d661`)

| 리터럴 | 호출 함수 | 하는 일 |
|---|---|---|
| `0x513dc` | `0x51108` (화면 쪽 타구 시작), 호출 `0x511b8` | `state[0x1c] = 0x9d660(각)` — **타구의 최초 페어/파울 판정** |
| `0xb1b08` | `0xb1900`, 호출 `0xb191e` | 수비 AI 쪽 |
| `0xb32e0` | `0xb3148`(튕김 처리), 호출 `0xb326c` | 바운드할 때마다 `state[0x1c]` 갱신 (P2 6절 "튕김 0xb3272") |

인자는 `ldrsh r0, [r5, #0]` — **부호 있는 16비트 각도(도)** 다 (r5 = [sp+0x98] = 공 객체의 각 칸, P2 가 말한 화면+0xfcc 와 같은 값).

```
000511b0: ldrb  r3, [r4, #0x19]      ; state[0x19] (0.1% 특수사건)
000511b2: cmp   r3, #0
000511b4: bne   0x511d0              ;   서 있으면 페어 판정 자체를 건너뜀
000511b6: ldr   r5, [sp, #0x98]
000511bc: ldrsh r0, [r5, r6]         ; r6=0  → 각
000511be: bl    0x9d660
000511c2: strb  r0, [r4, #0x1c]      ; state[0x1c] = 파울?
000511c6: ldrsh r0, [r1=0 → r5]      ; 같은 각
000511ca: bl    0x9d640              ; 넓은 판정(아래)
000511ce: strb  r0, [r4, #7]         ; state[0x7]
```

### 1-3. 같은 자리에 있는 **두 번째 각 문턱** `0x9d640` — 확정 (보너스)

바로 앞 함수 `0x9d640` 이 같은 각을 받아 `state[0x7]` 에 들어간다. 식은 같은 꼴인데 폭만 다르다.

```
if (a > 0) a -= 360;
return  (unsigned)(a + 145) <= 110  ?  1  :  0;      ; adds #0x91 / cmp #0x6e / bhi
```

> **−145 ≤ a ≤ −35 이면 1**. 페어 쐐기를 양쪽으로 **10도씩 넓힌** 범위다 (파울선 근처까지 포함).
> `state[7]` 은 이 직전 `0x511ae` 에서 기본값 1 로 세워지고, `state[0x19]==0` 일 때만 이 값으로 덮인다 —
> "타구가 그라운드 쪽(=수비가 쫓을 만한 방향)인가" 로 보인다(뜻은 **유력**, 식 자체는 확정).

### 1-4. 각 문턱 세 가지를 한자리에 (여기서 정리)

| 쓰이는 곳 | 범위 | 양끝 |
|---|---|---|
| **페어/파울** `0x9d660` → `state[0x1c]` | −135 ≤ a ≤ −45 | **포함**(선 위 = 페어) |
| 넓은 판정 `0x9d640` → `state[0x7]` | −145 ≤ a ≤ −35 | 포함 |
| 담장/필살수비 `0x36140` (P2 6절) | −135 < a < −45 | **제외** — 선 위는 폴(`state[0x80]`)로 따로 |

세 개가 서로 다르다는 점이 중요하다. **정확히 ±45·±135 선 위의 타구는 `0x9d660` 기준으로는 페어이지만, 담장 판정에서는 홈런이 아니라 "폴 맞음"(`state[0x80]`)으로 빠진다.** P2 6절이 적은 폴 충돌(튕김 ±25·속도 ½)이 그 경로다.

### 1-5. 웹판 비교 (고치지 않음)

`src/entities/batting/model/battedBallOutcome.ts:22,36` — 페어 판정을 `45 ≤ angle ≤ 135`(양끝 포함)로 한다.

- **양끝 포함은 원본과 같다** (P2 7절이 "웹은 포함, 원본은 제외" 로 적어 둔 것은 담장 판정 `0x36140` 과 비교한 것이고, 페어/파울 자체인 `0x9d660` 과는 **일치**한다). → P2 7절 그 줄은 이번 결과로 정정된다.
- 각 부호만 반대다: 원본 −135…−45 ↔ 웹 45…135. 같은 90도 쐐기이고, 웹에는 `a>0 → a−360` 정규화가 없다(웹 각은 이미 0~180 으로 만들어진다).
- 웹에 없는 것: `state[0x7]`(±10도 넓힌 판정), 선 위 폴 충돌, 그리고 **바운드마다 다시 페어/파울을 매기는 것**(`0xb3148`). 웹은 타구 시점에 한 번만 판정한다.

**확인**: 웹 주석(`battedBallOutcome.ts:17-19`)이 "원본은 저장할 때 a 를 음수로 뒤집는다(`0xb0614`)" 고 적어 둔 그대로다.
원시각 `w>>23` 이 45…135 → 저장될 때 부호가 뒤집혀 −135…−45 → `0x9d660` 이 페어로 본다.
**따라서 웹의 `FAIR_ANGLE = {45, 135}` 양끝 포함 판정은 원본 `0x9d660` 과 정확히 같다(추정이 아니라 일치).**
같은 파일 윗부분 주석 "페어 범위 45~135 는 원시값 분포로 확인한 것" 은 이제 디스어셈으로 뒷받침된다.
웹이 근사인 부분은 페어/파울이 아니라 그 **뒤의 속도 문턱(800/950/…)** 뿐이다.

## ② 2아웃 득점 보류 (메시지 `0x13`) — **확정** (P2 의 설명을 뒤집는다)

### 2-0. 먼저: **P2 의 "메시지 0x13 으로 보류" 는 방향이 반대다**

메시지 `0x13` 은 **보류가 아니라 "득점을 실제로 올려라"** 는 통지다. 보류는 메시지를 **안 보내고** `state[0]` 만 올리는 쪽이다.

- 수신자: `[주자목록+4]` = **경기 화면 객체**. 보내는 방법은 `obj->vtable[0xc](obj, msg, a, b)` — 중계 함수 `0xbfbac` → `0xbfb78` (`ldr r4,[r4,#0xc]`).
- 화면 쪽 분기(`0x50a76`): `cmp r2,#0x13 / bne / bl 0x51fb8` → **처리처는 `0x51fb8`**.
- `0x51fb8` 이 마지막에 하는 일: `r0 = 화면+0x230(팀/경기 ctx); bl 0xa5c34`.
  `0xa5c34` 는 `[ctx+0xc+공격팀*4] + 0x27c + 8` 을 **+1**(98 에서 멈춤) — **점수판의 득점 칸**이다.
  ```
  000a5c4a: ldr  r3, [r2, #8]
  000a5c4e: cmp  r3, #0x62        ; 98
  000a5c50: bgt  0xa5c56
  000a5c52: adds r3, #1
  000a5c54: str  r3, [r2, #8]
  ```
  → **메시지 0x13 = 득점 1 올리기.** (그 앞에서 인자로 받은 주자 번호 i 가 주자 수보다 작으면 그 주자의 `+0x95`(득점)·`+0x96`(처리끝) 도 세운다. `i = 0x64` 로 보내면 주자 표시 없이 점수만 올린다 — 아래 2-3 의 해제 경로가 그렇게 쓴다.)

### 2-1. 보류 판단 — `0xaa0a8`(주자 목록 틱) 안, 주자가 홈에 닿았을 때

주자 루프는 **index = 개수−1(가장 앞선 주자) → 0(타자주자)** 순으로 돈다(`0xaa0ce`: `r1 = [r6+0xc] − 1`).
홈 도착 처리에서:

```
000aa15e: ldr   r4, [r6, #4]       ; 화면. 없으면 0xaa1de (아무것도 안 함)
000aa164: ldr   r2, [r6, #0x10]    ; state
000aa166: movs  r3, #6
000aa168: ldrsb r3, [r2, r3]       ; state[6] = 아웃 수
000aa16a: cmp   r3, #1
000aa16c: ble   0xaa1b0            ; 아웃 <= 1  →  바로 득점(msg 0x13)
000aa16e: ldrb  r3, [r2, #0x1e]    ; state[0x1e] = 공이 땅에 닿은 플레이
000aa170: cmp   r3, #0
000aa172: beq   0xaa1b0            ; 땅볼 플레이 아님 → 바로 득점
000aa174: bl    0xa9ac4(list, 0)
000aa180: beq   0xaa18e
000aa182: bl    0xa9564(list, 0)   ; 0번 주자
000aa18a: cmp   r5, r0
000aa18c: beq   0xaa1b0            ; 득점한 주자가 0번(타자주자) 자신 → 바로 득점
000aa18e: r0 = 0xa9564(list, 0);  r2 = r0 + 0x78
000aa19a: ldr   r3, [r2, #0x14]    ; r0+0x8c 목표 루
000aa19e: ble   0xaa1c0            ; 목표 <= 0      → ★보류
000aa1a4: ldrb  r3, [r0+0x98]      ; 이번 타석 타자주자인가
000aa1a8: beq   0xaa1c0            ; 아니면        → ★보류
000aa1aa: ldrb  r3, [r2, #0x1e]    ; r0+0x96 아웃
000aa1ae: bne   0xaa1c0            ; 아웃이면      → ★보류
000aa1b0: 화면->msg(0x13, i, 0)    ; 바로 득점
000aa1be: b     0xaa1d6
000aa1c0: r0 = 0xa9564(list, i); [r0+0x78+0x1d] = 1   ; 주자 +0x95 = 득점 표시만
000aa1ce: r2 = state; state[0] += 1                    ; ★보류 개수 +1
000aa1d6: 0xa9520(list, i)         ; 두 경로 모두 주자를 목록에서 뺀다
```

정리하면 **보류(= `state[0]` 증가, 점수판은 그대로)** 조건은

> `아웃 ≥ 2` **그리고** `state[0x1e]`(공이 땅에 닿은 플레이) **그리고**
> `0번 주자(타자주자 칸)가 "살아서 어느 루로 가는 중" 이 아닐 것`
> (= `목표 루 ≤ 0` 이거나 `+0x98`(이번 타석 타자주자) 가 꺼졌거나 `+0x96`(아웃) 이 섰다)
>
> 그 밖에는 전부 **즉시 득점**(메시지 `0x13`).

즉 **"2아웃에 땅볼로 타자주자가 먼저 아웃되면"** 이 정확히 `+0x96 != 0` 가지다.

### 2-2. `state[0]` = 보류 칸 — **확정**

- 타석/플레이 초기화 `0xb67d0` 이 `state[0] = 0` 으로 지운다 (`000b67ea: strb r3, [r0]`, r3=0) → 보류는 플레이 단위로 리셋된다.
- 해제할 때 `state[0] = 0` 으로 되돌린다(`0xaa3ba`).
- 따라서 P2 가 "state[0] += 1 = 이번 플레이 득점 수로 보임(유력)" 이라고 적은 것도 **정정**된다:
  `state[0]` 은 플레이 득점 누계가 아니라 **아직 점수판에 안 올린 보류 득점 개수**다.

### 2-3. 보류를 푸는 곳 — 같은 틱 함수 `0xaa0a8` 의 꼬리 `0xaa34c` — **확정**

주자 루프가 끝난 뒤(index < 0 → `0xaa0d8: b 0xaa34c`) 곧바로 실행된다.

```
000aa34c: n = (int8)state[0];  if (n <= 0) return;
000aa358: r4 = 0xa9564(list, 0)            ; 0번 = 타자주자 칸
000aa364: bl 0xaa05c(list)                 ; "아직 정리 안 끝난 주자가 있나"
000aa36c: beq 0xaa386                      ;   없으면 곧장 아웃 검사로
000aa372: if (r4+0x96 != 0)   return;      ;   타자주자가 아웃  → 계속 보류
000aa378: if (r4+0x8c <= 0)   return;      ;   목표 루 없음     → 계속 보류
000aa380: if (state[0x1e]==0) return;      ;                    → 계속 보류
000aa386: r2 = state
000aa388: if ((int8)state[6] > 2) return;  ; ★ 3아웃이면 영영 안 푼다 = 득점 무효
000aa390: if ((int8)state[0] <= 0) goto 0xaa3b6
000aa39a: do { 화면->msg(0x13, 0x64, 0); } while (++r5 < (int8)state[0]);

```

- `0xaa05c(list)` = "주자 중에 `+0x96`(끝) 이 안 섰고, `+0x94`(요구 루 미이행) 이 섰거나 `vt+0x18`(멈춤?) 이 거짓인 놈이 하나라도 있나" → **아직 진행 중인 주자가 있나**.
- **핵심 한 줄: `0xaa388 cmp r3,#2 / bgt` — 아웃이 3이 되면 보류된 득점을 절대 풀지 않는다.**
  `state[6]` 은 살아 있는 아웃 카운트다(R10 2절: 메시지 3 "3아웃" 이 `st[6] = 3`).
  3아웃이 되면 플레이가 끝나 틱 자체가 더 안 돌고, `state[0]` 은 다음 플레이 초기화 때 `0xb67d0` 이 지운다 → **득점 무효**.
- 해제 때 주자 번호로 `0x64`(=100) 를 쓴다. 화면 처리기 `0x51fb8` 이 `번호 >= 주자수` 면 주자 표시 단계를 건너뛰므로(`0x51ffc: cmp r1,r0 / bge 0x5201a`) **점수만 n 번 올린다.**

## ①-보너스. `state[0x1c]`(파울) 이 어디로 흘러가나 — **확정**, E-10 1d 를 한 칸 정정

`0x9d660` 의 결과 `state[0x1c]` 는 **플레이 끝 판정 `0x9d5bc` 의 "파울로 끝" 가지**가 된다.

```
0xb68dc(state):                      ; E-10 이 "경기/이닝 끝" 으로 적어 둔 함수
   if (state[0x19] && (s8)state[4] > 1) return 0;
   if (state[0x1f]) return 0;        ; 뜬공 포구
   return state[0x1c];               ; ← 페어/파울 판정 그대로
```

```
0x9d5bc 안(0x9d5e2~0x9d600):
   if (0xb68dc(state)) {             ; = 파울
       if ((s8)state[4] > 1  &&  (s8)state[0x13] != 0)  return 11;   ; ★
       return 7;
   }
```

- `state[4]` = **스트라이크 수**, `state[0x13]` = **번트 종류**(P7 B1·Q1 3절: 화면 `+0xfdc` 에서 옮겨 옴, 0 이면 번트 아님).
- R2 7절 판정 글자표: **v = 7 → FOUL(그림 6·7, 음성 25)**, **v = 11 → OUT(그림 35~38, 음성 62)**.
- 따라서 이 두 줄은 **"2스트라이크에서 번트를 파울로 만들면 삼진 아웃"** 규칙이다 (코드 11 = 아웃).
  일반 타구의 파울은 코드 7 → 글자 FOUL 만 띄우고 스트라이크는 이 경로에서 올리지 않는다.
- **E-10 1d 정정**: `0xb68dc` 를 "경기/이닝 끝" 으로, 결과 7 을 "경기/이닝 끝" 으로 적어 둔 것은 잘못이다.
  `0xb68dc` = **"이 타구가 파울로 끝났나"**, 결과 7 = **파울**, 11 = **2스트라이크 번트 파울 아웃**이다.
  (L-sound 183 줄의 "7 경기/이닝 끝" 도 같은 이유로 "7 파울" 로 읽어야 한다. 음성 25 = "Foul!" 과도 맞는다.)
- 웹판: `battedBallOutcome.ts` 는 파울을 `{kind:'파울'}` 로만 돌려주고 **2스트라이크 번트 파울 아웃이 없다**
  (번트 코드 6~8 은 `case 6` 에서 곧장 희생번트 아웃, `case 9` 는 무조건 파울).

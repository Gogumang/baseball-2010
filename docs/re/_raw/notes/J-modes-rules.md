## 1. 일반모드 준비 흐름 · 히든 팀 · 구장

### 1-1. 히든 5팀 오픈 조건 — 확정(코드 경로) / 유력(+0x144 뜻)
팀 번호 10~14 = 대한민국·일본·쿠바·미국·외인구단 (teams.ts). 오픈 플래그 = `[0x1400054]→0x1f1d8()(= obj+0xac 포인터) + 0x7a + (팀−10)` 바이트.
- 히든 팀 오픈 함수 `0x65de4(this, k)` (k=0..4): 이미 1 이면 0 반환, 아니면 +0x7a+k = 1, 저장(0x1f1b9), 팝업 StrCOMMON[138] "히든 팀 오픈!! [%s]" + StrCOMMON[k+10](팀 이름).
  ```
  65df4: adds r0,r6,r0 ; adds r0,#0x7a ; ldrb r3,[r0] ; cmp r3,#0 ; beq → 65e0a: movs r3,#1 ; strb r3,[r0]
  65e28: movs r1,#0x8a (StrCOMMON 138) ... 65e30: adds r1,r6,#0 ; adds r1,#0xa (팀 이름)
  ```
- 부르는 곳 둘 — **국가대항전 경기 뒤**:
  - `0x19f30` = 나만의리그 상태 134(국가대항전 경기, B 노트) / `0xe684` ← `0xe9ac`(시즌모드 흐름).
  - 두 곳 다 같은 모양:
  ```
  e696: movs r1,#0 ; bl 65de5            ; 대한민국(k=0)은 국가대항전에 나가기만 하면 오픈
  e6a8: ldrb [리그+0x144] ; cmp #0xa ; bne 끝   ; +0x144 == 10(대한민국) 일 때만
  e6b6: r1 = s8 [리그+0x12e] ; cmp #0xa ; bne → r1 = s8 [리그+0x12f]
  e6ca: subs r1,#0xa ; bl 65de5          ; 결승 상대(11 일본·12 쿠바·13 미국) 오픈
  ```
  +0x144 = 국가대항전 우승 팀, +0x12e/+0x12f = 결승 두 팀으로 읽힌다(유력 — 쓰는 곳은 안 봤다). 즉 **대한민국이 우승하면 결승에서 이긴 나라가 열린다**.
  힌트 문구와 맞는다: 226 "당신은 국가대표!"(대한민국: 대표 선발만), 227 "라이벌을 물리쳐라!"(일본), 228 "아마최강을 넘어서라!"(쿠바), 229 "메이저를 넘어서라!"(미국).
- **외인구단(14)** — `0x7a690` 안 0x7b408: `for i in 0..9: if byte[저장+0x30+i]==0 → 중단`; 10명 모두 열려 있으면 `0x62368(obj, 12, 0)` (열기 id 12 = 히든 팀 k=4).
  저장+0x30..0x39 는 마선수 오픈 바이트(열기 함수 0x620b8: id≤3 → +0x31+id, 4..7 → +0x32+id). → **마선수 10명 전부 오픈 = 외인구단** ("마선수 총출동!", 230).
  0x7a690 이 어느 화면인지(마선수 선택 화면 유력)는 미확인.
- 열기 id 체계(0x620b8, 확정): 0..7 마선수(StrCOMMON 140), **8..12 히든 팀(+0x7a+id−8, StrCOMMON 138)**, 13 이상 아이템(139). 이벤트 보상 종류 8("팀 오픈") 을 쓰는 r_event 는 **없다**(events.json 전수 확인) → 팀 오픈은 위 두 코드 경로뿐.
- 힌트 화면 `0x14114`: 커서 팀(k=[+0x70]+0xc)의 오픈 바이트가 1 이면 StrMODE[225]+[226+k]+[1]("일반모드에서 사용할 수 있습니다"), 0 이면 [225]+[226+k]+[0]("선택 할 수 없는 팀입니다")+[1] 팝업. 나만의리그/시즌 등 **일반모드 밖 팀 선택에서 히든 팀은 늘 못 고른다**(유력: 이 함수가 0x106 장면 쪽).
- 웹판: 히든 팀 개념 없음. 리그 상대 10팀만(RALPH 493). 국가대항전 자체도 없음(B 노트).

### 1-2. 빠른실행 무작위 규칙 — 확정 (0x314b0 앞부분, 경기 장면 0x104 쪽)
경기 설정 레코드 = `[this+0x120]+0xbc` 16바이트. 빠른실행 표시(this+0x14c ≠ 0)일 때 이렇게 채운다:
```
31500: r0=저장 ; bl 0x9f5a0 → [rec+0] 유저 팀     31512: bl 0x9f5a0 → [rec+4] AI 팀 (같은 함수 두 번, 같은 팀 재추첨 없음)
3151a: bfa55(0,2) != 0 → [rec+8] = 1 (선공/후공 50%)
3152e: strb 유저팀 → [rec+0xc] (구장 = 유저 팀 번호)      31538: bl 0x9f650 → [rec+0xe] 마투수   31546: bl 0x9f604 → [rec+0xd] 마타자
```
- `0x9f5a0(저장)`: 목록 = 팀 0..9 + (저장+0x7a+k ≠ 0 인 히든 10+k), `bfa55(0, 개수)` 로 **균등** 선택.
- `0x9f650`: 저장+0x30..0x34(마투수 5명 오픈 바이트) 중 열린 것 균등. 하나도 없으면 표 0xd7638[0] = −1(없음).
- `0x9f604`: 저장+0x35..0x39(마타자 5명) 같은 방식. (마선수 열기 id 0..3 → +0x31.., 4..7 → +0x36.. 이므로 +0x30·+0x35 가 처음부터 열린 기본 마선수로 보인다 — 유력.)
- 이어서 +0xf4 = 0, this+0x154 = 20.
- **같은 팀끼리 경기가 나올 수 있다**(재추첨 코드 없음). 구장은 유저 팀 번호를 그대로 쓴다.
- 웹판: 일반모드 준비 화면 없음(검색 0건). 차이 = 전부 없음.

### 1-3. 구장 그림 (hidden_board / hidden_fence) — 확정(파일 선택) / 유력(아이템 대응)
로더 `0x76ba4(구장객체, 시즌여부)`:
- 시즌여부 0 → `stadium/fence.pzd` + `fence.pzf` (기본 구장).
- ≠0 → s8 [obj+0x88] ≤ 3 이면 `fence.pzd`+`fence_season.pzf`, >3 이면 `hidden_fence_(v−4)` (0x76c40~0x76cb4, `subs r1,#4`).
  s8 [obj+0x8a] ≤ 3 이면 `fence_board.pzx`, >3 이면 `hidden_board_(v−4)` (0x76cf0~0x76d2a).
- StrITEM 126~132 관중석 7종(1~4단 관중석 · **트로피컬·콜로세움·스페이스**), 133~139 전광판 7종(소형~초대형 · **내추럴·고대의·싸이키**), 140~143 잔디 4종.
  → +0x88 = 관중석 번호, +0x8a = 전광판 번호, 4~6 = 히든 3종 = hidden_fence/board_0~2 (유력). 즉 **hidden_* 그림은 일반모드 구장 선택이 아니라 시즌모드 구장관리 히든 아이템**이다.
  히든 관중석·전광판 오픈 힌트 StrITEM[249] "나는야 관중석 컬렉터", [252] "전광판 컬렉터" (보통 4종을 다 사면 열림 — 타자 장비 컬렉터와 같은 방식, 유력).
- 부르는 곳: 0x5f3c, 0x7958, 0x957c(시즌 구장관리 화면 쪽), 0xe4d0, 0x352e8(경기 장면), 0x5fd04.
- 웹판: `stadiumScene.ts` 는 구장 0 고정(RALPH 805 "구장 0"). hidden_* 참조 0.

## 2·4. 경기용 능력치 `0xb570c(팀레코드, 칸, 선수, 적용플래그, …, [sp+0x24] 체력, [sp+0x28] 팀보정플래그)` 의 시즌·팀 부분 — 확정
(G 노트가 나만의리그 부분을 풀었다. 아래는 같은 함수의 나머지.) 팀레코드 = s16 [+0 팀번호, +2 사기, +4 투구, +6 타격, +8 집중, +0xa 근성].
XlsTEAM_DATA 열 = [번호, 100, 투구, 타격, 집중, 근성] 과 같은 모양(100 = 시작 사기, 유력).
`0xb6278(선수)` = 투수인가 (아래 팀 능력치 대응이 설명서와 딱 맞아서 확정으로 본다). 칸: 투수 0 제구·1 구속·2 변화·3 체력 / 타자 0 히트·1 파워·2 수비·3 주루.

### 2-1. 보직 불일치 수비 −20% (시즌모드 판정) — 확정
0xb5844~0xb58a4, 모드(0x1552d10)==2 이고 **내 팀 선수**(시즌+1 == 팀레코드+0) 일 때만:
```
if !투수 && 칸==2 && !스킬비트21(0xb62b4(p,0x15) = [p+0x14]>>21&1, "모든 포지션 수비 가능") :
   pos = [p+0x1c] & 0xf ; if pos<=1 || pos==10 → 면제
   bar = [p+0xb] & 3 (0xb6704)
   bar==0 && pos∈2..6 → 면제 ; bar==1 && pos∈7..9 → 면제
   그 밖 → v += v/(−5)          ; b5898: movs r1,#5 ; rsbs r1,r1,#0 ; bl ca7b5 ; adds r4,r4,r0
```
- bar 0 = 내야(포수·유격·1루·2루·3루, StrMODE[4]), 1 = 외야. bar 2 이상(유력: 지명타자 계열)은 2~9 어디든 −20%. pos 0·1·10 은 벌점 없음(투수·미배치·지명 계열로 보임, 유력).
- **마타자 면제**: `0xb6278` 이 [p+0xa]&0x60==0x60 이나 id 0xb4..0xc7 도 참으로 본다 → 마선수·특수 id 는 "투수" 쪽으로 빠져 벌점을 안 받는다(유력: 설명서 "마타자는 페널티 없음" 과 맞음).
- **이 코드는 모드 2(시즌)에만 있다.** 설명서는 일반·대전도 벌점이 있다고 하지만 0xb570c 에서 모드 0·1·8·9 는 이 분기를 건너뛴다. 일반/대전 벌점은 다른 곳에 있거나 없다 → **미해결**(다른 곳에서 `v/−5` 꼴을 찾지 못했다: 0x51690·0x66e92·0x7570a 는 다른 용도).
- 웹판: 보직 벌점 없음 (엔트리 조정 화면 자체가 없음).

### 2-2. 시즌 팀 상태 보정 — 확정 (같은 분기)
- 팀 질병: s8 [시즌+6] > 0 이면 `v += (−30·v)/100` (0xb5824~0xb5842). (나만의리그 질병 −30% 와 같은 식.)
- 팀 사기(팀레코드+2) **정액 감소**: >50 없음 · 31~50 −50 · 11~30 −100 · ≤10 −200, 0 아래로는 0 (0xb58ac~0xb58e4). 나만의리그의 비율 감소(−10%/−20%/−50%)와 다르다.

### 4-1. 팀 능력치 4종 → 선수 능력치 — 확정 (0xb592c~0xb5a14)
조건: 팀보정플래그 [sp+8] ≠ 0 이고 모드 ∈ 비트마스크 0x306 = {1, 2, 8, 9}(일반·시즌·대전 두 가지, 모드 1 = 일반 유력).
| 선수 | 칸 | 팀 능력치 |
|---|---|---|
| 투수 | 1 구속·2 변화 | 투구(+4) |
| 타자 | 0 히트·1 파워 | 타격(+6) |
| 투수 0 제구 / 타자 2 수비 | | 집중(+8) |
| 투수 3 체력 / 타자 3 주루 | | 근성(+0xa) |
식: `T≠0 이면 v += (17·T − 5100) / 100` (0 쪽 버림) = **0.17 × (T − 300)**.
```
b5a04: lsls r0,r3,#4 ; adds r0,r0,r3 (17T) ; ldr r3,=0xffffec14 (−5100) ; adds ; movs r1,#100 ; bl ca7b5 ; adds r4,r4,r0
```
예: 330(게임빌즈 투구) +5 · 400 +17 · 500 +34 · 600 +51 · 666(외인구단) +62. T<300 이면 감소.
- 설명서 "팀의 모든 선수 능력치에 일정 비율 영향" = 이 식. 팀 능력치는 XlsTEAM_DATA 열 2~5(시즌에서는 트레이닝으로 오른 값).
- 이어서 투수 & 스킬비트14 & 칸≠3 & [시즌+0x6b] > 4 & 0xb6a4d(시즌) == 0xb6be9(시즌, 팀번호) 이면 +10% (뜻 미해독).

```
if 연차idx(+0xb3) != 9 : return −1          ; 10년차에만
k = s8 [시즌+0x7a]  (우승 횟수, 유력 — 최대 10 과 비교하므로 연도당 1회 세는 값)
pop = 0xb6e79(시즌) (인기도)
pop > 2000 && k == 10 → 4 "역사상 최고의 구단"
pop > 1500 && k > 6   → 3 "세계 일류 구단"
pop > 1000 && k > 3   → 2 "한국 최고 구단"
pop > 800             → 1 "지역 인기 구단"
그 밖                  → 0 "비 인기 구단"
→ StrENDING[15 + 결과]
```
- 순서대로 먼저 맞는 것. 우승 없이도 인기도 801 이상이면 "지역 인기 구단".
- s_event 500("시즌모드 10년은 모두 종료", 보상 종류 21) 이 엔딩 진입 트리거. 부르는 곳: 위 xref.
- 웹판: 없음.
- 엔딩 보너스 G (0x6b3c, StrMODE[214] "엔딩 보너스 획득 [%d G포인트]"): 표 `0xcbc2e`[결과] × 1000 G. (값은 아래 줄 참고)
  값 s8 [0, 3, 6, 9, 12] → 비 인기 0 · 지역 3000 · 한국 6000 · 세계 9000 · 역사상 12000 G. (지급 코드 뒤쪽은 안 읽음 — 문구·곱셈까지 확정)

### 4-9. 구장관리 아이템 — 확정(표) / 유력(가격 단위)
아이템 상점 0x83378 (시즌모드 & 탭 [+0x1a4]==4 = 구장 아이템):
| 종류 r7 | 이름(StrITEM) | 효과 표 0xd44f4 [7·r7+k] | 가격 표 0xd44c4 [8·r7+k] |
|---|---|---|---|
| 0 관중석 | 126~132: 1단·2단·3단·4단·트로피컬·콜로세움·스페이스 | 수용 [20,25,30,35,40,40,40]×1000명 ("%d명 수용 가능") | [0,200,500,800,1000,1000,1000] |
| 1 전광판 | 133~139: 소형·중형·대형·초대형·내추럴·고대의·싸이키 | 관중 +[0,2,3,4,5,5,5]×1000 ("관중 +%d") | [0,100,400,700,900,900,900] |
| 2 잔디 | 140~143 | 설명 문구만(StrITEM[144+k]) — 수치 효과 없음 | 표 행 0 (따로 있는지 미확인) |
- 경기 계산이 쓰는 표는 0xd7cc4 (4-7) 로 같은 값의 사본이다. 저장: 시즌 +0x1b8 관중석, +0x1b9 전광판, +0x1ba 잔디 (0x71494 대전 업로드가 세 바이트를 복사).
- 가격 단위는 소지금과 같은 100만으로 보인다(→ 2억·5억·8억·10억). 0번(1단·소형)은 기본 무료.
- 구매 뒤 StrMODE[184] "자동으로 적용되며 [구단관리]-[구장관리] 에서 교체".
- 히든 4~6 은 그림 hidden_fence/board_0~2 (1-3).

### 2-3. 경기진행 설정 — 저장 형식 확정 / 경기 루프 반영 확정(뜻 일부 유력)
**설정 화면**: 키 처리 0x5ffcc, 저장→화면 복사 0x5fef4, 화면 객체 +0x2bc..+0x2c3. 모드 칸 m = 전역 0x1552ad8
(0x3301c: 게임모드 2(시즌) → 1, 8·9(대전) → 2, 그 밖(일반=1 포함) → 0). 확인 시(0x60376~) 저장(0x1f1d8)에:
| 저장 위치 | 내용 |
|---|---|
| +0x12c+m (s8) | 종류: 0 찬스 · 1 이닝 · 2 상세 |
| +0x146+m (s8) | 찬스/이닝 선택값 |
| +0x120+2m (u16) | 상세 타자조작: 타순 비트 0..8 |
| +0x124+2m (u16) | 상세 투수조작: 이닝 비트 |
| +0x128+m (u8) | 상세 공격주자: 베이스 비트(1·2·3루) |
| +0x12a+m (u8) | 상세 수비주자: 베이스 비트 |
**경기 루프 판정** `0xc1e04(경기)` — 지금 장면을 사람이 조작하나(점프표 0xd90c0, 상황 [상태+1]−1 = 0..8). 결과 [sp+0xc]: 0 = 사람이 조작, 1 = 자동.
```
종류 0 찬스: 값 0 → 베이스 마스크 6(2·3루), 값 ≠0 → 마스크 4(3루)
            주자가 있고(0xa9599) 마스크 베이스에 주자(0xa97a1(b, i+1))가 있으면 조작, 아니면 자동   ; c1f52~c2014
종류 1 이닝: 값 0 → 늘 조작(전체) · 값 1 → 이닝idx [상태+0x6b] > 2 부터(4회~) · 값 2 → > 5 부터(7회~)   ; c2016~c2046
종류 2 상세(공격): 타순비트(현재 타자 타순 0xae85d ≤ 8) 가 켜졌거나, 공격주자 비트 베이스에 주자가 있으면 조작   ; c2050~c20f0
            (수비): 투수조작 비트[이닝idx] 또는 비트 8(연장으로 보임, 유력), 수비주자 비트 베이스에 주자 있으면 조작 ; c2110~
```
- 즉 [이닝] 3이닝/6이닝 = **7회부터/4회부터 직접 플레이**(앞 이닝은 자동 진행). 값 1·2 가 화면의 어느 문구인지는 화면 쪽 문자열을 안 봐서 유력.
- 찬스 두 가지 = "득점권(2·3루) 주자" / "3루 주자" 상황만 플레이 (유력: 마스크 값에서 읽음).
- 상세 최소 한 항목 검사 StrMAINMENU[126](0x60240), 확인 [125].
- 이 판정은 일반(m=0)·시즌(m=1)·대전(m=2) 공통. 설명서는 일반·시즌에서만 설정 가능하다고 한다.
- 웹판: 없음(경기는 항상 전부 조작).

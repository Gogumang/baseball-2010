## 요약
**풀린 것 (확정)**: 칭호 64개 모두의 원본 판정식·시점·저장 위치가 나왔다.

## 2. 문자열표·표시 위치
- 0xf684: `this+0x168 = 표(StrNICKNAME)`, 그리고 `[this+0xe0]+0x170` 에도 복사 (this+0xe0 = 0x7b7b8 생성 창 객체, 크기 0x398 = 선수정보/아이템·스킬 창). 확정 (0xfb30~0xfb60).
- 0x2407c: 다른 장면(0x103 계열) `[sp+4]+0x130` 에 로드. 확정.
- **표시 0x7d5cc (창 함수 0x7d34c)** — 확정:
  ```
  7d5d0: r5 = win+0x170 (StrNICKNAME)      ; 없으면 건너뜀
  7d5dc: r3 = [win+0x150] (선수) ; r4 = s8 [선수+0x1c4]
  7d5ea: if r4 < 0 → 안 그림
  7d5ee: if r4 <= 0x1f → 번호 r4
         else if 타자편(0x7b970) → r4  else → r4 + 0x10
  7d60a: 0x702b4(표, 번호)
  ```
  → **장착 칭호 = 선수+0x1c4 (s8, −1 = 없음)**. 저장값 32~47 은 타자편이면 그대로(32~47), 투수편이면 +16 (48~63) 으로 읽는다.
  → 투수 칭호도 비트·장착값은 **32~47 을 공유**하고 이름·조건만 48~63 을 쓴다.

## 3. 저장 위치 — 확정
| 함수 | 뜻 | 근거 |
|---|---|---|
| 0xa4088(선수, i) | i>63 → 0; 아니면 `(u64 [선수+0x178] >> i) & 1` | `movs r1,#0xbc; lsls #1` → +0x178, lo/hi 두 워드를 0xcaa60(64비트 시프트)로 |
| 0xa40b8(선수) | i=0..63 에서 0xa4088 참인 개수 | 루프 `cmp r4,#0x3f` |
| 0xa40e0(선수, i, on) | on≠0: `[선수+0x178] \|= 1<<i` 그리고 **기록연감 비트** 도 OR — 전역 [0x1400054]+0xc8 객체의 타자편(모드 4) +0xe4..+0xeb, 투수편(모드 3) +0xec..+0xf3 (바이트 단위 u64). on=0: 비트 해제(0xa421e 경로, 선수 비트만) | 0xa40f2~0xa41fc |
| 선수+0x1c4 s8 | 장착 칭호 (새 선수 = −1, 0x11292) | 0x11290~0x11296 |
| 관리 장면 this+0x270 s8 | 이번에 줄 칭호 번호 (−1 = 없음) | 0x1a1d4, 0x1b234 |
| 관리 장면 this+0x274 u32 | 판정 트리거 카운터 (=1 인 갱신에서만 판정) | 0x1af90~0x1afc2 |
- 0xa40e0 호출지는 0x1b1e4 하나뿐 → **칭호가 실제로 들어가는 곳은 팝업 확인 콜백 하나** (아래 4절).
- 기록연감 비트는 타자편/투수편 따로 64비트씩 (게임 전체 저장 객체). 모드 2(시즌)·그 밖이면 기록연감에 안 쓴다.

## 4. 판정 시점·부여 흐름 — 확정
- **판정 함수 0x1a1c0(관리 장면 this)**. 호출지는 0x1afac 하나 (관리 장면 갱신 함수 0x1aec4 끝):
  ```
  1af90: r4 = this+0x274 ; if [r4] != 1 → 건너뜀
  1af9c: r5 = this+0x270 ; if s8 [r5] < 0 → bl 0x1a1c0 (판정)
  1afb0: if s8 [r5] >= 0 → bl 0x1274c (팝업)
  1afbe: [r4] += 1
  ```
- this+0x274 = 0 은 장면 진입 0x11c64 에서. → **나만의리그 관리(메인) 화면에 들어올 때마다 두 번째 갱신 프레임에서 한 번 판정**. 경기 뒤·시즌 전환 뒤·이벤트 뒤 등 관리 화면으로 돌아오는 모든 때가 판정 시점이다. 판정 중 별도 "시즌 끝" 분기는 없고, 연차·경기 수 조건(+0xb3/+0xb2)으로 시점을 좁힌다.
- 0x1a1c0 은 칭호 번호 순서대로 `아직 비트 없음(0xa4088(선수,i)==0) && 조건` 을 검사해 **처음 맞는 하나만** this+0x270 에 쓰고 끝난다 (0x1a77a `strb r3,[r7]` 공통 출구). 맞는 게 없으면 −1 그대로.
- 팝업 0x1274c: `0x741a0(팝업관리자 [0x140005c], 종류 0x78, 그리기 0x1d5dc→0x1afe8, 키 0x1d5e8→0x1b1e4, this)`.
  - 그리기 0x1afe8 (0x1b052~0x1b082): 번호 i ≤ 31 이거나 모드(this+0xcc)==4(타자편) → 이름 StrNICKNAME[i], 조건 문구 [i+64]. 투수편이고 i>31 → 이름 [i+16], 조건 [i+80]. 확정.
- 확인 키 콜백 0x1b1e4 (키 −5 또는 0x35 = 확인/5):
  ```
  1b1f6: 0x742a8 (팝업 닫기)
  1b20c: 0xa40e0(선수, i, 1)       ; 비트 + 기록연감 비트
  1b214: 선수+0x1c4 = i            ; ★ 얻는 즉시 자동 장착
  1b224: 0x1fdec([0x1400054])      ; 저장
  1b22a: 0x22754([0x1400054], 1)
  1b234: this+0x270 = −1 ; this+0x274 = 1  ; → 다음 프레임에 다시 판정 (여러 개를 연달아 얻을 수 있다)
  ```
- 결론: 칭호는 한 번에 하나씩, 번호가 작은 것부터 팝업으로 주어지고, 확인하면 곧바로 장착된다. 투수편 칭호도 번호(비트·장착값)는 32~47 이다(판정 쪽도 7·8절에서 재확인).

## 10. 표시·장착·기록연감 규칙
### 10-1. 칭호 목록·장착 (관리 장면 하위 상태 129) — 확정
- 목록 만들기 0x104cc (디스패처 0x1cdec 의 0x1cf68 에서): this+0x16c 의 s32[64] 를 −1 로 채우고, i = 0..63 에서 `0xa4088(선수,i)` 이면 차례로 넣는다. 개수 this+0x26c. 목록 객체(this+0xa4)에 개수·한 화면 줄 수 min(개수, 9) 설정. → **얻은 칭호를 번호 오름차순으로** 보여 준다(얻은 순서가 아님).
- 그리기 0x198fc (그리기 스위치 0xcc884 칸 28 → 상태 0x65+28 = 129): 이름 = StrNICKNAME[i] (i > 31 이고 투수편이면 i+16, 0x19abe~0x19ad4), **지금 장착한 것(선수+0x1c4 == 목록값)** 을 다른 색으로 칠한다(0x19ae8~0x19af6).
- 키 처리 0x11f78 (갱신 스위치 0xcc7e0 칸 27):
  ```
  키 −5 / 0x35(확인·5): sel = list[(쪽·쪽당 + 커서)]           ; 11fa8~11fc2

  그 밖: 목록 객체 키 처리(커서 이동)
  ```
- 이 화면으로 들어오는 키가 [선수정보]→[기본정보] 의 `#` 이라는 것은 StrHOWTO[15] 원문("[선수정보] -> [기본정보]에서 (#) 키로 확인 및 변경")으로 붙였다 — **유력**(# 키 → 상태 129 전환 분기는 찾지 않음).

# R1. 하루치 CPU 리그 경기 0xc2a48 승패 판정 재확인

## 체크리스트
- [x] 1. score(side) 가 읽는 칸(state+0x7e+slot) · side 함수 0xb7844/0xb7845 대응 · 원정/홈 slot
- [x] 2. 0xc2a48 목록 +8 / +0x1c 가 어느 팀인지 (일정표 0xd89cb 에서 대진 채우는 코드)
- [x] 3. c2ba6 이후 승(0xb76dd)·패(0xb77e1) 대상 끝까지 추적 → 이긴 팀이 승을 받는가
- [x] 4. 포스트시즌 0xc2760 (c28e2~c2916) 과 비교 표
- [x] 5. 웹 leagueDay.ts 현재 동작과 원본대로 옮길 때 순위표 차이
- [x] 6. 요약·판정

## 요약
**확정: 원본 0xc2a48 의 CPU 끼리 정규시즌 경기 승패는 뒤집혀 있다 (원본 코드 버그).** score 칸·side 대응을 끝까지 따라갔다:
side(t)=0xb7844 가 1 인 팀이 A목록(+8)·경기 칸 1(st+0x29)·홈(말 공격)이고 득점은 st+0x7f 에, 0 인 팀이 B목록(+0x1c)·칸 0·원정이고 득점은 st+0x7e 에 쌓인다.
c2ba6 은 `원정 득점 > 홈 득점` 일 때 **홈(A)** 에 0xb76dd(승)·원정(B) 에 0xb77e1(패)를 주고, 아니면 반대 → 늘 진 팀이 승을 받는다(상대전적 +0x44 도 같이 뒤집힘, 동점이면 원정 승).
같은 준비·점수·승패 함수를 쓰는 0xc2760 은 `score(X) > score(Y) → X 승` 으로 정상이라, 목록 포인터를 엇갈려 넘긴 실수 하나로 설명된다.
점수 자체(+0x30 원정, +0x44 홈)는 바르게 저장·복사(c2c14)된다. 내 팀 경기는 이 루프를 타지 않아 영향 없음.
웹 `leagueDay.ts:87-89` 는 "원정 득점 > 홈 득점 → 원정 승, 아니면 홈 승" 으로 **버그를 고친 쪽**과 같다(원본을 그대로 옮기려면 winner/loser 를 맞바꿔야 함 — 옮길지는 결정 사항).
남은 것: 뒤집힌 순위가 화면에서 실제로 어떻게 보였는지(실기 확인), 0xb7844 의 라운드 반전(`날짜>22`)을 웹이 쓰지 않는 점.

## 중간 기록 (항목 1·2 진행 중)

### 목록 채우기 0xc2a48 첫머리 (c2a5c~c2ade) — 확정
- r6 = 하루치 경기 객체. `memset(r6+8, 0xff, 0x50)` (0x1400428) → A목록 r6+8[5], B목록 r6+0x1c[5] 를 −1 로.
- 팀 t=0..9, 칸 k=0..4: t 가 이미 A[k]/B[k] 에 있으면 다음 팀. 빈 칸(A[k]==−1)을 만나면
  `side = 0xb7845(league,t)`; side==1 → A[k]=t, B[k]=0xb765d(league,t) / 아니면 B[k]=t, A[k]=0xb765d(league,t).
  (c2ab2~c2aca: 팀은 r6+{side1:8, side0:0x1c}+4k, 상대는 r6+8+(side*5+k)*4 = 반대 목록 → 교차 저장)
- 0xb765d(league,t) 정규시즌 = `표 0xd89cb[(날짜 % 9)*10 + t]` (날짜 = (s8)league+0x32, 0xca911 = 나머지) = **t 의 상대**.
- 0xb7844(league,t) 정규시즌 (b7868~b78f4): d=(s8)league+0x32, r7 = (d/9)&1 (0xca7b5), d>0x16 이면 r7 = !r7.
  행 d%9 에서 `표[행][i]==t` 인 i<t 가 있으면(= t 가 짝 중 번호 큰 쪽) 반환 r7, 아니면 !r7. → **짝의 두 팀은 늘 반대 값** (확정).
  → **A목록(+8) = side 1 팀, B목록(+0x1c) = side 0 팀.**
- score 함수 0xb69b0(state, s) = `(s8)state[0x7e + s]` — 인자는 side 값 그대로 칸 번호.
- 경기 뒤 (c2b80~c2bca): `[r6+0x30+4k] = score(st, side(B)=0)` = state+0x7e, `[r6+0x44+4k] = score(st, side(A)=1)` = state+0x7f.
  `cmp [0x30], [0x44]; ble c2bba` → scoreB > scoreA 이면 `0xb76dd(league, A[k])`(r2 thunk 0xca9f4=bx r2) 뒤 `0xb77e1(league, B[k])`;
  아니면 `0xb76dd(league,B[k])`, `0xb77e1(league,A[k])`.

### 항목 1 — 팀이 앉는 칸과 점수 칸이 같은 번호 (확정)
- 0xc239c(sim, a1, league, A[k], B[k]) (c23d4~c2458, 0xc2b66 에서 호출):
  `sA = 0xb7845(league,A)` (r6), `sB = 0xb7845(league,B)` ([sp+0x14]).
  `0xb6c19(st,sA,1)`, `0xb6c2d(st,sA,날짜%4)`, **`0xb6bd5(st,sA,A)`** / 같은 셋을 sB·B 로.
  0xb6bd4 = `strb 팀, [st+0x28+s]` → **A 팀 = st+0x29, B 팀 = st+0x28.** (다른 곳에서 0xb6bd5 를 부르는 CPU 경기 코드는 c2c4c 뿐 — 도중에 칸을 바꾸지 않는다)
- 공격 팀 0xb6bf8 = `st[0x28 + st[9]]`, 수비 팀 0xb6c08 = `st[0x28 + st[0xa]]`.
- 득점 0xb6a9c(st, s): 점수판 `st+0x6c+(이닝%9)*2+s` ++, **`st+0x7e+s` ++** (99 상한). 간이 엔진 호출부 0xc100a·0xc109e 모두 `s = (s8)st[9]` (공격 쪽).
  → 칸 s 에 앉은 팀의 득점이 st+0x7e+s 에 쌓인다. 0xb68fc 끝내기 판정(st[9]=1 말, +0x7f 홈)과 합치면 **칸 0 = 원정(초 공격), 칸 1 = 홈(말 공격)**.
- 따라서 **side(t)==1 → 홈, 0 → 원정**. A목록(+8) = 홈팀, B목록(+0x1c) = 원정팀.
- 점수: `[r6+0x30+4k] = score(st,0)` = **원정 B 점수**, `[r6+0x44+4k] = score(st,1)` = **홈 A 점수**. 대응 어긋남 없음.

### 항목 2 — 대진 (확정)
- 상대 = 표 0xd89cb[날짜%9][팀] (9일 주기 라운드로빈 10팀). 홈/원정 = 짝 중 번호 작은 팀이 `!r7`, 큰 팀이 `r7`,
  r7 = (날짜/9)&1, 날짜>22 이면 반전 → 9일마다 홈·원정이 뒤바뀌고 23일째부터 한 번 더 뒤집힌다.
- 0xc2a48 은 내 팀(arg3, [sp+0x3c]) 이 A 또는 B 에 있는 칸은 건너뛴다(c2af8~c2b04) → CPU 4경기만 돈다.

### 항목 3 — 승·패가 누구에게 가나 (확정: 뒤집혀 있다)
```
c2b8a: r1=r5=sB(0)  → 0xb69b1(st,0) = st+0x7e = 원정 B 득점 → [r6+0x30+4k]
c2b96: r1=sA(1)     → 0xb69b1(st,1) = st+0x7f = 홈 A 득점   → [r6+0x44+4k]
c2ba0: ldr r3,[r4,#0x30] ; r0 = 홈 득점
c2ba6: cmp r3, r0 ; ble c2bba          ; 원정 > 홈 이면 아래로
c2baa: 0xb76dd(league, [sp+0x20]=A[k]) ; ← 홈(진 팀)에 승
c2bb4: 0xb77e1(league, [r7]=B[k])      ; ← 원정(이긴 팀)에 패
c2bba: 0xb76dd(league, B[k]) ; 0xb77e1(league, A[k])   ; 홈 ≥ 원정 → 원정에 승, 홈에 패
```
- 0xb76dd 정규시즌 경로 (b7724: league+0x34==0 → b77a0): `league[t]++`(승), `[t+0xa]++`(연승), `[t+0x14]=max`, `[t+0x28]=0`(연패 끊김),
  `[t*10 + 상대 + 0x44]++`(상대전적 승, 상대 = 0xb765c) → **승 처리**.
- 0xb77e1 정규시즌 경로 (b7812~): `[t+0x1e]++`(패), `[t+0x28]++`(연패), … → **패 처리**.
- 승·패 함수 모두 인자 r1 = 팀 번호 그대로 쓴다(바꿔치기 없음).
- **결론: CPU 끼리 정규시즌 경기는 매번 진 팀에 승, 이긴 팀에 패가 붙는다.** 상대전적(+0x44)도 같이 뒤집힌다.
  동점(연장 상한이 없어 실제로는 안 남)이면 원정 B 승.
- 루프 뒤 c2be0~c2c14: `arg1==2` 이고 정규시즌(league+0xac==0, +0x34==0)이면 `memcpy(0x1f55d()+0x1c0, r6+8, 0x50)` —
  A/B 목록과 점수 두 줄(+0x30 원정, +0x44 홈)을 그대로 저장 → 다른 구장 결과로 보이는 **점수는 제대로**, 순위표 승패만 뒤집힌다(보이는 곳 미확인, 유력).
- 내 팀 경기는 이 루프가 건너뛰므로(c2af8~c2b04) 사람 경기 승패는 이 버그와 무관.

### 항목 4 — 한 경기 루프 0xc2760 과 비교 (확정)
0xc2760 도 같은 준비 함수 0xc239c 를 쓴다 (c28c0: `0xc239c(sim, [sp+0x38], league, X=[sp+0x30], Y=[sp+0x104])` → X 는 칸 side(X), Y 는 칸 side(Y)).
```
c2866: r6 = sX = 0xb7845(league, X)      c2870: [sp+0x20] = sY = 0xb7845(league, Y)
c28e2: r5 = 0xb69b1(st, sX)  = X 득점      c28ec: r0 = 0xb69b1(st, sY) = Y 득점
c28f8: cmp r5, r0 ; ble c290a
c28fc: 0xb76dd(league, X) ; 0xb77e1(league, Y)     ; X 득점 > Y 득점 → X 승  (정상)
c290a: 0xb76dd(league, Y) ; 0xb77e1(league, X)     ; 아니면 Y 승
c291c: 0xb818d(league)  ; 하루 끝
```
| | 0xc2760 (한 경기) | 0xc2a48 (하루치 CPU 4경기) |
|---|---|---|
| 첫 비교값 | score(side(X)) | score(side(B)) → [+0x30] |
| 둘째 비교값 | score(side(Y)) | score(side(A)) → [+0x44] |
| 첫 값 > 둘째 값일 때 승 | **X** (첫 값의 팀) | **A** (둘째 값의 팀) ← 어긋남 |
| 동점이면 승 | Y | B(원정) |
- 두 함수 모두 팀 칸 배치(0xc239c)·점수 읽기(0xb69b1)·승패 함수가 같다. 다른 것은 c2baa/c2bba 의 목록 포인터(A=[sp+0x20], B=r7)가
  비교 순서와 엇갈려 있다는 것 하나 → **원본 코드 실수(뒤집힘)로 확정.** 데이터·해석 문제가 아니다.

### 항목 5 — 웹판과의 차이 (확정)
- `src/entities/league/model/leagueDay.ts:87-89`: `awayRuns > homeRuns ? record(away 승, home 패) : record(home 승, away 패)`.
  원본 0xc2a48: `원정 > 홈 ? (홈 승, 원정 패) : (원정 승, 홈 패)`. → **웹은 이긴 팀에 승, 원본은 진 팀에 승.**
  웹의 규칙은 원본 비교식에서 대상만 바로잡은 모양과 정확히 같다(동점 → 홈 승까지 일치). 원본대로 옮기려면 두 줄의 winner/loser 를 맞바꾸고 동점은 원정 승.
- 순위표 영향(원본대로 옮길 때, 추론): CPU 끼리 경기는 매 경기 결과가 반대로 들어가므로 **강한 CPU 팀일수록 CPU 상대로 패가 쌓인다**.
  내 팀과의 경기(사람 경기 경로)만 바른 결과. 한 시즌 45일(9일 주기 5바퀴)이면 CPU 팀마다 약 40경기가 뒤집혀 기록된다.
  상대전적(headToHead, 원본 +0x44)도 뒤집히므로 순위 동률 기준(E 3e, 0xb79d8)에도 반영된다.
- 홈/원정 배정도 다르다: 웹 `matchupsOf`(leagueDay.ts:29-40)는 번호 작은 팀 = 원정. 원본은 0xb7844: 짝 중 작은 번호가 `!r7`(1=홈),
  r7=(날짜/9)&1, 날짜>22 면 반전. 뒤집힌 판정에서는 홈/원정이 동점(원본엔 없음)과 9회말 생략에만 영향.
- `leagueDay.ts:15-16` MAXIMUM_INNINGS=14 로 동점이 생기는 것은 E-defense-rules 3d 에 이미 적힘(원본은 상한 없음).
- 파일 주석(leagueDay.ts:26-27 "승패 기록에는 영향이 없어")은 웹 규칙에선 맞다. 원본을 옮기면 동점 처리에서만 영향.

### 한 줄 (웹과의 차이)
원본 0xc2a48 은 `원정 득점 > 홈 득점이면 홈 승`(진 팀에 승 — 원본 버그, 0xc2760 은 정상), 웹 leagueDay.ts:87-89 는 `원정 득점 > 홈 득점이면 원정 승`(바로잡힌 쪽).

## 1. 칸과 쓰는 곳 전수 — **확정**

state = `경기+8`. 세 칸 모두 32비트 워드, **측(side) 0/1, 2 = 없음**.

| 칸 | 뜻 |
|---|---|
| state+0x44 / +0x48 | 승리 투수의 **측** / **등번호** |
| state+0x50 / +0x54 | 패전 투수의 측 / 등번호 |
| state+0x5c / +0x60 | 세이브 투수의 측 / 등번호 |
| state+0x64 | 세이브 "종류" 코드 (1 / 3 / 9) — 경기 끝에서 **≤ 0 이어야** 세이브 인정 (5절) |

전수(`all.txt` 전역 `str r?,[r?,#0x44|0x50|0x5c|0x64]` 208+349건을 베이스 레지스터가 `[x,#8]`(=state) 에서 온 것만 걸러 확인):

| 주소 | 하는 일 |
|---|---|
| **0xb6814**(경기 상태 초기화) 0xb682a~0xb682e | +0x44 = +0x50 = +0x5c = **2**(없음). 같은 함수가 +0x69 = **8**, +0x6a = **6**, +0x40 = 0 도 넣는다 |
| **0xa5c34**(1점 들어올 때마다 부르는 득점 처리, CORRECTIONS.md B) 0xa5d36·0xa5d5a | +0x44 무효화 / 재지정 (+0x48 같이) |
| 같은 함수 0xa5d90·0xa5db4 | +0x50 무효화 / 재지정 (+0x54 같이) |
| 같은 함수 0xa5dea | +0x5c **무효화만** (재지정 없음) |
| **0xa60c0**(투수 등판/교체 때) 0xa6150·0xa6162·0xa6168 | +0x5c·+0x60 **지정**, +0x64 = 세이브 종류 |
| **0xa7de8**(경기 끝 기록 반영) | 읽기만 — 0xa7dea~0xa7e02 에서 +0x44/0x48/0x50/0x54/0x5c/0x60 을 한꺼번에 읽는다 |
| **0xa9cfc·0xa9d00·0xa9d54** | state 가 아닌 다른 객체(주자 관리 쪽) — 무관 |

0xa7de8 머리(확정):
```
000a7dea: ldr r3,[r0,#8]      ; state
000a7df2: ldr r1,[r3,#0x48]   ; 승 투수 번호  → [sp+0xc]
000a7df8: ldr r1,[r3,#0x54]   ; 패 투수 번호  → [sp+8]
000a7dfa: ldr r2,[r3,#0x44]   ; 승 측
000a7dfc: ldr r7,[r3,#0x50]   ; 패 측
000a7e00: ldr r1,[r3,#0x5c]   ; 세 측        → [sp+4]
000a7e02: ldr r3,[r3,#0x60]   ; 세 투수 번호  → [sp]
000a7e0e: cmp r2,#2 ; beq ...  ; 측 == 2 면 건너뜀
```

보조 함수: `0xb69b0(state, 측)` = 그 팀 **점수**, `0xae83c(팀객체)` = **지금 마운드 투수의 레코드**(그 +0 바이트 = 등번호), `0xa9598(주자관리)` = **루상 주자 수**, `팀객체 = 경기+0xc+측·4`.

## 2. 승리 투수 — **확정** (0xa5c34, 0xa5cf6~0xa5d6a)

**부르는 시점**: 0xa5c34 는 **한 점 들어올 때마다** 부른다(사람 경기 0x51408 의 0x52096, 간이 엔진 0xc0fb4·0xc1054). 즉 득점이 날 때마다 승·패 투수를 다시 계산한다.

```
0xa5cf6  r3 = s8 state[0x6b]            ; 이닝(0-기준)
0xa5d02  cmp r3,#4 ; ble → 건너뜀        ; 이닝 index ≤ 4 (=5회까지) 면 승리투수 손 안 댐
0xa5d06  r3 = s8 state[0x69] ; cmp #8 ; bne → 건너뜀   ; 정규 9이닝 경기(마지막 이닝 index 8)에서만
0xa5d14  if state+0x44 != 2:            ; 이미 승리 투수가 정해져 있으면
0xa5d1c      r5 = 점수(state+0x44 측) ; r0 = 점수(1 − state+0x44)
0xa5d2e      if r5 <= r0:  state+0x44 = 2   ; 그 팀이 더 이상 앞서지 않으면 지운다
0xa5d38  if state+0x44 == 2:            ; 비어 있으면 새로 정한다
0xa5d44      def = 점수(state[0xa] 수비측), off = 점수(state[9] 공격측)
0xa5d46      if def > off : side = state[0xa]     ; 수비팀이 앞섬
0xa5d52      elif off > def : side = state[9]     ; 공격팀이 앞섬
             else: 그대로 2 (동점이면 아무도 아님)
0xa5d5a      state+0x44 = side
0xa5d5e~     state+0x48 = 0xae83c(경기+0xc+side·4)[0]   ; 그 팀의 지금 마운드 투수 등번호
```

정리하면 **승리 투수 = (6회 이후의 어느 득점 시점에서) 앞서 있는 팀의 그 순간 마운드에 선 투수**. 리드가 뒤집히면 칸을 2로 비우고 다음 득점 때 다시 잡는다. 5회까지의 득점에서는 아예 손대지 않으므로, 6회 이전에 결정 난 경기도 **6회 이후 첫 득점이 있어야** 승리 투수가 정해진다(득점이 전혀 없으면 2 = 없음 그대로).

- 원본에는 **선발 5이닝 요건·구원 승 인계 같은 진짜 규칙이 없다.** 이닝 index > 4 조건이 그 자리를 대신하는 근사다.
- 총 이닝이 9가 아닌 판(홈런더비 등 state+0x69 ≠ 8)에서는 승리 투수를 안 매긴다.

## 3. 패전 투수 — **확정** (0xa5c34, 0xa5d6c~0xa5dc4)

승리 쪽과 같은 함수의 바로 다음 토막인데 **이닝·경기종류 조건이 없다**(0xa5d04·0xa5d12 의 건너뛰기 대상이 아니다). 즉 1회 득점부터 갱신된다.

```
0xa5d6c  if state+0x50 != 2:
0xa5d76      r5 = 점수(state+0x50 측) ; r0 = 점수(1 − state+0x50)
0xa5d88      if r5 >= r0: state+0x50 = 2        ; 지고 있지 않게 되면 지운다
0xa5d92  if state+0x50 == 2:
0xa5d9e      def = 점수(수비측), off = 점수(공격측)
0xa5da0      if def < off : side = state[0xa]    ; 수비팀이 지고 있음
0xa5dac      elif off < def : side = state[9]
             else: 그대로 2
0xa5db4      state+0x50 = side
0xa5db6~     state+0x54 = 그 팀 현재 투수 등번호
```

**패전 투수 = 지고 있는 팀의 그 순간 마운드 투수**(득점이 날 때마다 갱신). 동점이 되면 지운다.

## 4. 세이브 조건 — **확정(식)** (0xa60c0)

**부르는 시점**: 투수 교체·등판 처리(사람 경기 0x51408 의 0x52284 가지, 간이 엔진 0xc262c 의 0xc26a2). 바로 앞 가지 0x52274 는 `0xa60a0` = 그냥 "수비측 현재 투수 레코드 얻기" 라 같은 묶음이다. → **구원 투수가 올라오는 그 순간 딱 한 번** 판정한다.

```
0xa60c0  st = 경기+8
         rem = 3·(s8 st[0x69] − s8 st[0x6b]) − s8 st[6] + 3     ; 남은 아웃 수 (r7)
                 (st[0x69]=8 마지막 이닝 index, st[0x6b]=이닝, st[6]=아웃)
         d  = 점수(st[0xa] 수비측)      ; r5   — 새로 올라오는 투수 팀
         o  = 점수(st[9]  공격측)       ; r4
         [sp]=0(플래그)  [sp+4]=0(코드)
0xa6108  if d <= o: return                       ; 리드 중이 아니면 세이브 상황 아님
0xa610c  gap = d − o
0xa6110  if gap > 3:
0xa6114      if rem > 8 : 코드 = 9, 플래그 = 1    ; 4점 차 이상이면 남은 아웃 9 이상(=3이닝 초과)
         else:                                    ; gap ≤ 3
0xa611c      if rem > 2 : 코드 = 3, 플래그 = 1    ; 남은 아웃 3 이상(=1이닝 이상)
0xa6128  n = 0xa9598(경기+0x14)                   ; 루상 주자 수
0xa6134  if d <= o + n + 2 and rem > 0:           ; 동점 주자가 대기 타석까지 와 있음
0xa613c      코드 = 1 (플래그와 무관하게 덮어씀)
0xa6142  if 플래그 == 0 and 위 조건도 아니면 return   ; 세이브 상황 아님
0xa6148  state+0x5c = st[0xa]                     ; 세이브 후보 = 수비측
0xa6152~ state+0x60 = 그 팀 현재 투수 등번호
0xa6168  state+0x64 = 코드 (1 / 3 / 9)
```

즉 **세이브 요건 세 가지**(실제 야구 규칙 그대로):
1. `점수차 ≤ 3` 이고 `남은 아웃 ≥ 3`(1이닝 이상 남음) → 코드 3
2. `점수차 > 3` 이고 `남은 아웃 ≥ 9`(3이닝 넘게 남음) → 코드 9
3. `점수차 ≤ 루상 주자 수 + 2` 이고 남은 아웃 ≥ 1 (동점 주자가 타석/대기 타석) → 코드 1

무효화: 득점 처리 0xa5c34 의 마지막 토막(0xa5dc6~0xa5dea)이 **세이브 측 팀이 더 이상 앞서지 않으면 state+0x5c = 2** 로 지운다(`cmp r5,r0 ; bgt 건너뜀` → `점수(세이브측) ≤ 점수(상대)` 이면 지움). 재지정은 없다 — 다음 교체 때만 다시 잡힌다.

경기 끝 반영(0xa7e9a~0xa7ed8):
```
if 세이브 측 == 2 → 없음
if 세이브 투수 번호 == 승리 투수 번호 → 없음      ; 0xa7ea0: [sp+0xc](승 번호) vs [sp](세 번호)
if state+0x64 > 0 → 없음                        ; 0xa7eaa
아니면 레코드 +0x24(세이브) += 1
```

### 4-1. **state+0x64 가 0 으로 되돌아가는 곳이 없다 — 세이브가 절대 안 붙는 것으로 보인다 (유력 버그)**
- `+0x64` 에 쓰는 곳은 초기화 0xb6814(+0x40 만 0, **+0x64 는 손대지 않음**)와 0xa6168(1/3/9) 뿐이고, 읽는 곳은 0xa7eaa 뿐이다. 전역 349건의 `str …,[r?,#0x64]` 를 **같은 함수 안 40줄 안에서 베이스가 `[x,#8]`(=state) 로 채워진 것**만 걸러내면 **0xa6168 하나뿐**이다. 감소(`ldr #0x64` → `subs` → `str #0x64`) 패턴도 경기 코드 범위에 없다(0x785b8 계열은 다른 객체).
- 따라서 0xa60c0 이 한 번이라도 돌면 +0x64 는 1·3·9 중 하나로 남고, 경기 끝의 `cmp r3,#0 ; bgt` 에 걸려 **세이브 기록(+0x24)이 올라가지 않는다**. 0xa60c0 이 아예 안 불린 경기라면 +0x64 는 0 이지만 그때는 +0x5c 도 2 라 역시 없음.
- 판정: **유력**. 막힌 고리 = "+0x64 를 0 으로 만드는 코드"를 전 바이너리에서 못 찾았다(레지스터 간접·memset 경유 가능성은 남음). 초기화 0xb6814 가 +0x64 를 안 건드리므로 이전 경기 값이 남을 수도 있다.
- 같은 결의 기존 발견: P1 5-1 "R+0x128(실점) 이 늘 0 이라 완투 승리가 늘 완봉" — 이 게임엔 이런 "쓰는 쪽만 있고 지우는 쪽이 없는" 칸이 더 있다.

## 5. 승계 주자 실점 귀속 — "책임 투수" — **확정**

주자 객체마다 **+0x30 = 그 주자를 내보낸 투수**를 적어 둔다.

**적는 곳**: 주자 생성 `0xa93ac(주자관리, 선수, r2, r3 = 투수 레코드)` 의 끝 (0xa94dc~0xa94ec)
```
000a94dc: ldr r2,[sp,#0xc]      ; r3 로 받은 투수 레코드
000a94de: cmp r2,#0 ; beq       ; 없으면 안 적음(초기값 −1 유지, 0xa9438)
000a94e8: ldrsb r3,[r1,#0xa]    ; 투수 레코드 +0xa = 투수 식별 번호
000a94ec: str  r3,[r2,#0x30]    ; 주자+0x30 = 그 번호
```
호출자는 모두 그 시점의 **수비팀 현재 마운드 투수 레코드**를 r3 로 넘긴다(간이 엔진 0xc1072~0xc108c 가 `[팀+0x78]` 로 현재 투수를 얻어 그대로 넘기는 것을 확인. 다른 호출자 0xa9a5a·0x4650e·0xc119e·0xc1940 도 같은 자리).
주자 승계(교체로 베이스가 옮겨 담길 때) 0xa9db8~0xa9dba 는 `+0x30` 을 **그대로 복사**한다 — 투수가 바뀌어도 책임 투수는 따라간다.

**실점 매기는 곳**: 득점 정산 0xa8ed4~0xa8f04
```
000a8ed6: ldr r1,[r5,#0x30]                 ; 홈 밟은 주자의 책임 투수 번호
000a8ed8: r3 = s8 state[0xa]                ; 수비측
000a8ee2: r0 = 경기+0xc+수비측·4            ; 팀 객체
000a8ee6: bl 0xb8c44(팀, 번호)              ; 레코드 +0xa == 번호 인 투수 레코드
000a8ef4: bl 0xa56dc(경기, 레코드, 0)       ; 그 레코드가 셀 대상인지
000a8f00: r3 = s16 레코드+0x22 ; +1 ; strh   ; 실점 +1
```

정리: **승계 주자가 홈을 밟으면 실점은 그 주자를 내보낸 투수에게 간다**(현재 마운드 투수가 아니라). 자책·비자책 구분은 없다(레코드 +0x22 하나뿐, P1 6절과 일치). 이어서 0xa8f06~ 에서 같은 주자·같은 책임 투수로 한 번 더 조회해 **다른 칸**도 올린다(같은 패턴 반복, P1 의 "자책 구분 없음" 과 모순 없음).

- 주의: 조회 키가 **등번호 성격의 +0xa 값**이라, 한 경기에서 같은 +0xa 를 가진 투수가 둘이면 앞쪽 레코드로 간다(0xb8c44 가 첫 일치를 돌려줌). 실제로 부딪힐 일은 거의 없다.

## 6. 무승부·콜드게임 — **확정(전이) / 유력(기록 쪽 귀결)**

- **무승부**: 경기 끝 요청 메시지 2(0x50cb0, R10 2-1)는 `경기+0x1104 ∈ {5,6}` 이 아니면 **두 팀 점수가 같으면 요청을 무시**한다 → 연장으로 계속. E-defense 가 적은 "연장 상한 없음·무승부 불가" 와 같다. 모드 값 5·6 (홈런더비 계열) 에서만 동점인 채로 상태 0x19 로 간다.
- 동점으로 끝나는 그 경우: 득점 처리 0xa5c34 가 동점이면 +0x44·+0x50 을 **2(없음)** 로 두므로 경기 끝 0xa7de8 의 `cmp r2,#2 ; beq` / `cmp r7,#2 ; beq` 에 걸려 **승·패 투수 모두 기록되지 않고** 평가 R+0x124 도 0 으로 남는다. (확정: 코드 경로. 유력: 실제로 그 모드가 투수 기록을 쓰는지)
- **콜드게임**: 0xb68fc 의 `이닝(0-기준) > 5` + 10점 차(E-defense 6절, 0xb694c). 별도의 승·패 투수 처리는 없다 — 그냥 상태 0x19 로 가고 0xa7de8 이 그때까지 갱신돼 있던 +0x44/+0x50 을 쓴다.
- **빈틈(확정)**: 승리 투수는 **6회(이닝 index ≥ 5) 이후의 득점 때만** 갱신된다. 5회까지 점수가 나고 6회 이후 한 점도 안 나면 +0x44 는 2 인 채로 경기가 끝나 **승리 투수가 없는 경기**가 된다(패전 투수는 이닝 조건이 없어 정상으로 남는다). 7회 콜드게임도 6회 이후 득점이 없으면 같은 일이 생긴다.
- 총 이닝이 9가 아닌 판(state+0x69 ≠ 8)에서는 승리 투수를 아예 안 매긴다(패전은 매긴다).

## 7. 웹판 현황 — 고치지 않음

- **승·패·세이브 투수 개념이 웹판에 없다.** `/usr/bin/grep -rniE "winPitcher|losePitcher|savePitcher|responsiblePitcher" src` → 0건. R10 9절의 "상태 0x18 결과 판에 승·패·세 3줄" 도 아직 안 그린다.
- `src/features/play-game/model/gameFlow.ts:276` — 완투 계열 판정에 넘기는 `runsAllowed: progress.game.opponentScore` 는 **팀 총실점**이다. 원본은 투수 레코드 +0x22(책임 투수별 실점)를 쓰고, 게다가 P1 5-1 이 적은 대로 평가 쪽 실점 칸은 늘 0 이다. 즉 웹판은 원본보다 "엄한" 완투 판정을 하고 있다(원본은 실점 항이 0 이라 완투 승리가 늘 완봉).
- 승계 주자 귀속(5절)에 해당하는 것도 웹판에 없다 — `progress.pitching` 은 사람 팀 투수 하나로 뭉뚱그려 센다.

## 요약

**풀린 것.** state+0x44/0x48(승)·+0x50/0x54(패)·+0x5c/0x60(세)·+0x64(세이브 코드) 를 건드리는 곳을 전수로 확인했다. 초기화 **0xb6814** 가 셋 다 2(없음)로 두고, **득점 처리 0xa5c34**(한 점마다 호출)가 승·패를 다시 잡는다: *6회(이닝 index ≥ 5) 이후·정규 9이닝 경기에서만* 앞선 팀의 현재 마운드 투수를 승리 투수로, (이닝 조건 없이) 뒤진 팀의 현재 투수를 패전 투수로 적고, 리드가 뒤집히거나 동점이 되면 칸을 2 로 비운다. **세이브는 투수 교체 0xa60c0** 에서만 잡히며 조건은 실제 야구 규칙 그대로 — `점수차 ≤ 3 && 남은아웃 ≥ 3`(코드 3) / `점수차 > 3 && 남은아웃 ≥ 9`(코드 9) / `점수차 ≤ 주자수 + 2 && 남은아웃 ≥ 1`(코드 1), 남은아웃 = `3·(state[0x69] − state[0x6b]) − state[6] + 3`. 경기 끝 **0xa7de8** 이 이 칸들로 레코드 +0x2e(승)·+0x2f(패)·+0x24(세)와 평가 R+0x124(1/2/3)를 올린다. 승계 주자 실점은 **주자+0x30 에 적어 둔 "내보낸 투수"** 에게 간다(0xa93ac 에서 적고, 주자 승계 시 0xa9dba 가 복사, 0xa8ed4 가 그 투수 레코드 +0x22 를 올림) — 자책 구분은 없다. 무승부는 모드 5·6 말고는 성립하지 않고(연장 계속), 성립해도 승·패 투수는 둘 다 없음으로 남는다. 콜드게임은 별도 처리가 없다.

**남은 것.** ① **state+0x64 를 0 으로 되돌리는 코드를 못 찾았다** — 그대로면 0xa7eaa 의 `> 0 이면 건너뜀` 때문에 **세이브가 한 번도 기록되지 않는다**(유력 버그, 4-1). 레지스터 간접 쓰기나 memset 경유를 더 봐야 확정. ② 0xa8f06~0xa8f36 이 책임 투수 번호로 `0xb8c0c(팀, 번호)` → `0xb8cdc(팀, 그것)` 을 거쳐 올리는 **다른 표의 +2 바이트**가 무엇인지(투수 레코드 +0x2a 또는 팀 기록판 후보) 안 봤다. ③ 0xa56dc(경기, 레코드, 0/1) 의 정확한 뜻(0 = 기록 대상 / 1 = 내 선수)은 P1 에 기대어 읽었다.

## 요약
**풀린 것(확정)**: ① 홈런더비 결과 화면 `0x45c18` — 176×213 가운데 창, "RESULT" 머리, 칸 A(162×84)에 **총 기회 / 최대 콤보 / 현재 비거리 / 최고 비거리** 네 줄(값 칸 42×12, 줄 간격 16, 단위 "회"·"M"), 칸 B(162×44)에 **획득 GP / 보유 GP**, 칸 C(162×49)에 StrMAINMENU[53] "재도전하시겠습니까?" + popup 예/아니오. 진입 `0x4f574` 가 최고 비거리(app+0x5c) 갱신·신기록 효과음 0x1f/0x20·획득 G(`0x3af4c`) 지급까지 하고, 키 `0x40a08` 이 예 → 전역 0x140006c = 0x27(다시 하기) / 아니오·취소 → 4(메인 메뉴), 갱신 `0x3c0b8` 이 페이드 뒤 장면 0x103 으로 넘긴다. ② 강판 뒤 감독 대사 창 — 상태 0x23 진입 `0x50754` → `0x86198` 이 **"[!c00CC00감독님!cFFFFFF] : " + 전역 버퍼 0x1552af4 의 StrUSER_EVT 대사**(`0x50434` 가 담는다)를 ui/mode_ui.pzx 창에 넣고, `0x7fbc4`/`0x7fad0` 이 **화면 아래 폭 전체·높이 55(15px/틱로 올라옴)·검정 알파 0xB4** 상자에 x=5·y=H−55+5·폭 W−20·줄높이 14 로 **틱당 3글자씩** 찍는다. 확인 키만 받고, 대사가 끝나면 `0xc1b48`(간이 엔진) + **상태 0x21** 로 — 스스로 강판과 같은 자리로 합류한다. ③ 겸사겸사로 정산 화면 `0x4a948` 갈래의 판 크기(**176×182**, 대전 승리만 202)와 "승리 추가 보상 … G포인트" 줄(대전모드 8·9 승리에만, 값 = app+0x112 / app+0x138)을 확정으로 올렸다.

**정정**: Q0 가 "감독 대사 창" 으로 적은 `0x85f38` 은 이 창이 아니다. 경기 상태 0x23 이 쓰는 것은 `0x86198` 하나뿐이고, `0x85f38` 은 시즌(0xe9ac)·나리(0x1cdec) 장면이 쓰는 **말하는 사람 얼굴 그림 고르기**(수치 >90 → 1, ≤50 → 6, 그 밖 0)다.

**남은 것**: 0x5eec4·0x7cfc8 의 인자 몇 개, 0x85f38 이 보는 수치의 정체, 대전모드 보상 칸 app+0x112/0x138 의 출처(서버로 보임), 정산 화면 기록 목록 줄 좌표(F 담당), Q0 의 경기 중 상태 12·19·30·33.





## 1. 홈런더비 결과 화면 — 그리기 0x45c18 (경기 상태 0x1a) — **확정**

경기 상태 0x1a 의 그리기 칸(R10 표). 앞부분은 상태 0x19(정산)·미션 결과 화면(0x4a384)과 같은 뼈대이고, 창 몸통만 다르다.

### 1-1. 부르는 도우미 (이미 풀린 것)
- `0xca9f8/0xca9fc/0xcaa04/0xca9f4/0xca9f0` = `bx r3 / bx r4 / bx r6 / bx r2 / bx r1` — 간접 호출 썽크. 아래에선 실제 대상 주소로 적는다.
- `0xba759(obj, 번호, 종류, x, y, a, b, y보정, 애니진행)` 스프라이트 그리기 (F 0장). 종류 0 이미지 / 1 프레임 / 2 애니.
- `0xba719(rect(x,y / w,h 두 워드), 종류1, 값, 기준 20, 숫자폰트, 정렬, …)` 숫자 그리기 (F 5-x, 0x3756c 와 같은 꼴).
- `0x55e60` 공용 창(F 6-2, #335FCD 판), `0x5eec4` 안쪽 칸(아래), `0x54a60` G포인트 숫자(P6 2절과 같은 함수), `0xba269(글, x, y, 폭, 색)` 글 상자(R11).
- `0x913e4(애니객체 [0x1552ae8], n)` = img_text 글자 **색 고르기**(R4 4번 칸과 같은 관용구). 이 함수에선 색 3 → 그리기 → 색 0 되돌리기 를 반복한다.
- 화면 크기 `[0x14008b8]`(W) `[0x14008c8]`(H), 스킨 `[0x1552cfc]`, img_text 스프라이트 `[0x1552aec]`, 그 애니 객체 `[0x1552ae8]`, 팝업 스프라이트 `[[0x140005c]+4] = ui/popup.pzx`(P6 31번 칸), 홈런더비 상태 구조체 `[0x1552d0c]`(H-2), 앱 기록 `0x1f1d8([0x1400054])`.

## 2. 홈런더비 결과 상태 0x1a 의 진입·갱신·키 — **확정**

### 2-1. 진입 0x4f574
```

### 2-3. 키 0x40a08
```

- **4 = 메인 메뉴 모드 목록**(Q2 2a 의 장면 0x107 상태 4 와 같은 뜻의 번호를 장면 0x103 에서 쓴다).
- 키 번호 −3/−4/−5/−16 과 '4'/'6'/'5' 는 I-controls 의 공용 키 규약과 같다.

## 3. 강판 뒤 감독 대사 창 (경기 상태 0x23) — **확정**

### 3-1. 나오는 시점
- 감독 강판 판정 `0x504cc`(P1 2-1) 가 참이면 `0x50434(scene, 글번호)` 로 대사를 전역 버퍼에 담고, 부르는 쪽 0x50674(상태 0xe 진입, BL 0x506ea) 가 **경기 상태 0x23** 으로 간다.
- 즉 **내 투수(모드 3 투수편)가 던지는 타석 준비 때** 판정 → 걸리면 곧바로 이 창.
- 스스로 강판(`#` 키)은 상태 0x21 로 가고 이 창을 거치지 않는다(P1 2-2). → **두 상태의 차이는 "감독 대사 창이 끼느냐"뿐**이고, 대사 창을 닫으면 결국 똑같이 0x21 로 간다(3-4).

### 3-2. 대사 고르기 0x50434(scene, 글번호) — **확정**
```
50444: 0x1400428(0x1552af4, 0, 0x200)              ; 전역 대사 버퍼 512바이트 비우기
50448: t = new(12); 0x701ac(t); 0x70264(t, "data/StrUSER_EVT.zt1", 1)
5046a: s   = 0x702b5(t, 글번호)                     ; 문자열
50476: len = 0x702d9(t, 글번호)                     ; 길이
50482: 0x1400408(0x1552af4, s, len)                ; 전역 버퍼로 복사
5048a: t 소멸 (0x701d8 / 0x1258)
```
- **전역 대사 버퍼 = 0x1552af4 (512바이트)**. P1 2-1 의 "0x50434 가 자원 0xd09dc 에서 읽어 0x1552af4 에 담는다" 를 식까지 확인.
- 글번호는 P1 2-1 표 그대로: 체력≤20% → 85+tier, 체력 0% → 88+tier, 한 이닝 4실점 → 91+tier, 만루 → 94+tier (tier = 평판 0/1/2).

### 3-3. 창 만들기 0x50754 (상태 0x23 진입) + 0x86198 — **확정**
```
50754: if scene+0x19a8 == 0: scene+0x19a8 = 0x7b7b8(new(0x398))   ; 대사 창 객체 (920바이트)
50776: 0x86198(창)
```
`0x86198(dlg)`:
```
861b2: 0x7f54c(dlg, &{2, 0, 0, 3})                 ; 창 종류/모양 설정 (바이트 4개)
861ba: dlg+0xa8 문자열 +0xc = 0                     ; 글 버퍼 길이 0 으로
861c0: 0xbc964(dlg+0xa8, "[!c00CC00감독님!cFFFFFF] : ")   ; 0xd4c70
861c6: 0xbc964(dlg+0xa8, 0x1552af4)                 ; 3-2 가 담아 둔 USER_EVT 대사를 이어 붙임
861ce: dlg+0xe4 = 1                                 ; 1 = 그냥 대사(선택지 없음)
861d4: 0x7f7d4(dlg) ; 0x7f7cc(dlg)                  ; 페이지 나누기 준비
861fa: if dlg+0x138 == 0: dlg+0x138 = 0xb9719("ui/mode_ui.pzx", 1, "ui/mode_ui.mpl", −1, …)
```
- **문구 = `[!c00CC00감독님!cFFFFFF] : ` + StrUSER_EVT[글번호]**. `!cRRGGBB` 는 색 지정 escape → **"감독님" 은 초록 #00CC00, 그 뒤는 흰색 #FFFFFF**, 대괄호는 글자 그대로.
- 창 그림 자원은 **ui/mode_ui.pzx (+ 팔레트 ui/mode_ui.mpl)** — F 6-4 가 "[this+0x138] 가 mode_ui 로 보임" 이라 했던 것을 확인.

### 3-4. 창 그리기·키·닫기 — **확정**
그리기 0x50828 (상태 0x23 의 그리기 칸):
```
50828: 0x38d1c(scene,0) · 0x49e64(scene,0) · 0x35b94(scene) · 0xbe6a0(scene+0x234)   ; 타석 화면 공용 묶음
50850: if scene+0x19a8: 0x7fbc4(창, 0, 1, 0)
```
`0x7fbc4(dlg, 고른칸, 상자그리기, 플래그)` = 공용 대사 창 그리기. 상자는 `0x7fad0(dlg, 1)`:
```
7fae2: dlg+0xea (s8 창 높이) += 0xf, **0x37(55) 에서 멈춤**      ; 아래에서 15px/틱씩 올라오는 연출
7fb36: 0x7cfc8(dlg, rect(0, H − h − 12, W, 12), W − 67)         ; 윗 띠 12px — #12307E 바깥 + #1D44A8 안쪽
7fb56: 0xb9f74(rect(0, H − h, W, h), 0xB4000000, 0, 0)           ; 본체 = **화면 폭 전체, 검정 알파 0xB4**
7fb96: 0xba19c([[dlg+0x138]+0xc]→+8→+0x54, W, 띠y, 0, 0)         ; 띠 위 장식 그림 (mode_ui)
7fba6: 돌려주는 값 = (h == 0x37)                                  ; **다 올라온 뒤에야 글을 그린다**
```
글 (dlg+0xe4 == 1 갈래, 0x7fc64~0x7fd1c):
```
0x6ef4c(글꼴, dlg+0xa8 문자열, x = 5, y = H − h + 5, 폭 = W − 20, 색 −1(흰색),
        정렬 3, 글자수 = s8 dlg+0xeb, 줄높이 0xe(14), …)
```
타자 효과·페이지 (0x7fcb6~0x7fcea):
| 칸 | 뜻 |
|---|---|
| dlg+0xe6 (u16) | 대사 전체 글자 수 |
| dlg+0xe8 (u16) | 지금까지 드러난 글자 수 — **틱마다 +3** |
| dlg+0xec (s32) | 단계: 0 시작 → 1 타자중 → 2 "끝까지 건너뛰기" → 3 페이지 끝(더 있음) → 4 대사 끝 |
| dlg+0xea (s8) | 창 높이 (0 → 55) |
| dlg+0xe4 | 1 = 대사, 그 밖 = 선택지 목록(고른 줄은 노랑 RGB(255,255,0), 0x7fd22 갈래) |
키 0x50794 (확인 −5 / '5' 만 받는다):
```
507b6: 단계 1 → 단계 2            ; 한 번 더 누르면 그 페이지를 끝까지 보여 줌
507c8: 단계 3 → 0x7f7f4(창)       ; 다음 페이지
507d0: 단계 4 → 0x7b870(창) · 0x86228(창) · 창 소멸, scene+0x19a8 = 0
        0xc1b48([scene+0x1780])   ; **간이 엔진 켜기 — 스스로 강판(P1 2-2) 과 같은 함수**
        0xbcb48(scene+0x18, 0x21) ; **경기 상태 0x21(자동진행)** 로
```
→ 감독 강판은 "대사 창 → 확인 → 간이 진행" 이고, 남은 경기는 스스로 강판과 똑같이 흘러간다. **좌/우·취소 키는 받지 않는다**(강판을 무를 수 없다).

### 3-5. 0x85f38 은 이 창이 아니다 (정정)
- Q0 표는 `0x85f38~0x8656c` 덩어리를 "감독님 대사 창" 으로 묶었는데, 경기 상태 0x23 이 부르는 것은 그 덩어리 안의 **0x86198** 뿐이다(`re xref 0x86198` → 0x50776 한 곳).
- `0x85f38` 을 부르는 곳은 **0xe9ac(시즌모드 장면 0x105 상태 기계)** 와 **0x1cdec(나리/관리 장면 상태 기계)** 뿐이다(0x4b50·0x4efc ← 0xe9ac, 0x11910·0x14a74 ← 0x1cdec).
- 하는 일은 대사 고르기가 아니라 **말하는 사람 얼굴 그림 고르기**(확정: 식):
  ```
  85f3c: 0x7b998(dlg) 가 참이면  v = s16 (0x1f570(app, s8 [dlg+0x150][1]))+2
         거짓이면               v = 0xa3a24([dlg+0x150])
  85f6c: v > 0x5a(90) → e = 1 ; v <= 0x32(50) → e = 6 ; 그 밖 e = 0
  85f82: [dlg+0x150]+5 (바이트) ≠ 0 → e = 6
  85f96: [dlg+0x150]+0x1b5 (s8) > 0 → e = 6
  85fc6: dlg+0x258 = e ; 값이 바뀌었으면 dlg+0x250 의 그림을 버리고 0x63a04(skin, …) 로 다시 적재
  ```
  → 컨디션/친밀도 계열 수치가 **90 초과면 1(웃음), 50 이하면 6(찡그림), 그 사이 0(보통)**, 어떤 플래그가 서면 강제로 6. 어느 수치인지(0x1f570 이 돌려주는 레코드의 +2)는 **미확인**.
- 감독 강판 창(0x86198)은 얼굴 그림을 쓰지 않는다 — 글만 있는 창이다.

- 그림 글자는 `base/sprites_v2/img_text/frames/*.png` · `base/sprites_v2/game_ui/frames/*.png` · `public/sprites/game_ui/030.png` 를 눈으로 읽어 확인했다(확정).

## 4. 겸사겸사 — 경기 끝 뒤 흐름에 남아 있던 화면

### 4-0. 흐름 지도 (이미 풀린 것 정리)
```
3아웃/경기 끝  → 0x18 공수교대·경기끝 판 (R10 5절, 승·패·세 투수 3줄)
              → 모드 5·6(미션) 이면 메시지 0x76c/0x76d 뒤  ┐
              → 그 밖은 0xae3a0 가 경기 끝 판정             ┴→ **0x19 정산** (진입 0x4ea0c · 갱신 0x4b100 · 그리기 0x4a384)
홈런더비(모드 7) 는 공 10개(+보너스)를 다 쓰면 0xae24c/0xae3e8 이 → **0x1a 결과**(이 문서 1·2절)
감독 강판(모드 3) 은 상태 0xe 에서 → **0x23 대사 창**(이 문서 3절) → 0x21
0x19 / 0x1a 둘 다 전역 0x140006c 에 다음 하위 상태를 남기고 **장면 0x103(메인 메뉴)** 로 나간다 (미션만 장면 0x107, Q2 2a).
```

### 4-1. 정산 화면 0x4a384 의 "그 밖 모드" 갈래 0x4a948 — F 6-1 의 유력 항목을 확정으로
F 6-1 이 "호출 인자만 확인" 으로 남겨 둔 부분이다. 새로 확인한 것:
```
4a97a: 0x41440(scene, W/2 − 0x78(120), H/2 − 0x50(80), 0, 0, 0)     ; 점수판 틀 → 240×320 이면 (0, 80)
4a980: 점수 0xb69b0(st, 0) → sp+0x74 , 0xb69b0(st, 1) → sp+0x70
4aa06: 0xba688(…, 값 sp+0x74, x, y, [sp]=0x46(70), [sp+4]=숫자폰트, [sp+8]=0x12(18), [sp+0xc]=0)   ; 왼쪽 점수
4aa58: 같은 꼴로 오른쪽 점수 (x = W/2 + 프레임상자 보정 − 0x76)
4aa76: mode = [scene+0x1104]  (sp+0x60 = &mode)
4aa84: 판 높이 h = 0xb6(182) 가 기본,
4aa88:   **mode − 8 ≤ 1 (= 대전모드 8·9) 이고 0x4a350(scene)(승리) 이면 h = 0xca(202), sp+0x64 = 1**
4aafe: 0x55e60(skin, W/2, H/2, w = 0xb0(176), h, 0, 정렬 0x22, 0x10, 0,0,0)
```
→ F 의 "176 × 202" 는 **대전모드에서 이겼을 때만**이고, 보통은 **176 × 182** 다 (확정).

**"승리 추가 보상" 줄 — 확정**
```
4ae4e: if sp+0x64 == 0 → 건너뜀                   ; 즉 **대전모드(8·9) 승리일 때만 나오는 줄**
4ae60: v = (mode == 8) ? s16 [app+0x112] : s16 [app+0x138]      ; app = 0x1f1d8([0x1400054])
4ae82: 글 = "승리 추가 보상[!cffff00"(0xd060c) + v + " G포인트!cffffff]"(0xd0624)
4aeb6: 0xbb28c(W/2, y, 0xa2(162), 0x12(18), 2) 칸 + 그 안에 글
```
→ 모드 8 과 모드 9 가 **서로 다른 저장 칸**(app+0x112 / app+0x138)을 보상액으로 읽는다. 두 칸이 무엇인지(서버에서 받은 값으로 보임)는 **미해결**.
- 같은 갈래 안의 "!R%d회"(0xd0970) · "!C기록이 없습니다!"(0xd0978) 는 그 위 기록 목록 칸의 글이다 — 줄 좌표까지는 안 봤다(**미해결**, F 담당 범위).

### 4-2. 그래도 남는 것 (미해결)
- Q0 표의 상태 **12·19·30·33** — 이 문서의 주제(부수 화면)와 겹치지만 경기 진행 중 화면이라 손대지 않았다.
- 0x5eec4(안쪽 칸 그리기)의 인자 뜻: (skin, x, y, w, h, 4, 2, ?, 0x56, 2, 0, 색 0x395DCE, 0, 0) 중 4·2·0x56·2 의 뜻은 미확인. 색 #395DCE 만 확실하다.
- 0x7cfc8(대사 창 윗 띠)의 셋째 인자 `W − 67` 이 무엇을 자르는지 미확인.
- 0x85f38 이 보는 수치(0x1f570 이 돌려주는 레코드의 s16 +2)가 컨디션인지 친밀도인지 미확인.

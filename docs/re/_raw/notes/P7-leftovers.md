## A1. 타석 기록 코드 5~9 — **확정** (9 의 "사구" 이름만 유력)

기록 함수 0xa8024 (경기 기록 객체 r6, state = [r6+8]). 이벤트 목록(r6+0x30, 개수 r6+0x2c)에서 먼저 센다:

a8a96:   else:                               링 ← 5 (a8a9e)             ; 5 = 그 밖의 아웃(땅볼·포스·태그)

### 상세 설정 그리기 (0x593c8 공용 페이지 안 0x59e82~0x5a226, 4줄 루프 `cmp r6,#4`)

## C1. PZX 효과 0x7E — **유력(강): 엔진이 아무것도 하지 않는다 (무시되는 표시)**

- 파트 효과를 다루는 곳은 셋뿐이고, 셋 다 0x7E 를 거른다:
  1. 파서 0xc8450~0xc8474 (같은 꼴 0xc84de·0xc85ec·0xc8668·0xca1ae): 효과 바이트 k 에 대해 `(k − 0x65) & 0xff ≤ 0xf` 일 때만 파트+0x10 = k, 파트+0x14 = 4바이트 값을 읽는다 → **값 달린 효과는 0x65~0x74 (0x66·0x67·0x6E·0x6F 등)**. 0x7E 는 0x19 라 값도 없고 +0x10 에도 안 들어간다.
  2. 적재 단계 0xc4e94: `k − 1 ≤ 0x63` (1~0x64) 만 (C 문서).
  3. 그리기 단계: 파트+0x10 의 0x65~0x74 만 (`subs #0x65` 분기들).
- 상수 0x7E 를 쓰는 곳 전수(`#0x7e` 38곳): 렌더러 구역(0xb9000~0xcb000)에 비교·분기가 **하나도 없다** (0xb67ae~0xb6b4e 는 경기 state+0x7e 점수 칸, 0x19dce·0x1aee0 는 게임 상태 번호, 0xcf190·0xd04d0 은 데이터 구역).
- 결론: defender(·ace/defender_*) 이미지 0·19 의 효과 0x7E 는 **원본 엔진에서 효과 없음**. 도구에서 만든 표시(예: 에디터용 그림자 표식)가 파일에 남은 것으로 보인다.
- 웹: `tools/decode_pzx.py:269` 가 0x7E 를 무시 → **원본과 같다**. 고칠 것 없음.

# H. 메뉴만 있고 기능이 없는 모드 — 원본 규칙 (작업 중)

## 요약

풀린 것: 원본의 **장면 구조**(0x103 메인 메뉴+경기 전 설정 / 0x104 경기 / 0x105 시즌 관리 / 0x106 나리 관리 / 0x107 미션 선택)와
**게임 모드 번호**(1 일반, 2 시즌, 3·4 나리 투수·타자, 5·6 미션, 7 홈런더비, 8·9 대전, 전역 0x1552d14 · 경기 this+0x1104),
모드 시작 함수 0x327b8, 경기 중 메뉴의 모드별 칸(자동진행/다시하기, 자동진행 비용 30G·대전 100G·대전 6회 제한).
**홈런더비는 규칙 전체가 풀렸다**: 기회 10, 홈런 비거리 = 거리/265(상한 160), 누적 800/1200/1600/2000 에서 마투수 1~4 등장(구질 22 마구만),
G = 누적/100 × [1,2,3,4,5][단계] + 콤보×5 + 이벤트 존 200, 최대 콤보만큼 보너스 게임, 최고 비거리 저장(+0x5c).
남은 것: 이벤트 존 적중 조건의 한 플래그(+0x127), 홈런더비 타자 선택(2/4)의 뜻, 마투수 표 순서, 대전모드 상대·보상(서버 쪽이라 로컬 근거 없음).
필살타법·마구, 아이템/스킬 창·필살타법 창은 아래 5·6절(포크 결과 합침). 일반모드 준비·시즌 구단관리·투수편은 범위 조정으로 에이전트 J 담당.

## 0-2. 장면·모드 번호 정정 (확정/유력)

**0x3c158 은 메인 메뉴가 아니라 경기 장면(0x104) 함수다.** this+0x1104 를 쓰는 함수 70여 개가 모두 0x33000~0x53000(경기 장면)에 있다.
경기 장면 +0x1104 = **게임 모드**. 전역 모드 변수는 **0x1552d14** (경기 장면 초기화 0x3301c 가 0x1552d10·this+0x1104 로 복사).
```
33074: ldr r3,=0x1552d14 ; ldr r2,[r3] ; ldr r3,=0x1552d10 ; str r2,[r3] ; str r2,[r7+0x1104]
33082: cmp r2,#2 → 0x1552ad8=1 ;  (r2−8)≤1 → 0x1552ad8=2 ; 그 밖 0
```
경기 끝 흐름 0x4b100 (최근게임/저장 +0xf6 = 마지막 모드): `모드−2` 로 점프표 0xd01f8(5칸):
모드 2 → 장면 0x105, 모드 3·4 → 장면 0x106, 모드 5·6 → 장면 0x107(또는 0x105/0x106, 저장 +0x11f·+0x176 조건), 그 밖(0·1·7…) → 0x140006c=4, 장면 0x103.
경기 중 메뉴 0x3c98e: 모드 5·6 → 장면 0x107(하위 3), 모드 7 → 장면 0x103(하위 0x27).

장면 역할(정정):
| 번호 | 역할 | 근거 | 판정 |
|---|---|---|---|
| 0x103 | 메인 메뉴 + 경기 전 설정 화면 묶음(하위 상태 2~0x2a) | StrMAINMENU(this+0x128)·StrITEM(+0x12c)·StrMODE(+0x138)·StrGAME, 하위 상태 문자열이 StrMAINMENU[13]·[15]·[115]·[106~120] | 확정 |
| 0x104 | 경기 | 크기 0x1b80, +0x1104 모드 | 확정 |
| 0x105 | **시즌모드 관리** (6칸 커맨드, 4칸 구단관리 하위 메뉴) | 모드 2 경기 뒤 돌아감, 초기화 0x3b14 의 6칸·4칸 메뉴, 관리 객체 +0x20==2 가 시즌(0x7b998) | 유력 |
| 0x106 | 나만의리그 관리 (타자 4·투수 3) | 모드 3·4 경기 뒤 돌아감, 0x7b970(+0x20==4 타자)·0x7b984(==3 투수) | 유력 |

게임 모드 값(유력, 한 고리 미확인): 2 시즌, 3 나리 투수편, 4 나리 타자편, 7 **홈런더비**(0x3af4c: 모드 7 에서만 비거리식 값을 돌려주고, 끝나면 메인 메뉴 장면의 하위 0x27 로 간다),
0x35034·0x39bd4 는 모드 7 에서 돌발/연출을 끈다. 0·1·5·6·8·9 는 아래에서 확인 중(0x8da4·0x14114 가 모드 1 + 장면 0x103 하위 5 로 보낸다, 0x31918(하위 15, 대전 문자열 StrMAINMENU[106~120])가 모드 8 을 쓴다).

### 모드 번호 확정 — 메인 메뉴의 모드 시작 0x327b8(this, 모드) (확정)
`0x1552d14 = 모드; 저장객체+0x3c = 모드; 모드−1 로 점프표 0xcf048(9칸)`:
| 모드 | 처리 | 뜻 |
|---|---|---|
| 1 | 저장 +0x4d(진행 중 경기) 있으면 0x213c0(앱,1,0) 로 불러와 경기 장면 0x104, 없으면 하위 상태 12(0x296f0, StrMAINMENU[13] "일반 모드를 진행하시겠습니까?") | **일반모드** |
| 2 | 진행 중이면 이어서, 아니면 0x140006c=0xc9, 장면 0x105 | **시즌모드** |
| 3·4 | 0x140006c=0x69, 장면 0x106 | **나리 투수편·타자편** |
| 5·6 | 장면 0x107 | **미션 타자·투수** (장면 0x107 은 StrMAINMENU[56]~[61] 미션다운·미션 도전 문구를 쓴다 → 미션 선택 장면, 확정) |

| 8·9 | 저장 +0x4c 플래그면 불러와 경기, 아니면 하위 상태 15(0x31918, StrMAINMENU[106]~[120] 대전 문구) | **대전모드** (9 는 도전리스트/이벤트리그 변형 유력) |

### 경기 중 메뉴 (경기 장면 0x3c158 상태 0, 확정)
행 = 모드 3·4 → 2, 모드 5~7 → 1, 그 밖 → 0. 칸→동작 표 0xcfcfc: 행0 [0,4,1,2,3] / 행1 [0,5,1,2,3] / 행2 [0,1,2,3,0].
동작 점프표 0xcff84: 0 0x3c1fe · 1 0x3c212 · 2 0x3c326 · 3 0x3c504 · 4 0x3c60c(StrGAME[2]~[4] 자동진행, G 소모) · 5 0x3c706(StrGAME[7] "새로운 기록을 위해 다시 플레이하시겠습니까?").
→ 미션·홈런더비는 "자동진행" 대신 "다시하기"가 들어간다. 동작 0~3 의 뜻(계속/설정/도움말/나가기 추정)은 미확인.

## 1. 홈런더비 (모드 7)

진입 (확정): 메인 메뉴(장면 0x103) 하위 16(갱신 0x29ac8)이 선택창 0x62568(StrMAINMENU[54] 질문 계열)의 결과 this+0x240→+0x12c 를 본다:
0 → 하위 5(모드 목록)로 되돌아감, **2 또는 4 → this+0x13c = 7, 하위 0x27** → 진입 처리 0x32988 → 0x327b8(this, 7) → 0x213c0(앱, 4, 0) 로 나리 타자편 저장을 올리고 곧바로 경기 장면 0x104.
결과 2/4 가 명예타자/육성타자 중 무엇인지는 유력 수준(0x62568 내부 미해독). 같은 꼴로 하위 13(0x2464c)은 나만의리그 타자(4)/투수(3), 하위 14(0x24698)는 시즌(2), 하위 17(0x29a54)은 모드 6 을 this+0x13c 에 넣고 0x27 로 간다.

경기 상태 구조체 = 경기 장면 this+0x174 = 전역 0x1552d0c (같은 객체). 초기화 0xb6814 (확정):
```
b6846: movs r3,#0xa ; strb r3,[+0x33]      ; 남은 기회 10
b6840: strb #0,[+0x38]                     ; 단계(마투수) 0
b685a: str  #0,[+0x40]                     ; 보너스 G 0
+0x68=0(던진 공 수) +0x39/+0x3a/+0x3b/+0x3d/+0x3e/+0x3f = 0
```
| 필드 | 뜻 | 판정 |
|---|---|---|
| +0x01 (s8) | 모드 사본(7) | 확정 |
| +0x33 | 남은 기회 (10 에서 시작) | 확정 |
| +0x34 (s16) | 누적 비거리 | 확정 |
| +0x36 (s16) | 이번 타구 비거리(표시용) | 확정 |
| +0x38 | 단계 = 등장한 마투수 수 | 확정 |
| +0x39 | 현재 콤보 | 확정 |
| +0x3a / +0x3b | 직전 공 홈런 / 이번 공 홈런 | 확정 |
| +0x3d | 최대 콤보 = 보너스 게임 수 | 확정 |
| +0x3e | 보너스 게임 중 | 확정 |
| +0x3f | 이번 공 이벤트 존 적중 | 확정 |
| +0x40 | 보너스 G 누계 | 확정 |
| +0x68 | 던진 공 수 | 확정 |
| +0x84 | 콤보 표시값 | 유력 |

### 공 하나의 결과 처리 — 0xae24c(아웃/헛스윙 쪽)·0xae3e8(타구 쪽) (확정)
둘 다 `구조체+1 == 7` 일 때만 이 길로 간다.
1. 콤보: 직전 공과 이번 공이 모두 홈런이면 `콤보++`, `+0x3d = max(+0x3d, 콤보)`, **보너스 G += 콤보×5** (`ldr r1,[+0x40]; r3=콤보*5; add; str`, 0xae45a~0xae46a).
   아니거나 기회가 다했으면 콤보 = 0.  그다음 `+0x3a = +0x3b; +0x3b = 0`.
2. 남은 기회가 1 보다 많으면 `+0x33−−, +0x68++`, 그리고 **누적 비거리 ≥ 단계표[단계] 이면 단계++** (표 0xd84dc = [800, 1200, 1600, 2000, 99999]). 다음 공(상태 0xd, 단계 올라도 0xd / 아니면 0xf).
3. 기회가 다했고 `+0x3d > 0` 이고 아직 보너스 전이면: `+0x3e = 1`, **남은 기회 = +0x3d(최대 콤보)**, 콤보 0 → 보너스 게임 시작(상태 0xd).
4. 그 밖이면 끝(상태 0x1a).
5. 이번 공이 이벤트 존에 들었으면(+0x3f) **보너스 G += 200** (`adds r3,#0xc8`, 0xae548) 후 +0x3f = 0.

### 비거리 (확정)
0x524c0 (모드 7 분기 0x526ca) → 0xa600c: 결과 코드(+0x26)가 8(홈런)이고 0xb68dc 가 거짓일 때
`d = |착지점 − (20000, 1000, 30000)| / 265`, **상한 160**, `+0x34 += d`. 기준점 표 0xd81f8 = 0xcfb70 = (20000, 1000, 30000).
```
a606a: movs r1,#0xa0 ; cmp r0,#0xa0 ; bge → r1=160 ; ... ldrsh r3,[r2,#0x34] ; adds r3,r1 ; strh r3,[r2,#0x34]
```

### 점수(G) — 0x3af4c, 정산 0x4f574 (확정)
`G = (누적 비거리 / 100) × 배율[단계] + 보너스G`, 배율 표 0xcfb10 = [1, 2, 3, 4, 5] (s8). 정산에서 소지 G 에 더하고 99999 로 자른다(0x4f6ea).
→ 설명서 "마투수가 등장하면 G포인트를 추가로" = 배율 상승.

### 상대 투수 (확정/유력)
- 단계 0: 일반 투수, 구질은 **1 고정**(0x344dc: 모드 7 이면 `단계>0 ? 0x16(마구) : 1`), 목표점은 타자 좌우(this+0x17e1)별 고정 표 0xcfbcc = 좌 (19415, 1202, 29705) / 우 (20585, 1202, 29705) (0x345fc, 확정).
- 단계 s>0: 0x48d50 에서 마투수 레코드 표[0xcfce8 = 1,2,3,4][s−1] 번째(앱 데이터 +0xac → +0xc64 + 번호×0x30, 0x1f824)를 상대 투수 레코드로 0x30 바이트 복사하고 **구질 22(마구)만** 던진다 (확정).
  마투수 순서가 XlsACE_PIT_DATA 행 순서와 같다면 단계 1 레오니 · 2 붕붕머신 · 3 발렌타인 · 4 드래고나(싸이커는 안 나옴) — 행 순서 = 메모리 순서는 **유력**.

### 표시(HUD) 0x45a54 (확정)
타석 화면 그리기 0x4c4bc 가 모드 7 이면 일반 점수판(0x373d0) 대신 0x45a54 를 부른다:
공 번호 = `(보너스 중 ? +0x3d : 10) − +0x33 + 1` 을 공 아이콘 10칸(0x3608c)으로, 최고 기록(저장 +0x5c, u16)과 현재 누적 비거리를 비교해 넘으면 강조.
스프라이트: 이벤트 존 `stadium/event_zone.pzx`(this+0x1070, 0x486e0 로드), 콤보 `ui/combo.pzx`, 결과 `ui/result.pzx`.

### 이벤트 존 (유력 — 조건 한 고리 미확인)
공마다 0x3de10 이 zone 좌표(this+0x17cc/0x17d0)를 −1 로 비운다. 0x36dfc(공 그리기)가 모드 7·zone 미설정·공이 비행 상태(0x357e0: 상태 24~26)·
공 화면 y 가 화면 높이/3 보다 위·필드 객체 +0x127 플래그일 때 zone 을 그 자리에 두고 +0x3f = 1 (→ +200G), 0x41098 가 그 자리에 event_zone 을 8프레임 주기로 깜빡이며 그린다.
+0x127 의 뜻(이벤트 존 판정 자체인지)은 미확인.

### 기록 저장·끝 (확정)
- 경기 상태 0x1a 정산(0x4f644~): `+0x34 > 저장+0x5c(u16)` 이면 저장 +0x5c = +0x34, 신기록 플래그 +0x3c = 1, 효과음 0x1f(아니면 0x20).
- 끝 확인창 0x40a08: 예(5/−5 키) → 0x140006c = 0x27 → 메인 메뉴 하위 39 → 모드 7 재시작. 아니오 → 0x140006c = 4(메인 메뉴).
  예일 때 단계>0 이면 rand[1,4) 번째 무언가를 0x30 바이트 복사한다(뜻 미해결).
- 경기 중 메뉴는 "자동진행" 대신 "다시하기"(StrGAME[7]) — 위 0x3c158 참고.
- 비거리 랭킹 등록은 통신(StrMAINMENU[100]) — 오프라인 규칙 없음.

## 2. 대전모드 (모드 8·9) — 오프라인으로 되는 부분

- 진입: 0x327b8 모드 8/9 → 저장 +0x4c(진행 중 대전) 있으면 불러와 경기, 없으면 메인 메뉴 하위 15(0x31918) (확정).
- 하위 15 = 통신 상태 머신: this+0x18 을 0~0x67 로 점프표 0xcee04 에 태우고, StrMAINMENU[111]~[120](상대찾기·내팀정보·도전리스트·대전하시겠습니까·대상 없음)를 띄운다.
  경기 직전 0x316dc 가 **통신 버퍼(net+0x2b9)의 바이트를 읽어** 상대 팀 레코드·이름을 채운다 → 상대(외인구단 포함)는 **서버가 정한다** (유력: 패킷 해석 코드만 있고 로컬 확률표를 못 찾음).
  0x31dfe: 버퍼 플래그가 0 이면 모드 8, 아니면 9 (9 = 도전/이벤트 쪽 유력).
  0x31746~0x31766: 한 팀 레코드의 능력치 4칸(+4,+6,+8,+0xa)을 ×2 한다 — 어느 팀·왜인지 미해결.
- **자동진행 규칙** (경기 중 메뉴 동작 4, 0x3c60c, 확정): 모드 8/9 는 이닝(구조체 +0x6b) > 5 이면 StrGAME[2] "6회까지만" 으로 거절, 아니면 StrGAME[3] 과 **100 G**. 그 밖 모드는 StrGAME[4] 과 **30 G**.
- 팀 능력치 적용: 모드 2·8·9 에서 0x1552ad8 ≠ 0 (0x33082) — StrHOWTO[7] 과 일치 (확정: 값 설정 / 유력: 사용처).
- 외인구단: 팀 14, TEAM_DATA 값 [14, 100, 666, 666, 666, 666] (웹 `src/shared/config/original/teams.ts:28` 에 이미 있음). 등급별 등장 확률(StrHOWTO[24])은 로컬 코드에서 찾지 못함 → **미해결(서버 쪽으로 판단)**.

## 6. 나리 선수정보 — 아이템/스킬 창·필살타법 창 (관리 장면 0x106)

### 스킬 장착/해제 — 키 처리 0x13140 (확정)
확인 키(this+0x40 = −5 또는 '5'(0x35))에서 창 0x85ad0 이 돌려준 스킬 번호 s 로:
1. `0x5f350(표, s)` 비트1(마이너스 스킬)이면 → "[" + 스킬명 + StrMODE[129] "스킬을 해제할 수 없습니다. 특별한 조건이나 [최면요법]으로 삭제 가능" (알림, 1,1).
2. 이미 장착(0xa4bf8)이면 → StrMODE[131] "해제하시겠습니까?" (예/아니오 2,3).
3. 장착 수 < 최대면 → StrMODE[130] "사용하시겠습니까?" (2,4).
4. 가득 찼으면: 슬롯 단계 L = 저장 +0x1c6 (s8).
   - L ≤ 1: `(표 0xcc4f7[L] × 1000)` + StrMODE[133] + `표 0xcc4f4[L+1]` + StrMODE[134] → "**5000** G포인트를 소모하여 **8**개까지 확장하시겠습니까?" / L=1 이면 "**10000** G … **10**개" (2,6).
   - L = 2: StrMODE[132] "동시에 최대 %d개의 플러스 스킬을 장착할 수 있습니다" (1,5).
- 최대 장착 수 표 0xcc4f4 = [6, 8, 10] (s8), 확장 비용 표 0xcc4f7 = [5, 10] × 1000 G. 확장 후 알림 StrMODE[135]/[136] (유력: 같은 흐름의 다음 상태).
- 장착 수 세기 0xa4aa4: 스킬 번호 **0~23** 중 장착(0xb62b4)이고 마이너스가 아닌 것만 센다 → 장착 대상 플러스 스킬은 번호 0~23 구간 (확정: 반복 상한 `cmp r4,#0x17`).
- 창 그리기 0x81dc0(this, …) 은 0x8453c 에서만 불린다 — 배치 좌표·색은 이번에 못 읽었다(미해결). 스킬 색 파랑/빨강/보라 구분은 0x5f350 의 비트로 유력.

### 필살타법(투수는 마구) 선택 — 키 처리 0x17cec (확정)
탭(창 +0x188) 0·1 = 필살타법/마구 목록, 탭 2 = 구질(투수편, J 담당).
칸 i(0~3)에서:
1. 이미 사용 중(0xa43c4: 선수 레코드 +0x18 == 번호)이면 StrMODE[69] "현재 사용 중인 스킬입니다".
2. 배운 수(저장 +0x201) ≤ i 이면 StrMODE[71] "트레이닝 완료 후 사용할 수 있습니다".
3. 아니면 "[이름]을 사용하시겠습니까?"(StrMODE[70]).
- **번호 = 표[i]** (타자 0xcc378·투수 0xcc368 둘 다 [1,2,3,4]), 번호가 4 이면 **4 + 레코드 +0xb 상위 3비트(타입/폼)**.
- 이름: 타자 StrCOMMON[24 + 번호] → 1 파워 스윙 · 2 플레임 스윙 · 3 토네이도스윙 · 4/5 미라지/메테오 스윙(타입 0/1).
  투수 StrCOMMON[30 + 번호] → 1 파이어 볼 · 2 웨이브 볼 · 3 썬더 볼 · 4+폼 → 샤이닝/캐넌/미라지 볼.
  → 한 선수가 가질 수 있는 필살타법은 **4개**, 넷째는 타입이 정한다 (확정). 배우는 순서는 훈련 칸 4(0x17f5c, 필요 횟수 4/5/6/7).
- 웹판: `src/widgets/special-swing/ui/SpecialSwingWindow.tsx:77` 이름을 `BATTER_BURSTS[cursor]` 로 뽑는다 → 넷째 칸이 늘 "미라지 스윙". 원본은 타입 1 이면 "메테오 스윙".
  같은 파일 :66 은 칸을 "레벨"(`index + 1 === level`)로 표시한다. 원본은 칸마다 다른 기술이고 "사용 중" 표시는 레코드 +0x18(고른 기술 번호)이다.
  확인 키로 기술을 바꾸는 동작(StrMODE[69]~[71])도 웹판에는 없다. 스킬 장착 상한 6/8/10·확장 5000/10000G 는 웹판에서 찾지 못했다(`/usr/bin/grep` 로 검색).

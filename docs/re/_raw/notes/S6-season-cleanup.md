## 1. U-18 — 시즌모드에서 `S+0x12c` 를 0 으로 되돌리는 곳 : **확정 — 없다(원본 버그)**

### 1-1. `S+0x12c` 를 만지는 모든 자리 (전수 조사)
`0x12c` 오프셋은 이 바이너리에서 **오직** `movs rX,#0x96 ; lsls rX,rX,#1` 로만 만들어진다
(`movs #0x4b ; lsls #2` 형태 0건, 리터럴 풀에 `= 0x12c` 0건 — all.txt 전수 스캔).
그 패턴 뒤 8줄 안에 `strb` 가 있는 자리 = **쓰기 15곳**이 전부다:

| 주소 | 객체 | 내용 |
|---|---|---|
| `0xe600` | S(시즌 `[this+0xa0]`) | 상태 242 들어옴 → `S+0x12c = 1` (대회 시작) |
| `0x1a098` / `0x1a0b4` | S(나리 `[this+0xb0]`) | 나리 대표 선발 `0x1a090` → 1 |
| `0x1b774` | S | 나리 새 시즌 `0x1b768` 머리 → 0 |
| `0x1b9ea` / `0x1baa0` | S | 나리 대회 끝 `0x1b92c` 두 가지 → 0 |
| `0x8cca6` / `0x8ccba` | S | 이벤트 461 선택 처리 — 463 이면 `S+0x50=3, S+0x12c=1` / 464 면 `S+0x50=0x11, S+0x12c=0` |
| `0x5ff26` / `0x60390` | S↔경기객체 | 복사 한 쌍 (`[경기+0x2bc] = [S+0x12c]` / 그 반대). 값을 바꾸지 않음 |
| `0xb28b4` `0xb28e8` `0xb306e` `0xb328c` `0xb33cc` | **다른 객체** | `0xb27ec` = 타구/플레이 객체(P2 3절 "플레이 vt18 = 0xb27ec"). vt 표 `0xd8630`, 스위치 표 `0xd877c`. 여기의 `+0x12c` 는 추적야수 칸이지 S 가 아니다 |

→ **시즌모드 쪽에서 0 을 쓰는 코드는 하나도 없다.** (`0x8ccba` 는 이벤트 464=거절 가지인데, 시즌모드는 거절 선택지를 타지 않는다 — 아래 1-3)

### 1-2. 시즌모드 대회 끝 경로 — 확정
- 243 키 `0xe6f8`: `S=[this+0xa0]`, `L=S+0x80`.
  - `L+0xad(=S+0x12d) == 1` 이고 `0xb8565(L)` 가 0 이면 → `0xb858d(L)` → 결과화면 `0x85e6d([this+0xc0], 0)` (e70a~e73c)
  - `L+0xad == 0` 이면 → `flag = (L+0xc4 == 0xa)` → `0x85e6d([this+0xc0], flag)` (e73e~e768)
  - `L+0xad > 1` 이면 → next `0xf4`(244) = 다음 경기 (e77c)
- 결과화면이 띄운 **팝업 1** 의 닫힘 처리 = `0x896c` (`0x897c` 에서 `[g+0x248]==1` 확인):
  - `L+0xc4(=S+0x144) == 0xa` → 우승 글 `StrMODE[0xc7=199]` + **팝업 0x23** (89a0~89f0)
  - 아니면 `0xb7615(L,1,0)` 또는 `(L,1,1)` 이 10 → 준우승 `StrMODE[0xc8=200]` + **팝업 0x24** (89f2~8a4e)
  - 둘 다 아니면 바로 `0x8b88`
- 팝업 0x23(`0x8a56`) / 0x24(`0x8b10`) 보상 처리 끝 → `0x8b88: bl 0x6e0c` (8b88~8b8a) = **다음 시즌**.
- `0x6e0c` 전체(6e0c~6f4a)에 `0x12c` 를 만지는 줄이 없다. 하는 일은
  `0xa3085(S)` 결과 ≥0 이면 `[팀…+0xa0]=1 · S+0x50=6 · 0x1fded · 0x22755 · 이벤트 0x1f4(500) · next 0xf5`,
  <0 이면 `S+0x50=1 · 0xa305d(S) · 0x204e1(g,2,0) · S+0xb3++(연차) · S+0x187=0 · …`.
- 대회 초기화 `0xb7bf0(L)` 도 `+0xac` 를 안 건드린다: `L+0xae/0xaf=0xf · L+0xa8..ab = 10,11,12,13 · L+0xb0..b7 = 0 · L+0xad = 4 · L+0xc4 = 0xf` (b7bf0~b7c40).

### 1-3. 나리와의 비대칭 = 버그의 모양
- 나리는 대회 끝 `0x1b92c` 의 **두 가지 모두**에서 0 을 쓰고(`0x1b9ea`, `0x1baa0`), 새 시즌 `0x1b768` 머리에서 또 0 을 쓴다.
  `0x1b92c` 의 호출자는 `0x1cdec`(나리 장면) **하나뿐** → 시즌모드에서는 절대 안 불린다.
- 시즌모드의 같은 자리 `0x896c` → `0x6e0c` 에는 그 한 줄이 빠져 있다. **복붙 누락형 원본 버그**로 읽힌다.

### 1-4. 새는 결과 (증상)
경기 뒤 재진입 `0x4b50`(시즌 장면)의 판정 순서:
```
0x4b8c  r2 = S+0x50
        r2 == 6 || r2 == 7  → next 0xee(238)
        r2 == 0x10          → next 0xf0(240)
0x4bc2  S+0x12c != 0        → next 0xf3(243)   ← 국가대항전 대진표
0x4bd6  그 밖               → 정규 시즌 흐름(S+0xb4 / S+0xb2 …)
```
대회가 끝난 뒤에도 `S+0x12c` 가 1 로 남으므로, 그 다음 시즌의 **모든 경기가 끝날 때마다 243(국가대항전 대진표)로 빠진다**.
바로 다음 화면은 `S+0x50`(6/1)에 걸려 넘어가므로 대회 직후 1~2 화면은 멀쩡하고, 정규 경기가 시작되면 새기 시작한다.
`0x83cc` 의 −16 키 가지(`0x845a~0x8478`)도 같은 플래그를 보므로 목록 화면의 뒤로가기가 215 대신 244 로 간다.

**판정: 확정.** 근거는 전수 스캔(쓰기 15곳 전부 위 표) + 끝 경로 `0xe6f8 → 0x896c → 0x6e0c` 전 구간 확인.
**이식 지침**: MEMORY 의 "원본 버그도 그대로 이식" 에 따라 웹판도 리셋을 넣지 않는 것이 원칙이나,
이 건은 그대로 두면 시즌이 진행 불가에 가까워진다 → **_DECISIONS 급 판단이 필요한 항목**으로 올려 둔다(여기서 고치지 않음).

## 2. U-19 — 대회 뒤 대표팀 명단 복구 : **확정 — 되돌리지 않지만 되돌릴 필요가 없다**

### 2-1. 대표팀은 리그 팀 배열과 **다른 슬롯**이다 (핵심)
팀 레코드 얻기 `0x1f9a8(g, 모드, 팀i)` → 점프표 `0xcd7e0`[모드−1]:

| 모드 | 가지 | 블록 | 평시 팀 i | 국가대항전 중(`S+0x12c`≠0) |
|---|---|---|---|---|
| 1 | `0x1f9d2` | `[g+0xb0]+0x29` 로 갈라짐 → `0x1f874` | — | — |
| **2 (시즌)** | `0x1f9ba` → **`0x1f570`** | `[g+0xb4]` | `base + 0x1c*i + 4` | i==10 → **`base+0x918`** / 그 밖 → **`base+0x934`** |
| 3 (나리 투수) | `0x1f9ca` → `0x1f940` | `[g+0xb8]` | 〃 | 〃(블록만 다름) |
| **4 (나리 타자)** | `0x1f9c2` → **`0x1f8f8`** | `[g+0xbc]` | `base + 0x1c*i + 4` | i==10 → **`base+0xbc4`** / 그 밖 → **`base+0xbe0`** |
| 5·6·7 | `0x1fa1e` | 없음(0 반환) | | |
| 8 | `0x1f9ee` | | | |
| 9 | `0x1fa06` | | | |

`0x1f570` 본문 (1f58a~1f5ac):
```
r0 = S ;  if (S[0x12c] != 0) { r0 = base + (i==10 ? 0x918 : 0x934) }
          else                 r0 = base + 0x1c*i + 4
```
→ **대회 중에는 팀 10 = 대표팀 슬롯, 나머지 전부 = 상대국 슬롯 하나**로 바뀐다.
그래서 `0x1a090` 이 팀 10 에 내 선수를 끼워넣어도 **리그 9팀 레코드는 애초에 건드려지지 않는다.**

### 2-2. 대회가 시작될 때마다 대표팀 슬롯을 새로 만든다
`0xb7bf0`(국가대항전 초기화, 나리 `0x1a0ea`·시즌 242 들어옴 `0xe5f8` 둘 다 호출) 끝부분:
```
0xb7c72  0x205c1(g, [0x1552d10]=현재 모드)      ← 대표팀 슬롯 재생성
0xb7c82  T = 0x1f9a9(g, 모드, 10)
0xb7c88  0xb6191(T)                            ← 투수 스태미나 전원 10000
```
`0x205c0(g, 모드)` (205c0~20632):
- 모드 2 → `base=[g+0xb4]`, 슬롯 `+0x918` / 모드 3 → `[g+0xb8]`, 모드 4 → `[g+0xbc]`, 슬롯 `+0xbc4`
- `memset(슬롯, 0, 0x1c)` (`0x1400428`)
- `src = 0x1f8c0(g, 10)` = `[g+0xac] + 0x1c*10 + 0xac0` = **마스터 팀 데이터**
- `0x1fe5c(g, &src, &dst, 0)` = 팀 레코드 깊은 복사(헤더 0xc + 로스터 배열)
→ **매 대회마다 팀 10 원본에서 명단을 새로 만든다. 누적되지 않는다.**

### 2-3. 대회 끝에 하는 일 / 안 하는 일
`0x1b92c`(나리 대회 끝) 두 가지 모두:
```
0x1b9f2 / 0x1baa0  S+0x12c = 0
0x1b9f4~0x1ba16    r2 = ([this+0xcc] == 4)      ; 0xcc = 모드(4=나리 타자)
                   0x1faa1(g, r2 ? 0 : 1, 1)    ; 내 선수 포인터 다시 찾기
```
= **명단에서 내 선수를 빼는 호출은 없다.** 하는 일은 `S+0x12c` 를 내려 팀 얻기 함수가 다시 평시 배열을 가리키게 하고,
내 선수 포인터(`g+0x38`)를 원래 팀 레코드 쪽으로 다시 잡는 것뿐이다. 슬롯 자체는 그대로 남지만 다음 대회에서 덮어써진다.

### 2-4. 곁가지 두 개 (원본 그대로 둘 것)
- **누수**: `0x205c0` 은 헤더 0x1c 바이트만 `memset` 하고 옛 로스터 배열을 `0xb4d9d`(팀 소멸자)로 놓아주지 않는다 (205e0~205f8 에 호출 없음).

  → 대표팀·상대국 슬롯은 일반 팀과 같은 자격의 저장 대상이다.

## 3. U-20 — 선수 `+0xa` 의 비트 `0x20` / `0x40` : **확정**

### 3-1. 원본 데이터로 직접 확인
선수 레코드는 Xls 표의 한 줄 그대로다 (`rowSize = 48 = 0x30`, `+0 = id`, `+1..` = CP949 이름).
`base/work/jar/data/*.zt1` 을 풀어 각 줄의 **10번째 바이트(`+0xa`)** 를 세어 보면:

| 표 | 줄 수 | `+0` (id) | **`+0xa`** |
|---|---|---|---|
| `XlsPITCHER_DATA` | 120 | 0 ~ 119 | `0x00 + (0..7)` 이 15번 되풀이 — 상위 3비트 **000** |
| `XlsBATTER_DATA` | 180 | 0 ~ 179 | `0x20 + (0..11)` 이 15번 되풀이 — 상위 3비트 **001** |
| `XlsACE_BAT_DATA` (마타자) | 5 | 245~249 (`0xf5..0xf9`) | `0x40 + (0..4)` — **010** |
| `XlsACE_PIT_DATA` (마투수) | 5 | 240~244 (`0xf0..0xf4`) | `0x60 + (0..4)` — **011** |

(헤더 길이 = 파일 길이 − 줄수·48 = 32(22칸)·33(23칸). zlib 스트림은 파일 +8 부터.)

### 3-2. 그래서 `+0xa` 의 구조
```
bit7  0x80 : 육성(내) 선수 · 명예의전당 선수      ← 0xb6388(P) 가 이 비트만 본다
bit6  0x40 : 마선수(ACE)                          ← 0xb633c(P) 가 이 비트만 본다
bit5  0x20 : 종류 보조 비트
bit4..0    : 번호  ← 0xb6394(P) = P[0xa] & 0x1f
```
**bit6:bit5 두 비트가 선수 종류 코드**다:

| 코드 | 뜻 | 하위 5비트 |
|---|---|---|
| `00` (0x00) | 일반 **투수** | 팀 안 투수 칸 **0~7** (8명/팀 × 15팀) |
| `01` (0x20) | 일반 **타자** | 팀 안 타순 칸 **0~11** (12명/팀 × 15팀) |
| `10` (0x40) | **마타자** | 마선수 순번 0~4 |
| `11` (0x60) | **마투수** | 마선수 순번 0~4 |

→ **U-20 답: `0x40` = 마선수 표시, `0x20` = (마선수가 아닐 때) 타자 표시 / (마선수일 때는 마투수 표시).**
표로 외우는 편이 정확하다: 종류 = `(b>>5) & 3`.

### 3-3. 투수 판정 `0xb6278(P)` — 식 확정
```
b = P[0xa] ; id = P[0]
if ((b & 0x60) == 0x60) return 1                  ; 마투수
if (id != 0xfe && id > 0xb3)  return (id <= 0xc7) ; 0xb4..0xc7 = 명전 투수 → 1, 0xc8.. = 명전 타자 → 0
                                                   ; (마선수 id 0xf0..0xf9 중 마타자는 여기서 0)
if (b & 0x20) return 0                            ; 일반 타자
if (b & 0x40) return 0                            ; 마타자
return 1                                          ; 일반 투수
```
= **투수 ⟺ bit5 == bit6**. 3-2 의 표와 정확히 맞는다 (b6278~b62b0).
id 구간: `0x00..0xb3` 일반(표 색인) · `0xb4..0xc7` 명예의전당 투수 20명 · `0xc8..` 명예의전당 타자 ·
`0xf0..0xf4` 마투수 · `0xf5..0xf9` 마타자 · `0xfe` 내 선수.
J-3 이 "마타자 면제" 로 적은 것은 **틀렸다** → 정정 절 참고.

### 3-4. 하위 5비트를 다시 쓰는 곳
`0xb6604(P, i)`: `P[0xa] = (P[0xa] & 0xe0) | (i & 0x1f)` — 상위 3비트(종류)는 보존하고 번호만 갈아끼운다.
로스터에서 자리가 바뀔 때마다 불린다(`0xb53f0` 안에서만 3번). 그래서 대표팀에 끼워넣은 뒤의 하위 5비트는
"지금 이 팀에서의 칸" 이고, 원본 표의 "팀 안 칸 번호" 와 같은 뜻으로 유지된다.

### 3-5. 대표팀 끼워넣기가 이 비트를 쓰는 방식 (P5 2절 보강)
`0xb6720(P, 마스크, &k)` — 확정 (b6720~b6744):
```
if ((s8)P[0xa] & 마스크) { *k = P[0xa] & 0x1f ; return 1 }
else                      { *k = -1           ; return 0 }
```
- **투수 `0xb521c(T,P,1)`**: `0xb6720(P, 0x60, &k)` = **마투수인가** → 맞으면 8번 칸.
  `T+0xc > 8` 이고 8번 칸 선수도 마투수(`0x60`)면 그 자리를 덮어쓴다. 아니면 한 칸 늘려 끼워넣는다.
  그 다음 `0xb6720(P, 0x80, &k)` = 내 선수 → k 칸.
- **타자 `0xb53f0(T,P,1)`**: `0xb6720(P, 0x40, &k)` = **마선수인가**(마타자) → 9번(첫 벤치) 칸, 같은 규칙.
  그 다음 `0x80`(내 선수) → k 칸, 마지막으로 `0x20`(일반 타자) → k 칸(같은 모양, b5532~b55dc).
- **죽은 가지**: `0xb547e` 에서 `0x80` 이 거짓이면 `0xb548e` 가 `0xc0` 로 한 번 더 묻는다.
  `0x40` 은 이미 위에서 걸러졌으므로 `0xc0` 검사는 `0x80` 검사와 결과가 늘 같다 → **도달 불가능한 중복 검사**(원본 그대로 둘 것).

**판정: 확정** (원본 데이터 4표 + `0xb6278`·`0xb6720`·`0xb6604` 식).

## 4. U-21 — 영입으로 밀려난 선수의 처리 : **확정 — 빠지지 않고 로스터 맨 끝으로 밀린다**

### 4-1. `0xb6720(P, 마스크, &k)` — 식 확정 (b6720~b6744)
```
if ((s8)P[0xa] & 마스크) { *k = P[0xa] & 0x1f ; return 1 }
else                      { *k = -1           ; return 0 }
```
(`ldrsb` 로 읽지만 쓰는 마스크가 0x20/0x40/0x60/0x80/0xc0 뿐이라 부호확장은 결과를 안 바꾼다.)

### 4-2. 영입이 부르는 순서 (R13 9절 이어서, c554~c5cc)
```
0xb6604(원본, (s8)j)     ; 원본 레코드의 +0xa 하위5비트 = 고른 자리 j   ← 3-4 의 그 함수
투수: 원본+0x2c = 0x2710 ; 0xb6cc4(원본) ; T = 0x1f570(저장, S[1]=내 팀) ; 0xb521c(T, 원본, 0)
타자: 0xb8e28(원본)      ;                                              ; 0xb53f0(T, 원본, 0)
```
영입 대상은 **나리 기록(`0x22168`/`0x220ec`)과 명예의전당(`0x1f62c`/`0x1f640`)** 뿐이라
`+0xa` 의 종류 코드가 `0x40`·`0x60`(마선수) 인 경우는 **영입에서 일어나지 않는다.**
따라서 `0xb521c`/`0xb53f0` 의 첫 검사(`0x60` / `0x40`)는 영입에선 늘 거짓이고,
`0x80`(육성·명전) 가지 또는 종류 비트가 없는 **마지막 기본 가지**로 간다. 둘은 동작이 같다.

### 4-3. 그 가지가 하는 일 — 확정
**투수 `0xb521c` (b52ce~b5344, 기본 가지 b5302~b533c 도 동일):**
```
0xb4e34(T, 1)                                   ; 투수 배열을 한 칸 늘린다 (T+0xc ++, realloc)
src = 0xb51fc(T, k)                             ; k 번 칸
memcpy(T[0x14] + 0x30*(T+0xc) − 0x30, src, 0x30); 옛 k번 선수를 **맨 끝 칸**으로 복사
memcpy(0xb51fc(T, k), 새선수, 0x30)             ; k 칸에 새 선수
if (flag) 0x1faa1(...)                          ; 영입은 flag=0 → 안 함
```
**타자 `0xb53f0` (b549e~b552e, `0x20` 가지 b5532~b55dc 도 같은 모양):**
```
0xb4e34(T, 0)                                   ; 타자 배열 한 칸 늘림 (T+0x10 ++)
old = 0xb53d0(T, k) ; old 없으면 그냥 끝
pos = old[0x1c] & 0xf                           ; 밀려날 선수의 수비 위치
0xb8e85(old, 0, 0)                              ; 그 선수 수비 위치 = 0
0xb6605(0xb53d0(T,k), T+0x10 − 1)               ; 그 선수 칸 번호 = 마지막
memcpy(T[0x18] + 0x30*(T+0x10) − 0x30, …, 0x30) ; 맨 끝 칸으로 복사
memcpy(0xb53d0(T,k), 새선수, 0x30)              ; k 칸에 새 선수
0xb8e85(0xb53d0(T,k), pos, 0)                   ; 새 선수 수비 위치 = 밀려난 선수의 자리
```
→ **U-21 답: 영입은 "교체" 가 아니라 "끼워넣기" 다.**
로스터 길이가 매 영입마다 **1 늘어나고**, 고른 자리 j 에 있던 선수는 **맨 끝(벤치 마지막)으로 옮겨질 뿐 빠지지 않는다.**
정원 상한도 없다 (`0x60`/`0x40` 가지에만 8번·9번 칸 덮어쓰기가 있는데 영입은 그 가지를 안 탄다).
R13 9절의 "정원 안에서는 늘려 붙이고 넘치면 마지막 자리를 덮어쓴다" 는 **틀렸다** → 정정 절.

### 4-4. 곁가지 (원본 그대로 둘 것)
- **진짜 교체 함수는 따로 있다**: `0xb5648(T, P, j)` = j 칸을 P 로 덮어쓰고 수비 위치·칸 번호를 되돌려 놓는다(b5652~b5680).
  로스터가 안 늘어난다. 부르는 곳은 `0xcf24` 하나뿐이고 **영입은 이걸 안 쓴다.**
- **투수 쪽만 뒷정리가 빠졌다**: 타자 가지는 밀려난 선수의 칸 번호를 `0xb6605` 로 고쳐 주는데
  투수 가지에는 그 줄이 없다 → 밀려난 투수와 새 투수가 **같은 `+0xa` 하위 5비트**를 갖게 된다.
  배열 접근(`0xb51fc`)은 첨자로만 하므로 경기에는 영향이 없다(표시용 칸 번호만 어긋난다).
- **원본 레코드가 바뀐다**: `0xb6604(원본, j)` 는 저장된 명예의전당/나리 기록의 `+0xa` 를 실제로 고친다(상위 3비트는 보존).
  다음 영입 때 그 값이 남아 있다.

**판정: 확정** (`0xb6720` 식 + `0xb521c`/`0xb53f0` 두 가지 전 구간 + 영입 호출부 `0xc554~0xc5cc`).

## 정정 (앞 노트를 뒤집는 것)

1. **P5 "남은 것" — "대회 뒤 대표팀 명단을 안 되돌리면 CPU 팀 로스터가 영구히 뒤섞인다"**
   → **성립하지 않는다.** 대회 중에는 팀 얻기 함수 `0x1f570`/`0x1f8f8` 이 팀 10 을 **별도 슬롯**
   (`base+0x918` / `base+0xbc4`)으로, 나머지 팀을 전부 상대국 슬롯 하나로 바꿔 준다.
   리그 9팀 레코드는 애초에 건드려지지 않는다. 게다가 대회가 시작될 때마다 `0xb7bf0 → 0x205c0` 이
   그 슬롯을 마스터 데이터에서 새로 만든다. (본문 2절)

2. **P5 2절 — "선수 `+0xa`: bit7 = 내 선수, bit6/5 = 다른 표시(미해결), 하위 5비트 = 로스터 칸 번호"**
   → bit6:bit5 는 **선수 종류 코드**다: `00` 일반 투수 · `01` 일반 타자 · `10` 마타자 · `11` 마투수.
   원본 Xls 4표에서 직접 확인했다. (본문 3절)

3. **P5 2절 — "투수 `0xb521c`: `P+0xa & 0x60` 이면 …"** 의 뜻
   → 그 조건은 "**마투수인가**" 다. 타자 쪽 `& 0x40` 은 "**마선수(마타자)인가**".
   영입으로 들어오는 선수(나리·명예의전당)는 이 가지를 절대 타지 않는다. (본문 4-2)

4. **J-3(= `J-modes-rules.md:252`, `_raw/notes/J-modes-rules.md:98`) — "마타자 면제: `0xb6278` 이 `[p+0xa]&0x60==0x60` 이나 id `0xb4..0xc7` 도 참으로 본다 → 마선수·특수 id 는 '투수' 쪽으로 빠져 벌점을 안 받는다"**
   → **틀렸다.** `(b&0x60)==0x60` 은 **마투수**뿐이고 마타자는 `0x40` 이라 이 조건에 안 걸린다.
   마타자는 id `0xf5..0xf9 > 0xc7` 가지로 가서 **0(타자)** 을 돌려준다. id `0xb4..0xc7` 은 명예의전당 **투수** 20명이다.
   즉 `0xb6278` 은 예외 없는 "투수인가" 판정이고, 마타자는 정상적으로 타자로 분류된다.
   "마타자는 보직 벌점 면제" 라는 설명서 문구는 **다른 코드에서 찾아야 한다**(이 함수가 근거가 아니다). → 새 미해결.

5. **R13 9절 — "밀려난 선수 (유력): 정원(투수 9명) 안에서는 자리를 늘려 붙이고, 넘치면 마지막 자리를 덮어쓴다"**
   → **틀렸다.** 덮어쓰기는 마선수 가지(`0x60`/`0x40`)에만 있고 영입은 그 가지를 안 탄다.
   영입은 늘 **로스터를 한 칸 늘리고 고른 자리의 선수를 맨 끝으로 밀어낸다** — 정원 상한도, 빠지는 선수도 없다. (본문 4절)

6. **R13 9절 — "선수 = `0xb6604(원본, (s8)j)` ; 원본 기록 → 시즌 선수 만들기"**

## 요약

U-18~U-21 **네 건 모두 확정**으로 닫혔다.

- **U-18**: 시즌모드에는 `S+0x12c` 를 0 으로 되돌리는 코드가 **없다**. `0x12c` 를 만드는 코드 모양이
  `movs #0x96 ; lsls #1` 하나뿐이라 전수 스캔이 가능했고, 쓰기 15곳을 전부 확인했다.
  나리는 `0x1b92c` 의 두 가지와 `0x1b768` 에서 세 번이나 내리는데 시즌모드의 같은 자리
  (`0xe6f8 → 0x896c → 0x6e0c`)에는 그 줄이 없다. 남으면 경기 뒤 재진입 `0x4b50` 이 매번 243(대진표)으로 샌다.
  **원본 버그이되 시즌 진행을 막는 급이라 이식 판단이 필요하다.**
- **U-19**: 되돌리지 않지만 **되돌릴 필요가 없다.** 대회 중 팀 10 은 리그 배열이 아닌 별도 슬롯
  (`base+0x918`, 나리는 `+0xbc4`)이고, 대회를 시작할 때마다 `0xb7bf0 → 0x205c0` 이 마스터 데이터에서 새로 만든다.
  P5 가 걱정한 "CPU 로스터 영구 오염" 은 일어나지 않는다.
- **U-20**: `+0xa` 의 **bit6:bit5 = 선수 종류 코드**(00 투수 · 01 타자 · 10 마타자 · 11 마투수),
  bit7 = 육성/명전 선수, 하위 5비트 = 팀 안 칸 번호(타자 0~11 · 투수 0~7) 또는 마선수 순번(0~4).
  원본 `XlsPITCHER_DATA`·`XlsBATTER_DATA`·`XlsACE_*_DATA` 를 풀어 **데이터로 직접 확인**했다.
  덕분에 `0xb6278` = "투수인가" 의 식이 완전히 풀렸고, J-3 의 "마타자 면제" 해석이 틀렸음도 드러났다.
- **U-21**: 영입은 교체가 아니라 **끼워넣기**다. 로스터가 한 칸 늘고 고른 자리의 선수는 맨 끝으로 밀릴 뿐
  빠지지 않는다. 정원 상한도 없다. 진짜 교체 함수(`0xb5648`)가 따로 있는데 영입은 그걸 안 쓴다.

"포스트시즌 플래그" 주석만 사실과 다르다. 새로 생긴 미해결 3건은 위 표에 적었다.

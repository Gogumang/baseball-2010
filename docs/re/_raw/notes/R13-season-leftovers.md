## 요약
P4 가 "미해결" 로 남긴 시즌모드 잔여를 **전부 풀었다**(한 가지만 빼고).
**확정**: ① 세 번째 점프표 **0xcc024 = 장면 0x105 의 상태별 그리기 표**(51칸, 0xe9ac 의 4단계) — 절반은 공통 화면 틀 0x9f60 하나로 가고, 나머지 21개 함수에 이름을 붙였다.
② **0xd4 = 연초 "올해의 목표" 이벤트**(나리 115 와 같은 0x8a680, 조건 SR+0x1bc==0 && SR+0x187==0, 다음 0xd3 → 뒤 0xc9).
③ **0xd9/0xda = 선수 기본정보 카드 ↔ 능력치 상세 창**(나리 119/120 과 같은 쌍, 글 만들기는 시즌판 0x897e8).
④ **0xdd = 경기 직전 경기정보 화면**(메인 메뉴 22 상당, '0' 으로 경기진행 설정 창, 확인하면 **SR+0x1a0 평판 기록 16칸을 0 으로** 지우고 경기 시작), **0xe0 = 엔트리 편집**(22↔23 좌우 밀기 쌍), **0xe1 = 경기 장면 0x104 로 넘기는 전환**(세 표 모두 빈 칸, 0xa1d0 만).
⑤ **0xde = 팀 트레이닝/지옥훈련 연출**(팝업 0x11·0x12 → 캐릭터 만들고 0x848d0 훈련 팝업 → 애니 끝 → 0xc074 굴림 → 팝업 0x13 → 0xc9).
⑥ **0xfa = G포인트 충전 페이지**(나리 139 와 같은 화면, 팝업 코드 2, 🌐 서버라 이식 대상 아님).
⑦ **포스트시즌 = 4팀·3라운드 계단식**(3위v4위 5전3선승 → 2위 5전3선승 → 1위 7전4선승), 칸은 L+0x38~0x43, **리그 레코드 L = SR + 0x80**.
⑧ **선수영입 원본 고르기**: 메뉴 칸 k → `0 나리 투수 / 1~4 명예 투수 / 5 나리 타자 / 6~ 명예 타자`, 쪽 = (k>4).
⑨ **구내매점 SR+0x55 는 경기 뒤 평가 0x8a6fc 에서 시즌모드일 때만 −1**, 0 이 되면 StrUSER_EVT[113] "구내매점 사용 기간이 끝났습니다" 팝업.
⑩ **히든 0x29 = 컬렉션 "오토봇 배트"** — 나리 투수편·나리 타자편·시즌 세 기록의 +0x7a(정규시즌 1위 횟수)가 모두 > 0 이면 열린다. 셋째 인자 0 = 중복 알림 막기 검사를 함.
**정정**: P4 5절의 "가격표 뒤 44칸 = 투수 쪽" 은 **타자 쪽**이다(컬렉션 이름이 증거 — A=0 머리띠/글러브/선글라스/신발=투수, A=1 헬멧/배트/밴드/부츠=타자). P4 표의 "그림" 열은 0xedb6 나무이고 진짜 그리기는 0xcc024 다. 선수영입의 "앱+0x12c/0x130" 은 목록객체 오프셋이다.
**남은 것**: 상태 **0xf4**(국가대항전 중 0xdd 에서 CLR 로 갈 수 있는데 나가는 길이 없다 — 원본 버그로 보임), 영입으로 밀려난 선수 처리 세부(0xb6720 판정), 0xfa 에서 빠져나오는 전이.
웹판은 시즌모드가 통째로 없고(mainMenu.ts:30), 포스트시즌 식만 `entities/league/model/league.ts:75-119` 에 원본과 같은 값으로 들어가 있다(나리 쪽에서만 쓴다).

## 1. 세 번째 점프표 0xcc024 = **장면 0x105 의 상태별 그리기 표** — 확정

**어디서 쓰나 (확정)**: 0xcc024 는 갱신 함수 **0xe9ac 안**에 있다. 0xe9ac 는 P4 1a 가 적은 3단계 뒤에 **4단계(그리기)** 를 더 돈다:

```
0000ef70~0000efa8  (상태별 덧그림: 상태 0xd8 계열 0xca9fc(…,0x1552ae0,…,0x65e81)
                    · 상태 0xe2 면 0x669c0([this+0xa8]))
0000efaa: 0x b810(this)          ; 공통 앞그림
0000efb0: r3 = [this+0x1c]       ; 현재 상태
0000efb2: r3 -= 0xc8 ; cmp 0x32 ; bls
0000efba: r2 = 0xcc024 ; r3 = [r2 + r3*4] ; mov pc, r3      ← 51칸 점프표
   각 칸 = 8바이트 토막 `adds r0,r7,#0 ; bl <그리기> ; b 0xf108`
0000f108: 공통 뒷그림([0x140005c] → 0x746cc, [0x1400068] …)
```
즉 P4 의 "그림 = 0xedb6 나무" 는 **그 앞의 배경 고르기 나무**이고, **0xcc024 가 진짜 상태별 그리기 표**다. 두 표는 다른 것이다.

## 2. 상태 0xd4 = **연초 "올해의 목표" 이벤트** — 확정

**들어오는 곳 (확정, 0x4ffc~0x5028 = 상태 0xc9 갱신 끝)**
```
SR = [this+0xa0]
[SR + 0x1bc] == 0  (0xde<<1)  그리고
[SR + 0x187] == 0  (0x1bc − 0x35)   →  0xbcb48(this+0x18, 0xd4)
```
**하는 일 (확정, 갱신 0xc038)**
```
0x8a680([this+0xf0] 이벤트 관리자, [this+0x15c] 모드)
0xbcb48(sm, 0xc9) ; 0xbcb48(sm, 0xd3)      → 다음 = 0xd3, 이전 = 0xc9
```
- **0x8a680 은 R9 7절(나리 상태 115 연초 처리)이 이미 푼 함수**다: 파일 이벤트가 아니라 **메모리에 내장 이벤트 두 줄**을 만든다 —
  ① 감독(캐릭터 2, 오른쪽) 대사 **StrUSER_EVT[1] "올해의 목표다!! 많이 달성할수록 1년 후 높은 보너스를 받을 수 있지!!"**,
  ② SYS(2, sub 1) = **올해의 목표 창**(0x741a0 팝업 id 0, 그리기 0x86fdc).
- 그래서 0xd4 자체는 **한 틀만 머무는 걸침 상태**다. 그리기(0x9f48)가 상태판 0x7d34c 하나뿐인 것과 맞는다 — 실제 화면은 곧바로 이어지는 **0xd3(이벤트 재생)** 이 그린다. 이벤트가 끝나면 이전 상태 0xc9(관리 메뉴)로 돌아온다.
- **나리와 다른 점(확정)**: 나리 115 는 `0xa4ee8(S)`(마이너스 스킬 해제 플래그 S+0x1d0~+0x1d7 지우기)도 하지만 **시즌 0xd4 는 하지 않는다**. 나리는 `[다음 114, 뒤 105]`, 시즌은 `[다음 0xd3, 뒤 0xc9]`.
- **한 해 한 번인 이유(확정)**: 목표 창이 닫히면 0x7fe90 이 **SR+0x187 = 1** 로 켠다(R9: "나리면 S+0x1b7, 시즌은 기록+0x187"). 새 해 초기화(0xa39a8 계열)가 다시 0 으로 되돌린다.
- **SR+0x1bc (유력)**: 10년차 엔딩 그리기 **0x8bd8** 안(0x8cf0~0x8d00)에서 `[this+0x140]==1` 이고 [0x140007c]+4 ≠ 0, +0x10 == 2 일 때 **SR+0x1bc = 1** 로 켜고 저장한다 → "엔딩까지 본 다 끝난 시즌" 표시. P4 진입 분기의 `SR+0x1bc != 0 → 0xc9` 와 여기의 0xd4 차단이 같은 플래그다.
- 웹판: 없음. (StrUSER_EVT[1] 은 `src/shared/config/original/userEvents.json` 에 있으나 연초 흐름은 미이식 — R9 7절과 같은 상태.)

## 5. 상태 0xde = **팀 트레이닝 / 지옥훈련 연출** — 확정

**들어오는 곳 (확정, 0x7570 = 0xedb6 나무의 상태 0xcf 가지)**
```
G = [0x140005c]                    ; 앱 전역(팝업 상태)
[G+9] != 0 (팝업 있음) 이고 (s8)[G+0x21c] == 0 (예/확인) 이면:
    [G+0x21c] = −1                 ; 답 소비
    코드 [G+0x248] == 0x11 또는 0x12  →  상태 0xde
    코드 [G+0x248] == 2              →  상태 0xfa  (7절)
```
- 팝업 **0x11 · 0x12 를 여는 곳은 상태 0xcf 의 키 0x9108**(J 4-6 트레이닝 가드): 0x9262 `0xbbef8(buf, 2, 0x12, 1)` (앞서 StrMODE[0x8d]=141 "지옥훈련 500G" 를 채움) · 0x9306 `0xbbef8(buf, 2, 0x11, 1)`. → **0x11 = 팀 트레이닝(칸 0~3), 0x12 = 지옥훈련(칸 4)** (유력: 문구 141 이 0x12 쪽에 붙는 것으로 갈림).

**화면 (확정, 갱신 0x5198 + 그리기 0xa0e4)**
```
t = [[this+0x84]+0x10] * [[this+0x84]+0x14] + [[this+0x84]+0xc]     ; 고른 훈련 칸(격자 열·행)
0x84664(gfx, t)                 ; 훈련 애니 파일·동작 고르기 점프표 5칸 (J 1절 — 0xd4990)
[this+0x114] 이전 캐릭터 지우기
t ≤ 1 이면 선수 캐릭터를 새로 만든다:
    t == 1 → 타자 객체 0x789f0 (크기 0x54, C 문서)     , 만든 뒤 obj+0x3c = 1
    t == 0 → 투수 객체 0x79368 (크기 0x4c, pitcher.mpl)
  [this+0xc0](gfx) + 0x16c = obj
  obj->vt[8](obj, (s8)[SR+1] 내 팀, 0, 0, 1, −1)       ; 우리 팀 유니폼
  obj+0x48 = 0
```
- 그리기 0xa0e4 = **공통 틀 + `0x848d0(gfx, 1, 0)`** = F 5절의 **훈련 팝업**(캐릭터 켬, 세로 보정 0 → 기준점 (120,137)). 공통 틀에서 가운데 판 0x7f814 를 빼는 네 상태(0xd3·0xde·0xe3·0xee) 중 하나다.

## 8. 포스트시즌 대진 · 라운드 수 — 확정

**먼저: 리그 레코드 L = SR + 0x80 (확정)** — P4·P5 가 따로 쓰던 두 오프셋이 같은 칸이다.
`SR+0x12c = L+0xac`(국가대항전) · `SR+0xb2 = L+0x32`(날짜/경기 수) · `SR+0xb4 = L+0x34`(포스트시즌) · `SR+0xb5 = L+0x35`(라운드) · `SR+0xb7 = L+0x37`(우승팀).

**대진표 칸 (확정)** — `0xb7648(L, r, side) = (s8)[L + 0x38 + r*2 + side]`
| 라운드 r | side 0 | side 1 | 남은 승수 L+0x3e+2r+side |
|---|---|---|---|
| **2 준플레이오프** | L+0x3c = 정규 3위 | L+0x3d = 정규 4위 | L+0x42·0x43 = **3, 3** → 5전 3선승 |
| **1 플레이오프** | L+0x3a = 정규 2위 | L+0x3b = **10**(빈 자리) | L+0x40·0x41 = **3, 3** → 5전 3선승 |
| **0 한국시리즈** | L+0x38 = 정규 1위 | L+0x39 = **10**(빈 자리) | L+0x3e·0x3f = **4, 4** → 7전 4선승 |
- 팀 번호는 0~9 이므로 **10 = 아직 안 정해진 자리**다.

**시작 0xb80a8(L) (확정)** — 정규시즌 45일이 끝나 `0xb818c` 가 부른다(P4 4b)
```
L+0x38 = 0xb802c(L,0,0)   ; 정규 1위        L+0x39 = 10
L+0x3a = 0xb802c(L,1,0)   ; 정규 2위        L+0x3b = 10
L+0x3c = 0xb802c(L,2,0)   ; 정규 3위        L+0x3d = 0xb802c(L,3,0) = 정규 4위
L+0x3e = L+0x3f = 4 ; L+0x40..L+0x43 = 3,3,3,3
L+0x35 = 2      ; 현재 라운드 = 준플레이오프부터
L+0x32 = 0      ; 날짜 0
L+0x37 = 0xf    ; 우승팀 미정
```
→ **포스트시즌은 4팀 · 3라운드(계단식), 총 최대 5+5+7 = 17 경기**.

**한 경기 뒤 처리 0xb76dc(L, 이긴 팀) 의 포스트시즌 가지 (확정, 0xb7724~0xb779e)**
```
L+0xac != 0 (국가대항전) → 다른 가지
L+0x34 == 0 (정규시즌)   → 다른 가지
r    = (s8)L[0x35]
side = (L[0x38 + 2r] == 이긴팀) ? 0 : 1
L[0x3e + 2r + side] -= 1                  ; 그 쪽 남은 승수
L[0x3e + 2r + side] != 0 → 여기서 끝(시리즈 계속)
시리즈가 끝났으면:
    L[0x35] = r − 1                       ; 라운드 번호가 내려간다
    L[0x32] = −1                          ; 하루 끝에서 +1 되어 날짜 0
    새 r' = L[0x35] 가 0 이상이면:
        L[0x39 + 2r'] = 이긴 팀           ; **승자가 윗 라운드의 side 1 자리로 올라간다**
    r' < 0 이면 (한국시리즈가 끝난 것):
        L[0x37] = 이긴 팀                 ; 우승팀
        L[0x36] = 1                       ; 포스트시즌 끝
```
- P4 4b 의 "리그+0x36 이면 StrMODE[137] 한국시리즈 우승! [SR+0xb7 이름]" 과 정확히 맞는다.
- 진 팀 쪽은 `0xb77e0(L, 진 팀)` 이 따로 처리한다(포스트시즌 순위 기록 — `0xb7aa0(L, 팀, 0)` 이 읽는 값, P4 4b 의 보상 표).
- 사람 팀이 낀 라운드가 아니면 상태 0xef 가 `0xc2760`(한 경기 시뮬) 을 **라운드 번호 L+0x35 가 바뀔 때까지** 반복한다(P4 4b) — 위 식대로 시리즈가 끝나야 라운드가 바뀌므로 "한 시리즈를 통째로 시뮬" 이 된다.
- 웹판: `src/…/leagueDay.ts` 는 정규시즌 하루만 옮겨져 있고 포스트시즌 대진·승수 칸은 없다(R1 4절).

## 9. 선수영입이 **원본 레코드를 고르는 규칙** — 확정 (P4 5절의 "유력" 을 확정으로)

```
점프표 0xcbe8c (5칸, u32) = [0xe3ce, 0xe3d6, 0xe400, 0xe41e, 0xe43e]

  1 → 나리 투수 · 2 → 나리 타자 · 3 → 명예 투수 · 4 → 명예 타자 (중복 검사 0xb5054/0xb50ac, P4 5절)
```
- **P4 가 "앱+0x12c" 로 적은 것은 실제로는 목록객체 `[this+0xa8] + 0x12c`** 이고, 명예 선수 번호도 `[this+0xa8] + 0x130` 이다(앱 전역이 아님).

**원본 레코드 고르기 (확정, 0xc4ea — 상태 0xdf 의 키 0xc3e8 안, this+0x110 == 3 가지)**
```
m = [this+0x9c]                                  ; 선수영입 화면의 커서 메뉴(0xe2 그리기가 쓰는 그것)
k = [m+0x10] * [m+0x14] + [m+0xc]                ; 고른 칸 번호
쪽 = (k > 4) ? 1(타자) : 0(투수)                  ; [sp] — 뒤에서 갈림에 쓰임
k == 0        → 원본 = 0x22168(저장)                        ; 나만의리그 투수 기록
k == 5        → 원본 = 0x220ec(저장)                        ; 나만의리그 타자 기록
1 ≤ k ≤ 4     → 원본 = 0x1f62c(저장, [[this+0xa8] + 0x130]) ; 명예의 전당 투수 i
k ≥ 6         → 원본 = 0x1f640(저장, [[this+0xa8] + 0x130]) ; 명예의 전당 타자 i
```
즉 **칸 배치는 `0 = 나리 투수, 1~4 = 명예 투수, 5 = 나리 타자, 6~ = 명예 타자`** 다(명예의 전당은 투수 2칸·타자 4칸, 슬롯 구매로 4·8 — H 문서).

**적용 (확정, 0xc554~0xc5cc)**
```
m2 = [[this+0xa8] + 0x41c]                       ; 팀 명단에서 고른 "바꿀 자리" 메뉴
j  = [m2+0x10] * [m2+0x14] + [m2+0xc]            ; 자리 번호 (s8 로 잘라 넘긴다)
선수 = 0xb6604(원본, (s8)j)                      ; 원본 기록 → 시즌 선수 만들기
투수(쪽 0): 선수+0x2c = 0x2710 (= 10000 스태미나) ; 0xb6cc4(선수)
            팀 = 0x1f570(저장, (s8)SR[1]) ; 0xb521c(팀, 선수, 0)
타자(쪽 1): 0xb8e28(선수) ; 0xb53f0(팀, 선수, 0)
→ 저장 ; StrMODE[180] "선수 영입을 완료하였습니다"
```
- 값을 그대로 베끼는 것이고 **비용·인기도 조건은 없다**(P4 5절 그대로).
- **밀려난 선수 (유력)**: 0xb521c(투수 넣기)는 `[팀+0xc]`(투수 수)가 8 을 넘으면 `0xb51fc(팀, 8)`(9번째 자리) 쪽을 먼저 보고, 그렇지 않으면 `0xb4e34(팀, 1)` 로 자리를 늘린 뒤 `팀+0x14 + 0x30*([팀+0xc]−1)` 에 0x30 바이트를 복사한다 → **정원(투수 9명) 안에서는 자리를 늘려 붙이고, 넘치면 마지막 자리를 덮어쓰는** 꼴이다. 0xb6720(선수, 0x60, …) 의 판정 내용은 못 읽었으므로 "되돌리기 없음" 까지만 확정, 정확한 밀어내기 규칙은 **미해결**.
- 웹판: 없음.

## 10. 구내매점 카운터 SR+0x55 가 줄어드는 곳 — 확정

**경기 뒤 평가 이벤트를 만드는 0x8a6fc** 안이다 (A 문서·웹 `gameEvaluation` 이 이미 아는 그 함수. 부르는 곳: **시즌 0xdea0 = 상태 0xe9 경기 뒤 관중·수입**, 나리 0x129fc = 상태 116).

```
0008afaa:  0x7b998([mgr+0xb4])  == 거짓 → 건너뜀      ; 0x7b998(x) = ([x+0x20] == 2) = **모드 2(시즌)일 때만**
0008afbc:  SR = [mgr + 0x2f8]
0008afc6:  (s8)[SR+0x55] <= 0 → 건너뜀
0008afd0:  [SR+0x55] -= 1
0008afdc:  줄인 값이 0 이 아니면 끝
           0 이면 이벤트 명령을 하나 더 붙인다:
               mgr+0x11(명령 수) += 1
               새 명령 8바이트(0xac8b4) : type 2 = SYS, sub 5, arg(u16) = 0
```
- **SYS sub 5** (실행기 하위표 0xd4ee4[5] = **0x8d41e**) → `0x8b1b8(mgr)` → 글 표 **data/StrUSER_EVT** 의 **[0x71 = 113]** 을 mgr+0xba 로 복사하고 팝업을 연다.
- **StrUSER_EVT[113] = `!C[!cFFFF00구내매점!cFFFFFF] 사용!N기간이 끝났습니다.`** (`base/extracted/StrUSER_EVT.json:114번째 항목`) — 문구까지 맞는다.

**정리 (확정)**: 구내매점은 **살 때 SR+0x55 = 45**(P4 6절, 구장 아이템 칸 6) → **시즌모드 경기가 끝날 때마다 1 씩 줄고**, 0 이 되는 그 경기의 평가 이벤트 끝에 "구내매점 사용 기간이 끝났습니다" 팝업이 붙는다. 남아 있는 동안 경기 수입 +2(=200만, 0xa3644). **45 = 정규시즌 45경기 = 딱 한 시즌**.
- 같은 함수 안에서 줄어드는 다른 칸은 없다(서브 아이템 SR+0x58+칸·자동안마기 SR+0x5c 는 기간 제한이 없다 — 확정).
- 웹판: 없음.

## 11. 0x6900 첫머리 히든 **0x29 오픈 조건** = 컬렉션 "오토봇 배트" — 확정

**조건 (확정, 0x6944~0x69d2 — 상태 0xef 갱신 = 시즌 결산에 들어갈 때마다)**
```
0x9f69c(저장, 1, 1, 2) != 0  →  건너뜀                ; 이미 얻었으면
0x213c0(저장, 3, 1) ; a = (s8)[0x1f8d4(저장,3) + 0x7a] ; 0x1f24c(저장, 3)   ; 나만의리그 **투수편** 기록
0x213c0(저장, 4, 1) ; b = (s8)[0x1f8d4(저장,4) + 0x7a] ; 0x1f24c(저장, 4)   ; 나만의리그 **타자편** 기록
c = (s8)[SR + 0x7a]                                                        ; 지금 시즌 기록
a > 0 이고 b > 0 이고 c > 0  →  0x62368([0x1552cfc] ui, 0x29, 0)
```
- 저장칸 번호는 K 3절이 이미 확정한 것: **2 시즌 · 3 나만의리그 투수 · 4 나만의리그 타자**. `+0x7a` 는 P4 4b 의 **정규시즌 1위 횟수**.
- 즉 **세 모드(나리 투수편·나리 타자편·시즌)에서 모두 정규시즌 1위를 한 번이라도 해야** 열린다. P4 의 짐작이 맞았다.

**세 번째 인자 0 의 뜻 (확정)** — `0x62368(ui, k, force)`
```
force == 0 이면:  k == −1 → 그냥 0 ; 0x61f5c(ui, k)(이미 열려 있나) 가 참이면 그냥 0
그 밖: 컬렉션 항목 k 를 열고 알림 창을 만든다
       0x620b8(ui, k)                       ; 오픈 비트 쓰기
       0x61e8c(ui, StrITEM 표, k)            ; 이름
       StrMAINMENU[0x8c](k ≤ 7) / [0x8a](k ≤ 0xc) / … 로 문구
```
→ **0 = "보통"(중복 알림 막기 검사를 거친다), 0 이 아니면 검사를 건너뛰고 무조건 연다.**

**항목 0x29 = 무엇인가 (확정)**
- 오픈 비트 쓰기 0x620b8 의 k = 0x27~0x2a 가지: `0x9f6ac(저장, 1, 1, k − 0x27, 1)`, 읽기 0x9f69c 와 짝.
  - `0x9f69c(save, A, B, C) = save[0xc0 + 16A + 4B + C]` · `0x9f6ac(save, A, B, C, v)` 가 같은 칸에 쓴다 (확정).
- 이름 0x61e8c 의 같은 가지: **StrITEM[k − 0x15]** → k = 0x29 → **StrITEM[20] = "오토봇 배트"**.
- 컬렉션 k ↔ 히든 장비 칸 전체 표 (확정, 0x620b8 · 0x61e8c):
| k | (A, B, C) | StrITEM | 이름 4개 |
|---|---|---|---|
| 0x13~0x16 | (0, 0, k−0x13) | k+0x20 | 토끼 머리띠 · 해적 선장모 · 사신의 두건 · 로얄 크라운 |
| 0x17~0x1a | (0, 1, k−0x17) | k+0x27 | 청옥의글러브 · 해적의글러브 · 사신의글러브 · 황금의글러브 |
| 0x1b~0x1e | (0, 2, k−0x1b) | k+0x2e | 선글라스 · 스카우터 · 사신의 눈 · 오페라마스크 |
| 0x1f~0x22 | (0, 3, k−0x1f) | k+0x35 | 토끼털 신발 · 선장의 신발 · 사신의 신발 · 황제의 신발 |
| 0x23~0x26 | (1, 0, k−0x23) | k−0x1c | 바이커 스컬 · 검투사 투구 · 프라임 헬멧 · 천상의 헬름 |
| **0x27~0x2a** | (1, 1, k−0x27) | k−0x15 | 폭주의 배트 · 글라디우스 · **오토봇 배트(0x29)** · 광휘의 배트 |
| 0x2b~0x2e | (1, 2, k−0x2b) | k−0xe | 바이커 밴드 · 검투사 밴드 · 프라임 밴드 · 천상의 밴드 |
| 0x2f~0x32 | (1, 3, k−0x2f) | k−7 | 바이커 부츠 · 플레이트부츠 · 트랜스폼부츠 · 이카로스슈즈 |
- **P4 5절 정정**: 가격표 0xcbca8 의 "뒤 44칸(앱+0x24c ≠ 0)" 은 **투수가 아니라 타자 쪽**이다. 이름이 증거다 — A = 0 이 머리띠·글러브·선글라스·신발(투수), **A = 1 이 헬멧·배트·밴드·부츠(타자)**. 따라서 부위 B 는 **0 머리 · 1 손(글러브)/배트 · 2 눈(선글라스)/손목밴드 · 3 신발** 이고, 히든 아이템 C = 아이템 번호 7·8·9·10 에 대응한다.
- 정리: **"오토봇 배트" = 타자 배트 부위의 히든 아이템 9번**이고, 세 모드 모두 정규시즌 1위를 해야 얻는다.
- 웹판: 히든 장비 오픈 비트 자체가 없다(P4 5절).

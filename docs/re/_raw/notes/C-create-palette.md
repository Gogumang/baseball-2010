# 주제 C — 선수 등록 · 피부색 · 대체 팔레트

## 요약
**풀림(확정)**: 0xcaa00 은 `bx r5` 베니어이고 0x10810 은 그림 객체 vtable+8 = 타자 적재 0x78ab0 을 부른다. 몸통 팔레트 번호 = **피부×15 + 팀**
(bat/batter_*.mpl · pitcher.mpl 45개), 피부로 바뀌는 색 번호·RGB 표 작성, PNG 로 눈 검증. 선수 레코드 +0xb 전체 비트 배치
(bit0-1 포지션/보직 · bit2-3 피부 · bit4 손 · bit5-7 타입). 좌/우타 = bit4 = 0xb63c0 → side (0 우타·1 좌타). MPL 포맷 두 종류
(0x30 통팔레트 / 0x40 이미지별 변형)와 PZX 효과 0x05~0x64 = "붙은 0x40 mpl 의 (kind−5)번 변형" (0xc4e94·0xc8bb4) — UI 상태색이지 팀색이 아니다.
시작 능력치 식(0x16e2c, 웹과 일치). 등록 화면은 관리 화면 기본정보 카드(0x15e20)에 커서만 얹은 것(0x15f34), 커서 좌표 표 작성.
**등록 화면에 타순 선택은 없다** — 타순 칸은 표시 전용, 신인 9번은 0xa4c2c.
**남음**: 0x7E 효과 뜻(defender 이미지 0·19 전용, 그리기 분기 못 찾음), 커서 옆 화살표 스프라이트 세부, side 값이 그림 좌우 반전에 쓰이는 줄(+0x3c) 직접 확인, event_char_0.mpl 팔레트 2 의 쓰임.

## 1. 피부색 팔레트 — 확정
- 0xcaa00 은 함수가 아니라 `bx r5` 베니어다 (0xca9f0~ `bx r1..sl` 표). 0x10810 에서
  `r4=[this+0xe4]; r5=[[r4]+8]; bl 0xcaa00` = **그림 객체의 vtable+8 가상 호출**.
- 타자 객체 vtable 0xd3a3c = [0x789a1, 0x789b9, **0x78ab1**, 0x78cf9, 0x78cfd, 0x78fd9]. 생성자 0x789f0 (크기 0x54, [this+0xcc]==4 타자모드),
  투수모드는 0x79368 (크기 0x4c, pitcher.mpl 을 0x793b0 이 연다).
- 0x10810 이 넘기는 인자: r1 = ldrsb [[this+0xb0]+1] (팀), r2 = rec[0xb]>>4 (타입·손 니블), r3 = (rec[0xb]<<28)>>30 = **bit2-3 피부**,
  [sp] = u8 0xb63c0(rec) (손 → 객체 +0x3c), [sp+4] = −1 (마선수 아님).
- 0x78ab0 (타자 적재): 타입 r2 ≤1 → bat/batter_balancer, 2~3 → bat/batter_sluger.
  ```
  78be8: lsls r3,r6,#4 ; ldr r0,=0xd3b78 "bat/batter_balancer" ; subs r3,r3,r6 ; ... adds r3,r3,[sp+0x1c]   ; r3 = 피부*15 + 팀
  78c02: ldr r4,=0xbbd0d ; bl bx_r4          ; 0xbbd0c(이름, -1, -1, 팔레트번호) → "이름.pzx"+"이름.mpl" 로 0xb9718
  78c14: 헬멧 0xd3ba0 "bat/batter_helmet" 팔레트번호 = 팀 (피부 없음)
  78c3c~78c58: 이미 떠 있으면 0xb9c34("bat/batter_balancer.mpl", 객체, 피부*15+팀) 로 팔레트만 갈아 끼운다
  ```
- 등록 화면에서 피부 줄([this+0x84] 목록)을 바꾸면 0x171a0: `rec[0xb] = (rec[0xb] & ~0xC) | (sel<<2)` 후 0x10810 재호출 → 즉시 다시 칠한다.
- mpl 45개 = 피부 3 × 팀 15. 피부 0 황인 / 1 백인 / 2 흑인 (문자열 표 0x140022c = [0xd4b50 황인, 0xd4b58 백인, 0xd4b60 흑인]).
  팀이 달라도 피부 색은 똑같다 (15팀 모두 동일 확인). 팀이 바꾸는 색 번호: balancer [15,18,19,23,40,56,60,70] · sluger [1,5,9,11,12,13,14,23,32,41,45,51,52] · pitcher [3~10,25] — 피부 번호와 겹치지 않는다.
- 웹판: `CreatePlayerScreen.tsx:20` 주석 "그림 팔레트는 아직 바꾸지 않는다", `playerCareer.ts:97 skinIndex` 기록만. 원본은 등록 화면 미리보기·타석 그림 모두 이 팔레트를 쓴다.

## 2. MPL 대체 팔레트 포맷과 PZX 효과 0x05~0x64 — 확정 (0x7E 는 미해결)

### 파일 포맷 (열기 0x91d98 · 통팔레트 0x91e58 · 이미지별 변형 0x91f0c · 오프셋 찾기 0x95e2c)
- 첫 바이트 h: 윗 니블 = 종류, 아래 니블 ≠ 0 이면 팔레트 뒤에 u32 하나 더 (실제 파일은 전부 0).
- **h>>4 = 2 또는 3 (통팔레트, 파일 대부분이 0x30)**: `u8 개수N | u32 절대오프셋×N | (u8 색수(0=256) | 색×색수)`.
  3 = RGB565 u16, 2 = RGB 3바이트. 0x95e2c: 데이터 시작 + idx*4 로 가서 u32 읽고 거기로 절대 seek.
- **h>>4 = 4 (0x40, 이미지별 변형)**: `u8 0x40 | u16 개수N | u16 이미지번호×N | u32 절대오프셋×N | 묶음…`,
  묶음 = `u8 변형수K | (u8 색수 | u16 RGB565×색수)×K`. 0x91f0c(mpl, 이미지번호, 변형) 가 이미지번호를 찾아 K 개 중 하나를 준다.
  h=5 는 (색번호 u8, 색) 쌍의 "일부 색만 바꾸기" 형 (코드엔 있으나 파일엔 없음). h=2/3 파일에 0x91f0c 를 부르면 0 을 돌려준다.
- 실제 파일 (모두 정확히 파싱됨):

### 적재 경로
- 0xb9718(pzx이름, 1, mpl이름, 팔레트번호, …) → mpl 이 있으면 0x6fb6c: pzx 열기(0x9575d) · mpl 열기(0x95c19) · 0x95c49(번호).
  번호 ≥0 → 렌더러 vtable+0x2c (16비트판 0xc8c7c: h 2/3 만) 가 그 번호 팔레트를 **이미지 전체 팔레트로 덮어쓴다** (0xc8eed, 색수만큼 앞에서부터).
  번호 = −1 → 덮어쓰지 않고 mpl 을 붙여 둔다 (효과용). mode_ui/game_ui 는 `0xb9718(pzx,1,mpl,-1)` (0x779e·0x77f6).
- 이미 뜬 그림의 팔레트만 바꾸기: 0xb9c34(mpl이름, 그림, 번호) → 0x91c38.

### PZX 파트 효과 적용 (0xc4e94, 렌더러 0xc4d10/0xc4d54 의 콜백 표 +0x18~+0x28)
```
c4eb4: ldrb r2,[효과목록+i] ; subs r1,r2,#1 ; cmp r1,#0x63 ; bhi 건너뜀   ; 0 과 0x65 이상(0x66,0x67,0x6E,0x6F,0x7E…)은 여기서 안 다룸
c4ec0: subs r3,r2,#5 ; cmp r3,#0x5f ; bhi → 그대로 ; 아니면 r1=4             ; 5~0x64 는 모두 5번째 콜백
c4ece: ldr r4,[this+0x18 + r1*4] ; 콜백(이미지사본, 이미지번호, kind, mpl, …)
```
- 콜백: kind 1 → +0x18(0xc5109), 2 → +0x1c(0xc524d), **3 → +0x20(0xc4fa1) 좌우**, **4 → +0x24(0xc5051) 상하**, **5~0x64 → +0x28 = 0xc5390(24비트)/0xc8bb4(16비트)**.
- 0xc8bb4: `subs r2,#5` → 0x91f0c(mpl, 이미지번호, kind−5) → 변형 색을 이미지 팔레트에 쓴다
  (색 목록이 있으면 그 번호만, 없으면 색수가 같을 때 통째로). 결과는 (이미지, 효과바이트열) 키로 캐시 (0x91800).
- **즉 효과 0x05+n = "붙은 0x40 mpl 에서 이 파트 이미지의 n 번째 변형 팔레트"**. 팀 색이 아니라 UI 상태색(선택/비활성 등)이다.
  실측: 효과 5~0xC 는 game_ui(이미지 8·9 에만), mode_ui(이미지 0·1·31 에만)에서만 나온다 — mpl 의 이미지번호 목록과 정확히 일치.
  img_text.pzx 도 5~7 을 쓰지만 mpl 이 0x30 형이라 0x91f0c 가 0 → **변화 없음** (유력: 코드상 그렇다, 화면 확인은 안 함).
- 0x66/0x67/0x6E/0x6F/0x7E 는 이 적재 단계에서 빠지므로 그리는 단계에서 처리된다. **0x7E 미해결**: defender(및 ace/defender_*) 이미지 0·19 에만 47번 붙는다
  (수비수 그림자/바닥 원으로 추정). 그리는 쪽 분기를 찾지 못했다 (0x19dce·0x1aee0 의 `cmp #0x7e` 는 게임 상태 번호였다).
- 웹판: `tools/decode_pzx.py:_part_style` 은 5~0xC·0x7E 를 무시한다 → mode_ui/game_ui 선택 칸이 기본색으로 나온다.
  `tools/generate_management_sprites.py` 가 "주황 팔레트" 변형을 따로 만들고 있는데, 원본은 이 mpl 변형이다 (같은 색인지는 미대조).

## 3. 선수 등록 화면 — 선택값 → 레코드 → 능력치

화면 상태 (0x1cdec 표 0xcc728 = 진입, 0x1d08a 표 0xcc7e0 = 갱신, 0x1d1b2 = 그리기):
0x65 팀 고르기(진입 0x10790, 그리기 0x14114, 목록 [this+0x70]) → 0x66 등록(진입 0x17360, 갱신 0x16f28, 그리기 0x1452c) → 0x67 확인(진입 0x10b18, 갱신 0x12410, 그리기 0x144e4, StrMODE[2]).

### 목록 구성 (0x17360 셋업, 목록 vtable+0x10(열, 행, 1)) — 확정
| 목록 | 크기 | 뜻 | 레코드 반영 |
|---|---|---|---|
| [this+0x74] | 1×5 | 줄 선택: 0 이름 · 1 타입 · 2 포지션/보직 · 3 손 · 4 피부 | — |
| [this+0x7c] | 타자 2 / 투수 3 | 타입 (0x1400258 타격형/장타형) | rec[0xb] 윗니블 = 2×A + B (0x16f9a) |
| [this+0x78] | 2 | 타자 내야/외야 · 투수 선발/구원 | 0xb670c: rec[0xb] bit0-1 (투수가 1 고르면 2 저장, 0x1707c) |
| [this+0x80] | 2 | 손 | rec[0xb] bit4 (= B) |
| [this+0x84] | 3 | 피부 | rec[0xb] bit2-3 (0x171a0) |
- 팀: 셋업 0x173b0 이 [this+0x70] 선택값을 `strb [[this+0xb0]+1]` — 이것이 1절의 팀 번호(유니폼·헬멧 팔레트, 0x175f8 team_logo 도 같은 값).
- 줄 1·3 을 바꾸면 0x10810 으로 그림을 다시 적재(타입→몸통 파일, 손→좌우), 줄 4 는 팔레트만, 줄 1·2 는 0x16eb8 으로 능력치 다시 계산.
- **타순 목록은 없다 (확정)** — 다섯 목록을 모두 해독했고 타순을 쓰는 곳이 없다. 신인 타순 9 는 나만의리그 초기화(0xa4c2c)가 넣는다 (웹 `battingOrder` 가 이미 그대로).
  웹 주석 "타순 선택은 원본 연결을 못 찾아 뺐다" 는 **없는 선택지를 찾던 것**이다.

### 레코드 byte +0xa / +0xb — 확정
- +0xa: 등록 셋업이 타자 0xa0 / 투수 0x80 을 쓴다 (0x17634). bit6(0x40) = "고정 포지션 있음", 아래 5비트 = 그 값 (0xb6394/0xb63a0).
- +0xb: bit0-1 포지션/보직 · bit2-3 피부 · bit4 손 · bit5-7 타입(A). (바디 파일 선택은 니블 ≤1 balancer / 2·3 sluger → A 가 고른다)
- 손 게터 0xb63c0: rec[0xa] bit6 이 0 이면 `(rec[0xb]>>4)&1` (등록 선수 0xa0 → 이 경로). bit6 이 1 인 선수(원본 명단)는 포지션 표 0xd88b0 로 정한다.
  0 = 우타/우완, 1 = 좌타/좌완 (0x7cd70: 0x1400238[side + (타자?0:2)] = [우타, 좌타, 우완, 좌완]).

### 좌/우타 → side0/side1 — 확정 (한 고리 유력)
- 0x10810 이 `u8 0xb63c0(rec)` 를 그림 객체에 넘기고 0x78ab0 이 +0x3c 에 저장. 타석 판정 0xab214 도 0xb63c0 을 직접 부른다 (0xab9f0·0xaba1e·0xabc50).
- 따라서 **side = rec[0xb] bit4 = 등록 화면 [0x80] 선택. 0 우타 → side0, 1 좌타 → side1.**

- 웹판: `RALPH_PROGRESS.md:749` "웹 화면은 side 1 배치라 타자 side 를 1 로 둔다" — 원본은 `career.battingSide` 를 그대로 쓴다.

# A. 이벤트 발동 조건 · 보상 · 스킬 (binary.mod 역분석)

## 요약

이벤트 판정 함수 0xacfbc 를 끝까지 읽었다. 조건 종류 0~25 는 모두 식까지 확정했다. 20/21 은 "스킬 v−1 을 가졌는가"를 먼저 보고, 이어서 스킬 번호별 하위 switch(0xd8408 획득 19칸, 0xd8454 해제 19칸)로 간다. 스킬 2~20 의 획득·해제 조건을 카운터 수준까지 풀었다.
이벤트 선택(0xadc70)은 **파일 순서로 훑어 처음 통과한 한 건**이다. 다만 커서를 이어 쓰므로 매번 처음부터 훑지 않는다.
호출 시점은 세 가지로 확정했다.
- 관리 화면(105)·외출 지도(112) 상태에서 매 갱신
- 외출 지도에 들어갈 때 장소별 1건 배정
- 코드가 번호로 직접 부름(0x8bdc8)

보상 0~20 을 전부 풀었다. 21 은 엔딩이다. 393~396 은 연차 보정이 붙는다. 이벤트 490 의 질병 보상은 원본 코드로는 "치료"가 된다.
화면효과 1~7 은 다음과 같다.
- 1: 진동
- 2: 진동과 흔들림
- 3: 흔들림
- 4~7: 흑/백 페이드

초상화 바닥선도 풀었다.
남은 것:
- 경기 내 카운터(+0x1f0 배열) 일부 칸의 뜻
- 타석 기록 코드 5~9 의 정확한 뜻
- 관리 화면 초상화 y 의 실제 수치

(판정: **확정** = 디스어셈으로 식·표 확인 / **유력** = 한 고리 미확인 / **미해결**)

## 0. 구조체 메모 (이 문서에서 쓰는 이름)

- `선수`: 이벤트 reader `[r6]` = 나만의리그 저장 레코드 (관리 화면 상태 `[r5+0xb0]`). 보상 실행기에서는 `[mgr+0x2f8]`.
  - +2 s16: 소지금(100만 단위). 보상 3 이 쓴다 **확정**
  - +5 u8: 질병 종류(0 = 건강). +6: 질병 남은 기간
  - +0x48 s16: 인기도 (0xb6e78) **확정**
  - +0x4a s8: 지난 경기 인기도 변화 (0xa68ca 가 쓴다) **확정**
  - +0x4b+i u8(i=0~4): 훈련 칸별 누적 횟수 (훈련 0x18a68 에서 ++) **확정**
  - +0x6b+i s8: 새 시즌 시작 때 +0x4b 를 복사해 둔 값 (0x10d16). 둘의 차 = 이번 시즌 훈련 횟수 **확정**
  - +0x57: 목표 타순 경로 (보상 18)
  - +0x62 s16: 평판 (보상 1 이 999 로 자른다) **확정**
  - +0x70~+0x74 s8: 마이너스 스킬 해제용 "연속 훈련" 카운터. +0x75: 몹쓸몸 훈련 수. +0x76: 유리몸 훈련 수 (0x18b5a~0x18bd8) **확정**
  - +0x78 u16: 연봉 계산 기준 인기도 (0xa39fc)
  - +0x7a: 정규시즌 1위 횟수 (웹 주석)
  - +0x7c s8: 질병 쿨다운
  - +0x80 기준 +0x32 = +0xb2 (이번 시즌 치른 경기 수), +0x33 = +0xb3 (연차, 0부터)
    - reader `[r6+4]` = 선수+0x80 (0x1d01c) **확정**
  - +0x1b8 u32: 스킬 보유 비트 (0xa3a74 / 추가 0xa4bd8 / 제거 0xa4430) **확정**
  - +0x1c0 s16 · +0x1cd s8: 먹튀 보유 중 인기도 변화 합 · 경기 수. 먹튀가 없으면 0 으로 되돌린다 (0x12c3c) **확정**
  - +0x1c2 s16: 이번 시즌 인기도 변화 합 (경기마다 += +0x4a, 새 시즌에 0) **확정**
  - +0x1c7 s8: 무력감 보유 중 "경기 뒤 사기 ≥ 90" 연속 경기 수 (0x12bc2~0x12c12) **확정**
  - +0x1ca u16: 연도별 비트 13개 (0xa4d2c 가 켠다). 전설 조건이 켜진 비트 수를 센다. 뜻은 **미해결** — 연봉 등급 함수 0xa4d78 에서 +2 를 주는 칸이라 MVP/우승 종류로 보인다
  - +0x1d0+k: 마이너스 스킬 k번째(표 0xd7e10 = [2,3,4,5,17,18,19,20])를 **한 번 해제한 적 있음** 플래그 (해제 0xa4430 → 0xa43fc 가 1 을 쓴다) **확정**
  - +0x1e0 / +0x1f0 u16[8]: 경기 뒤 누적 카운터 두 벌 (0xa690c 가 같은 값을 양쪽에 더한다). 칸 뜻은 5절 참조
  - +0x204+v: 마구 v 보유 (보상 6, 투수편)
- `선수기록(모드)` = 0x1fc74(전역, 모드): 능력치 +0xc+2i, +0xb 비트, +0x14 스킬 비트 사본 (0xb62b4)
- `연도 기록`
  - 타자: 현재 0x1fc20, 지난 해 i 0x1fa8c(전역, i) — 합산 0x9dbc0
  - 투수: 현재 0x1fbd0, 지난 해 0x1fa78 — 합산 0x9da28
- 모드 판정 (UI `[+0x20]`): 0x7b970 = 4(타자편), 0x7b984 = 3(투수편), 0x7b998 = 2(시즌) **확정**

## 1. 이벤트 판정 함수 0xacfbc (reader r6, 화면코드 r5, 장소 r7) — 확정

레코드 읽기 함수 (0xacb20~0xacd80):
- +0 u16 길이
- +2 id
- +4 대상(0 이면 코드 호출 전용)
- +5 반복(==1)
- +6 trigger
- +7 u16 requiresEvent
- +9~+0xc 날짜
- +0xd (읽고 버림)
- +0xe 조건 수
- 조건 i: +0xf+3i u8 종류, +0x10+3i s16 값

반환 경로:
- 0xadbe0 / 0xadc06 / 0xad14c / 0xad15a / 0xad16c 는 모두 `return 0`
- 0xadc34 = 다음 조건
- 0xadc44 = `return 1`

판정 순서:
1. 대상 == 0 → 불발.
2. 모드별로 허용하는 대상:
   - 모드 4(타자편): 대상 1·2
   - 모드 3(투수편): 대상 1·3
   - 모드 2(시즌): 대상 4
3. id 490 · 대상 1(또는 4) 이고 선수 +0x7c > 0 이면 불발 (강제 플래그 `[r6+0x34]` = mgr+0x304 가 0 일 때만 검사).
4. 대상 4 의 id 100 특례 (시즌모드 전용, 타자편 무관).
5. **본 적 있는 이벤트면 불발.** 반복 여부와 관계없다. 반복 이벤트는 불러오기(0xacf60)에서만 본 표시가 지워진다.
6. trigger 와 화면코드:
   - 0: r5 ∈ {105, 201}
   - 1: r5 == 112
   - ≥2: r5 == 113. r7 ≥ 0 이면 trigger−2 == r7 이어야 하고, r7 < 0 이면 장소를 보지 않는다
7. requiresEvent > 0 이면 그 이벤트를 봤어야 한다.
8. 날짜: 네 바이트 a,b,c,d 가운데 **하나라도 0 이면 검사를 생략**한다.
   `from=(a−1)*45+b`, `to=(c−1)*45+d`, `now=선수[+0xb3]*45+선수[+0xb2]+1` 로 두고 `from ≤ now ≤ to` 여야 통과. 45 로 자르지 않는다.
9. 조건 목록 (2절). 조건 수가 0 이면 통과.

웹 차이 (`src/entities/story/model/storyScene.ts`):
- `isInDateWindow`:
  - 웹은 연차 둘 다 0 일 때만 생략한다. 원본은 네 바이트 중 하나라도 0 이면 생략한다.
  - 웹은 경기 번호를 45 로 자른다.
- 웹 `nextEventFor` 는 본 이벤트를 후보에서 빼는 것까지는 같다. 그러나 매번 배열 처음부터 훑는다 (3절의 커서 이어 쓰기가 없다).

## 2. 조건 switch (0xad1ba, 점프표 0xd83a0, 0~25; 26 이상과 4~17 은 통과) — 확정

| 종류 | 주소 | 식 |

| 0~3 | 0xad1ca | 모드 2 면 통과. 그 밖에는 `0xb6414(선수기록, 종류, 0)`. 플래그 0 은 레벨 배율(육성 선수 100%)만 곱한 **기본 능력치**이고, 장착·스킬 보정은 없다(0xb64aa `cmp r2,#0; beq` 로 끝). v ≥ 0 이면 ≥ v, 음수면 < \|v\|. 인덱스 0 히트·1 파워·2 수비·3 주루 |
| 18 | 0xad212 | 인기도 (+0x48). v ≥ 0 이면 ≥, 음수면 < \|v\| |
| 19 | 0xad240 | 평판 (+0x62). 부호 규칙은 같다 |
| 20 | 0xad276 | 스킬 v−1 을 가졌으면 불발. 못 가졌으면 하위 switch 0xd8408[v−3] (v−3 > 18 이면 통과) |
| 21 | 0xad9ac | 스킬 v−1 을 못 가졌으면 불발. 가졌으면 하위 switch 0xd8454[v−3] |
| 22 | 0xadb32 | 선수 +5 ≠ 0 이면 불발. 확률 p 는 사기 m 으로 정한다: m>70 → 0, >50 → 2, >30 → 4, >10 → 7, 그 밖 14. **유리몸(스킬 4) +10**, **행운(스킬 6) −20**(0 미만은 0). `rand[0,100) < p` 면 통과 |

웹 차이:
- 0~3 은 기본 능력치 비교라 웹과 같다.
- 음수 값 규칙은 웹에 없다 (데이터에도 없음).
- 22: `illnessChanceOf` 에 유리몸 +10 · 행운 −20 이 없다.
- 20/21 은 웹에서 항상 false 다.

## 3. 선택 규칙과 호출 시점 — 확정

**선택 0xadc70** (유일한 호출자는 0x8be80):
```
if reader[+0x2c] > 0: cursor = reader[+0x2c]; reader[+0x2c] = 0
while cursor < size-1:
    if acfbc(reader, 화면코드, -1): return 1      ; 커서는 그 레코드에 멈춘다
    cursor += len
cursor = 0; return 0
```
- 우선순위·가중치·무작위 선택은 없다. 파일 순서로 훑어 **처음 통과한 한 건**이다.
- 커서를 이어 쓴다. 다음 호출은 지난 당첨 레코드(이제 본 것)부터 계속하고, 끝까지 없으면 0 으로 되감은 뒤 그 호출은 "없음"을 돌려준다.
- 번호로 부를 때(0xae170)는 "현재 레코드 다음 위치"를 +0x2c 에 저장한다. 그래서 분기를 마친 뒤에도 그 자리부터 이어서 훑는다.
- 0x8be80 은 **장소 인자로 항상 −1** 을 넘긴다.

**호출 시점:**
1. 타자·투수편 상태 루프 0x1cdec (0x1cf9c~0x1d04c).
   - 조건: 현재 상태 `[r5+0x1c]` 가 105(관리 화면) 또는 112(외출 지도)
   - 조건: 대기 상태 `[r5+0x20]` 가 0x72/0x73(이벤트 화면)이 아님
   - 조건: 전역 플래그 +0x11f · +0x176 이 0
   - 위 조건이 맞으면 **매 갱신마다** 0x8be80(mgr, 모드, 화면코드, 선수, 선수+0x80) 을 부른다. 찾으면 되돌아갈 상태를 저장하고 0x72(이벤트 재생)로 넘어간다.
   - 새 선수 플래그 `[r5+0x165]` 가 있으면 대신 0x8bde0 → 오프닝 451 을 먼저 본다 (0x8bde0: 모드 2 → 이벤트 400, 모드 3·4 → 451).
   - 결과: 관리 화면에 있는 동안 조건을 통과하는 이벤트가 **하나씩 연달아** 모두 나온다.
2. 0xe9ac: 다른 모드의 같은 구조. 화면코드는 201 / 209 다. trigger 0 은 201 만 받는다.
3. **외출 장소 [!] 배정 0x8cdc0** (지도 진입 0x118e4 가 부른다).
   - 지도 칸 5개를 비운다.
   - 처음부터 전체를 훑으며 `acfbc(reader, 113, −1)` 를 통과한 이벤트마다 장소 = trigger−2 로 둔다.
   - 그 장소 칸이 비어 있으면 id 를 넣는다. 결과적으로 장소마다 **파일 순서 첫 이벤트**가 들어간다.
   - 장소에 들어가면 0x8ce58 이 배정된 id 를 번호로 부른다(0x8bdc8). 없으면 0x16cc2 가 **440+장소**("특별한 일 없음")를 부른다.
4. 번호 직접 호출 0x8bdc8(id) 은 오프닝, 분기(선택지·예/아니오·경기 결과), 새 시즌(0x10c54: 13년차 504 / 5년차 이하 380 / 그 밖 502) 등에 쓰인다. 호출지 목록은 xref 0x8bdc9 (20여 곳).

웹 차이:
- 웹은 trigger 0/1 을 번호 순 첫 미시청으로 고른다. 원본과 거의 같지만 커서 이어 쓰기가 없다.
- 장소는 웹 `placeTriggerOf` 와 같다.
- 웹의 "분기 전용 63개 제외"는 원본에는 없는 규칙이다. 원본은 대상 0 으로 막는다.

## 4. 스킬 획득(조건 20)·해제(조건 21) — 스킬 번호 = v−1

공통:
- 조건 20 의 스킬 2·3·4·5·18·19·20 은 **+0x1d0 플래그(한 번 해제됨)가 켜져 있으면 불발**이다. 해제된 마이너스 스킬은 다시 얻지 못한다. 웹에는 이 플래그가 없다.
- 투수편에서 스킬 비트 n(≥8)의 이름은 StrCOMMON 스킬 **n+16** 이다.
  - 근거: 0xb6414 가 투수 스킬 22 에서 제구 +10% → 38 냉정.
  - 근거: 해제 카운터가 18 → 체력 훈련, 20 → 제구 훈련.
- `y` = 연차(0부터), `g` = 이번 시즌 치른 경기 수, `T` = 이번 시즌 훈련 수 합 Σ(+0x4b+i − +0x6b+i), `Ti` = 칸 i 만.
- `평균실효` = Σ0xb6414(선수기록, i, 1)/4 (장착·스킬 보정 포함).

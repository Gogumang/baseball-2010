## 4. "해결" 25건 중 표본 역검증 (끝)

무작위로 5건을 골라 **문서가 적은 식·표·주소를 디스어셈으로 직접 다시 읽었다.** 결과: **5건 모두 정확하다. 틀린 곳 없음.**

### 4-1. U-01 페어/파울 문턱 (S2) — ✅ **정확**
```
0009d660: push {lr}
0009d662: cmp  r0, #0
0009d664: ble  0x9d66a            ; a > 0 이면
0009d666: ldr  r3, [0x9d67c] = 0xfffffe98   ; = −360
0009d668: adds r0, r0, r3         ;   a −= 360   (정규화)
0009d66a: adds r3, r0, #0
0009d66c: adds r3, #0x87          ; r3 = a + 135
0009d66e: movs r2, #0
0009d670: cmp  r3, #0x5a          ; 90
0009d672: bls  0x9d676            ; (unsigned)(a+135) <= 90 → 페어
```
→ **페어 ⇔ 0 ≤ a+135 ≤ 90 ⇔ −135 ≤ a ≤ −45 (양끝 포함).** S2 18~73행과 **글자 그대로 일치**.
같이 적힌 담장 판정 `0x36140` 도 확인: `r3 = a+0x87 ; ble 파울`(a > −135 강제) · `r5 = a+0x2d ; bge 파울`(a < −45 강제) → **−135 < a < −45 (양끝 제외)**. S2 120행의 "세 판정이 서로 다르다" 도 맞다.

### 4-2. U-04 구장 아이템 가격·필요 인기도 (S3) — ✅ **정확**
```
0xcbc64 u16 = [0,3,6,10,20,20,20,20, 0,2,4,7,15,15,15,15, 0,1,2,3,0,0,0,0, ...]
0xd44c4 u16 = [0,200,500,800,1000,1000,1000,1000, 0,100,400,700]
0xcbc34 u16 = [0,200,500,800,1000,1000,1000,1000, 0,100,400,700]   ← 0xd44c4 와 완전히 같다
```
→ 가격(억) 관중석 **3·6·10·20** · 전광판 **2·4·7·15** · 잔디 **1·2·3** — S3 227행 그대로.
`0xd44c4` 가 `0xcbc34` 의 **사본이고 값이 인기도 단위(200~1000)** 라는 S3 의 정정도 **표 값으로 확인**된다(J 4-9 가 가격이라 한 것은 틀렸다).

### 4-3. U-06 시즌 평판 점프표 4↔5 뒤집힘 (S4) — ✅ **정확** (가장 의심스러웠던 주장)
```
0xd7d7c u32 = [0xa344e, 0xa3452, 0xa3456, 0xa345a, 0xa3462, 0xa345e,
               0xa3466, 0xa346a, 0xa346e, 0xa3472, 0xa3476, 0xa347a, 0xa347e, 0xa3482, 0xa3486]
                                            ↑ k=4      ↑ k=5   ← 오직 이 둘만 순서가 거꾸로
000a3442: cmp r1, #0xe ; bhi ...      ; k ≤ 14
000a3446: ldr r2, [0xa3498] = 0xd7d7c
000a3448: lsls r3, r1, #2 ; ldr r3,[r3,r2] ; mov pc, r3
000a345e: movs r3, #0xd2   (→ <<1 = 0x1a4)
```
→ k=4 → `0xa3462`(SR+0x1a5) · k=5 → `0xa345e`(SR+0x1a4). **S4 77행·181행의 "4↔5 만 뒤집혀 있다"가 표 값으로 확정**된다.
즉 **탈삼진 3개당 +1, 병살 3개당 −2** 가 실행값이라는 DECISIONS 의 "원본대로" 판단은 옳다.

### 4-4. U-24 마선수 레벨업 비용 (S9) — ✅ **정확**
```
0xd1724 u32 = [3, 6, 9, 12, ...]        → 비용 = 1000 × [현재레벨]
0xd1b0c s16 = [225, 315, 45, 135]       (U-51 4축 각도표)
0xd40b8 u8  = [3, 3, 3, 13, 13]         (5열 화면 열별 y 보정)
```
→ **3000 / 6000 / 9000 / 12000 G** 그대로. S9 233행 일치. 각도표·y보정표도 일치.

### 4-5. U-03 세이브 판정 (S1) — ✅ **정확**
```
000a7e9c: cmp  r2, #2 ; beq 0xa7ef2       ; 세이브 측 == 2(없음) → 건너뜀
000a7ea0: ldr  r3,[sp,#0xc] ; ldr r1,[sp] ; cmp r3,r1 ; beq 0xa7ef2
                                          ; 세이브 번호 == 승리 번호 → 건너뜀
000a7ea8: ldr  r3,[r6,#8]                 ; r3 = state
000a7eaa: ldr  r3,[r3,#0x64] ; cmp r3,#0 ; bgt 0xa7ef2
                                          ; state+0x64 > 0 → 건너뜀
```
→ S1 138~141행의 세 가드가 **명령어 단위로 일치**한다. 따라서 "`+0x64` 를 0 으로 되돌리는 코드가 없으면 세이브가 한 번도 안 붙는다" 는 **추론 구조도 타당**하다(부재 증명이라 S1 이 '유력' 으로 단 것도 적절한 표기다).

### 4-6. 역검증 결론
- **표본 5건 모두 맞다.** 특히 가장 "설마" 싶었던 S4 의 점프표 4↔5 뒤집힘은 표 값으로 확정되었다.
- 표기(확정/유력)도 적절하다 — 부재 증명에만 '유력' 을 달았고, 표·명령어로 확인한 것에는 '확정' 을 달았다.
- **따라서 앞선 문서들의 신뢰도를 낮출 이유가 없다.** Q4 가 아래 5·6 절에서 내리는 판단도 이 문서들을 믿고 세운 것이다.

### 5-2. 새 빈 곳 (Q4 가 새로 연 것) — 7건

| # | 새 빈 곳 | 근거 주소 | 필요도 | 한 줄 |

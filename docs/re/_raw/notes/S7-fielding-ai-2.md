## 요약

**U-07 확정 · U-08 확정 · U-09 핸들러 확정 / 호출부 미해결.**
`0xafb24` CPU 송구 목표 점수식은 루 4칸 후보표(0x30바이트)를 채워 `기본점수(0xd85ac = [홈 4000, 1루 1000, 2루 2000, 3루 3000])`
+ `확실한 아웃이면 100000 + 여유, 아니면 10000`(홈이면 각각 `+10000000` / `+1000000`)로 매기고,
첫 루 항에 2배 가중을 준 뒤 `2×첫 루 항 + 둘째 루 항 + 500` 과 기본점수 합을 더해 최댓값을 고른다.
난이도는 `난이도 + 유효 > 2` 한 곳에서만 쓰여, 높으면 "여유가 가장 큰 루"로, 낮으면 점수식(= 앞 루 욕심)으로 간다.
`0xaf284` 도착 틱은 **커버 야수가 없으면** `min(공 가진 야수가 직접 뛰기, 루 담당 야수 도착)`,
**있으면** `잡기까지 남은 틱 + max(송구 틱 + 준비 틱(내야 3 / 외야 6), 커버 야수 도착 − 남은 틱)` 이고
외야 + 17000 이상이면 중계(내야 2~5 중 최소, +3틱)가 낀다.
`0xa2bf0`(공 vt 0x6c)은 네 갈래(무시 / 사건틱 A / 사건틱 B + `공+0xac0=0` / 담장 튕김 / 높이 ≤ 1999 의 다른 충돌)로
전부 읽혔고 **구조체 오프셋을 P2 에서 정정**했지만, 이 슬롯을 부르는 충돌 검사기는 궤적 물리 루프 안이라 열지 않았다.
덤으로 제어기 `+0x14`→`+0x68` = 현재 틱, `플레이+0x16c/0x170/0x174` 의 쓰임, 플레이 vtable `0xd8618`,
야수 vtable `0xd7934`, 주자 vtable `0xd771c`, 공 vtable `0xd7afc` 와 보조 인터페이스 `0xd7b74` 를 확정했다.

# 1. 준비 — 출발점과 도우미 (확정)

- P2 5a절: 제어기(vtable `0xd8554`) `+8 주자관리 · +0xc 플레이 · +0x10 전역 0x1552d0c(설정)`.
  슬롯 8=`0xaf918` 자동 진루, 0xc=`0xafa60` CPU 송구 결정, 0x10=`0xb030c`, 0x14=`0xafb24` 목표 루 고르기.
- `0xafb24` 는 `0xafb24`~`0xb02f4`(마지막 `b #0xb02f0` = 반환) 한 덩어리다.
- 이 노트에서 쓰는 도우미(전부 `bx rN` 트램펄린 `0xca9f8`(r3)·`0xca9fc`(r4)·`0xcaa00`(r5)·`0xcaa04`(r6)·`0xcaa08`(r7) 경유 호출):
  - `0xb959c(dst, val, n)` = 워드 n 개를 val 로 채움
  - `0xcb618` = memset(ARM 베니어), `0xcb5d8` = memcpy(12바이트 = 위치 하나)
  - `0xca7b4` = 정수 나눗셈, `0x6c64c` = 정수 제곱근(추정), `0x6c5d8` = 나눗셈(P2)
  - `0xa9564(주자관리, i)` = i 번째 주자, `0xa9598(주자관리)` = 주자 수, `0xa98b4(주자관리)` = (아웃/제외 수로 보임),
    `0xa990c(주자관리)` = `0xa9598 − 0xa98b4`
  - `0xb0c7c(플레이, i)` = i 번 야수 객체, `0xb0c90(플레이)` = `0xb0c7c(플레이, 플레이+0x130)` = **추적(=공 가진) 야수 객체**
  - `0xbefec(주자)` = 목표까지 남은 틱(P2 의 진행률 분자), 주자 vt `0xa0` = 되돌아갈 때의 틱(유력)
- **위치는 12바이트(x, y, z)** 다: 루 좌표표 `0xd856c` 가 12바이트 간격으로 읽힌다(`[0]=홈.x`, `[8]=홈.z`, `[0xc]=1루.x`, `[0x14]=1루.z`). 야수·주자 객체의 `+0x20` 이 위치 12바이트.

# 2. U-07a — `0xafb24` 후보표 만들기 (확정)

스택 `sp+0xe4` 에 **루 4칸 × 0x30 바이트** 후보표를 둔다(`memset 0xc0` 로 0, 이어서 각 칸 `+0` 에 −1).
같이 쓰는 배열: `sp+0xd4` = 워드 4칸(`0xb959c(…, −1, 4)` 로 −1 초기화) = **루별 여유(margin)**.

## 2-1. 머리 (0xafb24~0xafb9c)

```
this=[sp+0x6c], 난이도=[sp+0x68]
플레이 = this[0xc]
[sp+0x64] = 플레이+0x130          ; 추적(공 가진) 야수 칸 번호
[sp+0x60] = 0xb0c90(플레이)       ; 그 야수 객체
r5 = (칸 ≤ 5)                     ; 내야수인가
r4 = 0xa990c(주자관리)            ; 살아 있는 주자 수로 보임(유력)
memset(후보표, 0, 0xc0) ; 후보표[b].+0(halfword) = −1 (b=0..3)
r4 == 0 && 내야수 → return −1     ; **주자가 없고 내야수가 잡았으면 안 던진다**
```

## 2-2. 주자마다 칸 채우기 (0xafb9e~0xafc64)

주자 부분객체 `R = 주자+0x78` (P2 5b 의 절대 오프셋 −0x78):
`R+4 = +0x7c 출발 루`, `R+0x10 = +0x88 요구 루`, `R+0x1c = +0x94 판정끝`, `R+0x1e = +0x96 아웃`, `주자+0x98 타자주자`.

```
아웃(+0x96) 이면 건너뜀 ; 주자 널이면 건너뜀
if (+0x94 판정끝 && +0x88 요구루 ≥ 0 && 타자주자 아님):     ; 포스/리터치 의무가 있는 주자
    후보표[요구루 % 4].+2 (byte) = 1                        ; **포스 표시**
    t = (출발루 > 요구루) ? 주자.vt0xa0() : 0xbefec(주자)   ; 되돌아가기 / 앞으로 가기 틱
    후보표[요구루 % 4].+0 (halfword) = t
else:
    후보표[출발루 % 4].+0 (halfword) = 0xbefec(주자)
후보표[해당 칸].+3 (byte) = 플레이.vt0x80(주자번호)
r4 = 주자번호                                               ; 마지막으로 안 걸러진 주자
(주자 수 = 0xa9598 만큼 반복)
r4 ≠ −1 이면 주자[r4].vt8() 한 번 부름 (반환값 버림)
```

## 2-3. 후보표 칸 (0x30 바이트)

| 오프셋 | 크기 | 뜻 |
|---|---|---|
| +0 | s16 | **주자 도착 틱** t_run (없으면 −1) |
| +2 | u8 | **포스/리터치 의무** 표시 |
| +3 | u8 | 플레이 vt `0x80`(주자) 의 결과 (유력: "그 주자를 반드시 잡을 수 있나" 표시) |
| +4 | s16 | **수비 도착 틱** t_def = `0xaf284(this, b)` |
| +6, +8, +0xa, +0xc | s16 ×4 | 루 b 로 보낸 뒤 **다시 루 r 로 보내는 데 드는 틱**(아래 2-5) |

## 2-4. 루마다 수비 틱 (0xafc7e~0xafca6)

```
[sp+0x50] = 1000 (최소 t_def), [sp+0x54] = 0 (그 루)
b = 0..3:
   후보표[b].+4 = 0xaf284(this, b)
   … 1루 예외(2-6) …
   t_def < 최소 → 최소 = t_def, [sp+0x54] = b
```

## 2-5. 루 b → 루 r 재송구 틱 (0xafdf6~0xafe8c)

```
r = 0..3, r ≠ b:
   C_r = 플레이+0xf0[r]                     ; 루 r 커버 야수 (−1 = 없음)
   C_r == −1 → 후보표[b].+6+2r = 100
   else:
      던지는이 = (플레이+0xf0[b] ≠ −1) ? 플레이+0xf0[b] : (공 가진 야수의 +0x88 = 칸 번호)
      플레이.vt0x8c(&res, 던지는이, C_r, 0)   ; = 0xb3444 송구 계획 (P2 4절)
      후보표[b].+6+2r = (s8)res[5]            ; 계획의 틱
```

## 2-6. 1루에 커버가 없을 때의 예외 (0xafcca~0xafddc) — 확정

`플레이+0xf0[b] == −1` 이고 `b == 1` 일 때만:

```
기울기 = 100 × (홈.z − 1루.z) / (홈.x − 1루.x)          ; 1루선
d  = |기울기×(야수.x − 홈.x) − 100×(야수.z − 홈.z)| / sqrt(기울기² + 100²) / 10
d > 499 → 아무것도 안 함                                 ; 야수가 1루선에서 멀다 (499 = P2 의 태그 거리와 같은 값)
주자[0](타자주자) 가 없으면 아무것도 안 함
if 0xbed30(주자[0], 1루좌표) > 0xbed30(야수, 1루좌표):   ; 타자주자가 더 늦게 닿는다
    후보표[1].+4 = 후보표[1].+0                          ; **수비 틱 = 주자 틱** (야수가 직접 1루를 밟는다는 뜻)
```

→ 1루 커버가 비어도 공 가진 야수가 1루선 가까이(≤499) 있고 타자주자보다 빠르면 1루를 "보낼 수 있는 루" 로 친다.

# 3. U-07b — `0xafb24` 점수식 (확정)

## 3-0. 표와 상수

- **루 기본 점수 표 `0xd85ac`** (u32 ×4) = `[홈 4000, 1루 1000, 2루 2000, 3루 3000]` — 앞 루일수록 값이 크다.
- **루 담당 야수 표 `0xd85a8`** = u8 `[1, 2, 3, 4]` (= `0x04030201`) — 홈→포수(1), 1루→1루수(2), 2루→2루수(3), 3루→3루수(4).
  야수 칸: **0 투수 · 1 포수 · 2 1루수 · 3 2루수 · 4 3루수 · 5 유격수 · 6~8 외야**(P2 의 중계맨 규칙과 일치).
- **루 좌표 표 `0xd856c`** (12바이트 ×4, x·y·z): 홈 `(20000, 0, 29445)` · 1루 `(25946, 0, 24175)` · 2루 `(20000, 0, 19170)` · 3루 `(14055, 0, 24175)`.
  (송구용 좌표표 `0xd86b0` 은 이것과 별개 — `0xb1268` 이 쓴다.)
- 설정 `[0x14000c0]` 의 `+0x20` (s16) = **3** = 중계 뒤 재송구 지연(P2 의 `cfg+0x20`).
- `0xb1268(플레이, 위치)` = `0xd86b0[0..3]` 중 **위치가 정확히 같은 루 번호**, 없으면 −1 (`0xbc0f4` = 위치 3성분 전부 같은가).
- `플레이 vtable = 0xd8618` (vt18=`0xb27ec`, vt30=`0xb1c90`, vt58=`0xb2c90`, vt8c=`0xb3444`, vt94=`0xb1b2c` 로 P2 와 맞음).
- **플레이 vt `0x80` = `0xb1b54(i)`** (확정):
  ```
  i == 0 → 1                                   ; 타자주자는 늘 1
  플레이+0x112 == 0 → 0                        ; 아직 안 잡힌 상태면 0
  (주자[i]+0x8c 목표 루) == (주자[i−1]+0x7c 출발 루) → 1, 아니면 0
  ```
  → "내 목표 루가 바로 앞 주자가 떠난 루" = **포스로 밀려 가는 주자**(후보표 `+3`).

## 3-1. 루 하나(b = r7)의 1차 점수 (0xafe9a~0xaff3e)

```
여유  = 후보표[b].t_run − 후보표[b].t_def          ; ≥ 0 이면 수비가 먼저 닿는다 = 아웃 가능
유효  = 0 ; A항 = 0 ; B항 = 0
여유 < 0            → 통과(점수 0)
후보표[b].t_run == 0 → 통과(점수 0)
A항 = 0xd85ac[b]                                    ; 루 기본 점수
if (vt80[b] || 후보표[b].force):                    ; 확실히 잡아야 하는 주자가 그 루로 온다
      여유표[b] = 여유 ; 유효 = 1
      B항 = 100000 + 여유
      b == 0(홈) → A항 += 10000000
else:
      b == 0(홈) → A항 += 1000000
      B항 = 10000
```

→ P2 가 본 상수 네 개가 **100000(확실한 아웃 기본) · 10000(불확실) · 10000000(홈 + 확실) · 1000000(홈 + 불확실)** 로 자리를 잡았다.
`여유` 는 100000 에 그대로 더해져 **같은 조건이면 여유가 큰 루**를 고르게 한다.

## 3-2. 주자별 보정 (0xaff40~0xb00a6) — 확정

먼저 `밖 = (0xb1268(플레이, 공 가진 야수 위치) == −1 && 추적야수 칸 ≠ 0)`
= **공 가진 야수가 어느 루 위에도 안 서 있고 투수도 아니다**.

주자 j 마다(아웃된 주자 제외):

```
도달 = cfg[0x20](=3) + 0xaf284(this, b) + 0xaf614(this, b, (주자.vt68 목표루 + 1) % 4)
if (도달 + 2 ≥ 주자.vt0xa0()):                       ; 던진 뒤 그 주자를 다음 루에서도 따라잡을 수 있다
     if ((주자 목표루 + 1) % 4 != b):
          도달 ≥ 주자.vt0xa0()  → B항 −= 45000       ; 0xffff5038
          도달 <  주자.vt0xa0() → B항 −= 22500       ; 0xffffa81c
          (다음 주자로)
if (주자+0x7c 출발 루 == b):                          ; 루 b 에서 출발한 주자
     밖 → B항 += (b == 0 ? 5004 : 5000 + b)
     주자.vt18()(멈춤) 이면 통과, 아니면 B항 += 10000
else if ((주자 목표루 + 1) % 4 == b && 밖):
     B항 = max(B항, b)                                ; ← 사실상 아무 효과 없음(원본 그대로)
```

- `−45000 / −22500` 은 "그 루로 던져도 다른 주자가 그 사이에 한 루 더 간다" 는 **감점**이다(감점 폭이 100000 보다 작아 확실한 아웃을 뒤집지는 못하고, 10000 짜리 불확실 후보끼리의 순서를 바꾼다).
- `B항 = max(B항, b)` 는 b(0~3) 와 비교하는 것이라 **B항이 음수일 때만** 0~3 으로 올라간다 — 원본 그대로 옮긴다(오타로 보이지만 고치지 않는다).

## 3-3. 두 번째 루(병살 상대) 점수와 칸 채우기 (0xb00ba~0xb015a)

루 b 마다 다시 루 r = 0..3 을 돌며:

```
둘째도달 = 후보표[b].t_def + 후보표[b].재송구[r]      ; 2-5 의 +6+2r
여유2    = 후보표[r].t_run − 둘째도달
C항 = 0 ; D항 = 0
if (유효 && r ≠ b && 여유2 > 0):
     C항 = 0xd85ac[r]
     if (vt80[r] || 후보표[r].force):  D항 = 100000 + 여유2 ; r == 0 → C항 += 10000000
     else:                              D항 = 10000        ; r == 0 → C항 += 1000000
후보표[b].A[r] (+0x10 + 4r, s32) = A항 + C항
후보표[b].B[r] (+0x20 + 4r, s32) = 2 × B항 + D항 + 500
if (난이도 + 유효 > 2) 확실플래그 = 1                  ; 0xb013a
```

→ 첫 루의 B항에 **2배 가중**이 붙는다(= 첫 아웃이 두 번째보다 두 배 값어치). `+500` 은 아무 후보가 없을 때도
점수를 0 이 아니게 만드는 바닥값이다.

후보표 칸 나머지:

| 오프셋 | 크기 | 뜻 |
|---|---|---|
| +0x10 + 4r | s32 | **A[r]** = 루 b 기본 + 루 r 기본 (홈 보너스 포함) |

## 3-4. 고르기 (0xb0164~0xb02ee) — 확정

```
최고 = 1000 ; 고른루 = [수비 틱이 가장 작은 루]           ; 2-4 에서 구해 둔 값
(가) 확실플래그(3-3) 이면:
      최고 = −1
      b = 0..3: 여유표[b] > 최고 && 여유표[b] ≥ 0 → 최고 = 여유표[b], 고른루 = b
      → **여유가 가장 큰(= 가장 여유 있게 잡을 수 있는) 루**. 바로 (다) 로.
(나) 아니면 점수식:
      b = 0..3: r = 0..3:
          s = 후보표[b].A[r] + 후보표[b].B[r]
          최고점[b] = max(최고점[b], s)
          최고 ≤ 최고점[b] → 최고 = 최고점[b], 고른루 = b       ; 같으면 뒤 루가 이긴다
      ─ 1루수 예외 ─
      F = 0xb0c7c(플레이, (플레이+0x16c)[1]) 가 칸 2(1루수) 이고
          F 의 위치가 1루 좌표(0xd8578 = 0xd856c+0xc)와 **정확히 같고**
          최고점[0..3] 이 전부 ≤ 19999 이면 → 고른루 = 1
(다) 최고 == 1000 (아무 후보도 점수를 못 얻음) 이면:
      F' = 0xb0c7c(플레이, (플레이+0x16c)[1]) 의 칸
      칸 > 5(외야) → 고른루 = 2 (2루) ; 아니면 고른루 = −1 (안 던짐)
return 고른루
```

- (다) 는 (나) 뒤에도 걸리므로 **1루수 예외로 정한 1 도 뒤집힐 수 있다**(원본 그대로).
- 홈 보너스 1000000 / 10000000 때문에 **홈에 던질 기회가 있으면 거의 항상 홈**이고, 그 다음이 3루 → 2루 → 1루 순(기본 점수 3000/2000/1000)이다.

# 4. U-07c — 난이도와 "안 던짐" (확정)

- 난이도 인자는 `0xafa60` 이 `제어기.vt14(난이도 바이트)` 로 넘긴 값(P2: 제어기 `+0x10` 전역 `0x1552d0c` 설정의 `+6` 바이트).
- **쓰이는 곳은 단 한 군데**, `0xb013a` 의 `난이도 + 유효 > 2` 뿐이다(`유효` ∈ {0,1}, 3-1 참조).
  - 난이도 ≥ 3 → 늘 참 → **늘 (가) "여유 최대" 규칙**(= 가장 안전한 아웃을 고름).
  - 난이도 == 2 → 확실한 아웃 후보(포스/vt80)가 하나라도 있을 때만 (가), 아니면 점수식.

- **−1(안 던짐) 은 두 곳**뿐:
  1. 머리 — `0xa990c(주자관리) == 0` 이고 **공 잡은 야수가 내야(칸 ≤ 5)** 일 때 (0xafb7e).
  2. 꼬리 — 어떤 루도 점수를 못 얻었고 공 잡은 야수가 내야일 때 (0xb02e4). 외야면 −1 대신 **2루**.

# 5. U-08 — `0xaf284(제어기, 루 b)` 송구 도착 틱 (확정)

먼저 P2 의 "미상" 두 개가 풀렸다:

- **`플레이+0x16c`~`+0x174` 는 P2 3절이 이미 이름 붙인 칸이다**: `+0x16c 포구 종류 · +0x170 고른(포구할) 야수 번호 · +0x174 포구 틱`.
  `0xaf284`·`0xafb24` 가 `플레이+0x16c` 를 12바이트로 통째 복사한 뒤 `[1]`(= `+0x170` 야수 번호)와 `[2]`의 하위 s16(= `+0x174` 포구 틱)을 쓴다.
- **제어기 `+0x14` 객체의 `+0x68` = 현재 틱** (`0xaf584`: `포구 틱 − 그 값` = 공을 잡기까지 남은 틱).

야수 vtable = `0xd7934`: `vt1c = 0xbf450`(어떤 점까지 가는 틱) · `vt68 = 0xa0b4c`(목표 루) ·
`vtb4 = 0xa1a60` · `vtb8 = 0xa1a98` · `vtbc = 0xa1adc`(송구 틱) · `vtc0 = 0xa1c3c`(제 목표에 닿는 틱).
주자 vtable = `0xd771c`: `vt18 = 0xbf3a0`(멈춤) · `vt68 = 0xa0b4c`(목표 루) · **`vt0xa0 = 0xa06ec`**.
`0xa06ec` = `0x6c5d8(거리(루[(목표루+1)%4], 루[목표루]), 속도 +0x3c) + 0xbefec(this)`
= **지금 목표 루까지 남은 틱 + 거기서 한 루 더 가는 틱**(= 한 루 더 갈 때의 총 틱). `0xbefec(obj)` = `obj.vt1c(obj+0x2c 목표점)` = 현 목표까지 남은 틱.

## 5-1. 전체 흐름

```
공야수   = 0xb0c90(플레이)                      ; 플레이+0x130 이 가리키는 야수
잡을야수 = 0xb0c7c(플레이, 플레이+0x170)        ; 포구 예정 야수 (보통 공야수와 같다)
남은 = 0
커버 = 플레이+0xf0[b % 4]

── (A) 커버가 없다 (커버 == −1 또는 그 야수 객체가 널) ──   0xaf2ee
    t1 = 공야수.vt1c(0xd856c[b])                 ; 공 가진 야수가 직접 루 b 까지 뛰는 틱
    D  = 0xb0c7c(플레이, (s8)0xd85a8[b])         ; 루 담당 기본 야수 (홈→포수1, 1루→2, 2루→3, 3루→4)
    t2 = D.vtc0()                                ; D 가 제 목표에 닿는 틱
    if (D.vt68() != b) t2 += D.vt1c(0xd856c[b])  ; D 의 목표가 루 b 가 아니면 거기서 더 뛴다
    return min(t1, t2)                           ; 0xaf366~0xaf370 (r6 > r7 ? r7 : r6)

── (B) 커버가 있다 ──                              0xaf372
    중계 = (공야수 칸 == 잡을야수 칸) && (칸 > 5, 외야)
           && 0xbf9f0(공야수 위치, 0xd856c[b]) ≥ cfg+0x42 (= 17000)
    if (중계):                                    0xaf3ec~0xaf530
        M = argmin(i = 2..5) [ 공야수.vtbc(야수i 목표점) + 야수i.vtbc(커버야수 목표점) ]
            (못 고르면: 유격수(5) 의 AI 상태 `+0x84` == 0xa 면 5, 아니면 3)
        T = 공야수.vtb4(M) + M.vtb8(0xd856c[b]) + cfg+0x20 (= 3)
    else:                                         0xaf532 / 0xaf53e (두 갈래가 같은 코드)
        T = 잡을야수.vtb4(커버야수)               ; 직접 송구 틱
    ── 포구 전/후 보정 ──                          0xaf550
    if (잡을야수+0xe0 == 0):                      ; 아직 공을 안 잡았다
        남은 = (s16)(플레이+0x174 포구 틱) − (제어기+0x14)+0x68 (현재 틱)
        T   += 잡을야수가 외야(칸 6~8, 0xb8da8) ? cfg+0x22 (= 6) : cfg+0x20 (= 3)
    else:                                         ; 이미 잡았다
        T   += [잡을야수+0xc8]                    ; 진행 중인 동작의 남은 틱
    ── 커버 야수 도착 보정 ──                      0xaf5ac
    if (커버야수 객체 있음):
        T = max(T, 커버야수.vt1c(0xd856c[b]) − 남은)
    return 남은 + T
```

# 6. U-09 — 공 vt `0x6c` (`0xa2bf0`) 충돌 처리 (핸들러 **확정** / 호출부 **미해결**)

## 6-1. 어디에 달려 있나 (확정)

공 vtable = **`0xd7afc`** (slot 0 = `0xa2510`, 0x48 = `0xa2974` 사건 틱 초기화, 0x4c = `0xa29bc` 점 기록,
0x50 = `0xa2a88` 깊은 타구, 0x68 = `0xa2b78` 공점(t), **0x6c = `0xa2bf0`**).

공 객체는 **다중 상속**이다 (생성자 `0xa24d4`):
```
[공+0x00] = 0xd7afc                  ; 본 클래스
[공+0x58] = 0xd7b74                  ; 보조 인터페이스 A (offset-to-top = −0x58)
[공+0x5c] = 0xd7ba8                  ; 보조 인터페이스 B (offset-to-top = −0x5c)
```
보조 인터페이스 A(`0xd7b74`) 의 슬롯 — 전부 `this −= 0x58` 하는 ARM 베니어(`0xa2d54`~`0xa2e23`, `ldr ip,[pc,#4] / sub r0,r0,#0x58 / bx ip`):

| 슬롯 | 베니어 | 본체 | 뜻 |
|---|---|---|---|
| 0x08 | 0xa2d94 | 0xa2974 | 사건 틱 초기화 |
| 0x0c | 0xa2da4 | 0xa29bc | **t 번째 점 기록** |
| 0x10 | 0xa2db4 | 0xa2a88 | 깊은 타구 표시 |
| 0x14 | 0xa2de4 | 0xa2ba8 | 이전 점 (`공점(공+0x68 − 1)`), `this` 가 **2번째 인자** |
| 0x18 | 0xa2df4 | 0xa2bc0 | 현재 점 |
| 0x1c | 0xa2e04 | 0xa2bd8 | 다음 점 |
| **0x20** | **0xa2e14** | **0xa2bf0** | **충돌 통지** |
| 0x24 / 0x28 | 0xa2dc4 / 0xa2dd4 | 0xa2b54 / 0xa2b64 | 공 vt0xc / vt0x18 로 넘김 |

→ 공은 "궤적을 가진 것" 인터페이스를 구현하고, **바깥의 충돌 검사기**가 매 틱 이 슬롯 0x20 으로 결과를 알려 준다.

## 6-2. 인자 구조체 오프셋 — **P2 정정**

`0xa2bf0(iface, t, 충돌결과)` 에서 구조체는 **r2·r3 + 스택**으로 값 복사된다.
`sub sp,#8` + `push {r4,r5,r6,lr}` 뒤 `str r2,[sp,#0x10]` / `str r3,[sp,#0x14]` 이므로 **구조체 시작 = sp+0x10**.

| 코드의 스택 오프셋 | **구조체 오프셋** | 뜻 |
|---|---|---|
| sp+0x10 / 0x14 / 0x18 | **+0x00 / +0x04 / +0x08** | 충돌 지점 (x, y, z) |
| sp+0x34 (s16) | **+0x24** | 충돌 뒤 각도 |
| sp+0x36 | **+0x26** | 충돌 있음 표시 (0 이면 즉시 return) |
| sp+0x38 | **+0x28** | 종류 C (담장 면 — 유력) |
| sp+0x39 | **+0x29** | 종류 B |
| sp+0x3a | **+0x2a** | 종류 A |

→ **P2 1b 의 "구조체 바이트 +0x3a / +0x39 / +0x38" 은 스택 오프셋이었다. 실제 구조체 오프셋은 +0x2a / +0x29 / +0x28 이다.**

## 6-3. 네 갈래 (확정)

```
+0x26 == 0                        → 아무것도 안 함                              (0xa2c00)
+0x2a ≠ 0  → 공+0xaa4 가 −1 이면 = t                                            (0xa2c10)
+0x29 ≠ 0  → 공+0xaa4 가 −1 이면 = t ; **공+0xac0 = 0**                          (0xa2c28)
+0x28 ≠ 0  → 담장 튕김                                                           (0xa2c48)
      공+0xab0 이 −1 이면 = t
      공+0x70 각도 = (s16)구조체+0x24 + rand(−25, 25)       (0xbfa54)
      공+0x20/0x24/0x28 = 구조체 +0x00/+0x04/+0x08          (충돌 지점으로 이동)
      공+0xa9c = 1 (바운드 표시) ; 공+0x48 = 공+0x40 ; 공+0x3c 속도 ½
      공+0x51 = 1                                           (0xbef24)

      구조체+0x04 (높이 y) > 1999 면 아무것도 안 함

      공+0x20 = 구조체+0x00 ; 공+0x28 = 구조체+0x08          (x·z 만, 높이는 유지)
```

## 6-4. 판정 — 미해결로 남기는 것과 그 이유

- **확정**: 핸들러 네 갈래 전부, 구조체 오프셋(위 정정), 각 갈래가 공에 하는 일, 인터페이스 A 의 슬롯 표.
- **미해결**: `슬롯 0x20` 을 부르는 **충돌 검사기**. 시도한 방법 —
  1. `re xval 0xa2bf1` → `0xd7b68`(공 vtable 0x6c) 과 `0xa2e20`(ARM 베니어의 목적지 워드) 둘뿐, 직접 `bl` 없음.
  2. 전체 디스어셈에서 `ldr rX,[rY]` + `ldr rZ,[rX,#0x20]` 꼴(가상 슬롯 0x20 호출) 을 모두 훑었으나(약 90곳)
     공 모듈(0xa2xxx) 안에는 없고, 같은 함수 안에 `+0x58` 을 읽는 곳도 없었다.
  3. 보조 vtable 주소 `0xd7b74` · `0xd7ba8` 을 코드에서 찾았으나 생성자(`0xa24d4`) 외 참조 없음 → 등록은 포인터 전달로만 일어난다.
  4. 구조체를 만드는 쪽(`+0x26/+0x28/+0x29/+0x2a` 에 strb) 도 전역 오프셋 기준으로는 없다(전부 sp 기준).
- 남은 경로는 **궤적을 한 틱씩 돌리는 물리 루프**인데, 이는 이 세션이 손대지 않기로 한 주제다
  (`_BRIEF2` 의 "공 궤적(투영·베지어) 코드는 해석하지 말 것", D 의 결정 = `pitch.zt1` 원본 데이터 사용).
- **U-09 의 전제에 대한 반례**: UNRESOLVED 는 이 슬롯을 "야수·주자·공 충돌" 로 적었지만,
  구조체에는 **위치·각도·종류 플래그만 있고 야수/주자 객체나 번호가 전혀 없다**.
  갈래가 하는 일도 "각도 바꾸고 속도 반으로 줄이고 바운드 표시" 뿐이라 **담장·구조물 쪽 충돌**로 보는 게 맞다(유력).
  야수가 공에 관여하는 길은 따로 있다 — 포구(P2 2b·3), 펌블 뒤 무작위 튕김(야수 vt78 = `0xb32e8`), 송구(`0xa1620`).
  즉 **원본에 "타구가 주자를 맞히는" 처리는 이 경로에 없다**(유력).

## 6-5. 야수·주자와 공의 접촉은 어디에 있나 (정리)

`0xa2bf0` 경로가 아니라 아래 셋으로 흩어져 있다(전부 앞 노트에 이미 있음 — 여기서는 위치만 모은다):

| 경우 | 곳 | 비고 |
|---|---|---|
| 야수가 공을 잡는다 | 예측표 `0xb12d0` → 고르기 `0xb3b38` → 포구 틱 `플레이+0x174` | P2 2a·3 |
| 잡다 놓친다(펌블) | 등급별 2.0~0.5% 굴림 → 야수+0xb8 = 6, 메시지 `0xbc2`, 야수 vt78 = `0xb32e8` 무작위 튕김 | P2 3 |
| 송구가 루로 간다 | `0xa1620`(원바운드 상한 20400) · `0xb2e38` · 받기(공 목록 종류 4) | P2 3·4, I 2b |
| 주자와 야수 | 태그 거리 ≤ 499 (`0xb36d0`) · 협살 `0xb3a94` | P2 4·5b, I 3c |

**타구가 주자 몸에 맞는 처리(주루방해·타구맞음 아웃)는 찾지 못했다 — 원본에 없는 것으로 본다(유력).**

# 8. 정정 (앞 노트를 뒤집는 것)

1. **P2 1b — 충돌 구조체 오프셋**: "구조체 바이트 `+0x3a` 또는 `+0x39`", "`+0x38`" 은 **스택 오프셋**이었다.
   구조체 기준으로는 **`+0x2a` / `+0x29` / `+0x28`** 이고, 유효 표시가 `+0x26`, 각도가 `+0x24`, 위치가 `+0x00~+0x08` 이다 (6-2).
2. **P2 5a — `0xb013a` 의 비교**: "난이도 + 여유 > 2" 가 아니라 **"난이도 + 유효(0/1) > 2"** 다.
   `유효` 는 "그 루에 포스/의무 주자가 있고 여유 ≥ 0" 이라는 0/1 플래그이며, 여유(틱 수)가 아니다 (3-3 · 4절).
3. **P2 5a — 제어기 `+0x14` (미확인)**: `+0x14` 객체의 **`+0x68` 이 현재 틱**이다 (`0xaf584`).
4. **P2 5a — `0xaf284` "세부 분기 유력"**: 두 갈래 모두 식까지 확정되었다 (5절). 특히 "직접 뛰기 vs 송구" 는
   **커버 야수 유무**로 갈리고, 커버가 없을 때만 `min(직접 뛰기, 루 담당 야수 도착)` 이다.
5. **P2 3 — 0xd85a8 표**: "홈→1 포수, 1루→2 …" 가 맞고, 값은 `0x04030201` (u8 4개) 로 확인됐다.
   바로 뒤 `0xd85ac` 는 **루 기본 점수 `[4000, 1000, 2000, 3000]`** 로, 표가 이어져 있으니 같이 읽을 때 주의.
6. **UNRESOLVED U-09 의 제목**: "야수·주자·공 충돌" 이 아니라 **담장·구조물 충돌**로 보는 게 맞다 (6-4).

# E. 수비 판정 · 경기 규칙 잔여 (간이 엔진 · 미션 · 순위)

> 판정: **확정** = 디스어셈으로 식·표까지 확인 · **유력** = 한 고리 미확인 · **미해결**
> 주소는 `binary.mod` VA. 웹 파일:줄은 main `2fa9283` 기준. ⚠️ = 다른 세션 작업 영역 — **이 주제의 수정 대상은 대부분 ⚠️ 영역**이다.
> 난수 0xbfa54 = rand(a,b) → [a, b). LCG `s = (s*0x343fd + 0x269ec3) >> 1`, a + s mod (b−a).

## 0. 웹판과 **같은** 것 (확정 — "(추정)" 을 뗄 수 있다)
- 미션 레코드 바이트 4 = 아웃(bit0-1) | 볼(bit2-3) | 스트라이크(bit4-5) — `tools/generate_game_data.py:450-451`
- 간이 엔진 부호 난수 rand(0,2), X 먼저 Y 나중 — `quickAtBat.ts:146-148`
- 상대 타순은 이닝을 넘어 이어진다 (1번으로 되돌리지 않음) — `simulateHalfInning.ts`, `leagueDay.ts:57-66`
- 땅볼 진루타 판정 (아웃<2, 주자 있음, 3루 비었음 → 전원 한 루) — `baseState.ts:31-38`
- 안타 진루: 모든 주자 += n, 4 이상 득점 — `baseState.ts:64-84`

## 1. 구현 명세 — 웹을 원본대로 고칠 것

### E-1. 연장 규칙 — 한 이닝 어긋남 (확정) ⚠️ `quickAtBat.ts:41,81` · `balance.json:187` · `leagueDay.ts:16,87-89`
- **원본 이닝은 0부터 센다** (0xb6814 가 마지막 이닝 칸에 8 = 9회)
- 간이 엔진 보정: 0-기준 이닝 > 9 (= **11회부터**) 이고 세기 > 50 → 세기 += (이닝−9)×5, 코스 오차 ×3 ÷ trunc(세기/20) (0xc13e0)
- 스윙 강제: 0-기준 이닝 == 14 (= **15회**, 그 이닝만) (0xc26e0)
- 웹은 1-기준 이닝에 0-기준 값(9·14)을 써서 **10회부터 보정, 14회 강제** → `from=10`, `forced=15` 로 바꾸거나 엔진에 `inning−1` 을 넘길 것
- **연장 상한 없음 · 동점 종료 없음** (0xb68fc): 원본은 점수가 갈릴 때까지 돈다 → `MAXIMUM_INNINGS = 14` 와 "동점이면 홈 승" 은 원본에 없다 (무한 루프 안전망이 필요하면 "원본에 없음" 으로 표기)
- 경기 끝 판정 (9회 이후):
  ```
  말: 아웃>2 → 점수 다르면 끝 / 아웃≤2 → 홈이 앞서면 끝(끝내기)
  초: 아웃>2 → 홈이 앞서면 끝
  콜드게임: 0-기준 이닝 > 5 (7회부터) 10점 차
  ```

### E-2. 희생플라이는 원본 간이 엔진에 없다 (확정) ⚠️ `baseState.ts:99-104`
- 간이 엔진 결과 코드 0(아웃)은 **주자를 움직이지 않는다**. 뜬공/직선타 구분도 없다.
- 웹의 "뜬공 + 3루 주자 + 2아웃 미만 → 1점" 은 CPU 경기에 원본보다 점수를 더 낸다 → CPU 경기(`simulateHalfInning.ts:93`)에서는 빼야 함

### E-3. 땅볼 진루타 난수 순서 (확정) ⚠️ `simulateHalfInning.ts:92-98`
- 원본: 아웃 ≤1 이면 **주자가 없어도** rand(0,10000) 을 먼저 뽑고, ≤ 5999 일 때 주자·3루 조건을 본다
- 웹은 조건이 맞을 때만 뽑는다 → 같은 시드 재현을 원하면 순서를 맞출 것

### E-4. 간이 엔진 결과 코드 25칸 (0xc11f0, 점프표 0xd9000) — 확정 (참고용 전체 표)
| 코드 | 하는 일 |
|---|---|
| 0 | 아웃 +1, 다음 타자. 주자 이동 없음 |
| 3 | rand(0,10000) < rand(0, 주력) 면 1루타, 아니면 땅볼 아웃 + 진루타 판정 |
| 6·7·8 | 번트: 진루타 판정 → 아웃 |
| 9 | 파울: 스트라이크 ≤1 이면 +1 |
| 12 | 1루타 (타자 1루 + 전 주자 1루씩) |
| 15·18 | rand(0,666) < rand(0, 주력) 면 코드+3 → 루타 = (코드−15)/3+1 |
| 21 | 3루타 (18+3 으로만 생김) |
| 24 | 홈런 (타자+주자 전원 득점) |
| 나머지 | 스트라이크 +1, 3이면 삼진 |
- 간이 엔진은 한 타석에 아웃을 **1개만** 만든다 → 병살·삼중살이 CPU 경기에서 나올 수 없다

### E-5. CPU 경기의 도루 (유력) ⚠️ 웹 간이 엔진에 **도루 자체가 없다**
- 투구 판정 경로(0xc1818, 볼·스트라이크) 뒤에만:
  ```
  if 주자 > 0:
      lead = 가장 앞선 주자; 주력 = min(실효 주루, 999)
      if lead.루 != 3 and rand(0,10000) < 표0xd9064[주력/100] × 100:
          모든 주자 +1루, 각 주자 도루 +1
  (실패 없음 — 안 되면 아무 일도 없다. 투수·포수 능력 무관)
  ```
- 표 0xd9064 = [1,5,10,15,20,30,40,50,60,80] (웹 `steal.ts` 가 이미 가진 표)

### E-6. CPU 투수 교체 (유력 — 식 일부 미확인) ⚠️ 웹은 선발 고정
*(검증 V3 정정: 아래 이닝은 원본 0-기준 값을 1-기준 회로 바꿨다. 1차 노트는 0-기준 숫자를 회로 적었고, 새 투수 고르기 방향도 반대로 적었다)*
- 간이 타석마다 0xc1ba4 를 먼저 부른다:
  1. 특정 모드(state[1]==3)에서 **8회**(0-기준 7)에 벤치의 첫 마선수로 교체 (못 찾거나 8회가 아니면 2로)
  2. 그 밖: 먼저 0xac228(공격측, 뜻 미확인)을 부르고, 이어서 CPU 수비 AI 0xac428 (0x66864 거짓이거나 모드 3 에서 현재 투수가 마선수면 건너뜀)
- 0xac428 조건 (리드 = 수비 − 공격 점수, s = 체력% = 투수 +0x2c ÷ 100 (모드 7 은 100), A = team+0x284, B = team+0x280):
  - 벤치가 비었으면 안 바꿈 (벤치 ≤1 이고 벤치 0번이 마선수이며 모드 3 이어도 안 바꿈). 교체 직후 한 투구 동안 막힘
  - 특수 투수: A>2 or B>3 or s≤39 → 교체
  - 역할 0·1: A>2 or s≤19 → 교체. 아니면 **1~4회**: B>4 / **5회**: B>4 and s≤49 / **7회**: B>2 and s≤29 / **6회·8회 이상**: A>1. **9회 이상**은 0<리드≤5 이고 (리드≤3 or 리드≤주자수+2) 면 "마무리 상황"
  - 역할 2: A≠0 and 리드 ≤ −2 → 교체
  - 새 투수: **마무리 상황이 아니고** 0xb8a8d(team,0) 참이면 0xac360 검사 → 참이면 벤치 마지막, 거짓이면 (벤치≤1 → 0번 / 아니면 0xabfcc). **마무리 상황이거나 0xb8a8d 거짓이면 0xabfcc**. 모드 3 이면 마선수를 건너뛰고 다시 고름
- 투구마다 투구 수(+0x28) 증가, 체력 소모 — 웹 `quickAtBat` 의 stamina 는 고정값
- **미확인**: A·B 가 무엇인지(피안타/실점/볼넷), 0xabfcc(새 투수 고르기) 내부 → 이식 전에 먼저 풀어야 함

### E-7. 투수 미션 조준점 흔들림 (확정) — 미션 조건코드(레코드 바이트 13)
- 투수 조준 매 틱 (0x39c5c, 투수 미션 모드 5 일 때만):
  ```
  조준 x += 입력dx×20, y += 입력dy×20 → 존 중심 기준 x ±600, y ±400 으로 자름
  조건코드 1: rand(0,100) ≤ 50 이면 x += rand(−40,40)
  조건코드 2: rand(0,100) ≤ 50 이면 x += rand(−80,80); y += rand(−80,80)
  조건코드 3: rand(0,100) ≤ 50 이면 x = rand(중심x−600, 중심x+600); y = rand(중심y−400, 중심y+400)
  ```
- 붙은 미션: 투수 4 로제·5 "흔들리지 않는 마음" = 1 · 투수 8 크라이져·12 킹타이거 = 2 · 투수 10 "난공불락의 철벽마무리" = 3. 타자편은 모두 0
- 웹: `missions.ts` `conditionCode` 를 읽기만 함 → 투수 미션 조준 입력에 넣을 것 (`pages/pitching`)

### E-8. 그라운드 홈런 (확정) — 웹은 3루타로 셈
- 타자주자가 **플레이 중 홈에 닿으면** 홈런으로 센다 (0xaa0a8 → state+0x25): 선수 홈런 +1, 솔로~만루 기록, 연속 홈런, **미션용 그라운드홈런 수 +1**
- 웹 타구 근사(`battedBallOutcome.ts`)에는 장내 홈런을 만들 길이 없다 → 수비 시뮬레이션(E-10, I 참고)이 들어와야 생긴다. 그 전까지 미션 "그라운드홈런" 판정만이라도 홈런 쪽으로 맞출 것

### E-9. 병살(26) · 삼중살(27) · 도루 저지(24) 기록 (26·27 확정, 24 유력)
- 26·27: 한 번의 플레이 정산에서 **아웃 이벤트(삼진 5 또는 그 밖 아웃 0xd)가 2개면 병살, 3개면 삼중살**. state+0x1a 가 서 있으면 병살 기록만 막는다(뜻 미확인)
- 24: 도루를 시작한 주자가 다음 루를 노리다 득점·세이프 없이 플레이가 끝나면 (= 도루 실패 아웃)
- 모두 **사람이 수비할 때만** 나온다 → 수비 시뮬레이션이 있어야 붙일 수 있다. `gameRecords.ts` 에 자리만 두면 됨

### E-10. 사용자 타구의 수비 시뮬레이션 (부품 확정, 전체 미해결)
원본은 결과표가 없다 — 타구를 3D 정수 물리로 날리고 수비수·주자가 매 틱 움직여 "누가 먼저 닿는가" 로 판정한다. 루타 수 = 플레이가 끝났을 때 타자주자가 서 있는 루.
- 공 물리 (0xa28c0, 틱마다): `x += cos(각)·속도 >>16`, `z += sin(각)·속도 >>16`, `y = y0 + v0·t − g·t²/2` (y<0 → 0). 궤적 최대 130점
- 결과 코드 25·26 이면 2% 로 특수 타구 표 0xcfb3c (6바이트 × 4)
- 수비수 9명 시작 위치 (x,y,z): 0 투수 (20000,0,24500) · 1 포수 (20000,0,29705) · 2 (25068,0,23275) · 3 (22130,0,19610) · 4 (14664,0,22750) · 5 (17273,0,19150) · 6 (30700,0,12300) · 7 (9100,0,12300) · 8 (20000,0,8000)
- 수비 등급 g = 실효 수비 경계 125/250/375/525/675/825/925 → 0,1,2,…
- 수비수 능력 (`data/d_level.dat`): 이동 = 3×(g+1) · 송구 = 940 + 8×(g+1) · 에러 = 10 − g
- 송구 공 중력 배율: 내야(칸 ≤5) 70% · 외야 80%. 발사각 = asin(거리·g·100/v²)/2
- **악송구**: rand(0,10000) < 에러 + (다이빙 ? 100 : 0) + 100 → 목표를 rand(−50,51)·rand(−49,51) 흩뜨림 (약 1%)
- 플레이 끝 분류 (0x9d5bc):
  ```
  포구 아웃 → 13 / 진행 중 → 0 / 경기·이닝 끝 → 11 또는 7
  담장 너머(state[0x80]>0) → state[0x1e](바운드) ? 10 안타(그라운드 룰 더블 추정) : 12 홈런
  state[0x20]>0 → state[0x1e] ? 10 : 8 홈런
  그 밖 → 6 안타
  ```
- **미해결**: 수비수가 쫓는 목표점, 포구 반경 전체 규칙(거리 상한 20400 사용처만 확인), 다이빙(필살수비) 확률, 자동 주루·태그/포스 판정. 수비 AI 함수: 0xaf284 · 0xb1edc · 0xb2c90 · 0xb3444 · 0xb3b38
- 웹 `battedBallOutcome.ts` 의 속도 문턱(800/950/1100/1300/1450)은 원본 식이 아니다

## 2. 원본 버그 — 그대로 옮기고 나중에 수정 후보
- **순위 동률 상대전적 색인 버그** (0xb79d8): 선택 정렬 중인 **배열 위치**로 팀 번호 기준 상대전적 표를 찾는다 → swap 이 한 번이라도 일어나면 엉뚱한 팀끼리 비교. 마지막 기준은 "현재 배열 위치가 앞선 팀". 웹 `league.ts:66-73` 은 바르게 정렬한다 ⚠️ — 원본대로라면 아래 선택 정렬을 그대로 옮길 것
  ```
  순서 = [0..9]
  for i in 0..8: best = i
    for j in i+1..9:
      if 승[best] < 승[j] → best = j
      elif 승 같고 패[best] > 패[j] → best = j
      elif 패도 같고 h2h[j][best] > h2h[best][j] → best = j   ; h2h 는 팀 번호 표인데 j·best 는 위치
    swap(승[i],승[best]); swap(패[i],패[best]); swap(순서[i],순서[best])
  ```
- **(재확인 필요) 하루치 경기 승패 뒤집힘** (0xc2a48): 읽은 그대로면 "B 점수 > A 점수일 때 A 승". 포스트시즌 한 경기 0xc2760 은 정상. score 칸과 side 대응을 다시 확인하기 전에는 옮기지 말 것

## 4. 상세 근거 (해독 노트 전문)

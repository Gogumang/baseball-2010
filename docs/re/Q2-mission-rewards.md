- **모드 5 = 미션 투수편, 6 = 미션 타자편** (H-modes 표의 순서가 거꾸로였다). 5 → XlsPITCHER_MISSION, 6 → XlsBATTER_MISSION.
- **미션 보상** = 레코드 1번 바이트(“stage”, 2·4·6·8·10) → 등급 d = 1~5. 0xa52b0: 첫 클리어 500·d, 2~5회째 300·d, 6~10회째 200·d, 11~20회째 100·d, 21회째~ 50·d G. 마선수 공략(id 16~20)은 0. 지급은 경기 뒤 0x4ef18 에서 G += 보상(99999 상한).
- **클리어 횟수** = 전역기록 +0x150 + 편×16 + 칸 (s8, −1 잠김 · 0 열림 · 1~99). 새 저장은 각 편 칸 0 과 이벤트 칸 14 만 열린다. 칸 i 를 처음 깨면 칸 i+1 이 열린다. 편별 14개를 모두 깨면 히든 해금이 열린다(타자 id 37, 투수 id 21).
- **재도전**: 결과 화면에 StrMAINMENU[53] 이 나오고 커서의 기본값은 “재도전”이다. 확인을 누르면 같은 미션을 곧바로 다시 하고, 커서를 옮기거나 취소하면 미션 목록으로 간다. 실패해도 불이익이나 비용은 없다.
- **선수 선택**(StrMAINMENU[14], 목록 0x62568/0x5eae0): 코드 1 육성 투수 · 2 육성 타자 · 3 명예 투수 · 4 명예 타자. 투수를 고르면 투수 미션, 타자를 고르면 타자 미션이 된다. 홈런더비는 2·4 만 받는다. 육성 선수와 명예 선수가 모두 없으면 들어갈 수 없다(신인 대체 없음). 명예 선수를 고르면 경기 선수 게터(0x1fc20/0x1fbd0)가 모드 5·6·7 에서 명전 기록을 돌려준다.
- **명예의 전당 능력치** = 등록 순간의 0x30바이트 선수 기록 사본이다(전역기록 +0x880 투수 / +0x940 타자). 등록할 때 나리 편을 초기화한다(유력). 시즌은 이 창 대신 선수영입(P4)으로 명예 선수를 쓴다.
- **전부 수집 보상 8칸 확정**: 리그 1위 1·5·10회 3000·10000·20000(0x6900, StrMODE[223]; P4 의 1000/5000/10000 은 표를 바꿔 읽은 오독) · 미션 28개 30000 · 기록달성 40종 40000 · 스킬 40종 50000 · 닉네임 64 60000 · 엔딩 20 90000. 받았는지는 전역기록 +0x145 비트로 남긴다.
남은 것: 전역기록 +0x11f / +0x176 플래그의 정확한 뜻(나리·시즌 쪽에서 부른 마선수 공략 미션으로 보임, 유력), 결과 화면 예/아니오 글자의 좌우 배치, 선택 화면 보상 표시가 0xa52b0 을 부르는지, StrMAINMENU[55] 사용처, 이벤트 미션(칸 14) 다운로드 🌐, ~~0x69c0 의 해금 id 41 조건~~(해결 2026-10-06 — 5-1).

## 1. 미션 클리어 G 보상 (1a·1b·1c) — 확정

### 1-0. 모드 번호 바로잡기 (확정)
- **모드 5 = 미션 투수편, 모드 6 = 미션 타자편.** H-modes.md 의 "5·6 미션 타자·투수" 는 순서가 거꾸로다.
  - 근거: 미션 객체 함수들이 `ldrsb [obj+0xbf]; cmp #6` 으로 편을 가르는데, 6 이면 행 크기 **0xa8=168** 표(0xa5258 → XlsBATTER_MISSION rowSize 168), 아니면 **0xa5=165** 표(0xa5284 → XlsPITCHER_MISSION rowSize 165).
  - 0x213c0 의 5→3(나리 투수), 6→4(나리 타자) 매핑과도 맞는다.

### 1a. 보상 열 = 레코드 1번 바이트("stage") (확정)
- `generate_missions` 가 `stage` 라 부르는 1번 바이트가 곧 보상 등급이다. 보상 함수 0xa52b0:
  ```
  a52c2: cmp r3,#6 → 0xa5268(obj,idx) (타자 표) / 0xa5294(obj,idx) (투수 표)   ; 레코드 포인터
  a52d8: ldrb r3,[r0,#1] ; lsls #0x1c ; lsrs #0x1d                          ; d = (byte1 >> 1) & 7
  ```
- 원본 값 2·4·6·8·10 → **d = 1·2·3·4·5** (세 미션마다 한 등급). 마선수 공략 5개(id 16~20)는 byte1 = 0 → **보상 0**.
- 레코드 고르기 0xa5268/0xa5294(obj, idx): idx ≤ 13 → 행 idx (id 1~14), **idx 14 → obj 자신을 레코드로 씀**(다운받은 이벤트 미션을 객체 안에 두는 칸으로 보인다 — 유력), idx ≥ 15 → 행 idx−1 (id 16~20). 행 주소 = [obj+0xa8] + idx×행크기 + 0x31(타자)/0x30(투수).

### 1b. 감소식 0xa52b0 (확정)
n = 그 미션의 **지금까지 클리어 횟수**(이번 클리어를 더하기 전, 0xa51d0). 나눗셈 0xca7b5 는 0 쪽 버림.
```
d <= 0            → 0
n <= 0 (첫 클리어) → (d*5 & 0x1f) * 100            ; a52fc
n 1..4            → (d*3 & 0xf) * 100               ; a5308
n 5..9            → (d*3 & 0xf) * 200 / 3           ; a531c
n 10..19          → (d*3 & 0xf) * 100 / 3           ; a5334
n >= 20           → (d*3 & 0xf) * 100 / 6           ; a534c
```
| 등급 d (byte1) | 첫 클리어 | 2~5회째 | 6~10회째 | 11~20회째 | 21회째~ |
|---|---|---|---|---|---|
| 1 (2) id 1~3 | 500 | 300 | 200 | 100 | 50 |
| 2 (4) id 4~6 | 1000 | 600 | 400 | 200 | 100 |
| 3 (6) id 7~9 | 1500 | 900 | 600 | 300 | 150 |
| 4 (8) id 10~12 | 2000 | 1200 | 800 | 400 | 200 |
| 5 (10) id 13~14 | 2500 | 1500 | 1000 | 500 | 250 |
(마스크 &0x1f/&0xf 는 d ≤ 5 에선 효과 없음.)

### 1c. 클리어 횟수 저장 위치 (확정)
- 전역 기록(0x1f1d9(0x1400054)) **+0x150 + 편×16 + idx**, s8. 편 = 0 타자(모드 6) · 1 투수(모드 5). 칸 16개씩(0x150~0x15f 타자, 0x160~0x16f 투수).
- 값 **−1 = 잠김**, 0 = 열렸지만 미클리어, 1~99 = 클리어 횟수(99 상한). 열림 판정 0xa520c = `횟수 >= 0`, 횟수 읽기 0xa51d0.
- 편별 올클리어 0xa5184: idx 0..13 (스토리 14개) 모두 횟수 > 0 → 참. 모드 6(타자) → 히든 id **37**(타자 헬멧 Lv9), 모드 5(투수) → 히든 id **21**(19번대 = 투수 장비 쪽으로 보임, 부위 미확인). (RALPH 13회차의 "28개 올 클리어 → 37" 은 타자 쪽만 맞다.)

## 2. 미션 선택·실패·재도전 (2a·2b·2c)

### 2a. 결과 화면의 재도전 (확정: 흐름 / 유력: 예·아니오 글자 배치)
- 미션 경기 끝 0x509a0: 목표 달성 → `0xa5368(미션객체, 1)`, 실패 → `0xa5368(미션객체, 0)`, 둘 다 경기 상태 **0x19**(결과 화면)로 (0x50cf8~0x50d2c). 실패(인자 0)는 횟수·보상·해금을 건드리지 않고 `[obj+0xbc] = 0` 만 적는다.
- 결과 화면 그리기 0x4a384 (게임상태 +1 = 모드 5·6 일 때): StrMAINMENU[**53**] "재도전하시겠습니까?" 를 화면에 그대로 그린다(0x4a7d4, 표 = 경기 장면 this+0x1060 = StrMAINMENU; +0x105c 는 StrGAME). 성공·실패 공통(유력 — 분기 안 보임).
- 결과 화면 키 0x407f0 (상태 0x19, 모드 5·6, 전역기록 +0x11f·+0x176 둘 다 0 일 때):
  ```
  ←/→ (−3/−4, '4'/'6')  : 커서 this+0x17f9 를 0↔1 뒤집기           ; 0x4086a
  확인 (−5, '5')        : 커서 1 → 0x140006c = 3, 커서 0 → 0x140006c = 1   ; 0x408f4~0x40908
  취소 (−16)            : 0x140006c = 1                             ; 0x408a2~0x408b6
  → 화면 전환 0xbdae9(…,1,0,5,1500) → 끝나면 0x4b100 이 장면 0x107 로
  ```
  - 커서 기본값 **1** (0x4ea0c 끝 0x4f410 `strb #1,[this+0x17f9]`).
- 장면 0x107 은 상태 0(0x1d9a4)에서 0x140006c 를 다음 상태로 삼는다(−1 이 아니면). 상태표 0x1e99c: 0 진입 · 1 목록(0x1daa4 갱신/0x1df08 그리기) · 2 0x1e798 · **3 경기 시작 0x1e908** · 4 메인 메뉴로(0x103, 하위 0x11).

  - **1 = 미션 목록으로**(커서는 방금 한 미션, 0x1da2e `this+0x9c = obj+0xbd`).
  - 즉 기본 선택(예) = 재도전, 옮기거나 취소 = 목록. 실패해도 불이익 없음(횟수·G 변화 없음), 재도전 비용 없음.

## 요약
풀린 것(모두 디스어셈 확정, 표시한 곳만 유력):
- **모드 5 = 미션 투수편, 6 = 미션 타자편** (H-modes 표의 순서가 거꾸로였다). 5 → XlsPITCHER_MISSION, 6 → XlsBATTER_MISSION.
- **미션 보상** = 레코드 1번 바이트(“stage”, 2·4·6·8·10) → 등급 d = 1~5. 0xa52b0: 첫 클리어 500·d, 2~5회째 300·d, 6~10회째 200·d, 11~20회째 100·d, 21회째~ 50·d G. 마선수 공략(id 16~20)은 0. 지급은 경기 뒤 0x4ef18 에서 G += 보상(99999 상한).
- **클리어 횟수** = 전역기록 +0x150 + 편×16 + 칸 (s8, −1 잠김 · 0 열림 · 1~99). 새 저장은 각 편 칸 0 과 이벤트 칸 14 만 열린다. 칸 i 를 처음 깨면 칸 i+1 이 열린다. 편별 14개를 모두 깨면 히든 해금이 열린다(타자 id 37, 투수 id 21).
- **재도전**: 결과 화면에 StrMAINMENU[53] 이 나오고 커서의 기본값은 “재도전”이다. 확인을 누르면 같은 미션을 곧바로 다시 하고, 커서를 옮기거나 취소하면 미션 목록으로 간다. 실패해도 불이익이나 비용은 없다.
- **선수 선택**(StrMAINMENU[14], 목록 0x62568/0x5eae0): 코드 1 육성 투수 · 2 육성 타자 · 3 명예 투수 · 4 명예 타자. 투수를 고르면 투수 미션, 타자를 고르면 타자 미션이 된다. 홈런더비는 2·4 만 받는다. 육성 선수와 명예 선수가 모두 없으면 들어갈 수 없다(신인 대체 없음). 명예 선수를 고르면 경기 선수 게터(0x1fc20/0x1fbd0)가 모드 5·6·7 에서 명전 기록을 돌려준다.
- **명예의 전당 능력치** = 등록 순간의 0x30바이트 선수 기록 사본이다(전역기록 +0x880 투수 / +0x940 타자). 등록할 때 나리 편을 초기화한다(유력). 시즌은 이 창 대신 선수영입(P4)으로 명예 선수를 쓴다.
- **전부 수집 보상 8칸 확정**: 리그 1위 1·5·10회 3000·10000·20000(0x6900, StrMODE[223]; P4 의 1000/5000/10000 은 표를 바꿔 읽은 오독) · 미션 28개 30000 · 기록달성 40종 40000 · 스킬 40종 50000 · 닉네임 64 60000 · 엔딩 20 90000. 받았는지는 전역기록 +0x145 비트로 남긴다.
남은 것: 전역기록 +0x11f / +0x176 플래그의 정확한 뜻(나리·시즌 쪽에서 부른 마선수 공략 미션으로 보임, 유력), 결과 화면 예/아니오 글자의 좌우 배치, 선택 화면 보상 표시가 0xa52b0 을 부르는지, StrMAINMENU[55] 사용처, 이벤트 미션(칸 14) 다운로드 🌐, 0x69c0 의 해금 id 41 조건.

## 1. 미션 클리어 G 보상 (1a·1b·1c) — 확정

### 1-0. 모드 번호 바로잡기 (확정)
- **모드 5 = 미션 투수편, 모드 6 = 미션 타자편.** H-modes.md 의 "5·6 미션 타자·투수" 는 순서가 거꾸로다.
  - 근거: 미션 객체 함수들이 `ldrsb [obj+0xbf]; cmp #6` 으로 편을 가르는데, 6 이면 행 크기 **0xa8=168** 표(0xa5258 → XlsBATTER_MISSION rowSize 168), 아니면 **0xa5=165** 표(0xa5284 → XlsPITCHER_MISSION rowSize 165).
  - 0x213c0 의 5→3(나리 투수), 6→4(나리 타자) 매핑과도 맞는다.

### 1a. 보상 열 = 레코드 1번 바이트("stage") (확정)
- `generate_missions` 가 `stage` 라 부르는 1번 바이트가 곧 보상 등급이다. 보상 함수 0xa52b0:
  ```
  a52c2: cmp r3,#6 → 0xa5268(obj,idx) (타자 표) / 0xa5294(obj,idx) (투수 표)   ; 레코드 포인터
  a52d8: ldrb r3,[r0,#1] ; lsls #0x1c ; lsrs #0x1d                          ; d = (byte1 >> 1) & 7
  ```
- 원본 값 2·4·6·8·10 → **d = 1·2·3·4·5** (세 미션마다 한 등급). 마선수 공략 5개(id 16~20)는 byte1 = 0 → **보상 0**.
- 레코드 고르기 0xa5268/0xa5294(obj, idx): idx ≤ 13 → 행 idx (id 1~14), **idx 14 → obj 자신을 레코드로 씀**(다운받은 이벤트 미션을 객체 안에 두는 칸으로 보인다 — 유력), idx ≥ 15 → 행 idx−1 (id 16~20). 행 주소 = [obj+0xa8] + idx×행크기 + 0x31(타자)/0x30(투수).

### 1b. 감소식 0xa52b0 (확정)
n = 그 미션의 **지금까지 클리어 횟수**(이번 클리어를 더하기 전, 0xa51d0). 나눗셈 0xca7b5 는 0 쪽 버림.
```
d <= 0            → 0
n <= 0 (첫 클리어) → (d*5 & 0x1f) * 100            ; a52fc
n 1..4            → (d*3 & 0xf) * 100               ; a5308
n 5..9            → (d*3 & 0xf) * 200 / 3           ; a531c
n 10..19          → (d*3 & 0xf) * 100 / 3           ; a5334
n >= 20           → (d*3 & 0xf) * 100 / 6           ; a534c
```
| 등급 d (byte1) | 첫 클리어 | 2~5회째 | 6~10회째 | 11~20회째 | 21회째~ |
|---|---|---|---|---|---|
| 1 (2) id 1~3 | 500 | 300 | 200 | 100 | 50 |
| 2 (4) id 4~6 | 1000 | 600 | 400 | 200 | 100 |
| 3 (6) id 7~9 | 1500 | 900 | 600 | 300 | 150 |
| 4 (8) id 10~12 | 2000 | 1200 | 800 | 400 | 200 |
| 5 (10) id 13~14 | 2500 | 1500 | 1000 | 500 | 250 |
(마스크 &0x1f/&0xf 는 d ≤ 5 에선 효과 없음.)

- 지급: 경기 뒤 처리 0x4ea0c 의 모드 5·6 갈래 **0x4ef18**:
  ```
  4ef18: 0x20095(전역, 5)                         ; (플레이 수 올림으로 보임)
  4ef28: [미션객체(this+0x178c)+0xbc] == 0 → 실패 갈래 0x4efb0 (보상 0, this+0x17f4 = 0)
  4ef3e: 전역기록+0x11f == 0 && 전역기록+0x176 == 0 일 때만:
  4ef60:   this+0x17f4 = [미션객체+0xa0]            ; 보상액(결과 화면 표시용)
  4ef72:   G(+0x64) += 보상, 99999 상한·음수면 0
  4ef86: 0xa5184(미션객체) 참 → 0x62368(…, 모드6 ? 0x25 : 0x15, 0)   ; 편별 올클리어 히든 해금
  ```
  - 전역기록 +0x11f / +0x176 이 켜져 있으면 G 를 주지 않고 클리어 여부만 +0x144 / +0x177 에 적는다(0x4efc6~0x4f018). 두 플래그는 네트워크 쪽(이벤트 미션·도전) 경로로 보인다 — 무엇인지 미확인.
  - 이 갈래에는 0x22c7d(획득 G 통계) 호출이 없다.
- 보상액 계산·기록 0xa5368(obj, 성공?) — 경기 끝에 불림:
  ```
  a5390: idx = [obj+0xbd] ; idx > 15 면 건너뜀
  a539e: [obj+0xa0] = 0xa52b0(obj)                  ; 보상액 (횟수 올리기 전)
  a53b4: 횟수[편*16+idx] += 1, 99 에서 멈춤           ; 전역기록 +0x150
  a540c: idx <= 12 이고 횟수[편*16+idx+1] == -1 → 다음 미션 열기 (0xa5114: 횟수 = 0, 저장)
  a5448: 저장 0x1f1b9 ; [obj+0xbc] = 성공?
  ```

### 1c. 클리어 횟수 저장 위치 (확정)
- 전역 기록(0x1f1d9(0x1400054)) **+0x150 + 편×16 + idx**, s8. 편 = 0 타자(모드 6) · 1 투수(모드 5). 칸 16개씩(0x150~0x15f 타자, 0x160~0x16f 투수).
- 값 **−1 = 잠김**, 0 = 열렸지만 미클리어, 1~99 = 클리어 횟수(99 상한). 열림 판정 0xa520c = `횟수 >= 0`, 횟수 읽기 0xa51d0.
- 편별 올클리어 0xa5184: idx 0..13 (스토리 14개) 모두 횟수 > 0 → 참. 모드 6(타자) → 히든 id **37**(타자 헬멧 Lv9), 모드 5(투수) → 히든 id **21**(19번대 = 투수 장비 쪽으로 보임, 부위 미확인). (RALPH 13회차의 "28개 올 클리어 → 37" 은 타자 쪽만 맞다.)

## 2. 미션 선택·실패·재도전 (2a·2b·2c)

### 2a. 결과 화면의 재도전 (확정: 흐름 / 유력: 예·아니오 글자 배치)
- 미션 경기 끝 0x509a0: 목표 달성 → `0xa5368(미션객체, 1)`, 실패 → `0xa5368(미션객체, 0)`, 둘 다 경기 상태 **0x19**(결과 화면)로 (0x50cf8~0x50d2c). 실패(인자 0)는 횟수·보상·해금을 건드리지 않고 `[obj+0xbc] = 0` 만 적는다.
- 결과 화면 그리기 0x4a384 (게임상태 +1 = 모드 5·6 일 때): StrMAINMENU[**53**] "재도전하시겠습니까?" 를 화면에 그대로 그린다(0x4a7d4, 표 = 경기 장면 this+0x1060 = StrMAINMENU; +0x105c 는 StrGAME). 성공·실패 공통(유력 — 분기 안 보임).
- 결과 화면 키 0x407f0 (상태 0x19, 모드 5·6, 전역기록 +0x11f·+0x176 둘 다 0 일 때):
  ```
  ←/→ (−3/−4, '4'/'6')  : 커서 this+0x17f9 를 0↔1 뒤집기           ; 0x4086a
  확인 (−5, '5')        : 커서 1 → 0x140006c = 3, 커서 0 → 0x140006c = 1   ; 0x408f4~0x40908
  취소 (−16)            : 0x140006c = 1                             ; 0x408a2~0x408b6
  → 화면 전환 0xbdae9(…,1,0,5,1500) → 끝나면 0x4b100 이 장면 0x107 로
  ```
  - 커서 기본값 **1** (0x4ea0c 끝 0x4f410 `strb #1,[this+0x17f9]`).
- 장면 0x107 은 상태 0(0x1d9a4)에서 0x140006c 를 다음 상태로 삼는다(−1 이 아니면). 상태표 0x1e99c: 0 진입 · 1 목록(0x1daa4 갱신/0x1df08 그리기) · 2 0x1e798 · **3 경기 시작 0x1e908** · 4 메인 메뉴로(0x103, 하위 0x11).
  - **3 = 곧바로 같은 미션 재시작**: 0x1e908 이 obj+0xbf = 모드, obj+0xbd = this+0x9c(고른 미션), `0xa5368(obj,0)`, 장면 0x104.
  - **1 = 미션 목록으로**(커서는 방금 한 미션, 0x1da2e `this+0x9c = obj+0xbd`).
  - 즉 기본 선택(예) = 재도전, 옮기거나 취소 = 목록. 실패해도 불이익 없음(횟수·G 변화 없음), 재도전 비용 없음.
- 경기 중 메뉴로 나가기 0x40140: 모드 5·6 이면 `0xa5368(obj,0)`(실패와 같음) 뒤 메인 메뉴(0x140006c=4, 장면 0x103).
- 전역기록 +0x11f 또는 +0x176 이 켜진 미션(나리/시즌 쪽에서 불려온 마선수 공략 미션으로 보임 — 유력): 재도전 커서 없음. 끝나면 모드를 저장 +0xf6(원래 모드)으로 돌리고 장면 0x105(시즌)/0x106(나리)로 돌아간다(0x4b328~0x4b376, 0x4090c~0x40942). G 보상 없이 결과만 +0x144 / +0x177 에 적는다(1b).

### 2b. 선택 화면 잠금 (확정)
- 격자 5열×3행 = 15칸: 칸 0~13 = 스토리 미션 id 1~14, **칸 14 = 이벤트(다운로드) 미션 칸**.
- 확인 키 0x1daa4 상태 0:
  ```
  1db06: 칸 == 14 → 이벤트 미션 메뉴 팝업 0x741a0(저장, 0x64, 콜백 0x1dcb1…)   ; StrMAINMENU[56] 계열
  1db26: 0xa520d(obj, 칸) = 횟수 >= 0 ?
         열림 → StrMAINMENU[61] "[%s] 미션에 도전하시겠습니까?" (이름 = 레코드+0x2e) 예/아니오 → 예면 상태 3(경기)
         잠김 → StrMAINMENU[60] "오픈 되지 않은 미션입니다. 이전 단계를 클리어해주세요" 확인 팝업
  ```
- 잠김 = 전역기록 +0x150/+0x160 칸 값 −1. 새 저장 0x9f26c: `memset(+0x150, 0xff, 32)` 뒤 **+0x150(타자 0번)·+0x160(투수 0번)·+0x15e(타자 14번)·+0x16e(투수 14번) = 0** (0x9f4b4~0x9f4d8). → 처음엔 각 편 1번 미션과 이벤트 칸만 열림.
- 여는 규칙: 칸 i(0..12) 를 **처음** 깨면 칸 i+1 을 연다(0xa540c, 이미 열려 있으면 그대로). 칸 13(id 14) 은 다음이 없다. 즉 단계가 아니라 **한 칸씩 순서대로** 열린다(StrMAINMENU[60] 의 "이전 단계"는 바로 앞 미션).
- 선택 화면 아래칸: 보상 `"!C%dG"` 와 성공 `"!C%d회"`(0xa51d1 = 횟수) — P6 2b. (표시 보상은 0xa52b0 과 같은 식일 것으로 보이나 그리기 쪽 호출은 확인 안 함 — 유력.)
- 웹 `src/pages/mission-select/ui/MissionSelectScreen.tsx:36` 은 "바로 앞 미션을 깼으면 열림" 으로 **원본과 같다**. 다만 이벤트 칸(14)·클리어 횟수 표시·보상 G 표시는 없다.

### 2c. 이벤트 미션 (칸 14) — 유력, 🌐
- 칸 14 팝업 콜백 0x1dcb0: ←/→ 로 this+0xa0 커서, 확인 시 커서 ≠ 0 이면 `[obj+0xa4]`(다운받은 미션 있음) → 하위 상태 5(= 0x1dc1e: obj+0xbd = 14 로 경기 시작), 없으면 하위 상태 3(StrMAINMENU[57] "미션이 존재하지 않습니다" 로 보임). 커서 0 쪽은 미션다운(StrMAINMENU[62], 네트워크 🌐).
- 칸 14 의 레코드는 표가 아니라 **미션 객체 자신**(0xa5268/0xa5294 가 idx 14 에서 obj 를 돌려줌) — 다운로드 데이터를 객체 앞부분에 둔다. 보상 등급도 그 byte1 에서 온다. 오프라인 이식에서는 칸 14 를 빈 칸(또는 "미션이 존재하지 않습니다")으로 두면 된다.

## 3. 미션에서 쓰는 선수 · 모드 매핑 (확정)

### 3-1. 선수 고르기 창 (메인 메뉴 하위 16 홈런더비 · 17 미션모드)
- 두 하위 상태 모두 메인 메뉴 this+0x120 의 선수 목록 객체를 0x62568(목록, 키, 0) 로 돌리고 결과 [목록+0x12c] 를 본다. 질문 머리 = StrMAINMENU[**14**] "어떤 선수로 플레이 하시겠습니까?" (0x25d78, 표 = 메인 메뉴 this+0x128 = StrMAINMENU, 팝업 종류 0x10).
- 칸 코드 0x5eae0(목록, 칸) — 칸 상태 = [목록+0x20c + 칸×8]:
  | 칸 상태 | 코드 | 뜻 | 결과 |
  |---|---|---|---|
  | 1 육성 선수 있음 | 편([목록+0x288]) 0 → **1**, 1 → **2** | 나리 투수(1) / 나리 타자(2) | 전역기록 +0xa5+편 = −1 |
  | 3 명예 선수 있음 | 편 0 → **3**, 1 → **4** | 명예 투수(3) / 명예 타자(4) | 명전 번호 → 목록+0x130, 전역기록 +0xa5+편 |
  | 2 육성 선수 없음 | 5 | StrCOMMON[38] "나만의리그 선수를 먼저 등록해야합니다" | 못 고름 |
  | 4 빈 명전 칸 | 6 | StrCOMMON[39] "명예의전당 선수를 먼저 등록해야합니다" | 못 고름 |
  | 5 잠긴 명전 칸 | 7 | StrCOMMON[45]/[54] 슬롯 현금 구매 🌐 | 못 고름 |
  - 명전 번호: 투수 = 칸−1 (칸 1~4), 타자 = 칸 ≤ 9 이면 칸−6, 아니면 칸−7 (칸 6~9, 11~14) — 4-2 의 0x62514 칸 배치와 같다. 칸 0 = 육성 투수, 칸 5 = 육성 타자(유력: 칸 상태 1/2 가 놓이는 자리).
  - 결과 기록 0x627ec~0x627f8: 코드 1→1, 2→2, 3→3, 4→4.
- 하위 17 (0x29a54, 표 0xcec00): 결과 0 → 하위 5(모드 목록), **1·3 → this+0x13c = 5**, **2·4 → 6**, 하위 0x27 → 모드 시작. → **투수를 고르면 투수 미션(모드 5), 타자를 고르면 타자 미션(모드 6)**. 미션 모드의 타자/투수 선택이 곧 이 선수 선택이다.
- 하위 16 (홈런더비): 2·4 → 모드 7 (H-modes 1절; "2/4 가 명예/육성 중 무엇" 은 **2 = 육성 타자, 4 = 명예 타자** 로 확정).
- StrMAINMENU[55] "육성타자가 없습니다…" 를 부르는 곳은 찾지 못함(r1 즉시값 0x37 + 0x702b5 조합 없음) — 원본에서 실제로 쓰는 문구는 StrCOMMON[38] 쪽이다(위 표).
- **신인 대체 없음**: 원본은 육성 선수도 명예 선수도 없으면 미션·홈런더비에 들어갈 수 없다(코드 5/6 은 팝업만). 웹은 "육성 선수가 없으면 신인 능력치"(RALPH 459) — 원본과 다름.

### 3-2. 모드 5→3 · 6→4 저장 매핑과 실제 선수
- 장면 0x107 초기화 0x1d784: this+0x88 = 모드(0x1552d14), `0x213c0(전역, 모드, 0)` — 0x213c0 이 모드 5→3(나리 투수 저장), 6→4(나리 타자 저장)으로 바꿔 올린다(H-modes). 미션 객체 = 0x1fa55(전역, 모드) → this+0x84, obj+0xbf = 모드. 표 = 0xa5588: 모드 5 → `data/XlsPITCHER_MISSION.zt1`(0xd8110), 그 밖 → `data/XlsBATTER_MISSION.zt1`(0xd812c).
- 경기에서 쓰는 선수 = 선수 게터 0x1fc74(저장, 종류): 종류 4(타자) → 0x1fc20, 3(투수) → 0x1fbd0:
  ```
  1fc20: [저장+0xbc]==0 → 0 (타자 저장 없음)
         모드(0x1552d10) ∈ {5,6,7} && 전역기록+0x11f == 0 && (s8)전역기록+0xa6 >= 0
             → 0x1f640(저장, +0xa6)       ; 명예 타자 기록
         그 밖 → [저장+0x38]              ; 나리(육성) 타자
  1fbd0: [저장+0xb8]==0 → 0
         모드 ∈ {5,6,7} && 전역기록+0x176 == 0 && (s8)전역기록+0xa5 >= 0
             → 0x1f62c(저장, +0xa5)       ; 명예 투수 기록
         그 밖 → [저장+0x3c]              ; 나리 투수
  ```
  → 미션·홈런더비에서 명예 선수를 고르면 **그 선수만** 명예 기록으로 바뀌고, 나머지 팀은 나리 저장 그대로다(유력: 팀은 0x213c0 이 올린 나리 저장).
- 웹: 미션은 육성 선수(없으면 신인), 명예 선수 선택 없음.

## 4. 명예의 전당 선수 — 선택 흐름과 능력치 출처 (확정)
- **기록 위치**: 전역기록 +0x880 + i×0x30 (투수 i 0~3, 0x1f62c) · +0x940 + i×0x30 (타자 i 0~7, 0x1f640). 한 명 = **0x30 바이트 선수 기록 통째 사본**.
- **등록 0x62d80~0x62e28** (나리 편 끝의 명전 등록): 빈 칸 0x62514 → `0x1f680(저장, 현재 선수(0x1fc20), 칸)`:
  ```
  1f682: 선수+0xa = 0x20 ; 선수+0 = 칸 − 0x38        ; 명예 선수 번호(음수 바이트) 표시
  1f69e: memcpy(전역기록+0x940+칸*0x30, 선수, 0x30)    ; (투수는 +0x880 쪽 같은 꼴)
  ```
  뒤이어 `0x224ec(저장, 4)`(타자편 초기화 — 나리 편 진행 기록을 지움, 유력), G −= 20000(0x22c29 분류 1/2), 저장, StrCOMMON[52] "등록이 완료되었습니다".
  → **능력치 = 등록 순간의 나리 선수 능력치 그대로 고정**(레벨업 없음). 이후 바뀌는 곳은 시즌 선수영입 선수의 장비 구매(0x2328c 가 명예 기록에도 반영, P4 5절)뿐.
- **홈런더비**: 하위 16 에서 코드 4(명예 타자) → 전역기록 +0xa6 = 명전 번호 → 모드 7 경기의 타자 = 0x1f640 기록. 코드 2 → +0xa6 = −1 → 나리 타자.
- **미션**: 3-1 · 3-2 대로. 투수 미션은 명예 투수(+0xa5), 타자 미션은 명예 타자(+0xa6).
- **시즌**: 이 선택창을 쓰지 않는다. 시즌 관리의 선수영입(P4 5절)으로 명예 선수를 번호별로 시즌 팀에 넣는다(0xb50ac 중복 검사, 0x1f62c/0x1f640 원본). 선수 게터는 모드 2 에서 명예 쪽으로 가지 않는다(조건이 모드 5·6·7 뿐).
- 명예 선수는 트레이드 불가 StrMODE[166].
- 웹: 명예의 전당 타자 4칸, 등록 비용 없음(K-4). 홈런더비·미션에서 명예 선수를 고르는 창 없음 → 원본은 "육성/명예 × 투수/타자" 네 갈래 + 빈칸 안내 3종.

## 5. 전부 수집 보상 8칸 — 지급 코드 (확정, K-4 의 "유력" 을 확정으로 올림)

### 5-0. 공통 저장
- **지급 여부 비트** = 전역기록 **+0x145 의 비트 k** (읽기 0x9f71c `(rec[0x145] >> k) & 1`, 켜기 0x9f709). 한 번 받으면 다시 안 준다.
- **달성 표시** = 0x22dd4(mgr, k): [mgr+0xc8] 객체 +0x106+k = 1 (기록 목록 StrGAME 48~55 칸의 달성 표시로 보임).
- **액수표** s8 0xcebd4 = [3, 10, 20, 30, 40, 50, 60, 90] × 1000 (k 0~7).

### 5-1. k = 0·1·2 시즌 리그 1위 누적 — 0x6900 · 0x85ec (시즌 쪽 두 곳)
```
69d4: 우승 수 = (s8)[0x1f55d(mgr) + 0x7a]            ; 시즌 저장의 리그 1위 횟수
69e8: 금액표 = s8 0xcbdec [3, 10, 20]  (sp+0x78)
69f6: 문턱표 = s8 0xcbdef [1, 5, 10]   (sp+0x74)
6a0e: for k in 0..2: 우승 수 >= 문턱[k] && !비트k →
        StrMODE[223] "시즌모드 리그 1위 %d회 달성 [%d G포인트] 지급" (문턱, 금액×1000)
        G += 금액×1000 (99999 상한), 비트 k 켜기(0x9f709), 저장, 0x22dd4(mgr, k)
```
- → **1회 3000 · 5회 10000 · 10회 20000 G.** (P4-season-flow 의 "3/10/20회 → 1000/5000/10000 G" 는 두 표를 뒤바꿔 읽은 것 — 0x69e8 은 sp+0x78(금액), 0x69f6 은 sp+0x74(문턱)에 복사하고 0x6a0e 가 sp+0x74 쪽을 문턱으로 비교한다.) 0x69c0 에서 해금 id 0x29(41) 이 이미 열렸으면 이 검사를 건너뛴다(뜻 미확인).

### 5-2. k = 3~7 — 판정 0x28e98 · 지급 팝업 0x292f8 (메인 메뉴 장면 0x103 하위 4, P3)
판정은 k = 3 → 7 순서로, 이미 받은 비트는 건너뛰고 **처음 만족한 k 하나** 를 돌려준다(없으면 −1). 달성 시 0x22dd4(mgr,k) + 저장.
| k | 조건 (주소) | 보상 | 제목 |
|---|---|---|---|
| 3 | 모드 5·6 저장을 차례로 올려(0x213c0) 미션 객체의 편별 올클리어 0xa5184 가 **둘 다 참** — 투수 14 + 타자 14 = 28개 모두 1회 이상 (0x28ea6~0x28f1e) | **30000** | StrMAINMENU[183] 미션모드 모두 성공 |
| 4 | [mgr+0xc8] +4..+43 (경기 중 기록달성 40종 누계, 0xd8158 표 순서) 가 **40개 모두 ≠ 0** (0x28f2c~0x28f6c) | **40000** | [184] 기록달성 모두 성공 |
| 5 | 스킬 비트 u32 두 개 [obj+0xf4](타자편) · [obj+0xf8](투수편): 비트 0~7 은 어느 쪽이든 1개(공통 8) · 비트 8~23 은 타자 16 · 투수 16 → **8 + 16 + 16 = 40** (0x28f8a~0x2905e) | **50000** | [185] 스킬 모두 수집 |
| 6 | 닉네임 공통 32 + 타자 16 + 투수 16 = 64 (P3 10-2) | **60000** | [186] 닉네임 모두 수집 |
| 7 | 전역기록 +0xa8..+0xb6 (15바이트) 와 +0xa0..+0xa4 (5바이트) 중 ≠ 0 인 칸이 **20개** (0x2928e~0x292ba) — 엔딩 20종(StrMAINMENU 189~208 과 개수 일치) | **90000** | [187] 엔딩 모두 수집 |
- 팝업 0x292f8(this, k): 제목 StrMAINMENU[180+k], 본문 StrMAINMENU[188] "달성! [%d G포인트] 지급" 에 `0xcebd4[k] × 1000`(0x2934a `movs #0xfa; lsls #2` = 1000) → 비트 k 켜기 0x9f709 → G += 보상(99999 상한, 0x293a2) → 0x22c7d(획득 G 통계).
- k 0~2 는 이 팝업으로 오지 않는다(StrMAINMENU[180~182] 는 "유료 충전·선물" 통계 칸 이름이라 맞지 않음) — 5-1 의 StrMODE[223] 로 따로 준다. 액수표만 같은 값을 공유한다.
- 웹: 전부 수집 보상 8칸 모두 없음(`src` 에 해당 문구·액수 없음).
